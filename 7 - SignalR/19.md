برای اینکه **مطمئن شوی یک کاربر واقعاً به SignalR Hub وصل شده** (و بفهمی کی وصل شد، کی قطع شد، و آیا هنوز آنلاین است یا نه)، چند روش استاندارد وجود دارد. در ادامه بهترین و عملی‌ترین روش‌ها را مرحله‌به‌مرحله توضیح می‌دهم.

---

# روش 1: استفاده از متدهای داخلی Hub (OnConnectedAsync / OnDisconnectedAsync)

SignalR زمانی که یک اتصال برقرار یا قطع می‌شود، دو متد داخلی را فراخوانی می‌کند:

```csharp
public override async Task OnConnectedAsync()
{
    var userId = Context.UserIdentifier;
    var connectionId = Context.ConnectionId;

    // ذخیره اتصال کاربر
    UserConnectionStore.Add(userId, connectionId);

    await base.OnConnectedAsync();
}

public override async Task OnDisconnectedAsync(Exception? exception)
{
    var userId = Context.UserIdentifier;
    var connectionId = Context.ConnectionId;

    // حذف اتصال
    UserConnectionStore.Remove(userId, connectionId);

    await base.OnDisconnectedAsync(exception);
}
```

### این روش چه چیزی می‌دهد؟
- **می‌فهمی چه زمانی یک کاربر وصل شد**
- **می‌فهمی چه زمانی قطع شد**
- **همه соединات‌های هم‌زمان یک کاربر (تب‌ها / دستگاه‌ها) را داری**

> *SignalR تضمین می‌کند این دو متد دقیقاً در زمان‌های درست اجرا شوند.*

# روش 2: نگهداری وضعیت اتصال در حافظه (In-Memory) یا Redis

معمولاً یک ساختار ساده نگه می‌داریم:

```
UserId → List<ConnectionId>
```

نمونه ساده:

```csharp
public static class UserConnectionStore
{
    private static readonly Dictionary<string, HashSet<string>> _connections = new();

    public static void Add(string userId, string connectionId)
    {
        lock (_connections)
        {
            if (!_connections.ContainsKey(userId))
                _connections[userId] = new HashSet<string>();

            _connections[userId].Add(connectionId);
        }
    }

    public static void Remove(string userId, string connectionId)
    {
        lock (_connections)
        {
            if (_connections.ContainsKey(userId))
            {
                _connections[userId].Remove(connectionId);

                if (_connections[userId].Count == 0)
                    _connections.Remove(userId);
            }
        }
    }

    public static bool IsUserOnline(string userId)
        => _connections.ContainsKey(userId);
}
```

### مزایا
- سریع، ساده  
- بهترین روش برای تشخیص آنلاین بودن کاربران  

### نکته مهم
اگر برنامه **کلاستر** یا **Load Balanced** باشد، باید همین اطلاعات را در **Redis** یا **SQL Server** نگهداری کرد.

# روش 3: پرسیدن از کلاینت (Heartbeat / Ping)

اگر بخواهی صد در صد مطمئن شوی که کلاینت واقعاً **زنده** است (مثلاً دیوایس sleep نشده):

- کلاینت هر X ثانیه یک پیام پینگ می‌فرستد
- سرور تاریخ آخرین پینگ را ذخیره می‌کند
- اگر مدتی پینگ نرسید → کاربر را آفلاین حساب می‌کنی

مثال:

کلاینت:

```javascript
setInterval(() => {
    connection.invoke("Heartbeat");
}, 10000);
```

سرور:

```csharp
public Task Heartbeat()
{
    var userId = Context.UserIdentifier;
    HeartbeatStore.Update(userId, DateTime.UtcNow);
    return Task.CompletedTask;
}
```

# روش 5: اطمینان از اتصال کلاینت در سمت کلاینت

کلاینت می‌تواند رویدادهای زیر را دریافت کند:

```javascript
connection.onclose(() => console.log("Disconnected"));
connection.onreconnected(() => console.log("Reconnected"));
connection.onreconnecting(() => console.log("Reconnecting..."));
```

این پیشنهاد‌شده‌ترین روش برای کنترل اتصال سمت کلاینت است.

# نتیجه‌گیری

برای اینکه **کاملاً مطمئن شوی یک کاربر به Hub وصل شده یا خیر**:

1. از `OnConnectedAsync` و `OnDisconnectedAsync` استفاده کن  
2. اتصال‌ها را در حافظه یا Redis نگه‌داری کن  
3. بر اساس وجود ConnectionIdها تصمیم بگیر کاربر آنلاین است یا نه  
4. اگر دقت خیلی بالا لازم داری، ذاتاً باید Heartbeat داشته باشی
