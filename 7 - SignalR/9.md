در **SignalR** ارسال پیام از **سرور به کلاینت** با استفاده از یک **اتصال دائمی (persistent connection)** انجام می‌شود. وقتی کلاینت به هاب (Hub) وصل می‌شود، سرور می‌تواند هر زمان که بخواهد برای آن پیام بفرستد، بدون اینکه کلاینت دوباره درخواست بزند.

مکانیزم به‌طور خلاصه این‌طور است:

1. **برقراری اتصال**
   - کلاینت به سرور SignalR وصل می‌شود (معمولاً از طریق WebSockets).
   - یک **ConnectionId** برای کلاینت ایجاد می‌شود.

2. **ثبت متدهای دریافت در کلاینت**
   - کلاینت مشخص می‌کند چه متدی برای دریافت پیام اجرا شود.
   - مثلاً در جاوااسکریپت:
   ```javascript
   connection.on("ReceiveMessage", function(user, message) {
       console.log(user + ": " + message);
   });
   ```

3. **ارسال پیام از سرور**
   - در سرور (داخل Hub) متدی فراخوانی می‌شود که به کلاینت پیام می‌فرستد.
   - مثال در ‎C#‎:
   ```csharp
   public async Task SendMessage(string user, string message)
   {
       await Clients.All.SendAsync("ReceiveMessage", user, message);
   }
   ```

4. **تحویل پیام به کلاینت**
   - SignalR پیام را از طریق اتصال فعال (مثلاً WebSocket) ارسال می‌کند.
   - کلاینت متد ثبت‌شده (`ReceiveMessage`) را اجرا می‌کند.

روش‌های مختلف ارسال پیام از سرور:

- **Clients.All** → به همه کلاینت‌ها  
- **Clients.Client(connectionId)** → به یک کلاینت خاص  
- **Clients.Group(groupName)** → به اعضای یک گروه  
- **Clients.User(userId)** → به یک کاربر خاص

خلاصه:  
در SignalR با ایجاد یک **ارتباط دائمی بین سرور و کلاینت** و استفاده از **Hub و متدهای Remote** اجازه می‌دهد سرور به‌صورت **real‑time** پیام را مستقیماً به کلاینت‌ها push کند.
