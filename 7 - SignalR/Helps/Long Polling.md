## مکانیزم Long Polling در SignalR

مکانیزم **Long Polling** یکی از روش‌های انتقال داده در **SignalR** (و به طور کلی در ارتباطات وب) است که برای شبیه‌سازی ارتباط Real-time بین کلاینت و سرور استفاده می‌شود.

### چگونه کار می‌کند؟

1. **درخواست اولیه**: کلاینت (مرورگر) یک درخواست HTTP به سرور ارسال می‌کند.
    
2. **انتظار سرور**: سرور درخواست را باز نگه می‌دارد و **منتظر می‌ماند** تا داده جدیدی برای ارسال وجود داشته باشد.
    
3. **ارسال پاسخ**: وقتی داده جدیدی تولید شود یا زمان مشخصی (Timeout) بگذرد، سرور پاسخ را برمی‌گرداند.
    
4. **تکرار بلافاصله**: کلاینت بلافاصله پس از دریافت پاسخ، یک درخواست Long Polling جدید ارسال می‌کند و این چرخه ادامه می‌یابد.
    

### مزایا

- **سازگاری بالا** ✅: در تمام مرورگرها و پروکسی‌ها کار می‌کند (بر خلاف WebSocket)
    
- **بدون نیاز به پورت خاص** ✅: فقط از پورت‌های استاندارد HTTP (80 و 443) استفاده می‌کند
    
- استفاده از **Fallback مناسب** ✅: در SignalR، وقتی WebSocket یا Server-Sent Events در دسترس نباشند، به Long Polling Fallback می‌شود

### معایب

- **تاخیر بیشتر** ❌: هر درخواست جدید نیاز به اتصال مجدد دارد
    
- **سربار بالا** ❌: تعداد زیادی درخواست HTTP خالی ایجاد می‌شود
    
- **مصرف حافظه سرور** ❌: هر اتصال باز باعث اشغال منابع سرور می‌شود
    
- **مقیاس‌پذیری کمتر** ❌: نسبت به WebSocket برای تعداد کاربران بالا مناسب نیست
    

### مقایسه با روش‌های دیگر SignalR

|مکانیزم|Real-time|سرعت|سربار|پشتیبانی مرورگر|
|---|---|---|---|---|
|**WebSocket**|عالی|خیلی بالا|کم|مدرن|
|**Server-Sent Events**|خوب|بالا|متوسط|خوب (به جز IE)|
|**Long Polling**|متوسط|پایین|زیاد|همه مرورگرها|

### مثال ساده در SignalR
‏‏‫‫‏‏‫‫
خود **SignalR** **به صورت خودکار بهترین روش را انتخاب می‌کند، اما می‌توان** **Transport‌****ها را محدود کرد****:**

```csharp

// در سمت کلاینت (JavaScript)
const connection = new signalR.HubConnectionBuilder()
    .withUrl("/chatHub", {
        transport: signalR.HttpTransportType.LongPolling
    })
    .build();
// در سمت سرور (ASP.NET Core)
app.UseEndpoints(endpoints =>
{
    endpoints.MapHub<ChatHub>("/chatHub", options =>
    {
        options.Transports = HttpTransportType.LongPolling;
    });
});
```
### جمع‌بندی

مکانیزم **Long Polling** یک روش **سازگار اما کند** است که در SignalR به عنوان **Fallback مکانیزم** استفاده می‌شود. برای برنامه‌هایی که نیاز به Real-time واقعی و مقیاس‌پذیری بالا دارند، **WebSocket** گزینه بهتری است، اما Long Polling تضمین می‌کند که برنامه در هر محیطی (مثل پروکسی‌های قدیمی یا مرورگرهای ضعیف) کار کند.
