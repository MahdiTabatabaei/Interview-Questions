درواقع MQTT یک **پروتکل پیام‌رسان سبک** برای دستگاه‌های IoT است.

ویژگی‌ها:

- lightweight
- مناسب شبکه‌های ضعیف
- TCP based
- publish/subscribe

تفاوت با RabbitMQ/Kafka:
![[1_difference_MQTT_vs_RabbitMQ_vs_Kafka.png]]

---

درواقع **MQTT** یک **پروتکل پیام‌رسانی سبک (Lightweight Messaging Protocol)** است که بیشتر برای **IoT، دستگاه‌های کم‌مصرف و شبکه‌های ناپایدار** طراحی شده است.  
وقتی می‌گوییم *MQTT Message Broker*، منظور سیستمی است که پیام‌ها را طبق پروتکل MQTT مدیریت می‌کند (مثل **Mosquitto، EMQX، HiveMQ**).

در مقابل، **RabbitMQ** و **Kafka** پیام‌بروکرهای «سنتی / سازمانی» هستند که برای **سیستم‌های بک‌اند با حجم بالا** طراحی شده‌اند.

---

# پروتکل MQTT چیست؟

MQTT مخفف:

```
Message Queuing Telemetry Transport
```

ویژگی‌های کلیدی:

- بسیار **سبک**
- مصرف کم **CPU / RAM / Network**
- مناسب **شبکه‌های ناپایدار**
- مدل **Publish / Subscribe**
- ارتباط **دائمی (TCP connection)**

معمولاً در سناریوهایی مثل:

- سنسورها
- دستگاه‌های IoT
- موبایل
- ارتباطات real-time سبک

---

# معماری MQTT

```
Device (Publisher)
        ↓
     MQTT Broker
        ↓
Device / Service (Subscriber)
```

مفاهیم اصلی:

- **Topic** (مثلاً: `home/kitchen/temperature`)
- **Client**
- **Broker**
- **QoS**

---

# QoS در MQTT (خیلی مهم)

پروتکلMQTT سه سطح تضمین تحویل دارد:

| QoS | معنی |
|----|------|
| **0** | At most once (ممکن است پیام گم شود) |
| **1** | At least once (ممکن است تکراری شود) |
| **2** | Exactly once (کندتر ولی مطمئن‌تر) |

# تفاوت MQTT با RabbitMQ و Kafka

## 1️⃣ هدف طراحی

| سیستم | هدف اصلی |
|------|---------|
| **MQTT** | IoT و دستگاه‌های کم‌مصرف |
| **RabbitMQ** | سیستم‌های توزیع‌شده، task queue |
| **Kafka** | event streaming و داده حجیم |

---

## 2️⃣ وزن و مصرف منابع

| سیستم | مصرف منابع |
|------|-----------|
| MQTT | بسیار کم |
| RabbitMQ | متوسط |
| Kafka | زیاد |

درواقع MQTT حتی روی دستگاه‌های ضعیف هم خوب کار می‌کند.

---

## 3️⃣ Throughput و مقیاس‌پذیری

| سیستم | Throughput |
|------|-----------|
| MQTT | کم تا متوسط |
| RabbitMQ | متوسط |
| Kafka | بسیار بالا (میلیون‌ها msg/sec) |

ابزار Kafka برای big data ساخته شده، MQTT نه.

---

## 4️⃣ ذخیره‌سازی پیام‌ها

| سیستم | Persistence |
|------|-------------|
| MQTT | محدود / اختیاری |
| RabbitMQ | قوی |
| Kafka | بسیار قوی (log-based) |

ابزار Kafka پیام‌ها را طولانی‌مدت نگه می‌دارد، MQTT معمولاً نه.

---

## 5️⃣ Latency

| سیستم | Latency |
|------|--------|
| MQTT | بسیار کم |
| RabbitMQ | کم |
| Kafka | کمی بیشتر |

پروتکل MQTT برای real-time عالی است.

---

## 6️⃣ مدل مصرف پیام

| سیستم | مدل |
|------|-----|
| MQTT | Pub/Sub |
| RabbitMQ | Queue + Pub/Sub |
| Kafka | Log + Consumer Group |

درواقع Kafka replay و offset دارد، MQTT معمولاً ندارد.

---

## 7️⃣ تضمین ترتیب و replay

| ویژگی | MQTT | RabbitMQ | Kafka |
|------|------|---------|-------|
| Ordering | محدود | در queue | در partition |
| Replay | ❌ | محدود | ✅ |

---

## 8️⃣ اتصال ناپایدار

پروتکل MQTT برای این ساخته شده:

- برای disconnect / reconnect
- موبایل / IoT
- شبکه ضعیف

ابزار Kafka و RabbitMQ برای این سناریوها مناسب نیستند.

---

# چه زمانی MQTT انتخاب درستی است؟

✅ وقتی:

- معماری IoT دارید
- دستگاه‌ها RAM/CPU کمی دارند
- شبکه ناپایدار است
- میزان latency بسیار مهم است
- پیام‌ها کوچک هستند

مثال‌ها:

- سنسور دما
- خانه هوشمند
- خودروهای متصل
- اپلیکیشن موبایل real-time

---

# چه زمانی MQTT مناسب نیست؟

❌ وقتی:

- میزان throughput خیلی بالا می‌خواهید
- نیاز به replay دارید
- تحلیل داده و streaming دارید
- نگهداری message retention طولانی لازم دارید

---

# خلاصه نهایی

```
MQTT = سبک، سریع، مناسب IoT
RabbitMQ = عمومی، انعطاف‌پذیر، enterprise
Kafka = سنگین، بسیار پرظرفیت، data streaming
```
