درواقع **Topic** در MQTT یک **رشته متنی (string)** است که مانند **آدرس پیام** عمل می‌کند.  

بصورتی که Publisher پیام را به یک Topic منتشر می‌کند و Broker آن پیام را برای تمام **Subscriberهایی که همان Topic را subscribe کرده‌اند** ارسال می‌کند.

بنابراین Topic در MQTT نقش **مسیر (routing path)** برای پیام‌ها را دارد.

---

# ساختار Topic در MQTT

ساختار Topicها به صورت **سلسله‌مراتبی (Hierarchical)** طراحی شده‌اند و سطوح مختلف آن با کاراکتر `/` از هم جدا می‌شوند.

ساختار کلی:

```
level1/level2/level3/...
```

هر بخش بین `/` یک **Level** محسوب می‌شود.

---

# مثال ساده

```
home/kitchen/temperature
```

ساختار آن:

```
home      → دامنه کلی (خانه)
kitchen   → مکان
temperature → نوع داده
```

اگر سنسور آشپزخانه دما را ارسال کند:

Publisher:

```
Topic: home/kitchen/temperature
Payload: 25
```

Broker پیام را برای همه Subscriberهایی که این Topic را subscribe کرده‌اند ارسال می‌کند.

---

# مثال واقعی IoT

فرض کنید یک ساختمان هوشمند دارید:

```
building1/floor2/room5/temperature
building1/floor2/room5/humidity
building1/floor2/room3/temperature
building1/floor3/room1/light
```

ساختار منطقی:

```
building / floor / room / sensor_type
```

---

# مثال Subscription

یک Subscriber می‌تواند دقیق یا با wildcard سابسکرایب کند.

دقیق:

```
building1/floor2/room5/temperature
```

wildcard:

```
building1/floor2/+/temperature
```

یا

```
building1/floor2/#
```

---

# ویژگی‌های مهم Topic

### 1. مکانیزم Broker ساختار را تفسیر نمی‌کند

درواقع MQTT Broker **هیچ معنایی برای Topic قائل نمی‌شود**؛ فقط رشته‌ها را مقایسه می‌کند.

یعنی:

```
car/speed
car/engine/temp
```

برای Broker فقط string هستند.

---

### 2. ساختار Topic از قبل ساخته نمی‌شود

برخلاف RabbitMQ یا Kafka:

- در MQTT Topic **از قبل تعریف نمی‌شود**
- با اولین publish **به طور خودکار ایجاد می‌شود**

---

### 3. حساس به حروف (Case Sensitive)

این دو متفاوت هستند:

```
home/temp
home/Temp
```

---

### 4. محدودیت کاراکترها

نمی‌توان از این‌ها در Topic استفاده کرد:

```
#  +
```

چون مخصوص wildcard هستند.

---

# تفاوت Topic در MQTT با Kafka

| ویژگی | MQTT | Kafka |
|------|------|------|
| ساختار | سلسله‌مراتبی | flat |
| wildcard | دارد | ندارد |
| ایجاد Topic | خودکار | باید ایجاد شود |
| routing | بر اساس Topic string | بر اساس partition |

---

# جمع‌بندی

تعریف Topic در MQTT:

- مسیر انتشار پیام است
- ساختار **hierarchical با `/`** دارد
- درواقع Publisher به آن publish می‌کند
- و Subscriber آن را subscribe می‌کند
- و Broker پیام را بر اساس تطابق Topic توزیع می‌کند

نمونه:

```
Publisher → home/livingroom/temp
Broker → message routing
Subscribers → receive message
```
