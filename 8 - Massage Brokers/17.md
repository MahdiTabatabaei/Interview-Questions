مفهوم Offset در Kafka یکی از کلیدی‌ترین مفاهیم برای درک نحوهٔ مصرف پیام‌هاست.  

ساده‌ترین تعریف:

درواقع Offset یک **شمارهٔ افزایشی و یکتا در هر پارتیشن** است که موقعیت هر پیام در log را مشخص می‌کند.

به عبارتی:
Offset = شمارهٔ خط پیام در پارتیشن.

---

# تعریف Offset چیست؟

هر پارتیشن Kafka یک **Log ترتیبی** است:

```
Partition 0:
Offset:   0   1   2   3   4   ...
Message: M1  M2  M3  M4  M5
```

Kafka پیام را به ته log اضافه می‌کند و Offset به صورت خودکار زیاد می‌شود.

ویژگی‌ها:

- یکتا **در همان پارتیشن** است (نه کل Topic)
- قابل تغییر نیست (immutable)
- ترتیب پیام را مشخص می‌کند

---

# ویژگی Offset چه کاربردی دارد؟

درواقع Consumerها باید بدانند:

- از کجای Log پیام بخوانند؟
- خوانده شده؟ پردازش شده؟
- اگر Crash شدند، از کجا ادامه بدهند؟

وجود Offset این مشکل را حل می‌کند.

---

# چگونه Offset مدیریت می‌شود؟

ابزار Kafka چند حالت برای مدیریت Offset دارد:

---

## 1. مدیریت خودکار (Auto Commit)

هر Consumer بعد از خواندن پیام‌ها، به صورت خودکار Offset را Commit می‌کند.

تنظیم:

```csharp
EnableAutoCommit = true,
AutoCommitIntervalMs = 5000
```

مزایا:
- ساده
- مناسب پردازش سبک و سریع

عیب:
- اگر Consumer پیام را *بخواند ولی قبل از پردازش Crash کند*، Offset جلو می‌رود → پیام از دست می‌رود (At Most Once).

---

## 2. مدیریت دستی (Manual Commit)

هر Consumer خودش بعد از **پردازش موفق** پیام، Offset را Commit می‌کند.

```csharp
EnableAutoCommit = false
```

مزایا:
- امن‌ترین روش
- تضمین At Least Once

عیب:
- کمی پیچیدگی بیشتر

---

## 3. ذخیره Offset در Kafka (روش استاندارد)

ابزار Kafka خودش یک Topic سیستمی دارد به نام:

```
__consumer_offsets
```

تمام Offsetهای Commit‌شده به صورت زیر ذخیره می‌شوند:

```
GroupId + Topic + Partition → Offset
```

ابزار Kafka این Topic را replicate می‌کند و بسیار پایدار است.

---

## 4. ذخیره Offset خارج از Kafka (غیرمعمول)

بعضی تیم‌ها Offset را در:

- دیتابیس
- دیتابیس Redis
- فایل

ذخیره می‌کنند.

این روش توصیه نمی‌شود مگر در شرایط خاص.

---

# مفهوم Commit چیست؟

درواقع Commit یعنی Consumer به Kafka می‌گوید:

"من پیام‌های این پارتیشن را تا Offset = X با موفقیت پردازش کرده‌ام، پس اگر دوباره از کار افتادم از اینجا ادامه بده."

ابزار Kafka این را در Topic `__consumer_offsets` ذخیره می‌کند.

---

# مثال ساده C# (Manual Commit)

```csharp
using Confluent.Kafka;

var config = new ConsumerConfig
{
    BootstrapServers = "localhost:9092",
    GroupId = "order-processors",
    EnableAutoCommit = false,
    AutoOffsetReset = AutoOffsetReset.Earliest
};

using var consumer = new ConsumerBuilder<string, string>(config).Build();

consumer.Subscribe("orders");

while (true)
{
    var cr = consumer.Consume();

    try
    {
        Console.WriteLine($"Processing message: {cr.Message.Value}");

        // پردازش پیام...
        // اگر موفق بود:
        consumer.Commit(cr);
    }
    catch (Exception ex)
    {
        Console.WriteLine("Error processing message");
    }
}
```

اینجا فقط وقتی پیام واقعاً پردازش شد، Offset جلو می‌رود.

---

# ارتباط Offset با تحویل پیام

معنای Modeهای معروف:

### At Most Once

- در این حالت Auto-Commit فعال
- پیام ممکن است گم شود
- سریع

### At Least Once

- در این حالت Manual Commit
- ممکن است پیام تکراری دریافت شود
- امن‌تر و استاندارد

### Exactly Once (در Kafka Streams و Transactional Producer)
- پیچیده‌تر
- بدون گم‌شدن و بدون تکرار

---

# خلاصهٔ شفاف

Offset = شمارهٔ پیام در پارتیشن  
Consumer Offset = آخرین پیام پردازش‌شده  
Commit = ثبت موقعیت پردازش در Kafka  
هدف = ادامه پردازش از نقطهٔ صحیح حتی پس از Crash
