این سه ابزار هر سه برای **انتقال پیام بین سرویس‌ها** در سیستم‌های توزیع‌شده استفاده می‌شوند، اما طراحی و هدفشان متفاوت است.

---

# 1. ابزار Kafka

**Apache Kafka** بیشتر یک **Distributed Event Streaming Platform** است تا یک Message Broker کلاسیک.

ویژگی‌های اصلی:

- مبتنی بر **Log و Stream**
- قابلیت **Throughput بسیار بالا**
- نگهداری پیام‌ها برای مدت طولانی
- امکان **Replay کردن پیام‌ها**
- مناسب برای **Event-driven architecture و data streaming**

مدل کار:

- تولیدکننده Producer پیام را در **Topic** می‌نویسد
- مصرف کننده Consumerها از Topic می‌خوانند
- پیام‌ها در **Partitionها** ذخیره می‌شوند

ویژگی مهم:

درواقع Consumer تعیین می‌کند از **کدام offset** بخواند.

کاربردهای رایج:

- Event streaming
- Data pipeline
- Event sourcing
- Analytics
- log aggregation

مثال:
```markdown

User Service → Kafka Topic → 
    Analytics Service
    Notification Service
    Recommendation Service

```
مزایا:

- مقیاس‌پذیری بسیار بالا
- تحمل خطای عالی
- مناسب Big Data

ضعف:

- برای queueهای ساده کمی پیچیده است
- میزان latency معمولاً بیشتر از RabbitMQ

---

# 2. ابزار RabbitMQ

ابزار RabbitMQ یک **Message Broker کلاسیک** است که بر پایه **AMQP protocol** کار می‌کند.

ویژگی‌ها:

- معماری Queue-based messaging
   ( پیام‌ها در صف قرار می‌گیرند تا مصرف‌کننده‌ها آن‌ها را به ترتیب دریافت و پردازش کنند )
- قابلیت routing پیشرفته
- میزان latency پایین
- مناسب task processing

مدل کار:
```markdown

Producer → Exchange → Queue → Consumer

```

درواقع Exchange تعیین می‌کند پیام به کدام queue برود.

انواع Exchange:

- Direct
- Topic
- Fanout
- Headers

کاربردها:

- background jobs
- microservices communication
- task queues
- RPC

مثال:
```markdown

Order Service → RabbitMQ → Payment Worker

```
مزایا:

- ساده برای استفاده
- قابلیت routing بسیار انعطاف‌پذیر
- و latency پایین

ضعف:

- برای streaming و داده‌های حجیم مناسب نیست
- نگهداری retention بلندمدت ندارد

---

# 3. Azure Service Bus

درواقع Service Bus یک **Managed Message Broker در Azure** است.

ویژگی‌ها:

- Queue و Topic
- **Enterprise messaging**
- built-in reliability
- dead-letter queue
- transaction support
- managed توسط Azure

مدل‌ها:

- Queue (point-to-point)
- Topic/Subscription (pub/sub)

کاربردها:

- enterprise integration
- microservices در Azure
- سیستم‌های سازمانی

مزایا:

- مدیریت ساده (serverless)
- امنیت و reliability بالا
- مناسب enterprise

ضعف:

- وابسته به Azure
- میزان throughput کمتر از Kafka

# خلاصه ساده

اگر خیلی خلاصه بگوییم:

- **Kafka → برای Event Streaming و Big Data**
- **RabbitMQ → برای Queue و Task Processing**
- **Service Bus → برای Enterprise Messaging در Azure**
