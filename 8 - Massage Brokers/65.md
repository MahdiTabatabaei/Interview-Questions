در **RabbitMQ** هر دو طرف **producer** و **consumer** *می‌توانند* Queue را ایجاد کنند، اما در عمل معمولاً یکی از این سه الگو استفاده می‌شود:

1. **Producer Queue را declare می‌کند**
2. **Consumer Queue را declare می‌کند** (خیلی رایج)
3. **Queue از قبل توسط سیستم/DevOps ساخته شده است**

نکته مهم: در RabbitMQ متد `QueueDeclare` **idempotent** است؛ یعنی اگر Queue از قبل وجود داشته باشد، دوباره ساخته نمی‌شود و فقط بررسی می‌شود که تنظیماتش یکسان باشد. بنابراین چند سرویس می‌توانند آن را declare کنند بدون مشکل.

در بسیاری از سیستم‌ها:
- مصرف کننده **Consumer** Queue را می‌سازد چون قرار است از آن مصرف کند.
- و تولید کننده **Producer** فقط به **Exchange** پیام publish می‌کند.

---

# مثال با #C

## 1. تولید کننده Producer (ارسال پیام)

تولید کنندهProducer معمولاً پیام را به **exchange** می‌فرستد.

```csharp
using RabbitMQ.Client;
using System.Text;

var factory = new ConnectionFactory() { HostName = "localhost" };

using var connection = factory.CreateConnection();
using var channel = connection.CreateModel();

channel.ExchangeDeclare(
    exchange: "orders_exchange",
    type: ExchangeType.Direct,
    durable: true);

var message = "New Order Created";
var body = Encoding.UTF8.GetBytes(message);

channel.BasicPublish(
    exchange: "orders_exchange",
    routingKey: "orders",
    basicProperties: null,
    body: body);

Console.WriteLine("Message Sent");
```

---

# 2. مصرف کننده Consumer (ساخت Queue و مصرف پیام)

```csharp
using RabbitMQ.Client;
using RabbitMQ.Client.Events;
using System.Text;

var factory = new ConnectionFactory() { HostName = "localhost" };

using var connection = factory.CreateConnection();
using var channel = connection.CreateModel();

channel.QueueDeclare(
    queue: "orders_queue",
    durable: true,
    exclusive: false,
    autoDelete: false,
    arguments: null);

channel.QueueBind(
    queue: "orders_queue",
    exchange: "orders_exchange",
    routingKey: "orders");

var consumer = new EventingBasicConsumer(channel);

consumer.Received += (model, ea) =>
{
    var body = ea.Body.ToArray();
    var message = Encoding.UTF8.GetString(body);
    Console.WriteLine($"Received: {message}");
};

channel.BasicConsume(
    queue: "orders_queue",
    autoAck: true,
    consumer: consumer);

Console.ReadLine();
```

---

اگر **هیچ‌کدام (نه Producer نه Consumer)** Queue را ایجاد نکرده باشند، رفتار بستگی به این دارد که پیام **کجا publish می‌شود**.

## حالت ۱: Producer به Exchange پیام می‌فرستد ولی Queue وجود ندارد

در RabbitMQ پیام ابتدا به **Exchange** می‌رود و Exchange باید آن را به یک **Queue** وصل‌شده (binding) ارسال کند.

اگر **هیچ Queueای به Exchange bind نشده باشد**:

- پیام **drop می‌شود (discard)**  
- یعنی پیام از بین می‌رود و ذخیره نمی‌شود.

ابزار RabbitMQ فرض می‌کند کسی برای دریافت این پیام وجود ندارد.

---

## حالت ۲: Producer مستقیم به Queue پیام بفرستد ولی Queue وجود نداشته باشد

اگر routingKey همان نام Queue باشد ولی Queue وجود نداشته باشد:

ابزار RabbitMQ خطای زیر می‌دهد:

```
NOT_FOUND - no queue 'queue_name'
```

و معمولاً **channel بسته می‌شود**.

---

## مثال ساده در C#

اگر Queue وجود نداشته باشد و declare نکرده باشیم:

```csharp
var factory = new ConnectionFactory() { HostName = "localhost" };

using var connection = factory.CreateConnection();
using var channel = connection.CreateModel();

var body = Encoding.UTF8.GetBytes("Hello");

channel.BasicPublish(
    exchange: "",
    routingKey: "test_queue",
    basicProperties: null,
    body: body);
```

اگر `test_queue` وجود نداشته باشد:

ابزار RabbitMQ این خطا را می‌دهد:

```
404 NOT_FOUND - no queue 'test_queue'
```

---

## نتیجه مهم در طراحی سیستم

به همین دلیل تقریباً همیشه یکی از این کارها انجام می‌شود:

- مصرف کننده **Consumer هنگام شروع برنامه Queue را declare می‌کند**
- یا **Producer آن را declare می‌کند**
- یا **Queue از قبل در RabbitMQ مدیریت شده است**

یعنی عملاً در اکثر پروژه‌ها قبل از ارسال پیام، Queue با `QueueDeclare` ساخته می‌شود.

---

# جمع‌بندی

در RabbitMQ:

- صف یا همان Queue را **هر دو می‌توانند declare کنند**
- معمولاً **Consumer آن را ایجاد می‌کند**
- تولید کننده Producer بیشتر با **Exchange** کار می‌کند
- تعریف `QueueDeclare` امن است و اگر Queue وجود داشته باشد خطا نمی‌دهد
