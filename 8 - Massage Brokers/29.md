
# ✅ تعریف Acknowledgment (ACK) چیست؟

درواقع **ACK یعنی تأیید دریافت و پردازش موفق پیام.**

وقتی Consumer یک پیام را دریافت و با موفقیت پردازش می‌کند، به Broker می‌گوید:

> ✅ این پیام را با موفقیت پردازش کردم، دیگر لازم نیست دوباره برایم بفرستی.

---

## چرا ACK مهم است؟

چون Broker باید بداند:

- پیام پردازش شده؟
- باید دوباره ارسال شود؟
- می‌توان آن را از صف حذف کرد؟

بدون ACK، سیستم نمی‌تواند At-least-once را تضمین کند.

---

# ❌ تعریف Negative Acknowledgment (NACK) چیست؟

درواقع **NACK یعنی اعلام شکست پردازش پیام.**

در این وضعیت Consumer به Broker می‌گوید:

> ❌ نتوانستم این پیام را پردازش کنم.

بسته به تنظیمات سیستم، Broker ممکن است:

- پیام را دوباره ارسال کند (Retry)
- آن را به Dead Letter Queue بفرستد
- یا Drop کند

---

# تفاوت اصلی ACK و NACK

| مورد | ACK | NACK |
|------|-----|------|
| معنی | پردازش موفق | پردازش ناموفق |
| نتیجه معمول | حذف پیام از صف | ارسال مجدد یا DLQ |
| هدف | جلوگیری از تکرار | جلوگیری از از دست رفتن پیام |

---

# در RabbitMQ چگونه است؟

ابزار RabbitMQ به صورت واضح ACK/NACK دارد.

### حالت Manual Ack:

```csharp
channel.BasicAck(deliveryTag, false);
```

یا در صورت خطا:

```csharp
channel.BasicNack(deliveryTag, false, true);
```

پارامتر آخر مشخص می‌کند:

```
true  → پیام دوباره در صف قرار گیرد (requeue)
false → پیام حذف یا به DLQ برود
```

---

# در Kafka چطور؟

ابزار Kafka دقیقاً ACK/NACK به شکل RabbitMQ ندارد.

در Kafka مفهوم ACK معادل **Commit Offset** است.

### ✅ Commit Offset = ACK

وقتی Consumer Offset را commit می‌کند یعنی:

> تا این پیام را با موفقیت پردازش کردم.

### ❌ اگر Commit نکند (Crash کند)

ابزار Kafka آن پیام را دوباره می‌دهد → مشابه NACK غیرمستقیم

---

# مفهوم ACK در سمت Producer (Kafka)

در Kafka یک نوع دیگر ACK هم داریم:

### Producer Acks

```properties
acks=0
acks=1
acks=all
```

| مقدار | معنی |
|--------|-------|
| 0 | منتظر تأیید نمی‌ماند (سریع ولی خطرناک) |
| 1 | فقط Leader تأیید کند کافی است |
| all | همه ISRها تأیید کنند (ایمن‌ترین حالت) |

این ACK مربوط به **نوشتن پیام روی Kafka** است، نه مصرف آن.

---

# نقش ACK/NACK در سطوح تحویل پیام

| مدل تحویل | نقش ACK |
|------------|-----------|
| At-most-once | ACK قبل از پردازش |
| At-least-once | ACK بعد از پردازش |
| Exactly-once | ACK + Transaction + Idempotency |

---

# مثال واقعی

فرض کن پیام "پرداخت 100 هزار تومان" دریافت شده.

### حالت ACK درست:

- پول کم شد ✅
- سپس ACK ارسال شد ✅
- پیام حذف شد ✅

### اگر قبل از ACK Crash شود:

- پول کم شده ❗
- ولی ACK نرفته ❗
- پیام دوباره می‌آید → دوبار پول کم می‌شود  

👉 اینجاست که Idempotency مهم می‌شود.

---

# جمع‌بندی ساده

| مفهوم | معنی ساده |
|--------|------------|
| ACK | پیام را درست انجام دادم |
| NACK | پیام را نتوانستم انجام دهم |
| Kafka | Commit Offset = ACK |
| RabbitMQ | BasicAck / BasicNack |
