**Consumer Group** در Kafka مکانیزمی است که چند Consumer را در قالب یک گروه قرار می‌دهد تا پیام‌های یک Topic را **به صورت موازی و بدون تکرار** پردازش کنند.

به زبان ساده:  
Consumer Group باعث می‌شود **کار خواندن پیام‌ها بین چند Consumer تقسیم شود**.

---

## مفهوم اصلی
وقتی چند Consumer با **یک `GroupId` یکسان** اجرا شوند، Kafka آن‌ها را یک **Consumer Group** در نظر می‌گیرد.

در این حالت Kafka:
- پارتیشن‌های Topic را بین Consumerهای گروه **تقسیم می‌کند**.

قانون مهم:

- هر **پارتیشن فقط توسط یک Consumer در یک Group خوانده می‌شود**.

اما:
- یک Consumer می‌تواند **چند پارتیشن** داشته باشد.

---

## مثال

فرض کن Topic زیر را داریم:

```
Topic: orders
Partitions: 4
```

و یک Consumer Group:

```
Group: order-processors
Consumers: C1, C2
```

تقسیم پارتیشن‌ها:

```
C1 → partition 0,1
C2 → partition 2,3
```

حالا هر دو Consumer **همزمان پیام‌ها را پردازش می‌کنند**.

---

## اگر Consumer جدید اضافه شود

```
Consumers: C1, C2, C3
Partitions: 4
```

Kafka یک **Rebalance** انجام می‌دهد:

```
C1 → partition 0
C2 → partition 1
C3 → partition 2,3
```

کار بین Consumerها دوباره توزیع می‌شود.

---

## اگر Consumer از کار بیفتد

مثلاً C2 Crash کند:

قبل:

```
C1 → p0
C2 → p1
C3 → p2,p3
```

بعد از Rebalance:

```
C1 → p0,p1
C3 → p2,p3
```

هیچ پیامى از دست نمی‌رود و پردازش ادامه پیدا می‌کند.

---

# چگونه باعث مقیاس‌پذیری می‌شود؟

Consumer Group دو نوع مقیاس‌پذیری ایجاد می‌کند:

### 1. Parallel Processing
چند Consumer می‌توانند **همزمان پیام‌ها را پردازش کنند**.

مثال:

```
10000 پیام در ثانیه
```

اگر یک Consumer باشد:

```
1 Consumer → 10000 msg/s
```

اگر 5 Consumer باشد:

```
5 Consumers → هر کدام ~2000 msg/s
```

پردازش سریع‌تر می‌شود.

---

### 2. Horizontal Scaling
اگر بار سیستم زیاد شود، فقط **Consumer جدید اضافه می‌کنیم**.

نیازی به تغییر Topic یا Producer نیست.

---

## نکته مهم درباره تعداد پارتیشن

حداکثر Parallelism = **تعداد پارتیشن‌ها**

مثلاً:

```
Partitions = 4
Consumers = 10
```

در این حالت:

```
4 Consumer فعال
6 Consumer بیکار
```

چون فقط 4 پارتیشن داریم.

---

# مثال ساده C#

### Consumer در یک Consumer Group

```csharp
using Confluent.Kafka;

var config = new ConsumerConfig
{
    BootstrapServers = "localhost:9092",
    GroupId = "order-processors",
    AutoOffsetReset = AutoOffsetReset.Earliest
};

using var consumer = new ConsumerBuilder<string, string>(config).Build();

consumer.Subscribe("orders");

while (true)
{
    var result = consumer.Consume();
    
    Console.WriteLine(
        $"Consumer {config.GroupId} - Partition {result.Partition} - {result.Message.Value}");
}
```

اگر همین برنامه را **چند بار اجرا کنی**:

```
dotnet run
dotnet run
dotnet run
```

Kafka آن‌ها را در یک **Consumer Group** قرار می‌دهد و پارتیشن‌ها را بینشان تقسیم می‌کند.

---

## خلاصه

Topic → دسته پیام‌ها  
Partition → تقسیم Topic برای پردازش موازی  
Consumer Group → تقسیم پارتیشن‌ها بین Consumerها

نتیجه:

- پردازش موازی
- افزایش throughput
- مقیاس‌پذیری افقی
- تحمل خطا (Failover)
