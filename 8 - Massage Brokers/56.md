در EMQX، امنیت در دو لایه اصلی پیاده‌سازی می‌شود:

- ✅ ابتدا **Authentication** → این کاربر/دستگاه کیست؟
- ✅ تعیین دسترسی **Authorization (ACL)** → این کاربر به چه Topicهایی دسترسی دارد؟

بیایید هرکدام را دقیق و عملی بررسی کنیم.

---

# ✅ 1️⃣ مفهوم Authentication در EMQX

درواقع Authentication هنگام **CONNECT** شدن Client انجام می‌شود.

ابزار EMQX چندین روش مختلف پشتیبانی می‌کند:

---

## 🔹 1. Username / Password

ساده‌ترین روش.

هر Client هنگام اتصال می‌فرستد:

```text
ClientID
Username
Password
```

ابزار EMQX می‌تواند این اطلاعات را از منابع مختلف بررسی کند:

### ✅ فایل داخلی (Built-in Database)

```bash
emqx ctl admins add user1 password1
```

یا از طریق Dashboard.

---

### ✅ دیتابیس خارجی

- MySQL
- PostgreSQL
- MongoDB
- Redis

درواقع EMQX کوئری اجرا می‌کند:

```sql
SELECT password_hash FROM mqtt_users WHERE username = ?
```

---

### ✅ HTTP Authentication

EMQX درخواست HTTP به سرویس شما می‌فرستد:

```http
POST /auth
{
  "clientid": "...",
  "username": "...",
  "password": "..."
}
```

اگر پاسخ 200 باشد → اتصال مجاز

📌 مناسب برای microservice architecture

---

## 🔹 2. مکانیزم JWT Authentication

درواقع Client یک JWT Token به عنوان password می‌فرستد.

EMQX:

- امضا را بررسی می‌کند (HMAC یا RSA)
- سپس expiration را چک می‌کند
- و claimها را استخراج می‌کند

مزایا:
- قابلیت Stateless
- مناسب Cloud
- قابل ادغام با OAuth2

---

## 🔹 3. قابلیت TLS / mTLS (Certificate-based)

امن‌ترین روش برای IoT صنعتی.

### ✅ TLS ساده

فقط server certificate بررسی می‌شود.

### ✅ mTLS (Mutual TLS)

- Server certificate
- Client certificate

EMQX:

- وقتی certificate را verify می‌کند
- می‌تواند CN یا SAN را به عنوان identity استفاده کند

مناسب برای:
- دستگاه‌های IoT
- کارخانه‌ها
- سیستم‌های حساس

---

## 🔹 4. قابلیت LDAP Authentication

برای سازمان‌ها:

```
Active Directory
Enterprise LDAP
```

ابزار EMQX به LDAP متصل می‌شود و کاربر را بررسی می‌کند.

---

## 🔹 5. قابلیت Built-in Authentication (EMQX 5+)

در EMQX 5 سیستم Authentication Chain دارد:

می‌توان چند روش را پشت‌سرهم تعریف کرد:

```
JWT → MySQL → HTTP
```

اگر اولی fail شد، سراغ بعدی می‌رود.

# ✅ 2️⃣ ویژگی Authorization (ACL) در EMQX

بعد از اینکه کاربر احراز هویت شد، باید مشخص شود:

- می‌تواند publish کند؟
- می‌تواند subscribe کند؟
- روی چه Topicهایی؟

---

## 🔹 ویژگی ACL (Access Control List)

ابزار EMQX از Rule-based ACL استفاده می‌کند.

مثال:

```text
{allow, {user, "device1"}, publish, ["sensors/device1/#"]}.
{deny, all, subscribe, ["#"]}.
```

یعنی:

- کنترل میشود device1 فقط روی topic خودش publish کند
- هیچ کس اجازه subscribe عمومی ندارد

---

## 🔹 قابلیت Topic-based Authorization

می‌توان از:

- username
- clientid
- IP
- certificate CN

در rule استفاده کرد.

مثال:

```
allow publish topic: sensors/${clientid}/#
```

یعنی هر دستگاه فقط روی topic خودش publish کند.

---

## 🔹 Authorization از دیتابیس

مثل Authentication می‌توان ACL را از:

- MySQL
- PostgreSQL
- MongoDB
- Redis
- HTTP

خواند.

مثال کوئری:

```sql
SELECT permission FROM mqtt_acl
WHERE username = ?
AND topic = ?
```

---

# ✅ 3️⃣ ترکیب Authentication + Authorization

سناریوی واقعی IoT:

1. Device با mTLS وصل می‌شود.
2. EMQX certificate را verify می‌کند.
3. CN = device123 استخراج می‌شود.
4. ACL rule:

```
allow publish sensors/device123/#
```

✅ امنیت کامل  
✅ بدون نیاز به password  
✅ جلوگیری از impersonation  

---

# ✅ 4️⃣ ویژگی Dynamic Authorization (در EMQX 5)

ابزار EMQX 5 از Authorization Chain پشتیبانی می‌کند.

می‌توان گفت:

```
Check Redis ACL
اگر نبود → Check MySQL
اگر نبود → Deny
```

---

# ✅ 5️⃣ نمونه Best Practice در مقیاس بالا

برای میلیون‌ها دستگاه:

- ✅ mTLS برای Authentication
- ✅ Topic isolation بر اساس clientid
- ✅ Deny-by-default policy
- ✅ استفاده از JWT برای اپلیکیشن‌ها
- ✅ Rate limit و connection limit

# ✅ تفاوت Authentication و Authorization

| مورد | Authentication | Authorization |
|------|--------------|--------------|
| چه چیزی بررسی می‌شود؟ | هویت | دسترسی |
| چه زمانی؟ | هنگام CONNECT | هنگام publish/subscribe |
| مثال | password، JWT | ACL rule |

---

# ✅ خلاصه نهایی

EMQX از روش‌های مختلف Authentication مانند:

- Username/Password
- JWT
- TLS / mTLS
- LDAP
- HTTP
- Database-backed auth

و برای Authorization از:

- ACL Rule-based
- Topic pattern
- DB/HTTP backend
- Dynamic chain

پشتیبانی می‌کند و می‌تواند در مقیاس صنعتی (میلیون‌ها دستگاه) به‌صورت امن اجرا شود.
