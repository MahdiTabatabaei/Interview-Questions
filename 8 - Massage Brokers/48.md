قابلیت **Retained Message** در MQTT قابلیتی است که باعث می‌شود **Broker آخرین پیام منتشرشده برای یک Topic را ذخیره کند** و هر **Subscriber جدیدی که آن Topic را subscribe می‌کند بلافاصله همان پیام آخر را دریافت کند**.

یعنی به‌جای این‌که مشترک منتظر پیام بعدی بماند، **آخرین وضعیت سیستم فوراً به او داده می‌شود**.

---

# مشکل بدون Retained Message

فرض کنید یک سنسور دما دارید:

در این حالت Publisher پیام می‌فرستد:

```
Topic: home/kitchen/temp
Payload: 24
```

اگر Subscriber بعد از ارسال این پیام وصل شود:

```
Mobile App → subscribe home/kitchen/temp
```

هیچ پیامی دریافت نمی‌کند چون پیام قبلاً ارسال شده و تمام شده است.

---

# رفتار با Retained Message

اگر Publisher پیام را با **retain flag** ارسال کند:

```
Topic: home/kitchen/temp
Payload: 24
Retain = true
```

در این حالت Broker این پیام را ذخیره می‌کند.

حالا اگر یک Subscriber جدید وصل شود:

```
subscribe → home/kitchen/temp
```

اینجا Broker فوراً آخرین پیام ذخیره شده را می‌فرستد:

```
24
```

حتی اگر آن پیام ساعت‌ها قبل ارسال شده باشد.

---

# مثال واقعی (خانه هوشمند)

یک لامپ هوشمند داریم.

Publisher:

```
Topic: home/light/status
Payload: ON
Retain = true
```

وقتی Broker آخرین وضعیت را نگه می‌دارد.

اگر اپلیکیشن موبایل بعداً وصل شود:

```
subscribe → home/light/status
```

بلافاصله دریافت می‌کند:

```
ON
```

بدون اینکه لازم باشد لامپ دوباره پیام بفرستد.

---

# تفاوت Retained Message با پیام معمولی

| ویژگی | پیام معمولی | Retained Message |
|------|-------------|----------------|
| ذخیره در Broker | ❌ | ✅ |
| ارسال به Subscriber جدید | ❌ | ✅ |
| نگهداری آخرین state | ❌ | ✅ |

---

# نحوه حذف Retained Message

برای حذف retained message باید یک پیام **خالی** با retain ارسال شود:

```
Topic: home/kitchen/temp
Payload: ""
Retain = true
```

با این کار Broker پیام ذخیره‌شده را پاک می‌کند.

---

# کاربردهای مهم Retained Message

### 1️⃣ نگهداری آخرین وضعیت دستگاه
مثلاً:

```
device/123/status
online
```

---

### 2️⃣ وضعیت سنسورها

```
factory/machine1/temp
```

---

### 3️⃣ تنظیمات سیستم

```
system/config/mode
AUTO
```

---

### 4️⃣ Service Discovery

دستگاه‌ها اعلام می‌کنند که فعال هستند.

---

# نکته مهم

درواقع Broker **فقط آخرین پیام retained هر Topic را نگه می‌دارد**، نه همه پیام‌ها.

یعنی:

```
temp = 20
temp = 21
temp = 22
```

فقط:

```
22
```

ذخیره می‌شود.

---

✅ **خلاصه**

مفهوم Retained Message در MQTT یعنی:

> این قابلیت مهم که Broker آخرین پیام یک Topic را ذخیره می‌کند و آن را به هر Subscriber جدید فوراً ارسال می‌کند.

برای سیستم‌هایی که **آخرین state مهم است** بسیار مفید است.
