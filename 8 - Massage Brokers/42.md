درواقع **Batching** یعنی چند پیام به‌جای ارسال یا پردازش تک‌تک، **در یک بسته (batch)** جمع شوند و با هم ارسال یا پردازش شوند.

مثال ساده:

بدون batching:

```
send(msg1)
send(msg2)
send(msg3)
send(msg4)
```

با batching:

```
send([msg1, msg2, msg3, msg4])
```

---

# مزایای Batching

## 1. افزایش Throughput

وقتی چند پیام با هم ارسال شوند:

- تعداد درخواست‌های شبکه کمتر می‌شود
- سربار (overhead) پروتکل کاهش می‌یابد

مثلاً:

بدون batching:

```
1000 request/sec
```

با batching:

```
100 request/sec
هر request شامل 10 پیام
```

نتیجه: throughput بالاتر.

---

## 2. استفاده بهتر از شبکه (Network Efficiency)

هر request شبکه overhead دارد مثل:

- TCP header
- serialization
- syscall

وقتی چند پیام در یک request قرار بگیرند:

```
overhead کمتر می‌شود
```

---

## 3. کاهش Load روی Broker

به جای اینکه broker هزاران request کوچک پردازش کند:

```
تعداد request کمتر می‌شود
```

در نتیجه:

- CPU کمتر مصرف می‌شود
- context switching کمتر می‌شود

---

## 4. بهبود Disk I/O (به‌خصوص در Kafka)

ابزار Kafka پیام‌ها را روی disk می‌نویسد.

نوشتن batch روی disk:

```
Sequential write
```

که خیلی سریع‌تر از:

```
random small writes
```

است.

---

# معایب Batching

## 1. افزایش Latency

برای تشکیل batch باید صبر کرد تا پیام‌های بیشتری جمع شوند.

مثلاً:

```
linger.ms = 10ms
```

یعنی producer تا ۱۰ میلی‌ثانیه صبر می‌کند تا batch کامل شود.

نتیجه:

```
Latency ↑
```

---

## 2. افزایش مصرف حافظه

پیام‌ها باید قبل از ارسال در buffer نگه داشته شوند.

اگر:

```
batch.size بزرگ باشد
```

مصرف RAM بیشتر می‌شود.

---

## 3. شکست دسته‌ای (Batch Failure)

اگر batch شامل 100 پیام باشد و خطا رخ دهد:

ممکن است:

```
کل batch fail شود
```

در نتیجه:

- عمل retry پیچیده‌تر می‌شود
- تشخیص پیام خراب سخت‌تر می‌شود

---

## 4. پیچیدگی در Error Handling

مثلاً:

```
Batch = 50 messages
1 message invalid
```

حالا باید مشخص شود:

- کل batch retry شود؟
- فقط پیام خراب حذف شود؟

---

## 5. احتمال افزایش Lag

اگر batch بزرگ باشد:

درواقع Consumer باید یک batch کامل را پردازش کند قبل از commit.

---

# مثال Kafka

در Kafka batching توسط producer انجام می‌شود.

پارامترها:

```
batch.size
linger.ms
compression.type
```

مثال:

```
batch.size = 32KB
linger.ms = 5ms
```

---

# چه زمانی Batching مناسب است؟

الگوی Batching خوب است وقتی:

- حجم پیام زیاد است
- میزان latency خیلی حساس نیست
- افزایش throughput مهم‌تر است

مثال‌ها:

- log ingestion
- analytics pipelines
- event streaming

---

# چه زمانی Batching بد است؟

الگوی Batching مناسب نیست وقتی:

- میزانی latency خیلی مهم است
- سیستم real-time است

مثال‌ها:

- trading systems
- payment processing
- realtime notifications

---

# خلاصه

مزایا:

- افزایش throughput بیشتر
- استفاده بهتر از شبکه
- داشتن load کمتر روی broker
- میزان disk I/O بهتر

معایب:

- افزایش latency بیشتر
- مصرف حافظه بیشتر
- مدیریت خطا پیچیده‌تر
- احتمال batch failure
