قابلیت **Rule Engine در EMQX** سیستمی داخل Broker است که اجازه می‌دهد **پیام‌های MQTT را فیلتر، پردازش و به مقصدهای مختلف ارسال کنیم**؛ بدون اینکه لازم باشد برنامه جداگانه‌ای بنویسیم.

به بیان ساده:

> قابلیت Rule Engine مثل یک **SQL‑based stream processor داخل EMQX** است که روی پیام‌های MQTT کار می‌کند.

---

# ایده اصلی

وقتی یک پیام MQTT وارد EMQX می‌شود:

```
Device → EMQX → Subscriber
```

قابلیت Rule Engine می‌تواند وسط این مسیر قرار بگیرد:

```
Device → EMQX
          ↓
      Rule Engine
          ↓
Kafka / DB / HTTP / MQTT / Redis
```

---

# اجزای اصلی Rule Engine

قابلیت Rule Engine سه بخش اصلی دارد:

### 1️⃣ Event Source
رویدادی که Rule روی آن اجرا می‌شود.

مثال:

- publish پیام
- connect شدن client
- disconnect شدن client
- subscribe شدن

نمونه:

```
$events/message_publish
```

یا

```
message from sensors/#
```

---

### 2️⃣ SQL Filter

قابلیت Rule Engine از **SQL-like syntax** استفاده می‌کند.

مثال:

```sql
SELECT
  payload.temperature as temp,
  clientid,
  topic
FROM
  "sensors/temperature"
WHERE
  payload.temperature > 30
```

این Rule می‌گوید:

- پیام‌های Topic مشخص را بگیر
- مقدار payload را parse کن
- اگر دما > 30 بود ادامه بده

---

### 3️⃣ Action

وقتی Rule match شد، عملی انجام می‌شود.

مثال:

- ارسال به Kafka
- ذخیره در MySQL
- افزودن HTTP webhook
- ارسال به Topic دیگر
- ثبت در Redis
- ارسال به Elasticsearch

---

# مثال واقعی

فرض کن سنسورها این پیام را می‌فرستند:

```
topic: factory/machine1/temp

payload:
{
  "temperature": 85,
  "machine": "M1"
}
```

Rule:

```sql
SELECT *
FROM "factory/+/temp"
WHERE payload.temperature > 80
```

Action:

```
Send to Kafka
```

نتیجه:

فقط پیام‌های **temperature بالا** وارد Kafka می‌شوند.

# قابلیت‌های مهم Rule Engine

### ✅ Filtering

فقط پیام‌های خاص را عبور می‌دهد.

```
WHERE payload.temp > 30
```

---

### ✅ Data Extraction

داده از payload استخراج می‌کند.

```
payload.temp
payload.device_id
```

---

### ✅ Transformation

ساختار پیام را تغییر می‌دهد.

```
SELECT
  clientid,
  payload.temp * 1.8 + 32 as temp_f
```

---

### ✅ Routing

ارسال پیام به مقصدهای مختلف.

مثلاً:

- Kafka
- HTTP
- DB

---

### ✅ Aggregation (محدود)

می‌تواند بعضی عملیات ساده انجام دهد.

# تفاوت Rule Engine با Bridge

| ویژگی | Rule Engine | Bridge |
|------|------|------|
| پردازش پیام | ✅ | ❌ |
| فیلتر پیام | ✅ | ❌ |
| تغییر payload | ✅ | ❌ |
| انتقال ساده | ✅ | ✅ |
| SQL | ✅ | ❌ |

درواقع Bridge فقط **forward** می‌کند  
و Rule Engine **تحلیل و پردازش** می‌کند.

---

# چرا Rule Engine مهم است؟

بدون Rule Engine باید این کارها را در یک سرویس جدا انجام دهی:

```
Consumer → parse → filter → send to DB
```

ولی با Rule Engine:

```
EMQX → SQL rule → DB
```

مزایا:

- میزان latency کمتر
- معماری ساده‌تر
- میزان load کمتر روی backend

---

# جمع‌بندی

قابلیت **Rule Engine در EMQX یک سیستم پردازش پیام داخلی است که با استفاده از SQL‑like query می‌تواند پیام‌های MQTT را فیلتر، استخراج، تبدیل و به سیستم‌های دیگر مانند Kafka، دیتابیس‌ها یا APIها ارسال کند.**
