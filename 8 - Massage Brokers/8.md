در واقع Exchange پیام را از Producer دریافت و به Queue مسیریابی می‌کند.

انواع:

- **Direct**: بر اساس کلید دقیق
- **Fanout**: ارسال به تمام queue ها
- **Topic**: الگوهای wildcard
- **Headers**: بر اساس header پیام
---

در RabbitMQ مفهوم **Exchange** یکی از مهم‌ترین بخش‌هاست و برای بسیاری افراد در ابتدا مبهم است.  
در واقع، **Exchange مغز مسیریابی پیام‌هاست**.

در ادامه تعریف دقیق و تفاوت انواع Exchange را به‌صورت کاملاً روشن توضیح می‌دهم.

---

# 1) تعریف Exchange چیست؟

در ابزار RabbitMQ یک **Producer پیام را مستقیماً به صف (Queue) ارسال نمی‌کند**.  

تولید کننده یا Producer پیام را به **Exchange** می‌فرستد.

و Exchange وظیفه دارد پیام را:

- به یک Queue
- یا چند Queue
- یا حتی هیچ Queue

بر اساس قواعدی **route** کند.

پس ساختار RabbitMQ این است:

```
Producer → Exchange → Queue → Consumer
```

---

# 2) چرا Exchange وجود دارد؟

به‌جای اینکه Producer بداند پیام باید دقیقاً وارد کدام Queue شود،  
در این فرایند Exchange به ما اجازه می‌دهد:

- مسیریابی پویا
- چندین Queue برای یک پیام
- عدم وابستگی Producer به Queueها
- الگوهای Publish/Subscribe

بنابراین Producer ساده می‌ماند و Exchange مسئول routing می‌شود.

---

# 3) انواع Exchange و تفاوت آن‌ها

ابزار RabbitMQ چهار Exchange اصلی دارد:

1. Direct
2. Fanout
3. Topic
4. Headers

به ترتیب از ساده‌ترین به پیشرفته‌ترین توضیح می‌دهم.

---

# 3.1) Direct Exchange

نوع **Exact matching** (تطابق دقیق با Routing Key)

نحوه کار:

- یک Producer پیام را با یک **Routing Key** ارسال می‌کند
- و Exchange آن را فقط به Queueهایی می‌فرستد که **Routing Key exactly match** دارند

مثال:

اگر Queue با binding key "email" به Direct Exchange وصل باشد:

```
send_message("email") → goes to EmailQueue
send_message("payment") → does NOT go to EmailQueue
```

این نوع مناسب برای:

- تسک‌های خاص
- سیستم‌هایی با مشکل تک‌هدفه
- و Messageهای دستوری (Command)

---

# 3.2) Fanout Exchange

نوع **Broadcast mode** (پخش همگانی)

نحوه کار:

- در این حالت Routing Key نادیده گرفته می‌شود
- پیام به تمام Queueهایی که bind شده‌اند ارسال می‌شود

رسمی:

```
Producer → Fanout → Queue A
                     Queue B
                     Queue C
```

همه پیام را دریافت می‌کنند.

کاربردها:

- انتشار لاگ‌ها
- سیستم‌های Pub/Sub ساده
- ارسال پیام به همه مصرف‌کنندگان

---

# 3.3) Topic Exchange

نوع **Pattern-based routing** (مسیریابی بر اساس الگو)

در این حالت Routing Key در این مدل شامل بخش‌های جداشده با نقطه است:

مثال:

```
logs.info
logs.error
user.created
order.paid
```

دو wildcard مهم وجود دارد:

- `*` جایگزین یک کلمه  
- `#` جایگزین چند کلمه

مثال‌های binding key:

```
logs.*        → matches logs.info, logs.error
logs.#        → matches logs.info.db, logs.warn.api, ...
user.*        → matches user.created, user.deleted
```

کاربردها:

- سیستم‌های logging
- رویدادهای گسترده
- دسته‌بندی پیام‌ها
- معماری‌های پیچیده Pub/Sub

این نوع، قدرتمندترین Exchange است.

---

# 3.4) Headers Exchange

نوع **Routing based on message headers**

در این مدل Routing Key اصلاً استفاده نمی‌شود.

به‌جای آن،routing بر اساس **headerهای پیام** انجام می‌شود.

شما هنگام Bind کردن Queue مشخص می‌کنید:

- چه headerهایی بررسی شوند
- و match بر اساس any باشد یا all

مثال header:

```
format = pdf
type = report
```

Bind rule:

```
x-match = all
format = pdf
type = report
```

پیام فقط اگر هر دو هدر را داشته باشد به Queue می‌رود.

کاربردها:

- روتینگ پیچیده و دینامیک
- پیام‌هایی با metadata زیاد
- سیستمی که نمی‌خواهد به routing key وابسته باشد

---

# 4) مقایسه سریع انواع Exchange

| Exchange | نوع routing | کاربرد |
|---------|-------------|--------|
| Direct | تطابق دقیق | دستورها، کارهای نقطه‌ای |
| Fanout | پخش همگانی | broadcast, Pub/Sub ساده |
| Topic | الگوی چندبخشی | logging، event-driven، routing پیچیده |
| Headers | بر مبنای headers | شرایط خاص، routing بسیار انعطاف‌پذیر |

---

# 5) خلاصه بسیار کوتاه

```
Direct: match exact
Fanout: match all
Topic: match pattern
Headers: match headers
```
