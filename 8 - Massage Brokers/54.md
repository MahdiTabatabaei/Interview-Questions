درواقع **Bridge در EMQX** قابلیتی است که اجازه می‌دهد **یک Broker EMQX به Broker یا سیستم دیگری متصل شود و پیام‌ها را بین آن‌ها منتقل کند**.  

به زبان ساده:

> مفهوم Bridge یعنی اتصال دو سیستم پیام‌رسان تا پیام‌ها از یکی به دیگری **forward** شوند.

---

## ایده اصلی Bridge

فرض کن دو سیستم جدا داری:

```
Site A (EMQX)
Site B (EMQX یا MQTT Broker دیگر)
```

با Bridge می‌توانی:

- پیام‌ها را از A به B بفرستی
- یا از B به A
- یا هر دو جهت

---

## معماری ساده

```
IoT Devices
     ↓
 EMQX Cluster (Edge)
     ↓  Bridge
 EMQX / Kafka / Cloud Broker
     ↓
 Cloud Applications
```

در اینجا Bridge پیام‌ها را از **Edge به Cloud** منتقل می‌کند.

---

# انواع Bridge در EMQX

ابزار EMQX چند نوع Bridge دارد.

## 1️⃣ MQTT Bridge

اتصال EMQX به **یک MQTT Broker دیگر**

مثال:

```
EMQX → AWS IoT Core
EMQX → HiveMQ
EMQX → Mosquitto
EMQX → EMQX دیگر
```

کاربرد:

- Multi‑region
- Edge → Cloud
- Migration بین Brokerها

---

## 2️⃣ Data Bridge (Integration)

ابزار EMQX می‌تواند پیام‌ها را به سیستم‌های دیگر بفرستد:

- Kafka
- RabbitMQ
- Redis
- MySQL
- PostgreSQL
- ClickHouse
- Elasticsearch
- HTTP API

مثال:

```
Device → EMQX → Kafka
```

یا

```
Device → EMQX → PostgreSQL
```

---

# نحوه کار Bridge

فرض کن این Topic وجود دارد:

```
sensors/temperature
```

وقتی پیام منتشر شود:

```
sensors/temperature → 25°C
```

در این حالت Bridge می‌تواند آن را **forward** کند:

```
EMQX A → EMQX B
```

یا:

```
EMQX → Kafka
```

---

# Topic Mapping

می‌توان Topic را تغییر داد.

مثال:

```
local topic: sensors/#
remote topic: cloud/sensors/#
```

پس پیام:

```
sensors/temp
```

می‌شود:

```
cloud/sensors/temp
```

---

# حالت‌های انتقال

درواقع Bridge می‌تواند:

### 1️⃣ Push

ابزار EMQX پیام را به سیستم دیگر می‌فرستد.

```
EMQX → Kafka
```

---

### 2️⃣ Pull

ابزار EMQX از Broker دیگر پیام دریافت می‌کند.

---

### 3️⃣ Bidirectional

دو طرفه:

```
EMQX A ↔ EMQX B
```

---

# مثال واقعی (IoT Edge)

یک کارخانه هزاران سنسور دارد.

```
Sensors
   ↓
Local EMQX (Edge)
   ↓ Bridge
Cloud EMQX
   ↓
Analytics / AI
```

مزیت‌ها:

- کاهش latency
- کاهش ترافیک اینترنت
- امکان resilience در صورت قطع اینترنت

✅ انتقال داده از Edge به Cloud

# تفاوت Bridge با Replication

| Bridge | Replication |
|------|------|
| انتقال پیام بین سیستم‌ها | کپی کامل داده |
| Topic‑based | Log‑based |
| قابل فیلتر | معمولاً کامل |
| مناسب Integration | مناسب HA |

---

# تفاوت Bridge با Rule Engine در EMQX

| Bridge | Rule Engine |
|------|------|
| انتقال ساده پیام | پردازش پیام |
| بدون transformation | با SQL processing |
| forwarding | filtering + routing |

# جمع‌بندی

تعریف **Bridge در EMQX قابلیتی برای اتصال EMQX به Brokerها یا سیستم‌های دیگر (مانند Kafka، دیتابیس یا MQTT Broker دیگر) است تا پیام‌ها بین آن‌ها منتقل شوند و Data Pipeline یا معماری Edge‑to‑Cloud ساخته شود.**
