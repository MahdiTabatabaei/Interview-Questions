
## مفهوم Topic در Kafka

مفهوم Topic در Kafka مشابه **یک کانال یا دسته‌بندی پیام** است.  
تولیدکننده‌ها (Producers) پیام‌ها را در یک Topic می‌فرستند و مصرف‌کننده‌ها (Consumers) از همان Topic پیام دریافت می‌کنند.

مثال:  
Topic = "orders" → تمام پیام‌های مربوط به ثبت سفارش در این Topic قرار می‌گیرد.

---

## مفهوم Partition

هر Topic می‌تواند از چند **پارتیشن (Partition)** تشکیل شود.  
پارتیشن‌ها در واقع **تقسیم‌های فیزیکی** یک Topic روی دیسک هستند.

چیزی شبیه:  
orders ⇒ partition-0, partition-1, partition-2

هر پارتیشن یک **log (لیست پیام) ترتیبی و فقط-افزایشی** است.

---

## چرا پارتیشن‌بندی اهمیت دارد؟

### 1. **مقیاس‌پذیری (Scalability)**

هر پارتیشن را می‌توان روی یک Broker جداگانه قرار داد.  
یعنی Topic می‌تواند روی چند سرور توزیع شود → سرعت بسیار بیشتر و حجم پیام بیشتر.

### 2. **افزایش توان عملیاتی (High Throughput)**

در این حالت Producers و Consumers به طور موازی روی پارتیشن‌های مختلف کار می‌کنند.  
مثلاً سه Consumer می‌توانند همزمان سه پارتیشن را پردازش کنند.

### 3. تحمل خطا **Fault Tolerance / Replication**
[[Fault Tolerance]]
هر پارتیشن رپلیکای مخصوص دارد  
(مثلاً 3 Replica)  
اگر یک Broker از کار بیفتد، Replica دیگری جایگزین می‌شود.

### 4. قابلیت **Ordering پیام‌ها**

ابزار Kafka فقط **داخل هر پارتیشن** ترتیب پیام‌ها را تضمین می‌کند.  
پس اگر پیام‌های مرتبط نیاز به ترتیب دارند، باید روی یک پارتیشن هدایت شوند (عموماً با کلید پیام).

## مثال ساده با C# (استفاده از Confluent.Kafka)

### نصب پکیج
```bash
dotnet add package Confluent.Kafka
```

---

## Producer نمونه (ارسال پیام به پارتیشن‌ها)

```csharp
using Confluent.Kafka;

var config = new ProducerConfig
{
    BootstrapServers = "localhost:9092"
};

using var producer = new ProducerBuilder<string, string>(config).Build();

for (int i = 0; i < 10; i++)
{
    // کلید تعیین می‌کند پیام در کدام پارتیشن برود
    string key = (i % 2 == 0) ? "even" : "odd";
    string value = $"Message #{i}";

    var result = await producer.ProduceAsync(
        "orders",
        new Message<string, string> { Key = key, Value = value });

    Console.WriteLine(
        $"Sent '{value}' to partition {result.Partition.Value}");
}

producer.Flush(TimeSpan.FromSeconds(5));
```

نکته مهم:
- پیام‌هایی که key یکسان داشته باشند همیشه به یک پارتیشن می‌روند → حفظ ترتیب.

---

## Consumer نمونه (مصرف پیام‌ها از چند پارتیشن)

```csharp
using Confluent.Kafka;

var config = new ConsumerConfig
{
    BootstrapServers = "localhost:9092",
    GroupId = "order-consumers",
    AutoOffsetReset = AutoOffsetReset.Earliest
};

using var consumer = new ConsumerBuilder<string, string>(config).Build();

consumer.Subscribe("orders");

while (true)
{
    var cr = consumer.Consume();
    Console.WriteLine(
        $"Partition {cr.Partition.Value}, Offset {cr.Offset}: {cr.Message.Value}");
}
```

این Consumer ممکن است بسته به تعداد اعضای Consumer Group فقط مسئول یک یا چند پارتیشن باشد.

---

## خلاصه
Topic = دسته‌بندی منطقی پیام‌ها  
Partition = تقسیم فیزیکی Topic برای مقیاس‌پذیری و پردازش موازی  

مزایا:
- پردازش موازی (Throughput بالا)
- مقیاس‌پذیری افقی
- تحمل خطا
- ترتیب پیام‌ها در سطح پارتیشن
