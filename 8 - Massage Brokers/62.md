استفاده از **Dead Letter Exchange (DLX)** یکی از **بهترین روش‌ها** برای مدیریت پیام‌هایی است که TTLشان تمام می‌شود یا توسط مصرف‌کننده‌ها رد (reject/nack) می‌شوند.  
بیایید گام به گام و با مثال دقیق بررسی کنیم 👇

---

## 🧩 مفهوم کلی

در RabbitMQ، وقتی یکی از این اتفاق‌ها بیفته، پیام می‌تونه وارد DLX بشه:

1. زمانی که TTL پیام یا صف تمام شود (`expired`)
2. پیام توسط consumer رد شود (`reject` یا `nack`)
3. صف پر شده باشد و پیام‌های جدید جایی نداشته باشند (`overflow`)

برای فعال کردن DLX، باید صف اصلی‌ات را طوری **تعریف کنی** که در تنظیماتش، آدرس یک **Dead Letter Exchange** و **Routing Key** مشخص شود.

---

## 🏗️ گام ۱: ساخت Exchangeهای اصلی و DLX

فرض کن پیام‌ها ابتدا وارد صف `main-queue` می‌شوند و اگر expire شدند یا reject شدند باید بروند به `dead-letter-queue`.

```csharp
using RabbitMQ.Client;

var factory = new ConnectionFactory()
{
    HostName = "localhost"
};

using var connection = factory.CreateConnection();
using var channel = connection.CreateModel();

// Exchange اصلی
channel.ExchangeDeclare(
    exchange: "main-exchange",
    type: ExchangeType.Direct,
    durable: true,
    autoDelete: false,
    arguments: null
);

// Exchange مخصوص Dead Letter
channel.ExchangeDeclare(
    exchange: "dlx-exchange",
    type: ExchangeType.Direct,
    durable: true,
    autoDelete: false,
    arguments: null
);

```

## 🐇 گام ۲: ساخت Dead Letter Queue

```csharp
using RabbitMQ.Client;

var factory = new ConnectionFactory()
{
    HostName = "localhost"
};

using var connection = factory.CreateConnection();
using var channel = connection.CreateModel();

// ساخت Dead Letter Queue
channel.QueueDeclare(
    queue: "dead-letter-queue",
    durable: true,
    exclusive: false,
    autoDelete: false,
    arguments: null
);

// Bind کردن Queue به DLX Exchange
channel.QueueBind(
    queue: "dead-letter-queue",
    exchange: "dlx-exchange",
    routingKey: "dlx"
);

```

## 📦 گام ۳: ساخت صف اصلی با تنظیمات DLX

در هنگام تعریف صف اصلی، باید مقادیر زیر را در آرگومان‌ها بدهی:

- `x-message-ttl`: مدت زنده بودن پیام (میلی‌ثانیه)
- `x-dead-letter-exchange`: نام مبادله‌ای که پیام‌های منقضی‌شده به آن ارسال می‌شوند
- `x-dead-letter-routing-key`: مسیری برای رسیدن پیام به صف DLX

```csharp
using RabbitMQ.Client;
using System.Collections.Generic;

var factory = new ConnectionFactory()
{
    HostName = "localhost"
};

using var connection = factory.CreateConnection();
using var channel = connection.CreateModel();

// آرگومان‌های TTL و DLX
var args = new Dictionary<string, object>
{
    { "x-message-ttl", 5000 },                   // 5 ثانیه
    { "x-dead-letter-exchange", "dlx-exchange" },
    { "x-dead-letter-routing-key", "dlx" }
};

// ساخت صف اصلی
channel.QueueDeclare(
    queue: "main-queue",
    durable: true,
    exclusive: false,
    autoDelete: false,
    arguments: args
);

// Bind کردن صف به main-exchange
channel.QueueBind(
    queue: "main-queue",
    exchange: "main-exchange",
    routingKey: "process"
);

```

## 🚀 گام ۴: ارسال پیام (Producer)

```csharp
using RabbitMQ.Client;
using System.Text;

var factory = new ConnectionFactory()
{
    HostName = "localhost"
};

using var connection = factory.CreateConnection();
using var channel = connection.CreateModel();

// پیام
var message = "hello, dead-letter example!";
var body = Encoding.UTF8.GetBytes(message);

channel.BasicPublish(
    exchange: "main-exchange",
    routingKey: "process",
    basicProperties: null,
    body: body
);

Console.WriteLine("Message sent!");

```

اگر این پیام تا ۵ ثانیه آینده توسط هیچ consumerی دریافت نشود، TTL آن تمام شده و RabbitMQ آن را به‌صورت خودکار به `dlx-exchange` با routing key `dlx` ارسال می‌کند.  
در نتیجه، پیام در **`dead-letter-queue`** ظاهر می‌شود.

---

## 👀 گام ۵: بررسی Consumer DLX

```csharp
using RabbitMQ.Client;
using RabbitMQ.Client.Events;
using System;
using System.Text;

var factory = new ConnectionFactory()
{
    HostName = "localhost"
};

using var connection = factory.CreateConnection();
using var channel = connection.CreateModel();

var consumer = new EventingBasicConsumer(channel);

consumer.Received += (model, ea) =>
{
    var body = ea.Body.ToArray();
    var message = Encoding.UTF8.GetString(body);

    Console.WriteLine($"📬 dead letter received: {message}");
};

channel.BasicConsume(
    queue: "dead-letter-queue",
    autoAck: true,
    consumer: consumer
);

Console.WriteLine("Waiting for dead-lettered messages...");
Console.ReadLine();

```

## 🔍 نکات حرفه‌ای

- اگر صف اصلی خودش TTL نداشته باشد، می‌توان TTL درجه‌به‌درجه در خود پیام هنگام ارسال تنظیم کرد با header `expiration`.
- درواقع DLX فقط برای پیام‌هایی فعال است که در صف اصلی به DLX اشاره دارد.
- می‌توان چند صف مختلف با DLX متفاوت داشت تا طبقه‌بندی‌های گوناگون برای پیام‌های منقضی یا ردشده ایجاد کرد.
