درواقع **Filtered Index** نوعی ایندکس است که فقط روی **بخشی از رکوردهای جدول** ساخته می‌شود، نه روی کل جدول.

یعنی هنگام ساخت ایندکس یک **شرط (`WHERE`)** مشخص می‌کنیم تا فقط رکوردهایی که آن شرط را دارند داخل ایندکس قرار بگیرند.

## مثال

فرض کنید جدول `orders` داریم:

```
order_id | customer_id | status | total
```

و بیشتر کوئری‌ها فقط روی سفارش‌های **فعال** انجام می‌شوند.

می‌توانیم یک Filtered Index بسازیم:

```sql
CREATE INDEX idx_active_orders
ON orders(customer_id)
WHERE status = 'active';
```

در این حالت:
- فقط رکوردهایی که `status = 'active'` دارند داخل ایندکس ذخیره می‌شوند.
- رکوردهای دیگر در ایندکس قرار نمی‌گیرند.

## مزایا
- **کوچک‌تر بودن ایندکس**
- **سرعت بیشتر در کوئری‌های خاص**
- مصرف **کمتر حافظه**

## چه زمانی استفاده می‌شود
وقتی:
- فقط بخشی از داده‌ها زیاد جستجو می‌شوند
- مقدار خاصی زیاد در شرط `WHERE` استفاده می‌شود

مثلاً:
- `status = 'active'`
- `deleted = 0`
- `is_active = 1`

## خلاصه
درواقع **Filtered Index** ایندکسی است که فقط روی **رکوردهایی که شرط مشخصی دارند** ساخته می‌شود تا عملکرد کوئری‌های خاص سریع‌تر شود.
