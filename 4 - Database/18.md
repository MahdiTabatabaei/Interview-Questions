درصدی که تعیین می‌کند صفحات Index هنگام ساخت چقدر پر باشند.

استفاده Fill Factor پایین → فضای خالی بیشتر → مناسب برای Insert زیاد

استفاده Fill Factor بالا → فضای کمتر wasted → مناسب برای Read زیاد

مثال

قفسه کتاب را 90٪ پر کنید → چیدن مجدد سخت‌تر

قفسه را 70٪ پر کنید → جا برای کتاب‌های جدید هست

---


در واقع **Fill Factor** مشخص می‌کند وقتی یک **Index ساخته یا Rebuild می‌شود، هر صفحه (Page) از ایندکس چند درصد پر شود.**

صفحات ایندکس در SQL Server معمولاً **8KB** هستند.

اگر Fill Factor را کمتر از 100 بگذاریم، مقداری **فضای خالی در هر صفحه** باقی می‌ماند.

هدف این کار این است که وقتی **داده جدید اضافه می‌شود**، SQL Server مجبور نشود صفحه را بشکند (Page Split).

---

## مثال خیلی شفاف

فرض کن یک قفسه داری که **۱۰ کتاب جا می‌گیرد**.

### حالت اول — Fill Factor = 100

قفسه را کامل پر می‌کنی.
```markdown

[📚📚📚📚📚📚📚📚📚📚]

```
حالا اگر یک کتاب جدید بیاید:

- دیگر جا ندارد
- باید قفسه را نصف کنی و دوباره مرتب کنی

در دیتابیس به این می‌گویند:

**Page Split**

که باعث می‌شود:

- سرعت کم شود
- Fragmentation ایجاد شود

---

### حالت دوم — Fill Factor = 70

فقط 7 کتاب می‌گذاری:
```markdown

[📚📚📚📚📚📚📚___]

```
حالا اگر کتاب جدید بیاید:
```markdown

[📚📚📚📚📚📚📚📚__]

```
هنوز جا هست و **نیازی به شکستن صفحه نیست**.

---

## مثال واقعی در SQL
```markdown

CREATE INDEX IX_UserName
ON Users(UserName)
WITH (FILLFACTOR = 70);

```
یعنی:

وقتی ایندکس ساخته شد، صفحات فقط **۷۰٪ پر شوند**.

---

## چه زمانی Fill Factor پایین بگذاریم؟

وقتی جدول **Insert و Update زیاد دارد**.

مثلا:

- سفارش‌ها
- لاگ‌ها
- تراکنش‌ها

---

## چه زمانی 100 خوب است؟

وقتی جدول **تقریباً فقط خوانده می‌شود**.

مثلا:

- جدول شهرها
- جدول کشورها
- جدول محصولات ثابت
