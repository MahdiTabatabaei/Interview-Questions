یک **View** در SQL Server زمانی **قابل Update (Insert / Update / Delete)** است که SQL Server بتواند **بدون ابهام تشخیص دهد هر ردیف View مربوط به کدام ردیف در جدول اصلی است**. اگر این نگاشت واضح باشد، View قابل Update است.

## شرایط اصلی قابل Update بودن View

### 1. View باید بر اساس یک جدول باشد
اگر View فقط از **یک جدول** ساخته شده باشد معمولاً قابل Update است.

مثال:
```sql
CREATE VIEW vEmployees
AS
SELECT id, name, salary
FROM Employees
```

```sql
UPDATE vEmployees
SET salary = salary * 1.1
WHERE id = 5
```

این کار در واقع جدول **Employees** را آپدیت می‌کند.

---

### 2. نباید شامل Aggregate باشد
اگر View شامل توابعی مثل این‌ها باشد قابل Update نیست:

- `SUM`
- `COUNT`
- `AVG`
- `MIN`
- `MAX`

مثال غیر قابل Update:

```sql
CREATE VIEW vSales
AS
SELECT CustomerID, SUM(Amount) total
FROM Orders
GROUP BY CustomerID
```

چون این View نتیجه **aggregation** است.

---

### 3. نباید GROUP BY یا DISTINCT داشته باشد

این‌ها هم باعث می‌شوند View قابل Update نباشد:

- `GROUP BY`
- `DISTINCT`

چون ردیف‌های واقعی جدول مشخص نیستند.

---

### 4. نباید UNION داشته باشد

```sql
UNION
UNION ALL
```

باعث می‌شود مشخص نباشد داده از کدام جدول آمده است.

---

### 5. نباید ستون محاسباتی باشد
اگر ستون در View از یک expression ساخته شده باشد نمی‌توان آن را Update کرد.

مثال:

```sql
CREATE VIEW vProducts
AS
SELECT price, price * 0.1 AS tax
FROM Products
```

ستون `tax` قابل Update نیست.

---

### 6. اگر JOIN وجود داشته باشد محدودیت دارد

Viewهایی که **JOIN** دارند معمولاً مشکل دارند.

مثال:

```sql
CREATE VIEW vOrderInfo
AS
SELECT o.OrderID, c.Name
FROM Orders o
JOIN Customers c
ON o.CustomerID = c.CustomerID
```

در این حالت:

- ممکن است بتوان `Orders` را Update کرد
- ولی SQL Server اجازه نمی‌دهد ستون‌هایی را Update کنیم که باعث ابهام شوند

---

## قانون ساده 

یک View قابل Update است اگر:

- از **یک جدول** ساخته شده باشد
- **GROUP BY / DISTINCT / UNION / Aggregate** نداشته باشد
- ستون‌ها **مستقیم از جدول** آمده باشند
- ابهامی در تشخیص ردیف اصلی وجود نداشته باشد

---

## نکته مهم حرفه‌ای

حتی اگر View قابل Update نباشد می‌توان آن را **با Trigger قابل Update کرد**:

```
INSTEAD OF INSERT
INSTEAD OF UPDATE
INSTEAD OF DELETE
```

درواقع Trigger عملیات را به جدول‌های واقعی هدایت می‌کند.
