اول یک نکته مهم: **Covering Index یک نوع ایندکس نیست**؛ بلکه یک **وضعیت (property)** است. یعنی اگر یک ایندکس تمام ستون‌هایی که یک کوئری لازم دارد را داشته باشد، آن ایندکس برای آن کوئری **Covering** محسوب می‌شود.

اما **Included Columns** یک **قابلیت برای ساخت ایندکس** است (در SQL Server و بعضی دیتابیس‌ها) که کمک می‌کند راحت‌تر یک Covering Index بسازیم.

---

# 1️⃣ مفهوم Covering Index چیست؟

وقتی **همه ستون‌های مورد نیاز کوئری** داخل ایندکس باشند.

یعنی ستون‌های:

- `WHERE`
- `JOIN`
- `SELECT`
- `ORDER BY`

همه در ایندکس وجود داشته باشند.

در این حالت دیتابیس دیگر لازم نیست به **جدول اصلی (Heap / Clustered Index)** برگردد.

به این مراجعه معمولاً می‌گویند:

```
Key Lookup
```

وقتی Key Lookup حذف شود، Performance خیلی بهتر می‌شود.

### مثال

کوئری:

```sql
SELECT name, city
FROM customers
WHERE customer_id = 10;
```

ایندکس:

```sql
CREATE INDEX idx_customer
ON customers(customer_id, name, city);
```

چون تمام ستون‌های مورد نیاز (`customer_id`, `name`, `city`) در ایندکس هستند، دیتابیس فقط از ایندکس می‌خواند.

این می‌شود **Covering Index**.

---

# 2️⃣ مفهوم Included Columns چیست؟

در SQL Server می‌توان ستون‌هایی را به ایندکس اضافه کرد **بدون اینکه جزو Key ایندکس باشند**.

ساختار:

```sql
CREATE INDEX idx_customer
ON customers(customer_id)
INCLUDE (name, city);
```

اینجا:

Key column:
```
customer_id
```

Included columns:
```
name, city
```

این ستون‌ها فقط در **leaf level** ذخیره می‌شوند و در ساختار B‑Tree دخالت ندارند.

---

# 3️⃣ چرا Included Columns مهم است؟

اگر همه ستون‌ها را به عنوان Key بگذاریم:

```
(customer_id, name, city)
```

مشکلات:

- ایندکس بزرگ‌تر می‌شود
- ساختار B‑Tree عمیق‌تر می‌شود
- مرتب‌سازی ایندکس سنگین‌تر می‌شود
- سرعت `INSERT/UPDATE` کاهش می‌یابد

ولی با `INCLUDE`:

```
(customer_id) INCLUDE (name, city)
```

- ایندکس کوچک‌تر می‌ماند
- فقط ستون مهم برای جستجو Key می‌شود
- بقیه فقط برای Covering اضافه می‌شوند

---

# 4️⃣ رابطه Covering Index و Included Columns

درواقع Included Columns معمولاً برای **ساختن Covering Index به شکل بهینه** استفاده می‌شود.

مثال:

کوئری:

```sql
SELECT name, city
FROM customers
WHERE customer_id = 10;
```

ایندکس بهینه:

```sql
CREATE INDEX idx_customer
ON customers(customer_id)
INCLUDE (name, city);
```

این ایندکس:

- جستجو سریع دارد (`customer_id`)
- نیاز به Key Lookup ندارد
- ایندکس کوچک باقی می‌ماند

---

# 5️⃣ چه زمانی Performance بهتر می‌شود؟

### استفاده از  Covering Index performance را بهتر می‌کند وقتی:

- کوئری‌های **read-heavy** داریم
- رخداد Key Lookup زیاد اتفاق می‌افتد
- جدول بزرگ است
- ستون‌های SELECT کم هستند

---

### استفاده از Included Columns performance را بهتر می‌کند وقتی:

- می‌خواهیم Covering Index بسازیم
- ولی نمی‌خواهیم همه ستون‌ها Key شوند
- ستون‌های SELECT زیاد هستند
- نمی‌خواهیم ایندکس بزرگ شود

---

✅ **خلاصه**

- تعریف  **Covering Index:** ایندکسی که تمام ستون‌های مورد نیاز کوئری را دارد و باعث حذف Key Lookup می‌شود.
- تعریف **Included Columns:** روشی برای اضافه کردن ستون‌ها به ایندکس بدون اینکه در Key ایندکس قرار بگیرند، تا بتوان یک Covering Index بهینه ساخت.
