## 1. تعریف View معمولی (برای درک بهتر)

اول باید بدانیم **View معمولی** چیست.

هر **View** در SQL در واقع یک **Query ذخیره‌شده** است و داده‌ای را ذخیره نمی‌کند.

هر بار که View را اجرا می‌کنیم، دیتابیس **Query اصلی را دوباره اجرا می‌کند**.

مثال:
```sql

CREATE VIEW SalesSummary AS
SELECT ProductID, SUM(Amount) AS TotalSales
FROM Sales
GROUP BY ProductID;

```
وقتی می‌نویسیم:
```sql

SELECT * FROM SalesSummary

```
دیتابیس هر بار Query بالا را اجرا می‌کند.

---

# 2. تعریف Indexed View چیست؟

درواقع **Indexed View** یک View است که روی آن **Index ایجاد شده است** و به همین دلیل **نتیجه آن به صورت فیزیکی ذخیره می‌شود**.

یعنی:

- View معمولی → فقط Query است
- Indexed View → نتیجه Query **واقعاً در دیسک ذخیره می‌شود**

---

## مثال
```sql

CREATE VIEW SalesSummary
WITH SCHEMABINDING
AS
SELECT ProductID, COUNT_BIG(*) AS TotalCount, SUM(Amount) AS TotalSales
FROM dbo.Sales
GROUP BY ProductID;

```
بعد روی آن Index می‌سازیم:
```sql

CREATE UNIQUE CLUSTERED INDEX IX_SalesSummary
ON SalesSummary(ProductID);

```
از این لحظه:

- نتیجه View **ذخیره می‌شود**
- ابزار SQL Server آن را **آپدیت نگه می‌دارد**

---

## مزیت Indexed View

مهم‌ترین مزیت:

✅ **افزایش سرعت Query**

چون:

- محاسبات سنگین مثل
    - `SUM`
    - `COUNT`
    - `GROUP BY`
- قبلاً محاسبه شده‌اند.

بنابراین Query سریع‌تر اجرا می‌شود.

---

## مثال کاربردی

فرض کنید:

جدول فروش **100 میلیون رکورد** دارد.

و Query زیر را زیاد اجرا می‌کنیم:
```sql

SELECT ProductID, SUM(Amount)
FROM Sales
GROUP BY ProductID

```
اگر **Indexed View** بسازیم:

- این محاسبه فقط یکبار انجام می‌شود
- بعداً سریع خوانده می‌شود

---

## مشکل Indexed View

وقتی داده در جدول اصلی تغییر کند:
```sql

INSERT
UPDATE
DELETE

```
و SQL Server باید **Indexed View را هم آپدیت کند**.

پس:

- سرعت **Insert / Update / Delete** کمی کاهش می‌یابد.

---

# 3. تعریف Materialized View چیست؟

درواقع **Materialized View** مفهومی شبیه Indexed View است اما در بعضی دیتابیس‌ها مثل:

- Oracle
- PostgreSQL
- BigQuery

استفاده می‌شود.

Materialized View یعنی:

> نتیجه یک Query به صورت **فیزیکی ذخیره می‌شود**.

---

## مثال در PostgreSQL
```sql

CREATE MATERIALIZED VIEW SalesSummary AS
SELECT ProductID, SUM(Amount) AS TotalSales
FROM Sales
GROUP BY ProductID;

```

---
## تفاوت مهم

درواقع Materialized View **به صورت خودکار آپدیت نمی‌شود**.

باید آن را **Refresh** کنیم:
```sql

REFRESH MATERIALIZED VIEW SalesSummary;

```

✅ **خلاصه**

- **View:** فقط Query ذخیره شده
- **Indexed View:** View با Index که نتیجه آن ذخیره می‌شود (SQL Server)
- **Materialized View:** نتیجه Query ذخیره می‌شود ولی باید Refresh شود (در دیتابیس‌های دیگر)
