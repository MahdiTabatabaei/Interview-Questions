تفاوت **B‑Tree Index** و **Hash Index** در **نوع ساختار داده و نوع جستجویی** است که بهینه انجام می‌دهند.

---

# 1. B‑Tree Index

بیشتر دیتابیس‌ها (مثل **SQL Server, PostgreSQL, MySQL**) به صورت پیش‌فرض از **B‑Tree** برای ایندکس استفاده می‌کنند.

ساختار آن یک **درخت متعادل (Balanced Tree)** است.

ساختار ساده:

```
        Root
       /    \
   Node      Node
   /  \      /  \
 Leaf Leaf  Leaf Leaf
```

در **Leaf Node**‌ها:

- یا خود داده‌ها ذخیره می‌شوند (Clustered)
- یا pointer به داده‌ها (Non‑clustered)

ویژگی مهم:

**کلیدها در درخت مرتب هستند.**

مثلاً:

```
10
20
30
40
50
```

---

## مزایای B‑Tree

### 1. جستجوی سریع

```
WHERE id = 20
```

به سرعت با **Index Seek** پیدا می‌شود.

---

### 2. Range Query

بزرگ‌ترین مزیت B‑Tree:

```
WHERE price BETWEEN 100 AND 200
```

یا

```
WHERE id > 500
```

یا

```
ORDER BY date
```

همه این‌ها بسیار سریع هستند چون داده‌ها **مرتب** هستند.

---

### 3. پشتیبانی از Sort

اگر ایندکس روی ستون باشد:

```
ORDER BY column
```

دیتابیس ممکن است اصلاً **Sort انجام ندهد**.

---

# 2. Hash Index

در Hash Index از **تابع Hash** استفاده می‌شود.

فرآیند:

```
Key → Hash Function → Bucket
```

مثال:

```
hash(100) → bucket 3
hash(200) → bucket 7
hash(300) → bucket 1
```

ساختار:

```
Bucket1 → rows
Bucket2 → rows
Bucket3 → rows
```

دیتابیس مستقیماً به Bucket مربوطه می‌رود.

---

# مزیت اصلی Hash Index

برای **Equality Search** بسیار سریع است.

مثلاً:

```
WHERE id = 500
```

این حالت تقریباً:

```
O(1)
```

زمان دارد.

در حالی که B‑Tree معمولاً:

```
O(log n)
```

است.

---

# مشکل Hash Index

بزرگ‌ترین مشکل:

**هیچ ترتیبی ندارد.**

پس این کوئری‌ها را نمی‌تواند بهینه کند:

```
WHERE price > 100
```

یا

```
BETWEEN
```

یا

```
ORDER BY
```

یا

```
LIKE 'abc%'
```

چون Hash ترتیب را از بین می‌برد.

---

# مثال

فرض کنید جدول کاربران داریم.

### B‑Tree

```
Index:

10
20
30
40
50
```

Range query:

```
20 → 30 → 40
```

سریع.

---

### Hash

```
hash(10) → bucket1
hash(20) → bucket7
hash(30) → bucket3
```

هیچ ترتیب منطقی وجود ندارد.

پس برای:

```
BETWEEN 20 AND 40
```

تقریباً باید کل ایندکس بررسی شود.

---

# مقایسه سریع

B‑Tree Index

- ساختار: درخت متعادل
- داده‌ها مرتب هستند
- مناسب برای:
  - Equality search
  - Range queries
  - ORDER BY
  - GROUP BY
- پیچیدگی جستجو: `O(log n)`
- پرکاربردترین نوع ایندکس

---

Hash Index

- ساختار: Hash table
- داده‌ها مرتب نیستند
- مناسب برای:
  - فقط Equality search (`=`)
- پیچیدگی: `O(1)`
- مناسب برای workload خاص

---

# در SQL Server

SQL Server عملاً از **B‑Tree برای همه ایندکس‌ها** استفاده می‌کند.

Hash Index فقط در:

```
Memory Optimized Tables
(In-Memory OLTP)
```

استفاده می‌شود.

---

# جمع‌بندی

**B‑Tree Index**

- عمومی‌ترین ایندکس
- پشتیبانی از Range و Sort
- مناسب برای اکثر Queryها

**Hash Index**

- فوق سریع برای `=`
- ولی برای Range و Sort بد
- کاربرد محدود
