درواقع Lock Escalation یا «ارتقای قفل» مکانیزمی است که وقتی تعداد قفل‌های ریزدانه روی ردیف‌ها/صفحات زیاد می‌شود، آن‌ها را به قفل‌های درشت‌دانه‌تر (مثلاً سطح صفحه یا جدول) تبدیل می‌کند تا:

- مصرف حافظه و مدیریت قفل‌ها (lock manager overhead) کاهش یابد.
- خطر تمام‌شدن بودجه قفل‌ها (lock memory pressure) کم شود.
- کارایی سیستم در سناریوهای دارای قفل‌های بسیار زیاد بهتر شود.

اما هزینه‌اش کاهش همزمانی (concurrency) است، چون قفل درشت‌دانه محدوده بزرگ‌تری از داده را می‌بندد.


به بیان ساده:  
به‌جای اینکه هزاران قفل روی ردیف‌ها نگه دارد، SQL Server آن‌ها را **به یک قفل Table تبدیل می‌کند**.

---

## چرا SQL Server این کار را می‌کند؟
مدیریت قفل‌ها حافظه و CPU مصرف می‌کند. اگر یک تراکنش مثلاً روی 50 هزار ردیف قفل بگیرد:

- نگه داشتن 50k lock هزینه دارد
- برای کاهش مصرف منابع، موتور قفل‌ها را **escalate** می‌کند.

یعنی:

```
Row Locks  →  Page Locks  →  Table Lock
```

در عمل معمولاً مستقیم به **Table Lock** ارتقا می‌دهد.

---

## مثال ساده

فرض کنید این کوئری اجرا شود:

```sql
BEGIN TRAN

UPDATE Orders
SET Status = 'Shipped'
WHERE OrderDate < '2023-01-01'
```

اگر این دستور هزاران ردیف را تغییر دهد:

1. ابتدا روی هر ردیف **Row Lock** می‌گیرد
2. وقتی تعداد قفل‌ها زیاد شود
3. ابزار SQL Server می‌گوید:

> به‌جای هزاران قفل، کل جدول را قفل می‌کنم

پس تبدیل می‌شود به:

```
Table Lock (X)
```

---

## مشکل Lock Escalation چیست؟

مشکل اصلی **کاهش Concurrency** است.

مثال:

Transaction A:

```sql
UPDATE Orders ...
```

بعد از Lock Escalation جدول قفل می‌شود.

Transaction B:

```sql
SELECT * FROM Orders
```

ممکن است **Block شود** چون کل جدول قفل شده است.

---

## چه زمانی Lock Escalation اتفاق می‌افتد؟

در SQL Server معمولاً وقتی رخ می‌دهد که:

- یک تراکنش **حدود 5000 lock** روی یک table بگیرد
- یا فشار حافظه روی lock manager زیاد شود

---

## چطور ببینیم Lock Escalation رخ داده؟

با DMV:

```sql
SELECT *
FROM sys.dm_tran_locks
```

یا با Extended Events.

---

## کنترل Lock Escalation در SQL Server

می‌توان رفتار آن را تنظیم کرد:

```sql
ALTER TABLE table_name
SET (LOCK_ESCALATION = AUTO)
```

گزینه‌ها:

**AUTO**  
- پیشفرض  
- اگر جدول partition شده باشد escalation روی partition انجام می‌شود

**TABLE**  
- همیشه escalation به table level

**DISABLE**  
- تا حد ممکن اجازه escalation نمی‌دهد

مثال:

```sql
ALTER TABLE Orders
SET (LOCK_ESCALATION = DISABLE)
```

---

## روش‌های جلوگیری از Lock Escalation

1. عمل **Batch کردن عملیات**

بد:

```sql
UPDATE Orders SET Status='X'
```

خوب:

```sql
UPDATE TOP (1000) Orders
SET Status='X'
```

در حلقه.

---

2. **ایندکس مناسب**

اگر query scan کامل انجام دهد lock زیاد می‌شود.

---

3. **کاهش طول تراکنش**

تراکنش‌های طولانی escalation را بیشتر می‌کنند.

---

✅ خلاصه کوتاه:

درواقع **Lock Escalation در SQL Server یعنی تبدیل تعداد زیادی Row/Page Lock به یک Table Lock برای کاهش مصرف منابع، که می‌تواند باعث کاهش همزمانی (Blocking بیشتر) شود.**
