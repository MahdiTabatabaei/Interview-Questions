در **Composite Index** ترتیب ستون‌ها خیلی مهم است، چون دیتابیس از ایندکس بر اساس **ستون‌های ابتدایی (Left‑most columns)** استفاده می‌کند.

به این موضوع معمولاً **Leftmost Prefix Rule** گفته می‌شود.

## مثال

فرض کنید این ایندکس را داریم:

```sql
CREATE INDEX idx_customer_date
ON orders(customer_id, order_date);
```

ترتیب ستون‌ها:
```
customer_id → order_date
```

### کوئری‌هایی که از ایندکس استفاده می‌کنند

```sql
WHERE customer_id = 10
```

یا

```sql
WHERE customer_id = 10 AND order_date = '2025-01-01'
```

چون از ستون اول ایندکس شروع شده است.

### کوئری‌ای که معمولاً از ایندکس استفاده نمی‌کند

```sql
WHERE order_date = '2025-01-01'
```

چون ستون اول ایندکس (`customer_id`) در شرط استفاده نشده است.

## چرا ترتیب مهم است؟

چون ساختار ایندکس معمولاً به شکل **B‑Tree** است و داده‌ها ابتدا بر اساس **ستون اول** مرتب می‌شوند، بعد ستون‌های بعدی.

پس اگر ستون اول در شرط نباشد، دیتابیس نمی‌تواند به‌خوبی از ایندکس استفاده کند.

## یک مثال واقعی

اگر بیشتر کوئری‌ها این باشند:

```sql
WHERE customer_id = ?
AND order_date BETWEEN ... 
```

بهتر است ایندکس این باشد:

```sql
(customer_id, order_date)
```

نه برعکس.

## خلاصه
ترتیب ستون‌ها در Composite Index مهم است چون:
- دیتابیس از **ستون‌های ابتدایی ایندکس** استفاده می‌کند
- ترتیب اشتباه می‌تواند باعث شود **ایندکس اصلاً استفاده نشود**
- باید ستون‌هایی که بیشتر در `WHERE` استفاده می‌شوند **اول قرار بگیرند**.
