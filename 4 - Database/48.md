**Blocking**

یک تراکنش منتظر قفل تراکنش دیگر است.

اگر اولی آزاد شود، دومی ادامه می‌دهد → مشکل موقتی.

**Deadlock**

دو تراکنش همزمان منتظر قفل یکدیگر هستند → هیچ‌کدام ادامه نمی‌دهند.

در SQL Server یکی را قربانی می‌کند.

مثال

در Blocking: تو پشت ماشینی هستی که دارد بار خالی می‌کند.

در Deadlock: دو ماشین روبروی هم در خیابان تنگ گیر کرده‌اند.

---
هر دو به **قفل‌ها (Locks)** در SQL Server مربوط‌اند، اما ماهیتشان فرق دارد.

## تعریف Blocking چیست؟

تعریف **Blocking یعنی یک تراکنش منتظر آزاد شدن قفلِ تراکنش دیگر است.**

سناریو ساده:

```
T1: UPDATE Customers SET Name='Ali' WHERE ID=1
```

این دستور روی آن ردیف **Exclusive Lock** می‌گیرد.

حالا همزمان:

```
T2: SELECT * FROM Customers WHERE ID=1
```


دراینجا T2 نمی‌تواند ردیف را بخواند چون T1 قفل دارد.  
پس **T2 منتظر می‌ماند** تا T1 `COMMIT` یا `ROLLBACK` کند.

ویژگی مهم Blocking:
- فقط **انتظار** اتفاق می‌افتد.
- وقتی تراکنش اول تمام شود، دومی ادامه می‌دهد.
- بن‌بست نیست.

به شکل ساده:

```
T1 ----(lock)----> Row
T2 ---- waiting ---->
```

---

## تعریف Deadlock چیست؟

تعریف **Deadlock یعنی دو تراکنش همدیگر را قفل کرده‌اند و هر کدام منتظر دیگری است.**

سناریو:

```
T1:
UPDATE Accounts SET Balance=Balance-100 WHERE ID=1
```

قفل روی ردیف 1 می‌گیرد.

همزمان:

```
T2:
UPDATE Accounts SET Balance=Balance-50 WHERE ID=2
```

قفل روی ردیف 2 می‌گیرد.

بعد ادامه می‌دهند:

```
T1:
UPDATE Accounts SET Balance=Balance+100 WHERE ID=2
```

اما ردیف 2 دست T2 است → T1 منتظر می‌شود.

```
T2:
UPDATE Accounts SET Balance=Balance+50 WHERE ID=1
```

اما ردیف 1 دست T1 است → T2 منتظر می‌شود.

الان وضعیت:

```
T1 waits for T2
T2 waits for T1
```

هیچ‌کدام نمی‌توانند ادامه دهند.

ابزار SQL Server این را تشخیص می‌دهد و **یکی از تراکنش‌ها را kill می‌کند**:

```
Transaction (Process ID XX) was deadlocked on resources...
```

---

## تفاوت اصلی

| ویژگی | Blocking | Deadlock |
|------|---------|---------|
| ماهیت | انتظار برای قفل | انتظار متقابل |
| پایان | با Commit/Release قفل حل می‌شود | دیتابیس یکی از تراکنش‌ها را kill می‌کند |
| تعداد تراکنش | معمولاً 2 یا بیشتر ولی یک طرف منتظر است | حداقل 2 تراکنش که حلقه انتظار دارند |
| خطا | خطا ندارد | خطای Deadlock (1205) |

---

## خلاصه خیلی ساده

- **Blocking** → یکی صبر می‌کند.  
- **Deadlock** → هر دو صبر می‌کنند و هیچ‌کدام جلو نمی‌روند.
