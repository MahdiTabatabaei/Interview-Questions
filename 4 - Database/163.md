## قفل‌ها (Locks) در پایگاه داده

وقتی چند کاربر یا چند تراکنش همزمان به دیتابیس دسترسی دارند، ممکن است **روی یک داده مشترک کار کنند**. برای جلوگیری از خراب شدن داده‌ها، دیتابیس از **قفل (Lock)** استفاده می‌کند.

قفل یعنی:

> دیتابیس برای مدتی دسترسی به یک داده را محدود می‌کند تا تراکنش‌ها با هم تداخل نداشته باشند.

مثلاً اگر یک تراکنش در حال **ویرایش یک رکورد** باشد، نباید تراکنش دیگری همزمان آن را تغییر دهد.

---

### انواع اصلی قفل‌ها

#### 1. Shared Lock (قفل اشتراکی)

این قفل هنگام **خواندن داده (SELECT)** استفاده می‌شود.

ویژگی‌ها:

- چند تراکنش می‌توانند همزمان داده را **بخوانند**
- اما هیچ تراکنشی نمی‌تواند آن داده را **تغییر دهد**

مثال:
```markdown

Transaction A → SELECT
Transaction B → SELECT

```
هر دو می‌توانند بخوانند.

اما اگر یکی بخواهد `UPDATE` کند باید منتظر بماند.

---

#### 2. Exclusive Lock (قفل انحصاری)

این قفل هنگام **تغییر داده** استفاده می‌شود.

مثل:
```markdown

INSERT
UPDATE
DELETE

```
ویژگی:

- فقط **یک تراکنش** اجازه دسترسی دارد
- دیگران نه می‌توانند بخوانند نه تغییر دهند

مثال:
```markdown

Transaction A → UPDATE
Transaction B → منتظر می‌ماند

```
---

### سطح قفل‌ها
قفل ممکن است روی بخش‌های مختلف داده اعمال شود:

- **Row Lock** → روی یک ردیف
- **Page Lock** → روی یک صفحه از داده
- **Table Lock** → روی کل جدول

هرچه قفل کوچک‌تر باشد، **همزمانی (Concurrency)** بیشتر است.

---

# سطح ایزولیشن (Isolation Level)

سطح ایزولیشن تعیین می‌کند:

> یک تراکنش چقدر باید از تغییرات تراکنش‌های دیگر جدا باشد.

یعنی مشخص می‌کند **دیتابیس چه نوع قفل‌هایی و چگونه استفاده کند**.

در واقع:

**Isolation Level = سیاست مدیریت قفل‌ها**

---

## انواع Isolation Level

### 1. READ UNCOMMITTED

کمترین سطح ایزولیشن.

تراکنش می‌تواند داده‌هایی را بخواند که هنوز **Commit نشده‌اند**.

مشکل:

**Dirty Read**

مثال:
```markdown

Transaction A → UPDATE
Transaction B → داده را می‌خواند
Transaction A → ROLLBACK

```
Transaction B داده اشتباه خوانده است.

---

### 2. READ COMMITTED

رایج‌ترین سطح ایزولیشن.

ویژگی:

فقط داده‌های **Commit شده** خوانده می‌شوند.

Dirty Read اتفاق نمی‌افتد.

---

### 3. REPEATABLE READ

اگر یک تراکنش داده‌ای را بخواند:

تا پایان تراکنش **آن داده تغییر نمی‌کند**.

از مشکل زیر جلوگیری می‌کند:

**Non-repeatable Read**

---

### 4. SERIALIZABLE

بالاترین سطح ایزولیشن.

تراکنش‌ها طوری اجرا می‌شوند که انگار **به صورت کاملاً سریالی** اجرا شده‌اند.

مزیت:

- بیشترین **Consistency**

عیب:

- **کاهش شدید Performance**
