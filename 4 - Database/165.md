ارتباط **قفل‌ها (Locks)** و **سطح ایزولیشن (Isolation Level)** این است که:

> **سطح ایزولیشن تعیین می‌کند دیتابیس از چه قفل‌هایی استفاده کند و این قفل‌ها چه مدت نگه داشته شوند.**

یعنی **Isolation Level سیاست کنترل همزمانی است** و **Lock ابزار اجرای آن سیاست** است.

به بیان ساده:

- **Isolation Level = قوانین**
- **Locks = مکانیزم اجرای این قوانین**

---

## مثال ساده

فرض کنید دو تراکنش داریم:
```markdown

Transaction A → در حال خواندن داده
Transaction B → در حال تغییر همان داده

```
حالا بسته به **Isolation Level** رفتار قفل‌ها فرق می‌کند.

---

# رفتار قفل‌ها در سطوح مختلف ایزولیشن

## 1. READ UNCOMMITTED

در این سطح:

- معمولاً **Shared Lock برای خواندن گرفته نمی‌شود**
- بنابراین داده‌ای که هنوز commit نشده هم ممکن است خوانده شود

نتیجه:

**Dirty Read ممکن است اتفاق بیفتد**

مثال:
```markdown

Transaction A → UPDATE
Transaction B → SELECT (بدون انتظار)

```
---

## 2. READ COMMITTED
رایج‌ترین سطح ایزولیشن.

رفتار قفل‌ها:

- هنگام `SELECT` یک **Shared Lock** گرفته می‌شود
- وقتی خواندن تمام شد قفل آزاد می‌شود

مزیت:

- از **Dirty Read** جلوگیری می‌کند

اما هنوز ممکن است:

**Non‑Repeatable Read** رخ دهد.

---

## 3. REPEATABLE READ

در این سطح:

- **Shared Lock تا پایان تراکنش نگه داشته می‌شود**

یعنی اگر داده‌ای خوانده شود:

هیچ تراکنش دیگری نمی‌تواند آن را تغییر دهد.

نتیجه:

- **Non‑Repeatable Read رخ نمی‌دهد**

اما هنوز ممکن است:

**Phantom Read** رخ دهد.

---

## 4. SERIALIZABLE

بالاترین سطح ایزولیشن.

رفتار قفل‌ها:

- علاوه بر Row Lock، دیتابیس **Range Lock** هم می‌گیرد
- یعنی حتی **رکوردهای جدید در محدوده Query هم نمی‌توانند اضافه شوند**

نتیجه:

- از **Phantom Read** هم جلوگیری می‌کند

اما:

- قفل‌های زیاد
- کاهش **Concurrency**
- کاهش **Performance**
