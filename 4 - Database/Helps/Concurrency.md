وقتی می‌گوییم **همزمانی (Concurrency) بالا** یعنی **چندین کاربر یا تراکنش می‌توانند همزمان روی دیتابیس کار کنند بدون اینکه مزاحم هم شوند**.

به زبان ساده:  
هرچه Concurrency بالاتر باشد، **کاربران بیشتری می‌توانند در یک زمان روی داده‌ها کار کنند** بدون اینکه سیستم آن‌ها را منتظر نگه دارد (Blocking).

---

### مثال ساده

فرض کنید یک جدول `Customers` داریم.

#### حالت Row Lock (همزمانی بالا)

Transaction A:

```sql
UPDATE Customers
SET Name = 'Ali'
WHERE ID = 1
```

در SQL Server فقط **ردیف با ID=1** را قفل می‌کند.

در همان لحظه:

Transaction B:

```sql
UPDATE Customers
SET Name = 'Reza'
WHERE ID = 2
```

چون ردیف ۲ قفل نیست، **Transaction B بدون انتظار اجرا می‌شود**.

✅ هر دو کاربر همزمان کار می‌کنند → **Concurrency بالا**

---

#### حالت Page Lock (همزمانی کمتر)

فرض کنید ردیف ۱ و ۲ در **یک Page** هستند.

در این حالت Transaction A ردیف ۱ را آپدیت می‌کند و SQL Server یک **Page Lock** می‌گیرد.

حالا Transaction B می‌خواهد ردیف ۲ را آپدیت کند.

❌ ولی نمی‌تواند، چون کل Page قفل شده است.  

پس باید **منتظر بماند (Block شود)**.

✅ کاربران کمتر می‌توانند همزمان کار کنند → **Concurrency پایین‌تر**

---

### جمع‌بندی

**Concurrency بالا یعنی:**

- کاربران بیشتری همزمان به دیتابیس دسترسی دارند
- Blocking کمتر است
- سیستم سریع‌تر به درخواست‌ها پاسخ می‌دهد

و معمولاً:

- **Row Lock → Concurrency بالا**
- **Page Lock → Concurrency متوسط**
- **Table Lock → Concurrency پایین**
