مفهوم **Parameter Sniffing** یکی از مهم‌ترین و معروف‌ترین مشکلات **Performance** در SQL Server است.

در ادامه آن را **خیلی ساده، شفاف و با مثال واقعی** توضیح می‌دهم.

---

# تعریف ساده

در واقع **Parameter Sniffing** یعنی:

وقتی یک Stored Procedure یا Query پارامتردار برای اولین بار اجرا می‌شود،

در SQL Server مقادیر _پارامتر اولین اجرا_ را «بو می‌کشد» (Sniff می‌کند) و بر اساس **همان مقدار** یک Execution Plan می‌سازد.

این Plan **کش می‌شود** و برای همه اجراهای بعدی استفاده می‌شود.

مشکل اینجاست که:

**اگر پارامترهای بعدی رفتار متفاوتی داشته باشند، همان Plan اولیه ممکن است اصلاً مناسب نباشد و باعث کندی شدید شود.**

---

# مثال فوق‌العاده ساده

در Stored Procedure داریم:
```sql

EXEC GetOrders @CustomerId = ?

```
سناریو:

1. بار اول این SP با `@CustomerId = 1` اجرا می‌شود.

فرض کنیم Customer 1 فقط **۵ رکورد** دارد.

در این حالت SQL Server Plan می‌سازد:

که باعث **Nested Loop + Index Seek** → عالی و سریع.

2. دفعه بعد SP با `@CustomerId = 9999` اجرا می‌شود.

اما این مشتری **۵ میلیون رکورد** دارد.

و SQL Server هنوز از **همان Plan قبلی** استفاده می‌کند.

ولی آن Plan اصلاً مناسب داده سنگین نیست و باید از:

مجموع **Hash Join + Scan** استفاده می‌کرد.

نتیجه؟

در این حالت **Query فوق‌العاده کند می‌شود.**
