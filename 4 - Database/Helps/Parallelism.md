## Parallelism چیست؟

SQL Server وقتی Query سنگین باشد، آن را بین چند CPU تقسیم می‌کند تا سریع‌تر اجرا شود.

این عالی است، اما:

- اگر هر Query کوچک هم Parallel شود،CPU خفه می‌شود
- یا اگر CPUهای زیاد درگیر شوند،**Context Switch** بالا می‌رود
- یا Threadهای اضافی → مصرف RAM زیاد
- TempDB فشار می‌گیرد
- ممکن است Queryهای سبک کند شوند

---

## مثال واقعی از زندگی

فرض کن ۳ نفر باید ۱۰ هزار جعبه را جابه‌جا کنند.

راه درست:

کار را بین ۳ نفر تقسیم کن → عالی → سریع

راه غلط:

برای جابه‌جایی یک جعبه کوچک ۳۰ نفر را بیاوری → هماهنگی و مدیریت افراد بیشتر از کار اصلی زمان می‌برد.

در SQL Server هم همین است:

اگر Query کوچک باشد ولی CPU زیاد برایش Parallel شود:

- کار هماهنگی Threadها = زمان بیشتر
- CPU مصرف غیرضروری
- Workload سنگین‌تر

---

## مثال 2: Parallelism غیر ضروری

یک Query ساده:
```sql

SELECT SUM(Amount) FROM Transactions

```
اگر جدول ۱۰ میلیون رکورد دارد → Parallel مناسب است

اگر جدول ۲۰۰ رکورد دارد → Parallel ضرر است

چرا؟

هزینه تقسیم کار + هماهنگی CPU بیشتر از اجرای ساده تک CPU است.
