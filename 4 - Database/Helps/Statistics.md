## تعریف Statistics چیست؟

در واقع Statistics اطلاعاتی هستند که SQL Server از **توزیع داده‌ها** جمع‌آوری می‌کند، مثل:

- چند ردیف وجود دارد
- مقدارهای ستون چگونه پخش شده‌اند
- کمترین/بیشترین مقدار چیست
- الگوی داده‌ها چطور است

SQL Server از Statistics استفاده می‌کند تا بداند:

- از **Seek** استفاده کند یا **Scan**
- کدام **Join** بهتر است
- چند ردیف را پیش‌بینی کند (Cardinality)

اگر Statistics **قدیمی** باشد، Query Plan اشتباه انتخاب می‌شود → Execution Plan بد → Query کند.

---

## مثال 1 (ساده)

فرض کن در فروشگاه، لیست قیمت کالاها 3 ماه آپدیت نشده است.

تو می‌خواهی بدانی:

«مردم بیشتر چه کالایی می‌خرند؟»

اگر داده‌ها قدیمی باشد:

- فروشنده فکر می‌کند نوشابه پرفروش است
- اما واقعیت این است که آب معدنی پرفروش‌تر شده

پس فروشگاه **برنامه اشتباهی** برای شارژ کالا می‌گیرد → کمبود محصول → اختلال.

در SQL Server هم اگر Statistics قدیمی باشد، Optimizer فکر می‌کند “10 ردیف برمی‌گردد” اما در واقعیت “1 میلیون ردیف” برمی‌گردد → Plan اشتباه → کندی.

---

## مثال 2 (فنی)

فرض کن ستون OrderDate این Query را دارد:
```markdown

SELECT *
FROM Orders
WHERE OrderDate > '2026-01-01'

```
اگر Statistics مربوط به OrderDate برای ۹ ماه پیش باشد، SQL Server تصور می‌کند:

- فقط ۱۰ هزار ردیف جدید وجود دارد

در حالیکه واقعیت:

- ۳ میلیون ردیف جدید وارد شده

پس SQL Server اشتباهی تصمیم می‌گیرد:

- از Nested Loop استفاده کند → فوق‌العاده کند

به جای اینکه از Hash Join سریع استفاده کند
