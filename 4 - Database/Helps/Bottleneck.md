درواقع **Database Bottleneck** یعنی جایی در سیستم که **گلوگاه عملکرد** شده و باعث می‌شود سرعت کل سیستم پایین بیاید.

به زبان ساده:  
یک بخش از دیتابیس آنقدر **کند یا محدود** است که بقیه سیستم مجبور می‌شوند منتظر بمانند.

مثل یک جاده ۴ بانده که ناگهان به **یک لاین باریک** تبدیل می‌شود؛ همه ماشین‌ها پشت آن گیر می‌کنند.

---

## مثال ساده

فرض کن 100 کاربر همزمان درخواست می‌فرستند.

اما دیتابیس:

- فقط می‌تواند 10 کوئری را سریع پردازش کند
- بقیه باید **در صف انتظار بمانند**

اینجا دیتابیس تبدیل شده به **Bottleneck سیستم**.

---

## رایج‌ترین Bottleneckهای دیتابیس

### 1. وجود Query کند

مثلاً:

```sql
SELECT *
FROM Orders
WHERE CustomerName = 'Ali'
```

اگر روی `CustomerName` ایندکس نباشد، دیتابیس مجبور می‌شود **کل جدول را اسکن کند (Table Scan)**.

اگر جدول چند میلیون رکورد داشته باشد → سیستم کند می‌شود.

---

### 2. قفل‌ها (Blocking)

مثلاً:

```
T1 → UPDATE روی یک جدول بزرگ
T2 → SELECT همان داده
```

T2 باید **منتظر آزاد شدن Lock بماند**.

در سیستم‌های پرتراکنش این می‌تواند گلوگاه شود.

---

### 3. استفاده از I/O دیسک

اگر:

- دیتابیس روی دیسک کند باشد
- حجم خواندن/نوشتن زیاد باشد

سرعت دیسک محدود می‌شود و همه کوئری‌ها کند می‌شوند.

---

### 4. استفاده از CPU

اگر کوئری‌ها:

- دارای Join زیاد
- استفاده از Sort سنگین
- استفاده از Aggregation زیاد

داشته باشند، CPU اشباع می‌شود.

---

### 5. استفاده از Memory

اگر RAM کم باشد:

- داده‌ها در Buffer Cache جا نمی‌شوند
- دیتابیس مجبور می‌شود مدام از دیسک بخواند

که خیلی کندتر است.

---

## مثال واقعی از Bottleneck

فرض کن جدول:

```
Orders
```

دارای 50 میلیون رکورد است.

کوئری:

```sql
SELECT *
FROM Orders
WHERE OrderDate = '2025-01-01'
```

اگر ایندکس نداشته باشد:

- ابزار SQL Server کل جدول را اسکن می‌کند
- میزان استفاده از CPU بالا می‌رود
- استفاده از I/O زیاد می‌شود
- بقیه Queryها هم کند می‌شوند

اینجا **Query + Table Scan تبدیل به Bottleneck شده**.

---

## چگونه Bottleneck را پیدا می‌کنند؟

در SQL Server معمولاً با این ابزارها:

- `Activity Monitor`
- `sys.dm_exec_requests`
- `sys.dm_os_wait_stats`
- `Execution Plan`
- `Query Store`

---

## خلاصه خیلی ساده

مفهوم **Database Bottleneck = گلوگاه عملکرد دیتابیس**

یعنی جایی که باعث می‌شود:

- دستورات Queryها کند شوند
- کاربران منتظر بمانند
- میزان throughput سیستم کم شود

دلایل رایج:

- استفاده از Query بد
- ایندکس نامناسب
- رخداد Lock / Blocking
- استفاده زیاد از CPU
- درگیر شدن Disk I/O
- استفاده نا نماسب از Memory
