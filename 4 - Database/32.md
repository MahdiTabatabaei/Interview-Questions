در SQL Server تابع Scalar Function و Table Function هر دو نوعی تابع (UDF = User Defined Function) هستند، اما از نظر **نوع خروجی، کاربرد، محدودیت‌ها، و عملکرد (Performance)** کاملاً با هم تفاوت دارند.

در ادامه یک مقایسه شفاف و کامل:

--------------------------------------
## 1. Scalar Function  
تابعی است که **فقط یک مقدار (یک سلول)** برمی‌گرداند.

مثال:
```
SELECT dbo.GetAge(@BirthDate);
```
خروجی چیزی مثل:
```
32
```

### ویژگی‌ها
*   خروجی: **یک مقدار اسکالر** (INT, VARCHAR, DATE, BIT, …)
*   ورودی: هر تعداد پارامتر
*   معمولاً برای محاسبات کوچک استفاده می‌شود
*   قابل استفاده در:
    *   SELECT list  
    *   WHERE  
    *   JOIN  
    *   ORDER BY  
    *   CHECK constraint  

### مشکل مهم Scalar Function (Performance Killer)

درواقع Scalar UDFها در SQL Server (تا قبل از 2019) در هر ردیف **به طور جداگانه اجرا می‌شوند** و باعث:

*   کندی شدید  
*   عدم موازی‌سازی  
*   استفاده از CPU زیاد  
*   عدم امکان Query Optimization  

می‌شوند.

(در SQL Server 2019 به بعد برخی UDFها به صورت خودکار inline می‌شوند، اما نه همه.)

--------------------------------------
## 2. Table Function  
تابعی که **به جای یک مقدار، یک جدول** برمی‌گرداند.

دو نوع اصلی دارد:
### 1. Inline Table-Valued Function (iTVF)

ساختار آن شبیه View است و یک SELECT ساده را بازمی‌گرداند.

مثال:
```
RETURN SELECT * FROM Orders WHERE CustomerID = @id;
```

مزیت مهم:
*   بسیار سریع  
*  ساختار Plan آن با Query اصلی یکی می‌شود (Inline)

### 2. Multi-Statement TVF (mTVF)

چند دستور دارد و داده‌ها را در یک table variable برمی‌گرداند.

مثال:
```
DECLARE @t TABLE (...)
INSERT INTO @t ...
RETURN SELECT * FROM @t
```

مشکلات:
*   معمولاً کندتر  
*   بدون آمار (Statistics)  
*   همیشه 1 ردیف تخمین زده می‌شود  
*   باعث Plan نادرست و کندی شدید می‌شود  

--------------------------------------
## تفاوت‌های کلیدی (خیلی مهم)

### 1. نوع خروجی
*   **Scalar Function:** یک مقدار
*   **Table Function:** مجموعه ردیف‌ها (شبیه یک جدول)

---

### 2. نحوه استفاده
**Scalar:**
```
SELECT dbo.CalcTax(Price)
```

**Table-valued:**
```
SELECT * FROM dbo.GetOrdersByDate('2023-01-01')
```

---

### 3. عملکرد (Performance)

*   تابع Scalar (به‌ویژه multi-statement) = معمولاً کند و غیرقابل موازی‌سازی  
*   بصورت Inline TVF = بسیار سریع و مانند JOIN با View رفتار می‌کند  
*  بصورت Multi-statement TVF = معمولاً کند و غیرقابل پیش‌بینی  

---

### 4. نقش در بهینه‌سازی (Optimizer)

*  تابع  Scalar UDF → معمولاً **black box** است، Query Optimizer نمی‌تواند داخل آن را تحلیل کند  
*  بصورت  Inline TVF → به صورت کامل **Inline** می‌شود، یعنی Optimizer می‌تواند آن را داخل Query باز کند  

---

### 5. موارد استفاده

توابع **Scalar Function مناسب است برای:**
*   محاسبه سن  
*   محاسبه مالیات  
*   پاکسازی متن  
*   کارهای کوچک و سریع  

توابع **Table Function مناسب است برای:**

*   بازگرداندن یک لیست رکورد  
*   اجرای لاجیک پیچیده که یک مجموعه داده خروجی می‌دهد  
*   جایگزین Stored Procedureهای فقط-خواندنی  

--------------------------------------
## جمع‌بندی سریع

*   **Scalar Function** → خروجی یک مقدار → مناسب محاسبات کوچک → ممکن است کند باشد  
*   **Inline Table Function** → سریع‌ترین نوع UDF → خروجی مانند جدول  
*   **Multi-statement Table Function** → انعطاف‌پذیر ولی کندتر
