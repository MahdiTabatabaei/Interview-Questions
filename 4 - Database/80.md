درواقع **Nested Loop Join** یکی از **الگوریتم‌های Join** در دیتابیس (مثل SQL Server) است که برای وصل کردن دو جدول استفاده می‌شود.

ایدهٔ اصلی آن خیلی ساده است:

> برای هر ردیف از جدول اول، دیتابیس می‌رود و در جدول دوم دنبال ردیف‌های matching می‌گردد.

یعنی دقیقاً مثل **دو حلقه تو در تو (nested loops)** در برنامه‌نویسی.

---

## مثال مفهومی

دو جدول داریم:

**Customers**

```
CustomerID | Name
1          | Ali
2          | Sara
3          | Reza
```

**Orders**

```
OrderID | CustomerID
10      | 1
11      | 1
12      | 2
```

کوئری:

```sql
SELECT *
FROM Customers c
JOIN Orders o
ON c.CustomerID = o.CustomerID
```

---

## نحوه کار Nested Loop

دیتابیس این کار را انجام می‌دهد:

1. اولین ردیف از جدول **Customers** را می‌گیرد (Ali)
2. می‌رود در جدول **Orders** و همه رکوردها را بررسی می‌کند
3. رکوردهای matching را برمی‌گرداند

بعد:

4. ردیف بعدی Customers (Sara)
5. دوباره Orders را بررسی می‌کند
6. رکورد matching را پیدا می‌کند

یعنی چیزی شبیه این:

```
for each row in Customers
    search Orders for matching rows
```

به همین دلیل اسمش شده **Nested Loop**.

---

## شکل ساده اجرای آن

```
Customers (Outer Table)
       ↓
Nested Loop
       ↓
Orders (Inner Table)
```

- جدول اول → **Outer Input**
- جدول دوم → **Inner Input**

---

## چه زمانی سریع است؟

Nested Loop وقتی **خیلی سریع** است که:

- جدول اول **کوچک باشد**
- جدول دوم **Index داشته باشد**

مثال:

```
Customers → 100 rows
Orders → 10 million rows
Index on Orders.CustomerID
```

در این حالت:

- برای هر customer
- دیتابیس با **Index Seek** سریع orderها را پیدا می‌کند.

---

## چه زمانی کند می‌شود؟

اگر:

- جدول اول بزرگ باشد
- یا جدول دوم Index نداشته باشد

آنگاه دیتابیس مجبور می‌شود **کل جدول دوم را برای هر ردیف بخواند**.

مثلاً:

```
Customers = 1M rows
Orders = 1M rows
```

این می‌شود تقریباً:

```
1M × 1M comparisons
```

که خیلی کند است.

---

## در Execution Plan چگونه دیده می‌شود؟

در SQL Server معمولاً می‌بینی:

```
Nested Loops (Inner Join)
   → Index Seek
   → Clustered Index Seek
```

یا

```
Nested Loops
   → Table Scan
   → Index Seek
```

---

## مقایسه با Joinهای دیگر

در SQL Server سه الگوریتم Join مهم دارد:

1️⃣ **Nested Loop Join**

- مناسب برای داده کم
- مناسب وقتی index وجود دارد

2️⃣ **Hash Join**

- مناسب برای جدول‌های بزرگ
- وقتی index مناسب نیست

3️⃣ **Merge Join**

- وقتی داده‌ها **sorted** باشند
- برای حجم زیاد هم سریع است

---

✅ **خلاصه**

Nested Loop Join یعنی:

- برای هر ردیف از جدول اول
- در جدول دوم دنبال match می‌گردد

بهترین حالت استفاده:

- Outer table کوچک
- Inner table دارای index

---

نکته ، **Nested Loop Join با `INNER JOIN` یا `LEFT JOIN` فرق دارد**.  
آن‌ها در **دو سطح متفاوت** هستند.

به زبان ساده:

- **INNER JOIN / LEFT JOIN** → نوع **منطق Join** (چه داده‌ای برگردد)
- **Nested Loop Join** → **روش اجرای Join** توسط موتور دیتابیس

---

## 1️⃣ INNER JOIN و LEFT JOIN چیست؟

این‌ها مشخص می‌کنند **کدام ردیف‌ها در نتیجه برگردند**.

### INNER JOIN
فقط ردیف‌هایی که در هر دو جدول match دارند.

```sql
SELECT *
FROM Customers c
INNER JOIN Orders o
ON c.CustomerID = o.CustomerID
```

اگر مشتری سفارشی نداشته باشد → در نتیجه نمی‌آید.

---

### LEFT JOIN

همه ردیف‌های جدول چپ برگردانده می‌شوند.

```sql
SELECT *
FROM Customers c
LEFT JOIN Orders o
ON c.CustomerID = o.CustomerID
```

اگر مشتری سفارش نداشته باشد:

```
Customer | Order
Ali      | NULL
```

---

## 2️⃣ Nested Loop Join چیست؟

این **نحوه اجرای Join** توسط SQL Server است.

SQL Server برای اجرای Join سه الگوریتم دارد:

- Nested Loop Join
- Hash Join
- Merge Join

مثلاً همین کوئری:

```sql
SELECT *
FROM Customers c
INNER JOIN Orders o
ON c.CustomerID = o.CustomerID
```

ممکن است توسط SQL Server این‌طور اجرا شود:

```
Nested Loops (Inner Join)
```

یا

```
Hash Match (Inner Join)
```

یا

```
Merge Join
```

یعنی **نوع Join همان INNER است**، ولی **روش اجرا فرق می‌کند**.

---

## مثال Execution Plan

فرض کن Execution Plan این را نشان بدهد:

```
Nested Loops (Inner Join)
```

معنی‌اش:

- نوع Join = **INNER JOIN**
- الگوریتم اجرا = **Nested Loop**

---

## مثال دیگر

اگر بنویسی:

```sql
SELECT *
FROM Customers c
LEFT JOIN Orders o
ON c.CustomerID = o.CustomerID
```

Execution Plan ممکن است بگوید:

```
Nested Loops (Left Outer Join)
```

یا

```
Hash Match (Left Outer Join)
```

---

✅ **خلاصه**

| مفهوم | نوع |
|------|------|
| INNER JOIN | نوع Join |
| LEFT JOIN | نوع Join |
| Nested Loop Join | الگوریتم اجرای Join |

یعنی:

```
Query Logic  → INNER / LEFT / RIGHT
Execution Method → Nested Loop / Hash / Merge
```
