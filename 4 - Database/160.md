تعریف **Shrink Database** در SQL Server عملیاتی است که برای **کاهش اندازه فایل‌های دیتابیس (Data File و Log File)** روی دیسک استفاده می‌شود.

به زبان ساده:

وقتی داده‌ای از دیتابیس حذف می‌شود، **فضای آن داخل دیتابیس آزاد می‌شود ولی اندازه فایل روی دیسک کوچک نمی‌شود**.

عملیات **Shrink** این فضای خالی را جمع می‌کند و فایل دیتابیس را **کوچک‌تر می‌کند**.

---

## مثال ساده

فرض کنید:

- دیتابیس شما **10GB** است.
- شما **6GB داده را حذف می‌کنید**.

بعد از حذف:

- اندازه فایل هنوز **10GB** است.
- اما **6GB فضای خالی داخل دیتابیس** وجود دارد.

اگر **Shrink** اجرا کنید:

- فایل دیتابیس ممکن است به **4GB** کاهش پیدا کند.

---

## انواع Shrink در SQL Server

### 1️⃣ Shrink Database

کل دیتابیس را کوچک می‌کند.
```sql

DBCC SHRINKDATABASE (MyDatabase);

```
---

### 2️⃣ Shrink File

یک فایل خاص از دیتابیس را کوچک می‌کند.
```sql

DBCC SHRINKFILE (MyDatabase_Data, 1000);

```
عدد **1000** یعنی اندازه هدف فایل (بر حسب MB).

---

## Shrink چگونه کار می‌کند؟

موتور SQL Server:

1. صفحات داده را به **ابتدای فایل منتقل می‌کند**
2. فضای خالی انتهای فایل را **آزاد می‌کند**
3. اندازه فایل روی دیسک **کم می‌شود**

---

## مشکل مهم Shrink (خیلی مهم در مصاحبه)

استفاده زیاد از Shrink باعث **Fragmentation شدید** در ایندکس‌ها می‌شود.

Fragmentation یعنی:

- داده‌ها به صورت **پراکنده در دیسک** ذخیره می‌شوند
- سرعت Query کاهش پیدا می‌کند

به همین دلیل:

✅ **Shrink نباید به صورت مداوم استفاده شود.**

---

## چه زمانی باید از Shrink استفاده کنیم؟

موارد مناسب:

- حذف مقدار بسیار زیادی داده
- آرشیو کردن داده‌ها
- پاک کردن جدول‌های بزرگ
- بعد از عملیات Maintenance بزرگ

مثال:

اگر 200GB داده حذف شده باشد.

---

## چه زمانی نباید استفاده کنیم؟

در این موارد **نباید Shrink اجرا شود**:

- به صورت روزانه
- به صورت اتوماتیک
- در سیستم‌های OLTP فعال
- فقط برای آزاد کردن کمی فضا

چون باعث **کاهش کارایی دیتابیس** می‌شود.

---

## بهترین Practice

اگر Shrink انجام شد بهتر است بعدش:

1️⃣ **Rebuild Index**
```sql

ALTER INDEX ALL ON TableName REBUILD;

```
یا

2️⃣ **Reorganize Index**

---

✅ **خلاصه:**

درواقع Shrink Database عملیاتی است که

فضای خالی داخل دیتابیس را جمع می‌کند و اندازه فایل دیتابیس را روی دیسک **کاهش می‌دهد**،

اما استفاده زیاد از آن باعث **Fragmentation و کاهش Performance** می‌شود.
