درواقع Deadlock Priority در SQL Server یک **تنظیم قابل تعیین برای هر سشن** است که به SQL Server می‌گوید اگر بن‌بست (Deadlock) رخ داد، **کدام تراکنش را قربانی کند**.

به زبان ساده:
وقتی دو تراکنش در وضعیت بن‌بست گیر می‌کنند، SQL Server باید یکی را بکشد تا چرخه قطع شود.  
درواقع Deadlock Priority کمک می‌کند **شما تعیین کنید کدام تراکنش مهم‌تر است و نباید قربانی شود**.

---

# تعریف Deadlock Priority چیست؟

ابزار SQL Server برای هر سشن یک مقدار Priority نگه می‌دارد:

```
SET DEADLOCK_PRIORITY { LOW | NORMAL | HIGH | <numeric range> }
```

مقادیر عددی بین **-10 تا +10** مجاز هستند.

هر تراکنش که Priority پایین‌تری داشته باشد، در زمان Deadlock **کشته می‌شود** و پیام 1205 دریافت می‌کند.

---

# چرا مطرح است؟ (اهمیت)

دلایل اصلی:

## 1) تعیین تراکنش «ارزان‌تر» برای قربانی شدن

مثلاً:
- تراکنش A: گزارش‌گیری سنگین، ولی قابلیت Retry دارد → می‌تواند قربانی شود.
- تراکنش B: عملیات مالی حیاتی → نباید متوقف شود.

با Priority شما مشخص می‌کنید:

```
T1 (مالی):  SET DEADLOCK_PRIORITY HIGH
T2 (گزارش): SET DEADLOCK_PRIORITY LOW
```

اگر بن‌بست شد، **گزارش‌گیری کشته می‌شود، نه عملیاتی که پول جابه‌جا می‌کند**.

---

## 2) کنترل رفتار در سیستم‌های پرتراکنش

در سیستم‌های:
- مالی  
- رزرو  
- انبار  
- پرداخت آنلاین  

بعضی تراکنش‌ها اصلاً نباید Fail شوند.

تعیین Priority باعث می‌شود تراکنش مهم **همیشه زنده بماند**.

---

## 3) کاهش خطاهای غیرقابل پیش‌بینی

وقتی Priority مشخص نباشد، SQL Server می‌گوید:
«کدام تراکنش هزینه‌ی کمتری برای Rollback دارد؟»  
و همان را می‌کشد.

ولی این همیشه مطابق منطق بیزینسی نیست.

---

# مثال واقعی با کد

### Session 1 (تراکنش مهم‌تر)

```
SET DEADLOCK_PRIORITY HIGH;
BEGIN TRAN
UPDATE Accounts SET Balance = Balance - 100 WHERE ID = 1;
-- ادامه عملیات...
```

### Session 2 (تراکنش قابل فدا شدن)

```
SET DEADLOCK_PRIORITY LOW;
BEGIN TRAN
UPDATE Accounts SET Balance = Balance - 50 WHERE ID = 2;
-- ادامه عملیات...
```

اگر بن‌بست رخ دهد:

- Session 1 زنده می‌ماند  
- Session 2 پیام Deadlock می‌گیرد و Rollback می‌شود

---

# نکته مهم

اگر **هردو تراکنش Priority یکسان** داشته باشند، SQL Server **کم‌هزینه‌ترین** تراکنش را قربانی می‌کند.

کم‌هزینه یعنی:
- کمتر تغییر داده
- مقدار Log کمتری تولید کرده
- و Rollback ساده‌تر است

---

# خلاصه کوتاه

تعریف Deadlock Priority یعنی:

«در زمان Deadlock بگو کدام سشن مهم‌تر است و نباید کشته شود.»

چرا مهم است؟

- کنترل رفتار سیستم در بن‌بست  
- حفظ تراکنش‌های حساس (مالی، بانکی، رزرو)  
- جلوگیری از Rollback ناخواسته  
- تعیین قربانی مناسب در چرخه Deadlock
