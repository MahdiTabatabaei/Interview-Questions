درواقع **Index Maintenance** یعنی مرتب‌سازی و بهینه‌سازی ایندکس‌ها تا عملکرد Queryها سریع بماند. با گذشت زمان و انجام عملیات **INSERT / UPDATE / DELETE** ایندکس‌ها دچار **Fragmentation** می‌شوند و کارایی پایین می‌آید.

---

## چه زمانی باید Index Maintenance انجام شود؟

معمولاً وقتی **Fragmentation ایندکس زیاد شود**.

در SQL Server معمولاً این معیارها استفاده می‌شود:

### 1️⃣ Fragmentation بین 5٪ تا 30٪  
بهتر است **Index Reorganize** انجام شود.

```
ALTER INDEX IX_TableName
ON TableName
REORGANIZE;
```

ویژگی‌ها:
- سبک‌تر است
- آنلاین اجرا می‌شود
- لاگ کمتری مصرف می‌کند

---

### 2️⃣ Fragmentation بیشتر از 30٪  
بهتر است **Index Rebuild** انجام شود.

```
ALTER INDEX IX_TableName
ON TableName
REBUILD;
```

ویژگی‌ها:
- ایندکس کاملاً دوباره ساخته می‌شود
- Fragmentation را کامل حذف می‌کند
- سنگین‌تر است

---

## چگونه Fragmentation را بررسی کنیم؟

در SQL Server با این DMV:

```sql
SELECT 
    dbschemas.[name] as 'Schema',
    dbtables.[name] as 'Table',
    dbindexes.[name] as 'Index',
    indexstats.avg_fragmentation_in_percent
FROM sys.dm_db_index_physical_stats (DB_ID(), NULL, NULL, NULL, NULL) indexstats
INNER JOIN sys.tables dbtables 
    ON dbtables.[object_id] = indexstats.[object_id]
INNER JOIN sys.schemas dbschemas 
    ON dbtables.[schema_id] = dbschemas.[schema_id]
INNER JOIN sys.indexes dbindexes 
    ON dbindexes.[object_id] = indexstats.[object_id]
    AND indexstats.index_id = dbindexes.index_id
WHERE indexstats.avg_fragmentation_in_percent > 5
ORDER BY indexstats.avg_fragmentation_in_percent DESC;
```

---

## چه زمانی در عمل انجام می‌شود؟

در محیط واقعی معمولاً:

- **هفتگی** برای دیتابیس‌های شلوغ
- **ماهانه** برای دیتابیس‌های سبک
- معمولاً در **زمان کم‌ترافیک (maintenance window)**

خیلی از DBAها آن را در **SQL Server Agent Job** زمان‌بندی می‌کنند.

---

## چرا Index Maintenance مهم است؟

اگر انجام نشود:

- Queryها کند می‌شوند
- I/O دیسک زیاد می‌شود
- Execution Planها بدتر می‌شوند

---

✅ **خلاصه**

Index Maintenance زمانی انجام می‌شود که:

- ایندکس‌ها Fragment شوند
- کارایی Query پایین بیاید
- بعد از حجم زیاد INSERT/UPDATE/DELETE

قانون رایج:

```
5% - 30%  → REORGANIZE
> 30%     → REBUILD
```
