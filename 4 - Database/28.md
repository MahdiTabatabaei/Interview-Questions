تفاوت **Primary Key Index** و **Unique Index** در ظاهر شباهت زیادی دارند (هر دو مانع از ورود داده‌های تکراری می‌شوند)، اما از نظر **مفهومی (Conceptual)**، **رفتار دیتابیس** و **محدودیت‌های فنی** تفاوت‌های کلیدی دارند.

در اینجا این تفاوت‌ها را از چند جنبه بررسی می‌کنیم:

---

### ۱. هدف و معنای منطقی (Logical Intent)
*   **Primary Key (کلید اصلی):** هدف آن **شناسایی منحصربه‌فرد یک سطر** در جدول است. دیتابیس با این فرض عمل می‌کند که این ستون (یا ترکیبی از ستون‌ها) بهترین راه برای ارجاع به یک رکورد خاص است. این «هویت» جدول است.
*   **Unique Index (ایندکس یکتا):** هدف آن فقط **جلوگیری از تکراری بودن داده‌ها** در یک ستون خاص است (مثلاً ایمیل کاربر یا کد ملی). این یک محدودیت داده‌ای (Data Constraint) است، نه لزوماً هویت اصلی جدول.

### ۲. محدودیت در تعداد (Quantity)
*   **Primary Key:** هر جدول **فقط و فقط یک** Primary Key می‌تواند داشته باشد.
*   **Unique Index:** هر جدول می‌تواند **چندین** Unique Index داشته باشد.

### ۳. برخورد با مقادیر NULL
این یکی از مهم‌ترین تفاوت‌های فنی است:
*   **Primary Key:** ستون‌های تشکیل‌دهنده کلید اصلی **هرگز نباید NULL باشند** (`NOT NULL`).
*   **Unique Index:** اکثر دیتابیس‌ها (از جمله SQL Server) اجازه می‌دهند ستونی که Unique Index دارد، **مقدار NULL داشته باشد**. اما نکته ظریف اینجاست: معمولاً **فقط یک مقدار NULL** پذیرفته می‌شود (چون دیتابیس NULL را با NULL برابر نمی‌داند، اما طبق استاندارد SQL در Unique Index، مقادیر تکراری NULL مجاز نیستند و فقط یکی اجازه ورود دارد).

### ۴. نحوه ایجاد (Implicit vs Explicit)
*   **Primary Key:** وقتی شما یک Primary Key تعریف می‌کنید، دیتابیس **به صورت خودکار** یک `Unique Index` (و معمولاً یک `Clustered Index`) برای آن می‌سازد تا بتواند سرعت جستجو را تضمین کند.
*   **Unique Index:** شما باید به صورت دستی آن را تعریف کنید (`CREATE UNIQUE INDEX ...`).

---

### جدول مقایسه سریع

| ویژگی | Primary Key | Unique Index |
| :--- | :--- | :--- |
| **تعداد در هر جدول** | حداکثر ۱ عدد | نامحدود |
| **مقدار NULL** | خیر (هرگز) | بله (معمولاً یکی مجاز است) |
| **هدف** | شناسایی هویت سطر | تضمین یکتایی داده |
| **ماهیت** | Constraint (محدودیت) | Index (ایندکس) |
| **ایندکس‌سازی** | به طور پیش‌فرض ساخته می‌شود | توسط کاربر ساخته می‌شود |

---

### چه زمانی از کدام استفاده کنیم؟

1.  **استفاده از Primary Key:** برای ستون‌هایی که به عنوان شناسه اصلی (ID) هستند، تغییر نمی‌کنند و همیشه باید وجود داشته باشند (مثل `UserID` یا `OrderID`).
2.  **استفاده از Unique Index:** برای ستون‌هایی که ذاتاً یکتا هستند اما هویت سطر محسوب نمی‌شوند و ممکن است بخواهید بعداً آن‌ها را خالی (NULL) بگذارید یا در کنار ID از آن‌ها برای جستجو استفاده کنید (مثل `Email`, `Username`, `SSN` یا `PassportNumber`).

### نکته مهم
 آیا هر ستونی که Unique Index دارد می‌تواند Primary Key باشد؟
پاسخ  : **خیر.** چون اگر ستون شامل مقادیر `NULL` باشد، نمی‌تواند `Primary Key` باشد (چون Primary Key همیشه باید `NOT NULL` باشد).
