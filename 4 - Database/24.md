تفاوت اصلی **Heap Table** و **Clustered Table** در این است که **داده‌ها چگونه در سطح فیزیکی ذخیره و پیدا می‌شوند**.

---

# Heap Table

درواقع **Heap** یعنی جدول **هیچ Clustered Index ندارد**.

بنابراین:

- داده‌ها **بدون ترتیب خاصی** در صفحات ذخیره می‌شوند.
- دیتابیس هیچ ساختار مرتب‌شده‌ای برای ردیف‌ها ندارد.

ساختار ساده:

```
Page1 → Rows
Page2 → Rows
Page3 → Rows
```

هیچ ترتیب منطقی بین صفحات وجود ندارد.

### ویژگی‌ها

- عمل Insert معمولاً سریع است (چون رکورد فقط در اولین فضای خالی قرار می‌گیرد)
- برای پیدا کردن داده‌ها اغلب **Table Scan** انجام می‌شود
- و Non‑clustered indexها برای اشاره به رکورد از **RID (Row Identifier)** استفاده می‌کنند.

عمل RID شامل این موارد است:

```
FileID + PageID + SlotID
```

یعنی آدرس فیزیکی رکورد.

---

# Clustered Table

وقتی یک **Clustered Index** روی جدول ایجاد می‌شود:

- داده‌های جدول **بر اساس کلید ایندکس مرتب می‌شوند**
- خود داده‌ها در **Leaf level ایندکس** ذخیره می‌شوند

یعنی:

```
Clustered Index = خود داده‌های جدول
```

ساختار B‑Tree:

```
Root
  ↓
Intermediate Nodes
  ↓
Leaf Nodes → Actual Rows
```

پس رکوردها **به ترتیب کلید ایندکس** ذخیره می‌شوند.

مثلاً اگر Clustered Index روی `OrderID` باشد:

```
1
2
3
4
5
```

---

# تفاوت مهم در Non‑Clustered Index

### در Heap

در Non‑clustered index اشاره می‌کند به:

```
RID (Physical location)
```

یعنی:

```
Index → Page + Slot
```

---

### در Clustered Table

در Non‑clustered index اشاره می‌کند به:

```
Clustered Key
```

یعنی:

```
Index → Clustered Key → Row
```

به همین دلیل انتخاب **Clustered Key کوچک** خیلی مهم است.

---

# مقایسه عملکرد

### جستجو

Heap:

```
SELECT * FROM users WHERE id = 10
```

اگر ایندکس نباشد:

```
Table Scan
```

Clustered Table:

```
Index Seek
```

خیلی سریع‌تر.

---

### Range Queries

مثلاً:

```
WHERE order_date BETWEEN ...
```

Heap:

```
Scan
```

Clustered Table:

```
Range Scan روی B‑Tree
```

بسیار سریع‌تر.

---

### Insert

Heap:

- سریع‌تر
- چون ترتیب مهم نیست

Clustered:

- ممکن است **Page Split** رخ دهد
- مخصوصاً اگر کلید تصادفی باشد

---

### Update

در Heap ممکن است **Forwarded Records** ایجاد شود.

یعنی:

اگر رکورد بزرگ‌تر شود:

```
Row منتقل می‌شود به Page دیگر
```

ولی اشاره‌گر قبلی باقی می‌ماند.

این باعث:

- ایجاد Fragmentation
- و I/O بیشتر

می‌شود.

اما Clustered Table این مشکل را کمتر دارد.

---

# چه زمانی Heap استفاده می‌شود؟

Heap برای موارد خاص مفید است:

- **Staging tables**
- **Bulk insert tables**
- **ETL processes**
- جداول موقتی

چون:

```
Insert بسیار سریع است
```

---

# چه زمانی Clustered Table بهتر است؟

در اکثر سیستم‌ها.

به خصوص وقتی:

- Query زیاد داریم
- Join زیاد داریم
- Range queries داریم
- Sort داریم

---

# جمع‌بندی

Heap Table:

- بدون Clustered Index
- داده‌ها بدون ترتیب
- Non‑clustered index → RID
- Insert سریع
- Query معمولاً کندتر

Clustered Table:

- داده‌ها بر اساس Clustered Key مرتب
- ساختار B‑Tree
- Non‑clustered index → Clustered Key
- Query سریع‌تر
- Range queries بسیار سریع

---

✅ در طراحی حرفه‌ای دیتابیس تقریباً همیشه توصیه می‌شود:

```
هر جدول یک Clustered Index داشته باشد
```

مگر در سناریوهای خاص مثل **ETL یا staging tables**.
