درواقع **Index Selectivity** یعنی اینکه یک ستون (یا ایندکس) چقدر **مقادیر یکتا (distinct)** دارد و چقدر می‌تواند داده‌ها را **خوب فیلتر کند**.

به زبان ساده:  
عدد Selectivity نشان می‌دهد وقتی با یک ستون فیلتر می‌کنیم، **چند رکورد باقی می‌ماند**.

---

### مثال

جدول:

```
users
```

تعداد رکوردها:

```
1,000,000
```

ستون `email`:

```
1,000,000 مقدار یکتا
```

selectivity:

```
خیلی بالا
```

چون تقریباً هر رکورد مقدار متفاوت دارد.

---

ستون `gender`:

```
male / female
```

distinct values:

```
2
```

selectivity:

```
خیلی پایین
```

چون با فیلتر هنوز تعداد زیادی رکورد باقی می‌ماند.

# High Selectivity vs Low Selectivity

### High Selectivity

ستون‌هایی که **مقادیر یکتای زیاد دارند**.

مثال:

- `id`
- `email`
- `national_code`
- `order_id`

مزیت:

ایندکس خیلی مؤثر است چون سریع تعداد رکوردها را کم می‌کند.

مثال:

```sql
WHERE email = 'test@gmail.com'
```

معمولاً فقط **یک رکورد** پیدا می‌شود.

---

### Low Selectivity

ستون‌هایی که **مقادیر تکراری زیاد دارند**.

مثال:

- `gender`
- `status`
- `is_active`
- `country` (در برخی سیستم‌ها)

مثال:

```sql
WHERE gender = 'male'
```

ممکن است **نصف جدول** را برگرداند.

در این حالت استفاده از ایندکس ممکن است حتی **از Table Scan کندتر باشد**.

---

# تأثیر Selectivity روی Performance

ابزار Optimizer دیتابیس تصمیم می‌گیرد:

- از **Index Scan / Seek**
- یا **Table Scan**

استفاده کند.

اگر selectivity بالا باشد:

```
Index Seek → سریع
```

اگر selectivity پایین باشد:

```
Table Scan → گاهی بهتر
```

چون خواندن بخش بزرگی از ایندکس + lookup ممکن است کندتر باشد.

---

# مثال عملی

جدول:

```
orders (10 million rows)
```

ستون:

```
status = pending / shipped / canceled
```

کوئری:

```sql
SELECT *
FROM orders
WHERE status = 'pending'
```

اگر 40٪ رکوردها pending باشند:

ایندکس روی `status` خیلی مفید نیست.

---

اما:

```sql
SELECT *
FROM orders
WHERE order_id = 105020
```

ایندکس روی `order_id` بسیار سریع است چون selectivity بالا است.

---

# مفهوم Selectivity در Composite Index

در Composite Index بهتر است **ستونی که Selectivity بالاتری دارد زودتر بیاید**.

مثال بهتر:

```
(email, status)
```

بدتر:

```
(status, email)
```

چون `email` فیلتر قوی‌تری ایجاد می‌کند.

---

# خلاصه

تعریف **Index Selectivity** نشان می‌دهد یک ستون چقدر داده‌ها را خوب فیلتر می‌کند.

- مقدار **High Selectivity:** مقادیر یکتای زیاد → ایندکس بسیار مؤثر
- مقدار **Low Selectivity:** مقادیر تکراری زیاد → ایندکس ممکن است کم‌اثر باشد

و دیتابیس از Selectivity برای انتخاب بهترین **Execution Plan** استفاده می‌کند.
