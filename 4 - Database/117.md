**Selectivity:**

درصد رکوردهایی که با شرط WHERE انتخاب می‌شوند.

هرچه کمتر → بهتر → Seek

**Cardinality:**

تعداد کل ردیف‌های یک جدول یا نتیجه.

مثال:

در جدول ۱۰۰۰۰۰ نفری:

`City = 'Tehran'` → ۷۰٪

Selectivity پایین (بد).

`City = 'Shiraz'` → ۵٪

Selectivity بالا (خوب).

----
در دنیای **Indexing** و **Query Optimization** دو مفهوم مهم وجود دارد که خیلی‌ها اشتباه می‌گیرند:

**Selectivity**  
و  
**Cardinality**

هر دو مربوط به این هستند که یک شرط (Predicate) چقدر رکورد برمی‌گرداند،  
اما معنی‌شان متفاوت است.

بیایید دقیق، ساده و کاربردی توضیح دهیم:

---

# 1) Cardinality چیست؟

**Cardinality = تعداد رکوردهایی که نتیجهٔ یک Query یا Predicate برمی‌گرداند.**

به عبارتی:
- "چند رکورد؟"

مثال:

جدول Employees = شامل 100,000 رکورد

```sql
SELECT *
FROM Employees
WHERE DepartmentID = 5
```

اگر 20,000 رکورد را برگرداند:

- Cardinality = 20,000

این یک مقدار **عددی** است.

---

# 2) Selectivity چیست؟

**Selectivity = درصد یا نسبت رکوردهایی که شرط انتخاب می‌کند.**

فرمول:

\[
\text{Selectivity} = \frac{\text{Number of rows returned}}{\text{Total rows}}
\]

در مثال بالا:

\[
\text{Selectivity} = \frac{20000}{100000} = 0.20
\]

یعنی:

- Selectivity = 20%
- این Selectivity **پایین** است (چون 20% داده را برمی‌گرداند)

---

# نکته مهم:

Selectivity **هر چه کمتر باشد بهتر است**.  
زیرا یعنی شرط تعداد کمی رکورد برمی‌گرداند → **Index Seek** را ترجیح می‌دهد.

---

# مقایسه مستقیم

| مفهوم | توضیح ساده | مثال |
|------|-------------|-------|
| **Cardinality** | تعداد رکوردهای بازگشتی | 20,000 |
| **Selectivity** | نسبت درصدی رکوردهای بازگشتی | 20% |

---

# مثال ساده برای درک تفاوت

### فرض کنید جدول 1,000,000 رکورد دارد.

1. Query:

```sql
WHERE Country = 'USA'
```

اگر 500,000 رکورد USA باشد:
- Cardinality = 500,000  
- Selectivity = 50% → خیلی بد → احتمال Index Scan

2. Query:

```sql
WHERE ID = 123
```

اگر فقط 1 رکورد باشد:
- Cardinality = 1  
- Selectivity = 0.0001% → فوق‌العاده → Index Seek

---

# چرا Optimizer به Selectivity اهمیت می‌دهد؟

SQL Server Optimizer تصمیم می‌گیرد:

- از **Index Seek** استفاده کند؟
- یا **Index Scan**؟
- یا **Table Scan**؟

تصمیم کاملاً بر اساس **Selectivity** انجام می‌شود.

قانون کلی:

- If Selectivity < 10% → معمولاً Seek  
- If Selectivity > 20–30% → احتمال Scan بالا  
(این اعداد تقریبی‌اند و بسته به Query متفاوت است)

---

# رابطه بین Selectivity و Cardinality

Selectivity از Cardinality به دست می‌آید.

\[
\text{Selectivity} = \frac{\text{Cardinality}}{\text{Total Rows}}
\]

اما برعکس صدق نمی‌کند:
از Selectivity نمی‌توان Cardinality دقیق را بدون تعداد کل رکوردها دانست.

---

# تشبیه بسیار ساده:

فرض کن 100 کتاب در کتابخانه داری.

- **Cardinality** = چند کتاب دنبال‌شده پیدا می‌شود؟  
مثلاً 5 کتاب.

- **Selectivity** = این 5 کتاب چند درصد کل کتاب‌ها هستند؟  
مثلاً 5%

همین.

---

# نتیجه‌گیری کوتاه برای مصاحبه‌ها

**Cardinality → مقدار**  
چند رکورد برمی‌گردد؟

**Selectivity → نسبت**  
چند درصد جدول را شامل می‌شود؟

Optimizer برای انتخاب نوع Index به **Selectivity** نگاه می‌کند،  
نه Cardinality.
