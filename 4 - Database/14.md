درواقع **Composite Index** (ایندکس ترکیبی) ایندکسی است که روی **بیش از یک ستون** ساخته می‌شود.

یعنی به جای اینکه ایندکس فقط روی یک ستون باشد، چند ستون با هم در یک ایندکس قرار می‌گیرند تا جستجو سریع‌تر شود.

## مثال

فرض کنید جدول `orders` داریم:

```
order_id | customer_id | order_date
```

اگر زیاد بر اساس `customer_id` و `order_date` جستجو کنیم، می‌توانیم یک Composite Index بسازیم:

```sql
CREATE INDEX idx_customer_date
ON orders(customer_id, order_date);
```

این ایندکس روی **دو ستون با هم** ساخته شده است.

## مزیت
کوئری‌هایی مثل این سریع‌تر اجرا می‌شوند:

```sql
SELECT *
FROM orders
WHERE customer_id = 10
AND order_date = '2025-01-01';
```

چون ایندکس دقیقاً روی همین دو ستون است.

## نکته مهم (ترتیب ستون‌ها)
ترتیب ستون‌ها در Composite Index **خیلی مهم است**.

اگر ایندکس این باشد:

```
(customer_id, order_date)
```

کوئری‌های زیر از ایندکس استفاده می‌کنند:

```sql
WHERE customer_id = 10
```

یا

```sql
WHERE customer_id = 10 AND order_date = '2025-01-01'
```

اما این کوئری معمولاً از ایندکس استفاده نمی‌کند:

```sql
WHERE order_date = '2025-01-01'
```

چون ستون اول ایندکس (`customer_id`) استفاده نشده است.

## خلاصه
- تعریف **Composite Index** = ایندکس روی **چند ستون**
- برای کوئری‌هایی که چند شرط دارند بسیار مفید است
- **ترتیب ستون‌ها در ایندکس اهمیت زیادی دارد**.
