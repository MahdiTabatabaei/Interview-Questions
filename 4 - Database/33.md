در SQL Server دو نوع **Table‑Valued Function** داریم:

- **Inline Table‑Valued Function (iTVF)**
- **Multi‑Statement Table‑Valued Function (mTVF)**

تفاوت اصلی آن‌ها در **ساختار، نحوه اجرا توسط Query Optimizer و Performance** است.

---

# 1. Inline Table‑Valued Function (iTVF)

این نوع تابع فقط **یک SELECT ساده** دارد و مستقیماً همان نتیجه را برمی‌گرداند.

ساختار:
```sql
CREATE FUNCTION dbo.GetOrdersByCustomer(@CustomerID INT)
RETURNS TABLE
AS
RETURN
(
    SELECT OrderID, OrderDate, TotalAmount
    FROM Orders
    WHERE CustomerID = @CustomerID
)
```

استفاده:
```sql
SELECT *
FROM dbo.GetOrdersByCustomer(10)
```

### ویژگی‌ها

- فقط **یک SELECT** دارد  
- **table variable ندارد**
- **RETURN (SELECT …)** مستقیم است  
- **بسیار سریع**

### دلیل سرعت بالا

ابزار SQL Server این تابع را **Inline** می‌کند.  
یعنی Query Optimizer آن را مثل یک **View** داخل Query اصلی باز می‌کند.

مثلاً:

```sql
SELECT *
FROM dbo.GetOrdersByCustomer(10)
WHERE TotalAmount > 100
```

Optimizer آن را تبدیل می‌کند به:

```sql
SELECT *
FROM Orders
WHERE CustomerID = 10
AND TotalAmount > 100
```

پس:

- Statistics استفاده می‌شود
- Parallelism ممکن است
- Execution Plan بهینه است

---

# 2. Multi‑Statement Table‑Valued Function (mTVF)

در این نوع تابع می‌توان **چندین دستور SQL** نوشت.

ساختار:

```sql
CREATE FUNCTION dbo.GetOrdersMulti(@CustomerID INT)
RETURNS @Result TABLE
(
    OrderID INT,
    OrderDate DATE,
    TotalAmount MONEY
)
AS
BEGIN

    INSERT INTO @Result
    SELECT OrderID, OrderDate, TotalAmount
    FROM Orders
    WHERE CustomerID = @CustomerID

    RETURN
END
```

استفاده:

```sql
SELECT *
FROM dbo.GetOrdersMulti(10)
```

---

## ویژگی‌ها

- چندین statement دارد
- از **table variable** استفاده می‌کند
- می‌توان IF، LOOP و logic پیچیده نوشت

اما یک مشکل بزرگ دارد.

---

# مشکل بزرگ Multi‑Statement TVF

ابزار SQL Server برای table variable **آمار (Statistics)** ندارد.

در نتیجه Query Optimizer **تخمین می‌زند فقط 1 ردیف وجود دارد.**

این باعث می‌شود:

- Joinهای بد انتخاب شود
- Nested Loop اشتباه انتخاب شود
- Query بسیار کند شود

مثلاً اگر تابع واقعاً **100000 ردیف** برگرداند، SQL Server هنوز فکر می‌کند **1 ردیف** است.

---

# تفاوت‌های مهم

### ساختار

Inline
```sql
RETURNS TABLE
RETURN (SELECT ...)
```

Multi
```sql
RETURNS @table TABLE(...)
BEGIN
INSERT ...
RETURN
END
```

---

### تعداد Query

Inline  
فقط **یک SELECT**

Multi  
چندین statement

---

### Performance

Inline  
✅ بسیار سریع

Multi  
❌ معمولاً کند

---

### Query Optimizer

Inline  
✅ کامل optimize می‌شود

Multi  
❌ به عنوان **black box** دیده می‌شود

---

### Statistics

Inline  
✅ دارد

Multi  
❌ ندارد

---

### قابلیت نوشتن logic پیچیده

Inline  
❌ محدود

Multi  
✅ IF / LOOP / چند query

---

# جمع‌بندی مهم 


**کدام بهتر است؟**

تقریباً همیشه:

**Inline Table Function**

چون:

- optimizer-friendly
- statistics دارد
- execution plan بهتر
- performance بسیار بالاتر

Multi‑Statement فقط وقتی استفاده می‌شود که **logic خیلی پیچیده** باشد.
