در ASP.NET Core می‌توان چند **Health Check** مختلف را با **Tag** دسته‌بندی کرد تا بتوانیم مشخص کنیم کدام health check در کدام endpoint اجرا شود (مثلاً برای **Liveness، Readiness یا Dependency checks**).

ایده اصلی این است که هنگام ثبت Health Check، یک یا چند **Tag** تعریف کنیم و بعد در `MapHealthChecks` فیلتر کنیم.

---

# 1️⃣ تعریف Health Check با Tag

در زمان ثبت health check می‌توان `tags` مشخص کرد.

مثال:

```csharp
builder.Services.AddHealthChecks()

    .AddSqlServer(
        builder.Configuration.GetConnectionString("DefaultConnection"),
        name: "sql",
        tags: new[] { "db", "ready" })

    .AddRedis(
        builder.Configuration.GetConnectionString("Redis"),
        name: "redis",
        tags: new[] { "cache", "ready" })

    .AddUrlGroup(
        new Uri("https://api.example.com"),
        name: "external-api",
        tags: new[] { "api", "ready" });
```

در اینجا:

- SQL → tag: `db`, `ready`
- Redis → tag: `cache`, `ready`
- API → tag: `api`, `ready`

---

# 2️⃣ فیلتر کردن Health Checks با Tag

در endpoint می‌توان مشخص کرد کدام health check اجرا شود.

### Liveness endpoint

```csharp
app.MapHealthChecks("/health/live", new HealthCheckOptions
{
    Predicate = _ => false
});
```

این یعنی:

- هیچ dependency بررسی نشود
- فقط بررسی شود که برنامه بالا است

---

### Readiness endpoint

```csharp
app.MapHealthChecks("/health/ready", new HealthCheckOptions
{
    Predicate = check => check.Tags.Contains("ready")
});
```

این endpoint فقط health checkهایی را اجرا می‌کند که tag `ready` دارند.

پس اجرا می‌شوند:

- SQL
- Redis
- External API

---

# 3️⃣ ساخت endpoint برای دسته خاص

مثلاً فقط Database checks:

```csharp
app.MapHealthChecks("/health/db", new HealthCheckOptions
{
    Predicate = check => check.Tags.Contains("db")
});
```

یا فقط Cache:

```csharp
app.MapHealthChecks("/health/cache", new HealthCheckOptions
{
    Predicate = check => check.Tags.Contains("cache")
});
```

---

# 4️⃣ مثال کامل

```csharp
builder.Services.AddHealthChecks()

    .AddSqlServer(
        builder.Configuration.GetConnectionString("DefaultConnection"),
        tags: new[] { "db", "ready" })

    .AddRedis(
        builder.Configuration.GetConnectionString("Redis"),
        tags: new[] { "cache", "ready" });

var app = builder.Build();

app.MapHealthChecks("/health/live", new HealthCheckOptions
{
    Predicate = _ => false
});

app.MapHealthChecks("/health/ready", new HealthCheckOptions
{
    Predicate = check => check.Tags.Contains("ready")
});

app.MapHealthChecks("/health/db", new HealthCheckOptions
{
    Predicate = check => check.Tags.Contains("db")
});

app.Run();
```

---

# 5️⃣ کاربرد واقعی Tagها

در پروژه‌های واقعی:

```
Tag: live
Tag: ready
Tag: db
Tag: cache
Tag: messaging
Tag: external
```

مثلاً:

- Kubernetes → `/health/ready`
- Monitoring → `/health/db`
- DevOps dashboard → `/health`

---

✅ خلاصه:

درواقع Tagها کمک می‌کنند:

- خروجی Health Checkها **گروه‌بندی شوند**
- و endpointهای مختلف **چک‌های متفاوتی اجرا کنند**
- سیستم مانیتورینگ **کنترل بیشتری داشته باشد**
