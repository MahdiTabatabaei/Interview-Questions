در  ASP.NET Core، این متدها برای پیکربندی Pipeline درخواست-پاسخ استفاده می‌شوند:

- **`Use`:**

- **عملکرد:** Middlewareای را به انتهای Pipeline اضافه می‌کند. این Middleware می‌تواند درخواست را پردازش کند و سپس آن را به Middleware بعدی ارسال کند (`await _next(context);`)، یا می‌تواند پردازش را متوقف کرده و پاسخ را زودتر ارسال کند.

- **ترتیب:** Middlewareهای اضافه شده با `Use` به ترتیبی که فراخوانی می‌شوند، اجرا می‌شوند.

- **کاربرد:** برای Middlewareهایی که بخشی از زنجیره پردازش هستند و ممکن است نیاز به اجرای Middlewareهای بعدی داشته باشند (مانند لاگینگ، احراز هویت، مسیریابی).

- **`Run`:**

- **عملکرد:** یک Middleware را به انتهای Pipeline اضافه می‌کند که **همیشه** پردازش را در همان نقطه متوقف می‌کند. این Middleware پاسخی را مستقیماً به کلاینت ارسال می‌کند و از اجرای Middlewareهای بعدی جلوگیری می‌کند.

- **ترتیب:** معمولاً آخرین Middlewareای است که در Pipeline فراخوانی می‌شود.

- **کاربرد:** برای تعریف یک نقطه پایانی که همیشه پاسخی را تولید می‌کند (مثلاً “Hello World!” ساده).

- **`Map` و `MapWhen`:**

- **عملکرد:** برای ایجاد Branching (انشعاب) در Pipeline استفاده می‌شوند. یعنی بر اساس شرطی خاص (مثلاً بخشی از مسیر URL)، یک زیر-Pipeline جداگانه ایجاد می‌کنند.

- **`Map(path, applicationBuilder => ...)`:** اگر مسیر درخواست با `path` شروع شود، کد داخل `applicationBuilder` اجرا می‌شود.

- **`MapWhen(predicate, applicationBuilder => ...)`:** اگر شرط `predicate` (یک تابع که `HttpContext` را می‌گیرد و Boolean برمی‌گرداند) برقرار باشد، زیر-Pipeline اجرا می‌شود.

- **کاربرد:** برای هدایت درخواست‌ها به بخش‌های مختلف برنامه بر اساس مسیر URL یا شرط دیگر، بدون اینکه لزوماً اجرای Pipeline اصلی متوقف شود (مگر اینکه Middlewareهای داخل Branch این کار را انجام دهند).


**مثال:**
```csharp

// Program.cs
var builder = WebApplication.CreateBuilder(args);
var app = builder.Build();

// Middleware 1: Use - همیشه اجرا می‌شود و به بعدی می‌رود
app.Use(async (context, next) =>
{
    Console.WriteLine("Middleware 1 (Use) - Before");
    await next(); // فراخوانی Middleware بعدی
    Console.WriteLine("Middleware 1 (Use) - After");
});

// Middleware 2: Map - فقط برای مسیر /branch اجرا می‌شود
app.Map("/branch", builder =>
{
    builder.Use(async (context, next) =>
    {
        Console.WriteLine("Branch Middleware - Before");
        await next();
        Console.WriteLine("Branch Middleware - After");
    });
    builder.Run(async context => await context.Response.WriteAsync("Hello from Branch!"));
});

// Middleware 3: Run - همیشه اجرا می‌شود و پردازش را متوقف می‌کند
app.Run(async context =>
{
    Console.WriteLine("Middleware 3 (Run) - Executing");
    await context.Response.WriteAsync("Hello from the end of the pipeline!");
});

app.Run();

```

**سناریوها:**

- **درخواست به `/`:**

1. `Middleware 1 (Use) - Before`
2. `Middleware 3 (Run) - Executing`
3. `Hello from the end of the pipeline!` (پردازش متوقف می‌شود)
4. `Middleware 1 (Use) - After` (این بخش بعد از اتمام Run اجرا نمی‌شود، چون Run پردازش را متوقف کرده بود)

- **درخواست به `/branch`:**

1. `Middleware 1 (Use) - Before`
2. `Branch Middleware - Before` (چون مسیر با `/branch` مطابقت دارد)
3. `Hello from Branch!` (متوقف می‌شود چون `Run` در branch بود)
4. `Branch Middleware - After` (بعد از اتمام `Run` در branch اجرا می‌شود)
5. `Middleware 1 (Use) - After` (بعد از اتمام branch اجرا می‌شود)
