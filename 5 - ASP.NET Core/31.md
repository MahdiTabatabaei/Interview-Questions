در ASP.NET Core دو روش اصلی برای ساخت API وجود دارد: **Controller API** و **Minimal API**. تفاوت آن‌ها بیشتر در **ساختار، سطح abstraction و سادگی کد** است.

---

# 1. Controller API

این همان **روش سنتی ASP.NET Core Web API** است که مبتنی بر **Controller و Attribute Routing** است.

### مثال

```csharp
[ApiController]
[Route("api/[controller]")]
public class ProductsController : ControllerBase
{
    [HttpGet]
    public IActionResult Get()
    {
        return Ok(new[] { "Laptop", "Phone" });
    }
}
```

### ویژگی‌ها

- ساختار **MVC-style**
- استفاده از **Controller**
- پشتیبانی قوی از:
  - Filters
  - Model Binding
  - Validation
  - Attribute Routing
- مناسب برای پروژه‌های **بزرگ و سازمانی**

---

# 2. Minimal API

در .NET 6 معرفی شد و هدف آن **نوشتن API با کمترین کد ممکن** است.

### مثال

```csharp
var app = builder.Build();

app.MapGet("/products", () =>
{
    return new[] { "Laptop", "Phone" };
});

app.Run();
```

### ویژگی‌ها

- بدون Controller
- بدون کلاس اضافی
- endpoint ها مستقیم در `Program.cs`
- ساده و سریع

---

# تفاوت اصلی

| ویژگی | Minimal API | Controller API |
|------|-------------|---------------|
| ساختار | ساده | لایه‌بندی شده |
| استفاده از Controller | ندارد | دارد |
| مقدار Boilerplate | خیلی کم | بیشتر |
| مناسب برای | سرویس‌های کوچک | پروژه‌های بزرگ |
| خوانایی در پروژه بزرگ | کمتر | بهتر |
| تست‌پذیری | سخت‌تر | بهتر |

---

# تفاوت معماری

### Minimal API

Flow ساده:

```
Request
   ↓
Endpoint (MapGet / MapPost)
   ↓
Response
```

---

### Controller API

Flow کامل‌تر:

```
Request
   ↓
Routing
   ↓
Controller
   ↓
Action
   ↓
Filters
   ↓
Response
```

---

# مثال مقایسه

### Minimal API

```csharp
app.MapPost("/users", (User user) =>
{
    return Results.Ok(user);
});
```

### Controller API

```csharp
[HttpPost]
public IActionResult Create(User user)
{
    return Ok(user);
}
```

---

# چه زمانی Minimal API بهتر است؟

- Microservices
- Prototype سریع
- APIهای ساده
- Serverless
- Backend for Frontend (BFF)

---

# چه زمانی Controller بهتر است؟

- پروژه‌های **Enterprise**
- API بزرگ
- نیاز به **Filters**
- نیاز به **Versioning**
- نیاز به **complex validation**

---

✅ **خلاصه**

- **Minimal API** → سبک، سریع، کد کمتر  
- **Controller API** → ساختارمند، قدرتمند، مناسب پروژه‌های بزرگ

---

یک نکته جالب که خیلی‌ها در مصاحبه نمی‌دانند:

**Minimal API هم در واقع از همان Pipeline و Endpoint Routing استفاده می‌کند که Controllerها استفاده می‌کنند.**

فقط یک **لایه abstraction کمتر** دارد.
