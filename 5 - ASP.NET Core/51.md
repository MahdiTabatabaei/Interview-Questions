اگر یک **Scoped service داخل Singleton inject شود** مشکل **lifetime mismatch** ایجاد می‌شود.

### چرا مشکل است؟

- وضعیت **Singleton** → یک بار برای کل عمر برنامه ساخته می‌شود.
- وضعیت **Scoped** → برای هر **request / scope** جدید ساخته می‌شود.

اگر Scoped داخل Singleton تزریق شود:

- درواقع Singleton فقط **یک بار ساخته می‌شود**
- همان **یک instance از Scoped** برای همیشه نگه داشته می‌شود
- در نتیجه دیگر برای هر request instance جدید ساخته نمی‌شود.

این باعث می‌شود:

- رفتار Scoped از بین برود
- داده‌های requestها با هم قاطی شوند
- مشکلات thread-safety ایجاد شود

در ASP.NET Core معمولاً حتی **Exception** هم می‌گیرید:
```markdown

Cannot consume scoped service 'X' from singleton

```
مثال
```csharp

public class MySingletonService
{
    private readonly IScopedService _scoped;

    public MySingletonService(IScopedService scoped)
    {
        _scoped = scoped;
    }
}

```
اگر `IScopedService` scoped باشد، container خطا می‌دهد.

### راه‌حل‌ها

معمولاً یکی از این کارها انجام می‌شود:

• تغییر lifetime

مثلاً Singleton را **Scoped** کنید.

• استفاده از `IServiceProvider` و ساخت scope
```csharp

using var scope = serviceProvider.CreateScope();
var scopedService = scope.ServiceProvider.GetRequiredService<IScopedService>();

```
• استفاده از `IServiceScopeFactory`

---

✅ خلاصه:

- آبجکت Singleton عمر طولانی دارد
- و Scoped وابسته به request است
- در Inject کردن Scoped داخل Singleton باعث **lifetime violation** و مشکلات منطقی یا runtime exception می‌شود.
