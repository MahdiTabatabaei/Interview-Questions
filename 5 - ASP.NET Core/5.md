در واقع Pipeline در ASP.NET Core مکانیزم اصلی پردازش درخواست‌های HTTP است. این Pipeline از توالی‌ای از **Middleware**ها تشکیل شده است که به ترتیب اجرا می‌شوند. هر Middleware مسئول انجام بخشی از وظایف مربوط به پردازش درخواست و/یا تولید پاسخ است.

**کاربردها:**

- **پردازش درخواست:** Middlewareها می‌توانند درخواست را قبل از رسیدن به Endpoint نهایی تغییر دهند، اطلاعاتی از آن استخراج کنند، یا حتی پاسخ را زودتر ارسال کنند.
- **مدیریت پاسخ:** Middlewareها می‌توانند پاسخ را قبل از ارسال به کلاینت تغییر دهند، اطلاعاتی به آن اضافه کنند، یا خطاها را مدیریت کنند.
- **وظایف متداول:** بسیاری از قابلیت‌های اصلی ASP.NET Core مانند مسیریابی (Routing)، احراز هویت (Authentication)، مدیریت خطا (Error Handling)، و Servicing فایل‌های استاتیک از طریق Middleware پیاده‌سازی می‌شوند.
- **انعطاف‌پذیری و ترتیب اجرا:** ترتیب قرارگیری Middlewareها در Pipeline بسیار مهم است، زیرا تعیین می‌کند که کدام Middleware قبل از دیگری اجرا شود.

**مثال:**

تصور کنید Pipeline مانند یک خط تولید کارخانه است. هر ایستگاه کاری (Middleware) کاری را روی محصول (درخواست/پاسخ) انجام می‌دهد و سپس آن را به ایستگاه بعدی می‌فرستد.
```csharp

// Program.cs
var builder = WebApplication.CreateBuilder(args);
var app = builder.Build();

// ترتیب اجرا مهم است!

// 1. Middleware برای نمایش پیام خطا در صورت بروز خطا
app.UseDeveloperExceptionPage();

// 2. Middleware برای فعال کردن مسیریابی (Routing)
app.UseRouting();

// 3. Middleware برای احراز هویت (Authentication)
app.UseAuthentication();

// 4. Middleware برای مجوز دسترسی (Authorization)
app.UseAuthorization();

// 5. Middleware برای تعریف Endpointها و نحوه پردازش آن‌ها
app.UseEndpoints(endpoints =>
{
    endpoints.MapGet("/", async context => await context.Response.WriteAsync("Hello!"));
});

app.Run();

```
در این مثال، ابتدا `UseDeveloperExceptionPage` خطاها را مدیریت می‌کند، سپس `UseRouting` مسیر را پیدا می‌کند، `UseAuthentication` کاربر را شناسایی کرده و `UseAuthorization` دسترسی او را بررسی می‌کند، و در نهایت `UseEndpoints` درخواست را به کد مربوطه هدایت می‌کند.
