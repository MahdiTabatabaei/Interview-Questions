مسئله `ProblemDetails` یک استاندارد (RFC 7807) برای تعریف ساختار استاندارد خطاها در پاسخ‌های HTTP API است. هدف آن ارائه یک فرمت JSON مشخص و قابل فهم برای خطاها است تا کلاینت‌ها بتوانند به راحتی خطاها را شناسایی و پردازش کنند.

**چرا استفاده می‌شود؟**

قبل از `ProblemDetails`، APIها از فرمت‌های مختلفی برای خطا استفاده می‌کردند که پردازش آن‌ها برای کلاینت‌ها دشوار بود. `ProblemDetails` یک فرمت واحد و قابل پیش‌بینی ارائه می‌دهد.

**اجزای اصلی `ProblemDetails`:**

- `type` (URL): یک شناسه برای نوع خطا (اختیاری).
- `title` (string): یک توضیح کوتاه و قابل خواندن برای خطا.
- `status` (integer): کد وضعیت HTTP مربوط به خطا (مانند 400, 404, 500).
- `detail` (string): توضیح دقیق‌تر و قابل فهم‌تر خطا برای توسعه‌دهندگان.
- `instance` (URL): شناسه‌ای برای نمونه خاص خطای رخ داده (اختیاری).
- **Extensions:** فیلدهای اضافی که می‌توانند اطلاعات بیشتری در مورد خطا ارائه دهند (مثلاً نام فیلد نامعتبر در اعتبارسنجی).

**نحوه استفاده در ASP.NET Core:**

- **خطاهای اعتبارسنجی:** هنگامی که از `[ApiController]` استفاده می‌کنید و `ModelState.IsValid` نادرست باشد، ASP.NET Core به طور خودکار یک پاسخ `ProblemDetails` با کد وضعیت 400 برمی‌گرداند که حاوی جزئیات خطاهای اعتبارسنجی است.
- **خطاهای سفارشی:** می‌توانید با استفاده از `Results.Problem()` در Minimal APIها یا بازگرداندن یک `ObjectResult` حاوی یک نمونه `ProblemDetails`، خطاهای سفارشی خود را با این فرمت برگردانید.

**مثال:**
```csharp

// Minimal API Example
app.MapGet("/items/{id}", (int id) => {
    if (id == 0)
    {
        // بازگرداندن ProblemDetails برای خطای نامعتبر
        return Results.Problem(
            detail: "Item ID cannot be zero.",
            title: "Invalid Request",
            statusCode: StatusCodes.Status400BadRequest,
            type: "https://example.com/errors/invalid-id"
        );
    }
    // ... logic to get item ...
    return Results.Ok(new { Id = id, Name = "Sample Item" });
});

// Controller Example (using Validation ProblemDetails)
[ApiController]
[Route("api/[controller]")]
public class OrdersController : ControllerBase
{
    [HttpPost]
    public IActionResult CreateOrder(OrderViewModel order) // Assume OrderViewModel has validation attributes
    {
        // If ModelState is invalid due to validation attributes on OrderViewModel,
        // [ApiController] will automatically return a ProblemDetails response.
        if (!ModelState.IsValid)
        {
            // No need to manually return BadRequest with ProblemDetails here if using [ApiController]
            // as it's handled automatically. However, you could return custom details if needed.
            return BadRequest(ModelState); // This will also be formatted as ProblemDetails by the framework.
        }

        // ... process order ...
        return CreatedAtAction(nameof(GetOrder), new { id = 123 }, order);
    }

    // Example of manually returning ProblemDetails
    [HttpGet("error-example")]
    public IActionResult GetErrorExample()
    {
        return Problem(
            detail: "An unexpected error occurred during processing.",
            title: "Internal Server Error",
            statusCode: StatusCodes.Status500InternalServerError
        );
    }
}

```

اگر به `/items/0` درخواست GET بزنید، پاسخ JSON زیر را دریافت خواهید کرد:
```json
{
  "type": "https://example.com/errors/invalid-id",
  "title": "Invalid Request",
  "status": 400,
  "detail": "Item ID cannot be zero."
}

```
