برای بررسی سلامت وابستگی‌ها مثل **Database، Redis، External API** در ASP.NET Core از **Health Checks** استفاده می‌شود. این کار کمک می‌کند سیستم‌های مانیتورینگ یا Kubernetes بفهمند که آیا برنامه واقعاً آماده سرویس‌دهی هست یا نه.

سه روش رایج وجود دارد:

---

# 1️⃣ استفاده از Health Checkهای آماده (بهترین روش)

پکیج‌های آماده برای اکثر سرویس‌ها وجود دارد.

### مثال: SQL Server

ابتدا پکیج:

```bash
dotnet add package AspNetCore.HealthChecks.SqlServer
```

سپس در `Program.cs`:

```csharp
builder.Services.AddHealthChecks()
    .AddSqlServer(
        builder.Configuration.GetConnectionString("DefaultConnection"),
        name: "sql",
        failureStatus: HealthStatus.Unhealthy);
```

کارهایی که انجام می‌دهد:

- اتصال به SQL Server
- اجرای یک query ساده
- بررسی قابل دسترس بودن دیتابیس

---

### مثال: Redis

پکیج:

```bash
dotnet add package AspNetCore.HealthChecks.Redis
```

سپس:

```csharp
builder.Services.AddHealthChecks()
    .AddRedis(
        builder.Configuration.GetConnectionString("Redis"),
        name: "redis",
        failureStatus: HealthStatus.Unhealthy);
```

Health check در اینجا:

- اتصال به Redis
- بررسی پاسخگویی server

---

### مثال: External API

پکیج:

```bash
dotnet add package AspNetCore.HealthChecks.Uris
```

سپس:

```csharp
builder.Services.AddHealthChecks()
    .AddUrlGroup(
        new Uri("https://api.example.com/health"),
        name: "external-api",
        failureStatus: HealthStatus.Degraded);
```

این کار:

- یک HTTP request می‌فرستد
- status code را بررسی می‌کند

# 2️⃣ ساخت Custom Health Check

اگر health check آماده وجود نداشت، می‌توانیم خودمان بسازیم.

مثال برای Database:

```csharp
public class DatabaseHealthCheck : IHealthCheck
{
    private readonly string _connectionString;

    public DatabaseHealthCheck(IConfiguration config)
    {
        _connectionString = config.GetConnectionString("DefaultConnection");
    }

    public async Task<HealthCheckResult> CheckHealthAsync(
        HealthCheckContext context,
        CancellationToken cancellationToken = default)
    {
        try
        {
            using var connection = new SqlConnection(_connectionString);
            await connection.OpenAsync(cancellationToken);

            return HealthCheckResult.Healthy("Database reachable");
        }
        catch (Exception ex)
        {
            return HealthCheckResult.Unhealthy("Database not reachable", ex);
        }
    }
}
```

ثبت در DI:

```csharp
builder.Services.AddHealthChecks()
    .AddCheck<DatabaseHealthCheck>("database");
```

# 3️⃣ تعریف endpoint برای Health Check

در `Program.cs`:

```csharp
app.MapHealthChecks("/health");
```

حالا با این آدرس:

```
GET /health
```

همه dependencyها بررسی می‌شوند.

# بهترین Practice در پروژه‌های واقعی

معمولاً دو endpoint می‌سازند:

```
/health/live
/health/ready
```

- **live** → فقط بررسی می‌کند برنامه بالا است  
- **ready** → Database + Redis + API را بررسی می‌کند

---

✅ خلاصه:

برای بررسی سلامت وابستگی‌ها:

- Database → `AddSqlServer()`
- Redis → `AddRedis()`
- API → `AddUrlGroup()`
- Custom dependency → `IHealthCheck`
