
## 🧩 مفهوم Reverse Proxy

تعریف **Reverse Proxy** (پروکسی معکوس) یک **سرور واسط** بین کاربر و سرور اصلی (مثلاً Kestrel) است.

وقتی کاربر در مرورگر Request می‌فرستد:

```
Client → Reverse Proxy → Application Server (Kestrel)
```

درواقع Reverse Proxy **درخواست را دریافت** می‌کند، ممکن است پردازش اولیه‌ای انجام دهد (مثل کش، امنیت، load balancing)، سپس آن را به سرور اصلی (مثل Kestrel) **ارسال (forward)** می‌کند.

برخلاف **Forward Proxy** که سمت کاربر قرار دارد، Reverse Proxy در **سمت سرور** مستقر است.

---

## ⚙️ وظیفه و مزایای Reverse Proxy

یک Reverse Proxy معمولاً کارهای زیر را انجام می‌دهد:

### 1. 🔒 امنیت
- پنهان کردن سرور داخلی (Kestrel) از دسترسی مستقیم.
- استفاده از SSL/TLS termination؛ یعنی ارتباط HTTPS را روی Proxy پیاده می‌کند و داخل شبکه با HTTP معمولی با Kestrel حرف می‌زند.
- فیلتر یا محدود کردن درخواست‌های ناامن.

---

### 2. ⚡ کش و بهینه‌سازی

- می‌تواند پاسخ‌ها را کش کند و بدون اجرای اپلیکیشن دوباره پاسخ دهد.
- فایل‌های استاتیک (CSS, JS, تصاویر) را سریع‌تر سرویس دهد.

---

### 3. 🧭 ایجاد Load Balancing

- اگر چند instance از برنامه وجود دارد، reverse proxy می‌تواند بین آن‌ها توزیع ترافیک کند.

---

### 4. 🏗️ مدیریت Port و Domain

- درواقع Kestrel فقط روی پورت خاص (مثلاً 5000 یا 8080) گوش می‌دهد.
- ولی Reverse proxy روی پورت 80/443 کار می‌کند و درخواست‌ها را به آن فوروارد می‌کند.
- این یعنی کاربران به `https://myapp.com` وصل می‌شوند نه به پورت داخلی برنامه.

---

## 💥 چرا از Nginx یا YARP در کنار Kestrel استفاده می‌شود؟

درواقع ASP.NET Core از **Kestrel** به‌عنوان وب‌سرور داخلی استفاده می‌کند. Kestrel بسیار سریع است، ولی:

### محدودیت‌های Kestrel:

- برای ارتباط مستقیم با اینترنت طراحی نشده.
- و TLS termination، فیلتر امنیتی، و routing پیچیده ندارد.
- در موارد production نیاز به لایه محافظتی و مدیریتی دارد.

بنابراین معمول است که Kestrel را **پشت یک Reverse Proxy قرار دهند** مثل:

| Reverse Proxy | نقش کلیدی |
|----------------|------------|
| **Nginx** | محبوب در لینوکس، سبک و سریع، پشتیبانی عالی از SSL و load balancing |
| **YARP (Yet Another Reverse Proxy)** | کتابخانهٔ رسمی .NET برای ساخت Reverse Proxy داخلی، مناسب برای سناریوهای مبتنی بر ASP.NET Core |

---

## 🔧 مسیر معمول در محیط Production

```
Internet
   ↓
Nginx / YARP / IIS (Reverse Proxy)
   ↓
Kestrel (ASP.NET Core App)
   ↓
Your Code: Controllers, Middleware, etc.
```

ابزار Kestrel در واقع **application host** است، و Reverse Proxy جلوی آن مثل **نگهبان و مدیر ترافیک** عمل می‌کند.

## 🎯 نتیجه نهایی

| ویژگی | توضیح |
|--------|--------|
| **Reverse Proxy** | سرور جلویی که درخواست‌ها را دریافت و به سرور اصلی فوروارد می‌کند |
| **معمولاً استفاده می‌شود با:** | Nginx، Apache، IIS، یا YARP |
| **دلایل استفاده:** | افزایش امنیت، مدیریت HTTPS، بهینه‌سازی، Load Balancing |
| **نقش Kestrel:** | اجرای منطق ASP.NET Core و هندل کردن پاسخ‌ها، نه مدیریت ارتباط سطح پایین اینترنت |
