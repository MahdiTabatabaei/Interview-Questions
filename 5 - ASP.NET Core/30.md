هر سه برای **ذخیره موقت داده** استفاده می‌شوند، اما در **محل ذخیره‌سازی**، **حجم مجاز**، **امنیت** و **عمر داده** تفاوت اساسی دارند.

---

## جدول مقایسه سریع

|ویژگی|Cookies|Session|Cache|
|---|---|---|---|
|**محل ذخیره**|مرورگر کاربر|سرور (حافظه/Redis)|سرور (حافظه/Redis)|
|**حجم مجاز**|~4KB|نامحدود (تا پر شدن حافظه)|نامحدود (با مدیریت)|
|**عمر پیش‌فرض**|تا تاریخ مشخص یا پایان جلسه|پایان جلسه مرورگر|بر اساس سیاست (TTL، LRU)|
|**امنیت**|کم (دستکاری توسط کاربر)|متوسط (قابل دزدیده شدن Session ID)|بالا (دسترسی فقط سمت سرور)|
|**قابلیت اطمینان**|کم (کاربر می‌تواند پاک کند)|متوسط (ریست سرور از بین می‌برد)|کم (تحت فشار حافظه آزاد می‌شود)|
|**سرعت دسترسی**|سریع (Local)|متوسط (شبکه + سرور)|بسیار سریع (RAM)|
|**مقیاس‌پذیری**|عالی (روی کلاینت)|متوسط (نیاز به sticky session)|خوب (با Redis توزیع می‌شود)|

## 1. Cookies (کوکی‌ها)

### چیستی

فایل‌های متنی کوچک که **در مرورگر کاربر** ذخیره می‌شوند و با هر درخواست به سرور ارسال می‌شوند.

### نحوه کار

```csharp

// سمت سرور - تنظیم کوکی
Response.Cookies.Append("Theme", "Dark", new CookieOptions
{
    Expires = DateTime.Now.AddDays(30),
    HttpOnly = true,  // جلوگیری از دسترسی جاوااسکریپت
    Secure = true     // فقط از طریق HTTPS ارسال شود
});
// خواندن کوکی
var theme = Request.Cookies["Theme"];
```


### کاربردهای واقعی

|کاربرد|مثال|
|---|---|
|**تنظیمات کاربری غیرحساس**|تم سایت (Dark/Light)، اندازه فونت|
|**Remember Me**|ذخیره توکن لاگین (با احتیاط!)|
|**رفع باگ اول ورود**|نمایش پاپ‌آپ خوش‌آمدگویی (فقط یک بار)|
|**تحلیل بازدید**|شمارش تعداد دفعات بازدید کاربر|
|**شخصی‌سازی غیرحساس**|زبان سایت، کوکی قبول شده توسط کاربر (GDPR)|

### مزایا و معایب

✅ **مزایا:**

- بدون مصرف حافظه سرور
    
- ساده و پشتیبانی همه مرورگرها
    
- پایدار (تا تاریخ انقضا)
    

❌ **معایب:**

- محدودیت حجم (4KB)
    
- ارسال با هر درخواست (افزایش ترافیک)
    
- **قابل دستکاری توسط کاربر** (هشدار امنیتی!)
    
- نباید داده حساس ذخیره کنید
    

### ⚠️ هشدار امنیتی مهم

csharp

// هرگز در کوکی ذخیره نکنید:
❌ رمز عبور
❌ شماره کارت بانکی
❌ اطلاعات احراز هویت کامل
❌ داده اختصاصی که نباید دستکاری شود
// می‌توانید ذخیره کنید:
✅ UserId (امضا شده با رمزنگاری)
✅ SessionId (تصادفی و یکتا)
✅ تنظیمات ظاهری (Theme)

## 2. Session (نشست)

### چیستی

ذخیره‌سازی داده‌های هر کاربر **در حافظه سرور**، با شناسه یکتایی که در کوکی یا URL ذخیره می‌شود.

### نحوه کار

```csharp

// ثبت Session در Program.cs
builder.Services.AddDistributedMemoryCache(); // یا AddDistributedSqlServerCache
builder.Services.AddSession(options =>
{
    options.IdleTimeout = TimeSpan.FromMinutes(20);
    options.Cookie.HttpOnly = true;
});
app.UseSession();
// استفاده در کنترلر
HttpContext.Session.SetString("UserName", "Ali");
HttpContext.Session.SetInt32("CartItemCount", 3);
var name = HttpContext.Session.GetString("UserName");
```


### کاربردهای واقعی

|کاربرد|مثال|
|---|---|
|**سبد خرید موقت**|کاربر لاگین نکرده، محصولات را به سبد اضافه می‌کند|
|**داده موقت پردازش چند مرحله‌ای**|فرم ثبت‌نام ۳ مرحله‌ای|
|**کد OTP موقت**|ذخیره کد تایید دو مرحله‌ای|
|**وضعیت کاربر (لاگین شده)**|پس از احراز هویت موفق|
|**پیشرفت عملیات طولانی**|وضعیت آپلود فایل، درصد پیشرفت|

### حالت‌های ذخیره Session

|Provider|توضیح|مناسب|
|---|---|---|
|**In-Memory**|ذخیره در RAM سرور (پیش‌فرض)|توسعه، ترافیک کم|
|**Redis**|ذخیره در Redis خارجی|مقیاس بالا، چند سرور|
|**SQL Server**|ذخیره در دیتابیس|قابلیت اطمینان بالا|
|**Custom**|پیاده‌سازی سفارشی|نیاز خاص|

### مزایا و معایب

✅ **مزایا:**

- امن‌تر از کوکی (دستکاری سخت‌تر)
    
- می‌توانید اشیاء پیچیده ذخیره کنید
    
- کاربر نمی‌تواند مستقیم ببیند
    

❌ **معایب:**

- مصرف حافظه سرور
    
- مشکل در Load Balancing (نیاز به Sticky Session یا Redis)
    
- اگر سرور ریست شود، همه Sessionها از بین می‌روند

## 3. Cache (کش)

### چیستی

ذخیره موقت داده‌های **همگانی یا نیمه‌همگانی** در حافظه سریع برای کاهش بار دیتابیس و افزایش سرعت.

### تفاوت کلیدی با Session

> **Session = داده اختصاصی هر کاربر**  
> **Cache = داده مشترک بین کاربران**

### نحوه کار

```csharp

// کش ساده درون حافظه
services.AddMemoryCache();
public class ProductService
{
    private readonly IMemoryCache _cache;
    
    public async Task<Product> GetProductAsync(int id)
    {
        var cacheKey = $"Product_{id}";
        
        // تلاش برای دریافت از کش
        if (!_cache.TryGetValue(cacheKey, out Product product))
        {
            // دریافت از دیتابیس
            product = await _db.Products.FindAsync(id);
            
            // ذخیره در کش با زمان انقضا
            _cache.Set(cacheKey, product, TimeSpan.FromMinutes(10));
        }
        
        return product;
    }
}
```


### کاربردهای واقعی

|کاربرد|مثال|زمان انقضا|
|---|---|---|
|**اطلاعات محصولات پربازدید**|صفحه محصول آمازون|۵-۱۰ دقیقه|
|**لیست دسته‌بندی‌ها**|منوی بالای سایت|۱ ساعت|
|**تنظیمات عمومی سایت**|AppSettings از دیتابیس|۲۴ ساعت|
|**نتایج جستجوی اخیر**|جستجوی پرتکرار|۲-۳ دقیقه|
|**توکن‌های API خارجی**|توکن اکسس گوگل مپ|تا زمان انقضا|

### استراتژی‌های کش

```csharp
// 1. Absolute Expiration (ثابت)
cache.Set(key, data, TimeSpan.FromMinutes(30));
// 2. Sliding Expiration (در صورت استفاده تمدید می‌شود)
cache.Set(key, data, new MemoryCacheEntryOptions
{
    SlidingExpiration = TimeSpan.FromMinutes(10)
});
// 3. Priority (در شرایط کمبود حافظه)
cache.Set(key, data, new MemoryCacheEntryOptions
{
    Priority = CacheItemPriority.High  // Low, Normal, High, NeverRemove
});
// 4. Dependency (وابستگی به فایل یا دیتابیس)
cache.Set(key, data, new MemoryCacheEntryOptions
{
    ExpirationTokens = { new CancellationChangeToken(cancellationToken) }
});

```


### مزایا و معایب

✅ **مزایا:**

- سرعت بسیار بالا (نانوثانیه)
    
- کاهش چشمگیر بار دیتابیس
    
- می‌توان بین کاربران به اشتراک گذاشت
    

❌ **معایب:**

- داده می‌تواند قدیمی باشد (Stale Data)
    
- تحت فشار حافظه، داده‌ها حذف می‌شوند (Eviction)
    
- پیچیدگی Invalidation (بی‌اعتبارسازی)

## سناریوهای واقعی: کدام را انتخاب کنیم؟

### سناریو ۱: فروشگاه اینترنتی

```csharp

// ✅ Cookies
Response.Cookies.Append("LastVisitedCategory", "Electronics", ...);
// ذخیره آخرین دسته مشاهده شده توسط کاربر
// ✅ Session
HttpContext.Session.SetObject("UserCart", shoppingCart);
// سبد خرید کاربر (لاگین نکرده)
// ✅ Cache
_cache.Set("TopProducts", top100Products, TimeSpan.FromMinutes(5));
// لیست ۱۰۰ محصول پرفروش برای نمایش در صفحه اصلی

```

### سناریو ۲: سایت خبری

```csharp

// ✅ Cookies
// "NewsLayout": "List" یا "Grid" - تنظیمات نمایشی کاربر
// ❌ Session
// استفاده نکنید - خبری از وضعیت کاربر نیست
// ✅ Cache
_cache.Set($"Category_{categoryId}_{page}", newsList, TimeSpan.FromSeconds(30));
// لیست اخبار هر دسته‌بندی
```


### سناریو ۳: سیستم بانکی آنلاین

```csharp

// ❌ Cookies
// فقط SessionId در کوکی، هیچ داده حساسی
// ✅ Session
HttpContext.Session.SetString("OTPCode", generatedCode);
// ذخیره کد تایید دو مرحله‌ای
// ✅ Cache
_cache.Set("ExchangeRate_USD_IRR", rate, TimeSpan.FromSeconds(10));
// نرخ ارز لحظه‌ای (به‌روز هر ۱۰ ثانیه)

```

## معیار انتخاب سریع 🎯

|نیاز شما|راه‌حل|
|---|---|
|ذخیره تنظیمات ساده کاربر (Theme، Layout)|Cookie|
|ذخیره سبد خرید موقت|Session|
|کاهش بار دیتابیس برای داده‌های عمومی|Cache|
|ذخیره داده اختصاصی تا 4KB|Cookie|
|ذخیره اشیاء پیچیده (List, Object)|Session یا Cache|
|داده‌ای که نباید کاربر ببیند یا دستکاری کند|Session|
|داده مشترک بین همه کاربران|Cache|
|ذخیره توکن Remember Me|Cookie (امضا شده)|
|ذخیره وضعیت لاگین کاربر|Session|
|داده‌ای که با هر درخواست تغییر می‌کند|هیچکدام (برو دیتابیس)|

## ترکیب قدرتمند: هر سه با هم

```csharp

// سناریو: صفحه محصول آمازون
// 1. Cookie: آخرین محصول مشاهده شده (4KB کافی است)
Response.Cookies.Append("LastProduct", productId.ToString());
// 2. Cache: اطلاعات پایه محصول (همه کاربران یکسان می‌بینند)
var product = await _cache.GetOrCreateAsync($"Product_{productId}", async entry =>
{
    entry.AbsoluteExpirationRelativeToNow = TimeSpan.FromMinutes(5);
    return await _db.Products.FindAsync(productId);
});
// 3. Session: اطلاعات شخصی‌سازی در این جلسه
var comparedProducts = HttpContext.Session.Get<List<int>>("ComparedProducts") ?? new();
comparedProducts.Add(productId);
HttpContext.Session.Set("ComparedProducts", comparedProducts);

```

**نکته پایانی:** هیچکدام برای ذخیره داده‌های حساس مانند رمز عبور یا شماره کارت مناسب نیستند. برای آن‌ها از دیتابیس رمزنگاری شده استفاده کنید. 🔒
