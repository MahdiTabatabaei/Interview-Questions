این یکی از **مهلک‌ترین اشتباهات** در برنامه‌نویسی [ASP.NET](https://asp.net/) است که می‌تواند باعث **Deadlock**، **کاهش شدید کارایی** و **بلاک شدن تردها** شود.

---

## مشکل اصلی: Deadlock در SynchronizationContext

### سناریوی فاجعه‌بار

```csharp

// ❌ هرگز این کار را نکنید
public IActionResult GetUser()
{
    var data = _db.Users.ToListAsync().Result;  // Deadlock!
    return Ok(data);
}
// یا این
public IActionResult GetUser()
{
    var task = _db.Users.ToListAsync();
    task.Wait();  // Deadlock!
    return Ok(task.Result);
}
```


### چه اتفاقی می‌افتد؟

text

ترد شماره 5 (درخواست کاربر):
│
├─ شروع اجرای Action
│
├─ فراخوانی ToListAsync() → شروع عملیات I/O
│
├─ منتظر ماندن با .Result (بلاک کردن ترد)
│   │
│   └─ ترد شماره 5 خوابیده و منتظر است ⏸️
│
└─ عملیات دیتابیس تمام شد → می‌خواهد ادامه دهد
    │
    └─ اما نیاز به SynchronizationContext اصلی دارد
        │
        └─ ترد شماره 5 هنوز بلاک است ❌
            │
            └─ DEADLOCK! 💀

## دلیل فنی دقیق

### 1. SynchronizationContext در [ASP.NET](https://asp.net/)

```csharp

// در ASP.NET (Non-Core) هر درخواست یک SynchronizationContext دارد
// این Context تضمین می‌کند ادامه کار روی همان ترد انجام شود
// جریان عادی (async/await):
await _db.Users.ToListAsync();  
// ✅ بعد از اتمام، به همان Context برمی‌گردد
// جریان اشتباه (Result):
_db.Users.ToListAsync().Result;
// ❌ ترد اصلی بلاک شده، Context نمی‌تواند ادامه دهد

```

### 2. نمودار Deadlock

text

ردیف زمان | ترد ASP.NET (درخواست) | عملیات دیتابیس
----------|----------------------|------------------
t1        | شروع اجرا            | -
t2        | فراخوانی async method | شروع عملیات
t3        | .Result ← بلاک شد    | در حال اجرا
t4        | منتظر... ⏸️          | در حال اجرا
t5        | منتظر... ⏸️          | تکمیل شد ✅
t6        | منتظر... ⏸️          | تلاش برای برگشت به Context
t7        | هنوز بلاک ⏸️          | منتظر Context آزاد
t8        | DEADLOCK 💀           | DEADLOCK 💀

## مشکلات دیگر (حتی بدون Deadlock)

### 1. مصرف بی‌رویه تردها (Thread Pool Starvation)

```csharp

// ❌ بد: یک درخواست = یک ترد بلاک
public IActionResult GetData()
{
    var data = _api.CallAsync().Result;  // ترد کامل بلاک شد
    return Ok(data);
}
// ✅ خوب: یک درخواست = ترد آزاد می‌شود
public async Task<IActionResult> GetData()
{
    var data = await _api.CallAsync();  // ترد به pool برمی‌گردد
    return Ok(data);
}
```


**تاثیر روی سرور:**

text

سرور با 100 ترد:
- با .Result: حداکثر 100 درخواست همزمان (بلاک)
- با async/await: هزاران درخواست همزمان
زمان پاسخگویی در 500 درخواست همزمان:
- .Result: 30 ثانیه (و بسیاری timeout)
- async/await: 2 ثانیه

### 2. حذف مزایای async/await

```csharp

// کاری که async/await برایتان می‌کند:
1. آزاد کردن ترد در زمان I/O
2. کاهش مصرف حافظه
3. افزایش Throughput
4. مقیاس‌پذیری بالا
// .Result تمام این مزایا را نابود می‌کند:
5. ترد بلاک می‌ماند ← مصرف حافظه بالا
6. Throughput پایین می‌آید
7. مقیاس‌پذیری صفر

```

## استثناها و موارد خاص

### در [ASP.NET](https://asp.net/) Core وضعیت کمی متفاوت است

[ASP.NET](https://asp.net/) Core **SynchronizationContext ندارد** (به طور پیش‌فرض)، بنابراین Deadlock رخ نمی‌دهد:

```csharp

// در ASP.NET Core 3+ 
public IActionResult GetUser()
{
    var data = _db.Users.ToListAsync().Result;  
    // ❌ Deadlock نمی‌دهد! اما همچنان مشکل دارد
    return Ok(data);
}

```

**اما همچنان نباید استفاده کرد چون:**

- Thread Pool Starvation همچنان وجود دارد
    
- کارایی پایین می‌آید
    
- استثناها به درستی مدیریت نمی‌شوند (AggregateException)
    
- عادت بد برنامه‌نویسی

## راه‌حل‌های صحیح (و جایگزین‌های امن)

### راه‌حل 1: Async All the Way Up (توصیه شده)

```csharp

// ✅ درست: از Controller تا Database همگی async
public async Task<IActionResult> GetUser(int id)
{
    var user = await _userService.GetUserAsync(id);
    return Ok(user);
}
public async Task<User> GetUserAsync(int id)
{
    return await _db.Users.FindAsync(id);
}

```

### راه‌حل 2: اگر نمی‌توانید از async استفاده کنید (قدیمی)

```csharp

// ⚠️ راه‌حل موقت: ConfigureAwait(false) + GetAwaiter()
public IActionResult GetUser()
{
    var user = _db.Users
        .ToListAsync()
        .ConfigureAwait(false)
        .GetAwaiter()
        .GetResult();
    
    return Ok(user);
}
```


**اما:** همچنان ترد را بلاک می‌کند، فقط Deadlock نمی‌دهد.

### راه‌حل 3: برای متدهای Main/Constructor

```csharp

// ✅ فقط در Console App یا تست
static void Main()
{
    var result = GetDataAsync().GetAwaiter().GetResult();
}
// ✅ در Constructor (بد نیست ولی طراحی را عوض کنید)
public class MyService
{
    private readonly User _user;
    
    public MyService()
    {
        _user = InitializeAsync().ConfigureAwait(false).GetAwaiter().GetResult();
    }
    
    private async Task<User> InitializeAsync()
    {
        return await _db.Users.FirstAsync();
    }
}
```

## موارد خاص: کتابخانه‌ها و کدهای قدیمی

### اگر در کتابخانه هستید و نمی‌توانید async کنید:

```csharp

// گزینه 1: ConfigureAwait(false) + GetAwaiter()
public string GetData()
{
    return _service.GetDataAsync()
        .ConfigureAwait(false)
        .GetAwaiter()
        .GetResult();
}
// گزینه 2: Use Task.Run (فقط در特定 scenarios)
public string GetData()
{
    return Task.Run(async () => 
        await _service.GetDataAsync()).Result;
}
// گزینه 3: بازطراحی کتابخانه
public interface IMyService
{
    Task<string> GetDataAsync();  // نسخه async
    string GetData();              // نسخه sync (که از async استفاده می‌کند)
}
```

## خلاصه نهایی ⚡

|روش|Deadlock|Thread Blocking|کارایی|توصیه|
|---|---|---|---|---|
|`await` (صحیح)|❌|❌|عالی|✅ **استفاده کن**|
|`.Result` (اشتباه)|✅ (در .NET Framework)|✅|افتضاح|❌ **هرگز استفاده نکن**|
|`.Wait()` (اشتباه)|✅ (در .NET Framework)|✅|افتضاح|❌ **هرگز استفاده نکن**|
|`GetAwaiter().GetResult()`|گاهی|✅|بد|⚠️ **فقط در شرایط خاص**|
|`Task.Run().Result`|❌|✅|متوسط|⚠️ **موقتی**|

### قانون طلایی 🥇

> **اگر متد Async دارید، از همان ابتدا تا انتها Async بروید. هیچگاه Async را Sync نکنید.**

```csharp

// در ASP.NET:
Controller (async) → Service (async) → Repository (async) → Database (async) ✅
// هرگز:
Controller (sync) → Service (async).Result → Repository (async).Result → ❌

```

### یک جمله برای همیشه به خاطر بسپارید:

> **".Result و .Wait() در [ASP.NET](https://asp.net/) مثل بمب ساعتی هستند - امروز کار می‌کند، فردا در ترافیک بالا منفجر می‌شود."** 💣
