ویژگی Endpoint Routing یک سیستم مسیریابی (Routing) مدرن و منعطف در ASP.NET Core است که جایگزین سیستم‌های قدیمی‌تر شده است. این سیستم به طور موثرتری درخواست‌های HTTP را به **Endpoints** مناسب نگاشت می‌کند. Endpoint در ASP.NET Core یک “فعالیت” است که می‌توان آن را اجرا کرد و معمولاً با یک الگوی URL مطابقت دارد.

**چگونه کار می‌کند:**

1. **انتخاب Endpoint:** Endpoint Routing با استفاده از دو مرحله اصلی، Endpoint مناسب برای درخواست ورودی را انتخاب می‌کند:

- **مرحله اول (Matching):** موتور مسیریابی (که با `app.UseRouting()` فعال می‌شود) URL درخواست را با الگوهای تعریف شده برای Endpoints مختلف مقایسه می‌کند. این الگوها می‌توانند از طریق:
- Controller-based routing (در MVC)
- Razor Pages routing
- Minimal API routing (`MapGet`, `MapPost`, …)
- Attribute routing
- و …

تعریف شده باشند. در این مرحله، تمام Endpointsی که با URL مطابقت دارند، شناسایی می‌شوند.

- **مرحله دوم (Selection):** اگر بیش از یک Endpoint با URL مطابقت داشته باشد، یک الگوریتم انتخاب، بهترین Endpoint را بر اساس معیارهایی مانند طولانی‌ترین تطابق الگو یا اولویت، انتخاب می‌کند.

2. **اجرای Endpoint:** پس از انتخاب Endpoint، این Endpoint توسط Middleware بعدی در Pipeline (معمولاً `app.UseEndpoints(...)`) اجرا می‌شود. اجرای Endpoint می‌تواند شامل فراخوانی یک Action Method در Controller، اجرای یک Razor Page Handler، یا اجرای delegate تعریف شده در Minimal API باشد.

**مزایا:**

- **انعطاف‌پذیری:** ترکیب انواع مختلف مسیریابی (MVC, Razor Pages, Minimal APIs) را در یک برنامه ممکن می‌سازد.
- **کارایی:** بهبود یافته نسبت به سیستم‌های قدیمی‌تر.
- **جداسازی مسئولیت‌ها:** مسئولیت مسیریابی (Matching) از مسئولیت اجرای Endpoint جدا شده است.

**مثال:**

در مثال Minimal API (سوال ۱۱) یا مثال MVC (سوال ۶)، وقتی `app.UseRouting()` و سپس `app.UseEndpoints(...)` را فراخوانی می‌کنیم، Endpoint Routing فعال می‌شود. موتور مسیریابی URL را بررسی کرده و Endpoint مربوطه (مثلاً اکشن Controller یا delegate در Minimal API) را پیدا و آماده اجرا می‌کند.
