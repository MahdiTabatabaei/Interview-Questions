خیر. در **.NET Dependency Injection** بعد از اینکه `ServiceProvider` ساخته شد دیگر نمی‌توان **Service جدیدی اضافه کرد**.

### چرا؟

فرآیند به این صورت است:

1. ابتدا همه سرویس‌ها در `IServiceCollection` ثبت می‌شوند.
2. سپس با `BuildServiceProvider()` یک **ServiceProvider immutable** ساخته می‌شود.
3. بعد از build شدن، container **قفل می‌شود** و تغییر در registrationها ممکن نیست.

مثال:
```csharp

var services = new ServiceCollection();

services.AddTransient<IUserService, UserService>();

var provider = services.BuildServiceProvider();

```
بعد از این مرحله دیگر نمی‌توانید service جدید اضافه کنید که provider آن را بشناسد.

اگر این کار را بکنید:
```csharp

services.AddTransient<IOrderService, OrderService>();

```
در این حالت`provider` قبلی **از این سرویس خبر ندارد** چون قبل از آن ساخته شده است.

### اگر نیاز باشد چه کار کنیم؟

دو راه معمول:

• همه serviceها را **قبل از Build** ثبت کنید.

• اگر registration تغییر کرد، **ServiceProvider جدید بسازید**:

```csharp

var provider = services.BuildServiceProvider();

```
(در ASP.NET Core این کار معمولاً توسط framework انجام می‌شود.)

✅ **خلاصه:**

درواقع `ServiceProvider` بعد از build شدن **[[196 | Immutable]]** است و نمی‌توان سرویس جدیدی به آن اضافه کرد.
