چند روش رایج برای تشخیص **Shadow Propertyهای ناخواسته** در EF Core وجود دارد، چون این propertyها در کلاس‌های C# دیده نمی‌شوند و فقط در **مدل داخلی EF** وجود دارند.

---

## 1. بررسی مدل در زمان اجرا (Model Metadata)

می‌توان از متادیتای مدل EF استفاده کرد و propertyهایی که Shadow هستند را پیدا کرد.

```csharp
var shadowProperties = context.Model
    .GetEntityTypes()
    .SelectMany(e => e.GetProperties())
    .Where(p => p.IsShadowProperty());

foreach (var prop in shadowProperties)
{
    Console.WriteLine($"{prop.DeclaringEntityType.Name} - {prop.Name}");
}
```

این کد:

- تمام entityها را بررسی می‌کند
- propertyهایی که `IsShadowProperty()` هستند را پیدا می‌کند

اگر چیزی چاپ شد یعنی **Shadow Property در مدل وجود دارد**.

---

## 2. بررسی Migrationها

گاهی Shadow property به صورت ناخواسته ساخته می‌شود، مخصوصاً برای **Foreign Keyها**.

مثلاً در migration ممکن است ببینی:

```
UserId1
OrderId1
CustomerId1
```

این معمولاً یعنی EF نتوانسته relationship را درست تشخیص دهد و یک **Shadow FK** ساخته است.

---

## 3. بررسی Model Debug View

EF Core یک debug view از مدل دارد.

```csharp
Console.WriteLine(context.Model.ToDebugString());
```

در خروجی می‌توان propertyهایی را دید که در کلاس‌ها وجود ندارند.

---

## 4. فعال کردن Warningهای EF Core

EF Core برای بعضی Shadow Propertyها warning می‌دهد. می‌توان آن‌ها را در logging دید:

```csharp
optionsBuilder
    .UseSqlServer(connectionString)
    .EnableSensitiveDataLogging()
    .LogTo(Console.WriteLine);
```

---

## 5. بررسی Relationship configuration

یکی از رایج‌ترین جاهایی که Shadow Property ناخواسته ایجاد می‌شود **Foreign Keyها** هستند.

مثلاً اگر FK در مدل تعریف نشود:

```csharp
public class Order
{
    public int Id { get; set; }
    public Customer Customer { get; set; }
}
```

EF ممکن است یک FK shadow بسازد مثل:

```
CustomerId
```

اگر FK را صریح تعریف کنیم مشکل کمتر می‌شود:

```csharp
public int CustomerId { get; set; }
public Customer Customer { get; set; }
```

---

✅ خلاصه:

برای پیدا کردن Shadow Propertyهای ناخواسته:

- بررسی **Model Metadata با `IsShadowProperty()`**
- نگاه کردن به **Migrationها**
- استفاده از **`Model.ToDebugString()`**
- بررسی **warningهای EF**
- بررسی درست بودن **Foreign Key configuration**

رایج‌ترین دلیل ایجاد Shadow Property ناخواسته:  
**تعریف ناقص یا اشتباه relationship بین entityها**.
