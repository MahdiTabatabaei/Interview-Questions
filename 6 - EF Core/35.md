در EF Core از طریق **کلیدهای خارجی (Foreign Keys)** و **پیکربندی در `OnModelCreating`** رابطه‌ها را تشخیص می‌دهد.

1. **وجود Foreign Key Property:** اگر یک پراپرتی با نام convention شده (مثلاً `OrderId` برای رابطه با `Order`) وجود داشته باشد، EF Core آن را به عنوان Foreign Key شناسایی کرده و به جدول مرتبط می‌کند.
2. **پیکربندی Fluent API:** صریحاً با استفاده از `HasForeignKey()` یا `HasPrincipalKey()` در `OnModelCreating`، EF Core را راهنمایی می‌کنید که کدام Foreign Key به کدام Primary Key اشاره دارد.
3. استفاده از **Data Annotations:** استفاده از `[ForeignKey("RelatedEntityId")]` روی Navigation Property.
4. و **Navigation Properties:** وقتی EF Core یک Navigation Property (مثلاً `public Order Order { get; set; }`) را می‌بیند، سعی می‌کند Foreign Key متناظر آن را پیدا کند (مثلاً `OrderId`). اگر نام Foreign Key به صورت convention شده نباشد، ممکن است نیاز به پیکربندی صریح (Fluent API یا Data Annotation) باشد.

**مثال:**

فرض کنید `Order` دو Navigation Property به `Customer` داشته باشد (که معمولاً این وضعیت مطلوب نیست و باید دلیل آن را بررسی کرد):
```csharp

public class Order
{
    public int Id { get; set; }
    public int PrimaryCustomerId { get; set; } // FK 1
    public Customer PrimaryCustomer { get; set; } // Navigation 1

    public int SecondaryCustomerId { get; set; } // FK 2
    public Customer SecondaryCustomer { get; set; } // Navigation 2
}

```
در `OnModelCreating` باید صریحاً مشخص کنید:
```csharp

modelBuilder.Entity<Order>()
    .HasOne(o => o.PrimaryCustomer)
    .WithMany() // Assuming Customer has no navigation back to Order for this relationship
    .HasForeignKey(o => o.PrimaryCustomerId);

modelBuilder.Entity<Order>()
    .HasOne(o => o.SecondaryCustomer)
    .WithMany()
    .HasForeignKey(o => o.SecondaryCustomerId);

```
اگر بدون پیکربندی صریح رها شود، EF Core ممکن است نتواند به درستی تشخیص دهد که کدام Foreign Key به کدام Navigation Property مرتبط است.
