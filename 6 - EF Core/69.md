در EF Core وقتی از **`AsSplitQuery()`** استفاده می‌کنید، انتظار دارید هر `Include` (یا مسیرهای مربوط به Many‑to‑Many) به چند کوئری جدا تبدیل شود. اما در بعضی شرایط EF Core **به‌صورت خودکار به Single Query برمی‌گردد**. این رفتار معمولاً به خاطر محدودیت‌های ترجمهٔ کوئری یا نیاز EF به حفظ درستی نتایج است.

## دلیل‌هایی که EF Core به Single Query برمی‌گردد

### 1. وجود Projection پیچیده (`Select`)
اگر بعد از `Include` از `Select` استفاده کنید و شکل داده تغییر کند، EF ممکن است نتواند آن را به چند کوئری جدا تقسیم کند.

مثال:

```csharp
context.Posts
    .Include(p => p.Tags)
    .AsSplitQuery()
    .Select(p => new { p.Id, p.Tags })
```

در چنین حالتی EF گاهی مجبور می‌شود **یک کوئری واحد** بسازد.

---

### 2. استفاده از `Distinct`, `GroupBy`, `OrderBy` خاص
برخی عملیات LINQ نیاز دارند که **کل داده در یک result set واحد** باشد.

مثال‌ها:

- `Distinct()`
- `GroupBy()`
- بعضی `OrderBy` ها روی navigation

در این موارد split query ممکن است نتیجه را تغییر دهد، بنابراین EF به **single query** برمی‌گردد.

---

### 3. Many‑to‑Many با join table
در رابطه‌های **Many‑to‑Many** که EF از **join table پنهان (skip navigation)** استفاده می‌کند، اگر مسیر Include پیچیده باشد EF گاهی برای حفظ ترتیب و جلوگیری از دادهٔ ناقص **join واحد تولید می‌کند**.

مثال:

```csharp
context.Posts
    .Include(p => p.Tags)
        .ThenInclude(t => t.Category)
```

---

### 4. عملیات Pagination در جای نامناسب
اگر `Skip` یا `Take` در جای خاصی از کوئری باشد، EF برای حفظ صحت pagination مجبور می‌شود **single query** تولید کند.

---

### 5. نسخه EF Core و محدودیت‌های provider
در برخی نسخه‌ها یا providerها (مثل SQL Server vs PostgreSQL) بعضی کوئری‌ها هنوز قابل split شدن نیستند.

---

# چگونه این رفتار را کنترل کنیم

## 1. اجبار Split Query در سطح Query
مستقیم در کوئری:

```csharp
context.Posts
    .Include(p => p.Tags)
    .AsSplitQuery()
    .ToList();
```

---

## 2. تنظیم پیش‌فرض در DbContext
می‌توانید کل برنامه را روی Split Query قرار دهید:

```csharp
optionsBuilder
    .UseSqlServer(connectionString)
    .UseQuerySplittingBehavior(QuerySplittingBehavior.SplitQuery);
```

در صورت نیاز می‌توانید در یک کوئری خاص برعکس کنید:

```csharp
.AsSingleQuery()
```

---

## 3. ساده‌سازی Query
برای اینکه EF بتواند split کند:

- Projection پیچیده را حذف کنید
- `GroupBy` یا `Distinct` را بعد از materialization انجام دهید
- Pagination را روی root entity اعمال کنید

---

## 4. استفاده از Projection به جای Include
برای Performance بالا در Many‑to‑Many معمولاً بهتر است:

```csharp
context.Posts
    .Select(p => new {
        p.Id,
        Tags = p.Tags.Select(t => t.Name)
    })
```

این روش اغلب از Include سریع‌تر است.

---

✅ **جمع‌بندی**

EF Core وقتی از Split Query صرف‌نظر می‌کند که:

- عملیات LINQ نتیجه را وابسته به یک result set واحد کند
- pagination یا ordering پیچیده وجود داشته باشد
- projection شکل داده را تغییر دهد
- محدودیت ترجمهٔ query وجود داشته باشد

برای کنترل رفتار:

- `AsSplitQuery()` یا `AsSingleQuery()`  
- تنظیم `UseQuerySplittingBehavior` در DbContext  
- ساده‌سازی query یا استفاده از projection
