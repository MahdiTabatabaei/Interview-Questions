در **EF Core (نسخه‌های جدید)** می‌توان رابطه **Many‑to‑Many** را بدون تعریف کلاس واسط ایجاد کرد. EF خودش یک **Join Table مخفی (Shadow Join Table)** می‌سازد.

اما در بعضی شرایط **حتماً باید یک Join Entity واقعی تعریف کنیم**.

---

# زمانی که باید Join Entity تعریف کنیم

## 1. وقتی جدول واسط فیلد اضافی دارد

اگر جدول واسط فقط دو FK نباشد و **اطلاعات اضافی نگه دارد**.

مثال:

```
Student
Course
StudentCourse
```

جدول واسط:

```
StudentCourse
-------------
StudentId
CourseId
EnrollmentDate
Grade
```

در این حالت باید یک Entity بسازیم:

```csharp
public class StudentCourse
{
    public int StudentId { get; set; }
    public int CourseId { get; set; }

    public DateTime EnrollmentDate { get; set; }
    public int Grade { get; set; }

    public Student Student { get; set; }
    public Course Course { get; set; }
}
```

چون EF نمی‌تواند این ستون‌ها را در join مخفی مدیریت کند.

---

# 2. وقتی می‌خواهیم Join Table را مستقیماً Query کنیم

مثال:

می‌خواهیم بدانیم:

```
کدام دانشجو چه زمانی در یک درس ثبت‌نام کرده
```

یا:

```
فقط رکوردهای join را فیلتر کنیم
```

در این حالت وجود Entity لازم است.

---

# 3. وقتی Join Table منطق یا رفتار دارد

مثال:

```
Membership
UserRole
OrderProduct
```

ممکن است:

- Status داشته باشد
- تاریخ ایجاد داشته باشد
- Soft delete داشته باشد

پس باید مدل جدا داشته باشد.

---

# 4. وقتی نیاز به کنترل کامل روی جدول داریم

مثلاً:

- تعریف **Index**
- تعریف **Composite Key**
- تنظیم **Cascade Behavior**
- اضافه کردن **Concurrency Token**

در این حالت داشتن Entity بهتر است.

---

# مثال Fluent API

```csharp
modelBuilder.Entity<StudentCourse>()
    .HasKey(sc => new { sc.StudentId, sc.CourseId });

modelBuilder.Entity<StudentCourse>()
    .HasOne(sc => sc.Student)
    .WithMany(s => s.StudentCourses)
    .HasForeignKey(sc => sc.StudentId);

modelBuilder.Entity<StudentCourse>()
    .HasOne(sc => sc.Course)
    .WithMany(c => c.StudentCourses)
    .HasForeignKey(sc => sc.CourseId);
```

---

# چه زمانی Join Entity لازم نیست؟

اگر جدول واسط فقط این باشد:

```
StudentId
CourseId
```

در این حالت می‌توان مستقیم نوشت:

```csharp
public ICollection<Course> Courses { get; set; }
public ICollection<Student> Students { get; set; }
```

و EF خودش جدول join می‌سازد.

---

# جمع‌بندی سریع

Join Entity لازم است وقتی:

- جدول واسط **ستون اضافی دارد**
- می‌خواهیم **مستقیماً آن را query کنیم**
- جدول **منطق یا metadata دارد**
- نیاز به **کنترل کامل روی جدول** داریم
