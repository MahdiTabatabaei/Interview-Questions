در EF Core دو نوع **Navigation Property** وجود دارد:

1. **Reference Navigation**  
2. **Collection Navigation**

این دو نوع، دو **سمت متفاوت از Relationship** را نمایش می‌دهند.

بیایید دقیق، روشن و با مثال توضیح دهیم.

---

# 1. Reference Navigation Property

یک **شیء واحد** را نشان می‌دهد (سمت "One").

مثال:

```csharp
public Author Author { get; set; }
```

یعنی:

- هر Book **یک Author** دارد.
- این یک رابطه **تکی** است.

ویژگی‌ها:

- همیشه **single object reference** است  
- معمولاً در سمت Dependent قرار دارد  
- EF Core آن را برای **اصلاح، دسترسی و بارگذاری یک رکورد مرتبط** استفاده می‌کند

مثال‌های رایج:

- Book → Author  
- Order → Customer  
- Employee → Department  

---

# 2. Collection Navigation Property

یک **لیست** یا **مجموعه‌ای** از اشیاء مرتبط را نشان می‌دهد (سمت "Many").

مثال:

```csharp
public ICollection<Book> Books { get; set; }
```

یعنی:

- یک Author می‌تواند **چندین Book** داشته باشد.
- این یک رابطه **چندتایی** است.

ویژگی‌ها:

- همیشه یک **Collection (ICollection / List / IEnumerable)** است  
- معمولاً در سمت Principal قرار دارد  
- EF از آن برای **بارگذاری لیست آیتم‌های وابسته** استفاده می‌کند

مثال‌های رایج:

- Author → Books  
- Customer → Orders  
- Category → Products  

---

# 3. مقایسه کوتاه (Reference vs Collection)

| نوع Navigation | سمت رابطه | مقدار | مثال |
|----------------|-----------|--------|--------|
| Reference | One | یک شیء تکی | Book.Author |
| Collection | Many | مجموعه‌ای از اشیا | Author.Books |

---

# 4. رابطه این دو با EF Core

در یک رابطه **One‑to‑Many**:

- سمت **Many** → دارای Reference Navigation است  
- سمت **One** → دارای Collection Navigation است  

مثال:

```csharp
// Many side
public Author Author { get; set; }  

// One side
public ICollection<Book> Books { get; set; }
```

در Fluent API:

```csharp
.HasOne(b => b.Author)      // reference
.WithMany(a => a.Books);    // collection
```

---

# 5. ارتباط با Foreign Key

Reference navigation معمولاً با یک **FK ساده** همراه است:

```csharp
public int AuthorId { get; set; }
```

اما Collection navigation **خودش FK ندارد**،  
FK در سمت وابسته قرار می‌گیرد:

```
Books.AuthorId
```

---

# 6. مثال تصویری ساده

```
Author (ONE)
 └── Books (MANY)
```

Navigation Properties:

```
Author.Books → Collection
Book.Author  → Reference
```

---

# خلاصه نهایی (خیلی مختصر)

- **Reference Navigation** = یک شیء مرتبط  
- **Collection Navigation** = چندین شیء مرتبط  
- Reference در سمت Dependent  
- Collection در سمت Principal  
- ترکیب این دو یک رابطه One‑to‑Many را می‌سازد
