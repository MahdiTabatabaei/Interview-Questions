
درواقع **Lazy Loading** یعنی داده‌های مرتبط با یک موجودیت **فقط زمانی از دیتابیس گرفته شوند که واقعاً به آن‌ها دسترسی پیدا کنیم**، نه هنگام گرفتن داده اصلی.

به بیان ساده:  
دیتابیس **دیرتر و در صورت نیاز** داده‌های مرتبط را لود می‌کند.

## مثال در Entity Framework

فرض کنید دو مدل داریم:

```csharp
public class Order
{
    public int Id { get; set; }
    public virtual Customer Customer { get; set; }
}
```

کد:

```csharp
var orders = context.Orders.ToList();
```

در این مرحله فقط این کوئری اجرا می‌شود:

```sql
SELECT * FROM Orders
```

اما وقتی به Customer دسترسی پیدا کنیم:

```csharp
foreach (var order in orders)
{
    Console.WriteLine(order.Customer.Name);
}
```

Entity Framework برای هر سفارش یک کوئری جدا می‌زند:

```sql
SELECT * FROM Customers WHERE Id = 1
SELECT * FROM Customers WHERE Id = 2
SELECT * FROM Customers WHERE Id = 3
...
```

## مشکلی که Lazy Loading ایجاد می‌کند

مهم‌ترین مشکل آن **N+1 Query Problem** است.

به جای اینکه یک کوئری بهینه اجرا شود:

```
1 query برای داده اصلی
+ N query برای داده‌های مرتبط
```

مشکلاتی که ایجاد می‌کند:

- افزایش شدید تعداد کوئری‌ها
- کاهش performance برنامه
- افزایش latency دیتابیس
- مصرف بیشتر منابع سرور

به‌خصوص در **APIها و لیست‌های بزرگ** این مشکل خیلی جدی می‌شود.

## راه‌حل

معمولاً از **Eager Loading** استفاده می‌شود:

```csharp
var orders = context.Orders
                    .Include(o => o.Customer)
                    .ToList();
```

در این حالت داده‌های مرتبط از ابتدا با **یک کوئری** گرفته می‌شوند.

---

خلاصه:  
درواقغ **Lazy Loading یعنی بارگذاری داده‌های مرتبط فقط هنگام دسترسی به آن‌ها، که اگر کنترل نشود می‌تواند باعث افزایش زیاد کوئری‌ها و افت performance شود.**


فعال‌سازی:
```csharp

services.AddDbContext<AppDbContext>(o =>
    o.UseLazyLoadingProxies());

```
