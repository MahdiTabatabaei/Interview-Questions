وقتی دو موجودیت از یک **کلید ترکیبی (Composite Key)** مشترک استفاده می‌کنند، EF Core به‌تنهایی نمی‌تواند تشخیص دهد که کدام فیلدها با هم جفت (Pair) می‌شوند. برای حل این مشکل، باید در `OnModelCreating` به‌صورت دستی رابطه را تعریف کنید.

فرض کنیم ما `Order` و `OrderItem` را داریم که هر دو از `OrderId` و `StoreId` به عنوان کلید ترکیبی استفاده می‌کنند.

### ۱. تعریف مدل‌ها
هر دو کلاس باید فیلدهای تشکیل‌دهنده کلید را داشته باشند:

```csharp
public class Order
{
    public int StoreId { get; set; }
    public int OrderId { get; set; }
    public ICollection<OrderItem> OrderItems { get; set; }
}

public class OrderItem
{
    public int StoreId { get; set; }
    public int OrderId { get; set; }
    public int ItemId { get; set; }
    public Order Order { get; set; }
}
```

---

### ۲. تنظیم در `OnModelCreating` (Fluent API)
این مرحله کلیدی است. شما باید به EF بگویید که رابطه بین این دو موجودیت، دقیقاً روی کدام ستون‌ها برقرار است.

```csharp
protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    // 1. تنظیم کلید ترکیبی برای Order
    modelBuilder.Entity<Order>()
        .HasKey(o => new { o.StoreId, o.OrderId });

    // 2. تنظیم کلید ترکیبی برای OrderItem
    modelBuilder.Entity<OrderItem>()
        .HasKey(oi => new { oi.StoreId, oi.OrderId, oi.ItemId });

    // 3. تنظیم رابطه Composite
    modelBuilder.Entity<OrderItem>()
        .HasOne(oi => oi.Order)
        .WithMany(o => o.OrderItems)
        .HasForeignKey(oi => new { oi.StoreId, oi.OrderId }) // اینجا جفت‌سازی انجام می‌شود
        .OnDelete(DeleteBehavior.Cascade);
}
```

---

### نکات بسیار مهم برای موفقیت در این پیاده‌سازی:

#### الف) ترتیب ستون‌ها (Column Order)
در متد `HasForeignKey`، **ترتیب فیلدها** باید دقیقاً با ترتیب کلید اصلی در موجودیت والد (`Order`) یکی باشد. اگر در `Order` کلید را به‌صورت `new { StoreId, OrderId }` تعریف کرده‌اید، در `HasForeignKey` هم حتماً باید همین ترتیب رعایت شود.

#### ب) استفاده از `IsRequired`
اگر کلید خارجی شما در `OrderItem` نباید Null باشد (که معمولاً نیست)، EF Core خودش آن را `Required` در نظر می‌گیرد. اما اگر مدل‌های شما طوری است که EF شک دارد، حتماً از `.IsRequired()` استفاده کنید.

#### ج) مشکل Data Annotation
با استفاده از `Attribute` ها (مثل `[Key]`) نمی‌توانید روابط Composite پیچیده را تعریف کنید. **تنها راه اصولی و دقیق برای Composite Relationshipها استفاده از Fluent API است.**

---

### چرا این کار لازم است؟
وقتی کلید ترکیبی دارید، دیتابیس (مثل SQL Server) یک **Unique Index** روی آن ستون‌ها ایجاد می‌کند. EF Core بدون تنظیم دستی `HasForeignKey` نمی‌تواند بفهمد که `OrderItem.StoreId` باید با `Order.StoreId` تطبیق داده شود و به جای یک رابطه، ممکن است دو رابطه جداگانه (و اشتباه) ایجاد کند یا در تشخیص Navigation Property شکست بخورد.
