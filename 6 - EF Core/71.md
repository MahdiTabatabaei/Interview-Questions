در رابطهٔ **One‑to‑One بین `User` و `UserProfile`** این خطا معمولاً زمانی رخ می‌دهد که **کلید خارجی (Foreign Key) به‌درستی تنظیم نشده باشد یا EF Core نتواند تشخیص دهد کدام موجودیت وابسته (Dependent) است.**

پیام خطا:

```
Cannot insert because foreign key is not set
```

یعنی EF هنگام `SaveChanges()` می‌خواهد رکوردی را در جدول وابسته ذخیره کند، اما مقدار **Foreign Key** آن هنوز مشخص نیست.

---

# ریشهٔ اصلی مشکل

در رابطهٔ One‑to‑One همیشه یکی از جدول‌ها باید **Dependent** باشد و **Foreign Key** داشته باشد.

مثلاً ساختار درست معمولاً این است:

```
User
----
Id (PK)

UserProfile
-----------
Id (PK)
UserId (FK)
```

اگر این رابطه در مدل یا Fluent API درست تعریف نشود، EF نمی‌داند:

- کدام جدول FK دارد
- ترتیب Insert چگونه باید باشد

در نتیجه هنگام ذخیره خطای FK می‌دهد.

---

# حالت‌های رایج که این خطا را ایجاد می‌کنند

## 1. تنظیم نکردن Foreign Key در مدل

مدل اشتباه:

```csharp
public class User
{
    public int Id { get; set; }
    public UserProfile Profile { get; set; }
}

public class UserProfile
{
    public int Id { get; set; }
    public User User { get; set; }
}
```

در این حالت EF نمی‌داند FK کجاست.

---

# راه‌حل 1 (بهترین روش) — تعریف FK صریح

```csharp
public class UserProfile
{
    public int Id { get; set; }

    public int UserId { get; set; }   // Foreign Key
    public User User { get; set; }
}
```

و در Fluent API:

```csharp
modelBuilder.Entity<User>()
    .HasOne(u => u.Profile)
    .WithOne(p => p.User)
    .HasForeignKey<UserProfile>(p => p.UserId);
```

---

# راه‌حل 2 — تنظیم Navigation هنگام ایجاد داده

اگر FK مقدار نداشته باشد:

❌ اشتباه

```csharp
var profile = new UserProfile();
context.UserProfiles.Add(profile);
context.SaveChanges();
```

چون `UserId` خالی است.

✅ درست

```csharp
var user = new User();
var profile = new UserProfile();

user.Profile = profile;

context.Users.Add(user);
context.SaveChanges();
```

EF خودش FK را تنظیم می‌کند.

---

# راه‌حل 3 — Shared Primary Key (الگوی رایج One‑to‑One)

گاهی `UserProfile.Id` همان `User.Id` است.

```
User
----
Id

UserProfile
-----------
Id (PK + FK)
```

مدل:

```csharp
public class UserProfile
{
    public int Id { get; set; }
    public User User { get; set; }
}
```

Fluent API:

```csharp
modelBuilder.Entity<User>()
    .HasOne(u => u.Profile)
    .WithOne(p => p.User)
    .HasForeignKey<UserProfile>(p => p.Id);
```

---

# ترتیب صحیح ذخیره‌سازی

EF باید بداند:

1. ابتدا `User` insert شود
2. سپس `UserProfile` با FK ذخیره شود

اگر FK مشخص نباشد EF این ترتیب را نمی‌تواند بسازد.

---

# جمع‌بندی

ریشهٔ مشکل:

- مشخص نبودن **Foreign Key**
- عدم تعیین **Dependent Entity**
- یا مقدار نداشتن FK هنگام `SaveChanges`

راه‌حل‌ها:

- تعریف FK صریح (`UserId`)
- پیکربندی رابطه با `HasForeignKey`
- اتصال navigation properties قبل از ذخیره
- یا استفاده از **Shared Primary Key**
