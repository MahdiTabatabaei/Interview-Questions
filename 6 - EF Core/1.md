در **C# با Entity Framework** مشکل **N+1 Query** معمولاً به خاطر **Lazy Loading** رخ می‌دهد. یعنی EF ابتدا داده‌های اصلی را می‌گیرد و بعد برای هر رکورد، یک کوئری جدا برای داده‌های مرتبط می‌زند.

## مثال

فرض کنیم دو موجودیت داریم:

```csharp
public class Author
{
    public int Id { get; set; }
    public string Name { get; set; }

    public virtual ICollection<Book> Books { get; set; }
}

public class Book
{
    public int Id { get; set; }
    public string Title { get; set; }

    public int AuthorId { get; set; }
    public Author Author { get; set; }
}
```

## کدی که باعث N+1 می‌شود

```csharp
var authors = context.Authors.ToList();

foreach (var author in authors)
{
    Console.WriteLine(author.Name);
    foreach (var book in author.Books)
    {
        Console.WriteLine(book.Title);
    }
}
```

## چه اتفاقی در دیتابیس می‌افتد؟

فرض کنیم 100 نویسنده داریم.

کوئری اول:

```sql
SELECT * FROM Authors
```

بعد برای هر نویسنده:

```sql
SELECT * FROM Books WHERE AuthorId = 1
SELECT * FROM Books WHERE AuthorId = 2
SELECT * FROM Books WHERE AuthorId = 3
...
SELECT * FROM Books WHERE AuthorId = 100
```

در نتیجه:

```
1 + 100 = 101 queries
```

این همان **N+1 Query Problem** است.

## راه حل در EF: Eager Loading با Include

باید داده‌های مرتبط را همان اول بگیریم.

```csharp
var authors = context.Authors
                     .Include(a => a.Books)
                     .ToList();

foreach (var author in authors)
{
    Console.WriteLine(author.Name);
    foreach (var book in author.Books)
    {
        Console.WriteLine(book.Title);
    }
}
```

حالا EF یک کوئری join می‌زند:

```sql
SELECT a.*, b.*
FROM Authors a
LEFT JOIN Books b ON a.Id = b.AuthorId
```

در نتیجه:

```
فقط 1 query
```

## روش بهتر برای performance (Projection)

گاهی حتی بهتر است فقط داده مورد نیاز را بگیریم:

```csharp
var authors = context.Authors
    .Select(a => new
    {
        a.Name,
        Books = a.Books.Select(b => b.Title)
    })
    .ToList();
```

این روش:

- داده کمتر از دیتابیس می‌گیرد
- performance بهتر دارد
