درواقع **Change Tracker** در **Entity Framework (EF / EF Core)** سیستمی است که تغییرات اشیاء (Entities) را در حافظه دنبال می‌کند تا هنگام `SaveChanges()` مشخص شود چه چیزی باید در دیتابیس **Insert / Update / Delete** شود.

به بیان ساده:

ابزار EF یک نسخه از وضعیت اولیه Entity را نگه می‌دارد و هر تغییری که در آن ایجاد شود را تشخیص می‌دهد.

---

# نحوه کار Change Tracker

وقتی شما داده‌ای را از دیتابیس می‌خوانید:
```csharp

var user = context.Users.First();

```

ابزار EF این شیء را **Track** می‌کند.

اگر مقدار آن را تغییر دهید:
```csharp

user.Name = "Ali";

```
و بعد ذخیره کنید:

```csharp

context.SaveChanges();

```

ابزار EF می‌فهمد که فیلد `Name` تغییر کرده و این SQL را تولید می‌کند:
```sql

UPDATE Users SET Name = 'Ali' WHERE Id = 1

```
بدون اینکه شما دستور Update بنویسید.

---
# وضعیت‌های Entity در Change Tracker

هر Entity یکی از این State ها را دارد:

- **Added** → باید Insert شود
- **Modified** → باید Update شود
- **Deleted** → باید Delete شود
- **Unchanged** → تغییری نکرده
- **Detached** → اصلاً Track نمی‌شود

مثال:
```csharp

context.Entry(user).State

```
---

# غیر فعال کردن Change Tracking

در EF Core می‌توان Tracking را خاموش کرد:
```csharp

var users = context.Users
                   .AsNoTracking()
                   .ToList();

```
در این حالت EF فقط داده را می‌خواند و **هیچ تغییری را دنبال نمی‌کند**.

---

# مزایای فعال بودن Change Tracker

1️⃣ **ذخیره خودکار تغییرات**

نیازی به نوشتن SQL ندارید.
```csharp

user.Name = "Reza";
context.SaveChanges();

```
ابزار EF خودش Update می‌زند.

---

2️⃣ **مدیریت رابطه‌ها**

مثلاً:
```csharp

order.User = user;

```
ابزارEF رابطه را تشخیص می‌دهد.

---

3️⃣ **مدیریت Cascade و Navigation properties**

مثلاً حذف یک parent و حذف child ها.

---

4️⃣ مدیریت **Concurrency Handling**

برای کنترل همزمانی داده‌ها.

---

# مزایای خاموش کردن Change Tracker

مهم‌ترین مزیت: **Performance**

فعال بودن Tracking هزینه دارد:

- مصرف RAM
- پردازش اضافی
- نگهداری snapshot از داده

در Queryهای فقط خواندنی بهتر است Tracking خاموش شود.

مثال:
```csharp

var products = context.Products
                      .AsNoTracking()
                      .ToList();

```
---

# تاثیر واقعی روی Performance

در Queryهای بزرگ:

با Tracking می‌تواند **۳۰٪ تا ۵۰٪ کندتر** باشد.

به همین دلیل در پروژه‌های واقعی برای Read Queryها معمولاً از:
```csharp

AsNoTracking()

```
استفاده می‌شود.

---

# فعال کردن پیش‌فرض NoTracking

می‌توانید کل Context را NoTracking کنید:
```csharp

optionsBuilder.UseQueryTrackingBehavior(QueryTrackingBehavior.NoTracking);

```

```markdown

Edit / Update / Delete

```

# چه زمانی Tracking را خاموش کنیم؟

✅ وقتی فقط **خواندن داده** مهم است

مثل:

- استفاده در APIهای Read
- گزارش‌ها
- لیست‌ها
- وجود Pagination

# خلاصه کوتاه

درواقع Change Tracker در EF:

- تغییرات Entityها را دنبال می‌کند
- هنگام `SaveChanges` SQL مناسب تولید می‌کند

حالت‌ها:

- Added
- Modified
- Deleted
- Unchanged
- Detached

برای **Performance بهتر در Read Queryها** از:
```csharp

AsNoTracking()

```
استفاده می‌شود.
