برای پیاده‌سازی **Self‑Reference Relationship** (رابطه‌ای که یک Entity به خودش اشاره می‌کند)، مثل:

```
Category
 └── ParentCategory
     └── ParentCategory
         ...
```

در EF Core معمولاً از یک رابطه **One‑to‑Many خودارجاعی** استفاده می‌کنیم.

به بیان ساده:

- هر Category می‌تواند **یک ParentCategory** داشته باشد (Reference)
- هر Category می‌تواند **چندین SubCategory** داشته باشد (Collection)

بیایید قدم‌به‌قدم اجرا کنیم.

---

# 1. تعریف Entity

این ساختار استاندارد Self‑Referencing است:

```csharp
public class Category
{
    public int Id { get; set; }

    public int? ParentId { get; set; } // nullable → رابطه اختیاری

    // Reference navigation (به والد)
    public Category ParentCategory { get; set; }

    // Collection navigation (به فرزندها)
    public ICollection<Category> SubCategories { get; set; }
}
```

توضیح:

- `ParentId` nullable است → یعنی یک Category ممکن است Parent نداشته باشد (مثلاً Root Category).
- `ParentCategory` → اشاره به یک والد (Reference)
- `SubCategories` → لیست فرزندها (Collection)

---

# 2. مدل‌سازی با Fluent API

```csharp
modelBuilder.Entity<Category>()
    .HasOne(c => c.ParentCategory)
    .WithMany(c => c.SubCategories)
    .HasForeignKey(c => c.ParentId)
    .OnDelete(DeleteBehavior.Restrict);
```

---

# معنی Fluent API

### 1. `.HasOne(c => c.ParentCategory)`

- هر Category فقط **یک والد** دارد.

### 2. `.WithMany(c => c.SubCategories)`

- هر Category می‌تواند **چندین فرزند** داشته باشد.

### 3. `.HasForeignKey(c => c.ParentId)`

- FK مربوطه `ParentId` در همین جدول قرار دارد.

### 4. `.OnDelete(DeleteBehavior.Restrict)`

- **خیلی مهم**  
  اگر DeleteBehavior را Cascade بگذارید، حذف یک Category باعث حذف recursive همه Category های زیرمجموعه می‌شود.  
  در ۹۰٪ موارد این خطرناک است.

---

# 3. ساختار دیتابیس نهایی

```
Categories
-----------
Id
ParentId  (FK to Categories.Id)
```

و EF ساختار درختی تولید می‌کند:

```
Electronics
 ├── Computers
 │    ├── Laptops
 │    └── Desktops
 └── Phones
      ├── Android
      └── iPhone
```

---

# 4. نکته خیلی مهم (کسانی که EF تازه‌کار هستند معمولاً اشتباه می‌کنند)

### باید Parent و Children در **یک Entity** باشند  
نه اینکه:

```csharp
public class ParentCategory { ... }
public class Category { ... }
```

Self‑Reference یعنی **خودش به خودش اشاره کند**.

---

# 5. کوئری‌نویسی Self‑Reference (چند مثال کاربردی)

### گرفتن SubCategory ها

```csharp
var subs = context.Categories
    .Include(c => c.SubCategories)
    .First(c => c.Id == 1);
```

---

### گرفتن ParentCategory

```csharp
var category = context.Categories
    .Include(c => c.ParentCategory)
    .First(c => c.Id == 10);
```

---

### گرفتن Category های ریشه (بدون والد)

```csharp
var roots = context.Categories
    .Where(c => c.ParentId == null)
    .ToList();
```

---

# 6. آیا امکان Many‑to‑Many Self‑Reference هم هست؟

بله، مثلاً:

```
User → Followers → User
```

اما آن یک سناریوی دیگر است و نیاز به Join Table دارد.  

---

# جمع‌بندی

Self‑Reference در EF Core یعنی:

- یک Entity به خودش FK دارد
- یک Navigation از نوع Reference (والد)
- یک Navigation از نوع Collection (فرزندها)
- بهترین انتخاب DeleteBehavior = Restrict

و با همین الگو می‌توان **ساختارهای درختی (Tree / Hierarchical)** را پیاده‌سازی کرد.
