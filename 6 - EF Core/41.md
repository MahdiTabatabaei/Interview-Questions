در **EF Core** برای مشخص کردن اینکه یک رابطه **Required (اجباری)** یا **Optional (اختیاری)** است، معمولاً از دو چیز استفاده می‌شود:

- نوع **Foreign Key**
- متد **`IsRequired()`** در Fluent API

اصل ماجرا این است که EF از **nullable بودن یا نبودن Foreign Key** تشخیص می‌دهد رابطه اجباری است یا نه.

---

# 1. Required Relationship (رابطه اجباری)

یعنی موجودیت وابسته **حتماً باید به موجودیت دیگر وصل باشد**.

مثال: هر **Book حتماً باید Author داشته باشد**.

### Entity

```csharp
public class Book
{
    public int Id { get; set; }

    public int AuthorId { get; set; }   // NOT NULL

    public Author Author { get; set; }
}
```

### Fluent API

```csharp
modelBuilder.Entity<Book>()
    .HasOne(b => b.Author)
    .WithMany(a => a.Books)
    .HasForeignKey(b => b.AuthorId)
    .IsRequired();
```

نتیجه در دیتابیس:

```
AuthorId INT NOT NULL
```

یعنی:

- Book بدون Author نمی‌تواند وجود داشته باشد.

---

# 2. Optional Relationship (رابطه اختیاری)

یعنی موجودیت وابسته **می‌تواند بدون رابطه هم وجود داشته باشد**.

مثال: Book ممکن است **Author نداشته باشد**.

### Entity

```csharp
public class Book
{
    public int Id { get; set; }

    public int? AuthorId { get; set; }   // nullable

    public Author Author { get; set; }
}
```

### Fluent API

```csharp
modelBuilder.Entity<Book>()
    .HasOne(b => b.Author)
    .WithMany(a => a.Books)
    .HasForeignKey(b => b.AuthorId)
    .IsRequired(false);
```

نتیجه در دیتابیس:

```
AuthorId INT NULL
```

---

# 3. نکته مهم (در EF Core جدید)

از **C# Nullable Reference Types** هم استفاده می‌شود.

مثال:

```csharp
public Author? Author { get; set; }
```

این هم به EF می‌گوید رابطه optional است.

---

# 4. جمع‌بندی ساده

| حالت | Foreign Key | IsRequired | نتیجه |
|-----|-------------|-----------|-------|
| Required | `int` | `IsRequired()` | NOT NULL |
| Optional | `int?` | `IsRequired(false)` | NULL |

---

✅ **قانون اصلی در EF Core:**

```
nullable FK  → Optional relationship
non-null FK → Required relationship
```
