وضعیت **Single Query (پیش‌فرض):**

- در این حالت EF Core سعی می‌کند تمام داده‌های مورد نیاز (موجودیت اصلی و موجودیت‌های مرتبط که `Include` شده‌اند) را در **یک کوئری SQL واحد** با استفاده از `JOIN`های متعدد واکشی کند.
- **مزیت:** تعداد کوئری‌ها کم است.
- **مشکل:** اگر `Include`های زیادی داشته باشید، کوئری SQL بسیار بزرگ، پیچیده و کند می‌شود. همچنین ممکن است داده‌ها تکرار شوند (Column Splitting).

در حالت **Split Queries:**

- در این حالت EF Core کوئری را به **چند کوئری SQL مجزا** تقسیم می‌کند.
- یک کوئری اصلی برای موجودیت اصلی اجرا می‌شود.
- برای هر `Include`، یک کوئری جداگانه اجرا می‌شود.
- **مزیت:** کوئری‌های SQL ساده‌تر، خواناتر و اغلب سریع‌تر هستند. مشکل تکرار داده در `JOIN`ها را ندارد.
- **مشکل:** تعداد کوئری‌ها بیشتر است.

**نحوه استفاده:**
```csharp

// Split Query برای یک کوئری خاص
var blogs = await context.Blogs
    .Include(b => b.Posts)
    .Include(b => b.Author)
    .AsSplitQuery() // فعال‌سازی Split Query
    .ToListAsync();

// فعال‌سازی Split Query به صورت Global برای کل DbContext
// در Startup.cs یا Program.cs
services.AddDbContext<AppDbContext>(options =>
    options.UseSqlServer(...)
           .UseQuerySplittingBehavior(QuerySplittingBehavior.SplitQuery));

```

---

درواقع **Split Query مثل Lazy Loading عمل نمی‌کند**.  
در Split Query کوئری‌ها **در همان ابتدا و توسط EF Core اجرا می‌شوند**، نه داخل حلقه و نه هنگام دسترسی به Navigation Property.

تفاوت دقیق را ببینیم.

---

# Lazy Loading
در Lazy Loading، داده‌ی navigation وقتی لود می‌شود که **کد به آن property دسترسی پیدا کند**.

مثال:

```csharp
var orders = context.Orders.ToList();

foreach (var order in orders)
{
    var items = order.Items; 
}
```

اتفاقی که می‌افتد:

1 query برای Orders  
N query برای Items

یعنی:

```
1 + N queries
```

چون هر بار که به `order.Items` دسترسی می‌زنیم EF یک query جدید می‌زند.

---

# Split Query در EF Core

Split Query وقتی استفاده می‌شود که **Include** داشته باشیم.

مثال:

```csharp
var orders = context.Orders
    .Include(o => o.Items)
    .AsSplitQuery()
    .ToList();
```

در این حالت EF Core:

1. ابتدا Orders را می‌گیرد
2. سپس Items همه Orders را **در یک query جداگانه** می‌گیرد

یعنی:

```
Query 1 → Orders
Query 2 → Items
```

مثال SQL تقریبی:

```
SELECT * FROM Orders

SELECT * FROM OrderItems
WHERE OrderId IN (...)
```

بعد EF در حافظه این‌ها را **fix‑up** می‌کند و Items را به Order مربوطه وصل می‌کند.

---

# نکته مهم

در Split Query:

- queryها **قبل از حلقه اجرا می‌شوند**
- تعداد queryها **بر اساس تعداد Includeها** است
- **به تعداد رکوردها query نمی‌زند**

مثلاً اگر داشته باشیم:

```csharp
context.Orders
   .Include(o => o.Items)
   .Include(o => o.Customer)
   .AsSplitQuery()
```

تقریباً می‌شود:

```
Query 1 → Orders
Query 2 → OrderItems
Query 3 → Customers
```

---

# چرا Split Query وجود دارد؟

برای حل مشکل **Cartesian Explosion** در Eager Loading.

اگر Join بزنیم:

```
Orders × Items × Payments × ...
```

ممکن است حجم داده شدیداً بزرگ شود.

Split Query این مشکل را کم می‌کند.

---

# جمع‌بندی تفاوت

Lazy Loading:

- query هنگام **دسترسی به property**
- معمولاً **N+1 query**

Split Query:

- queryها **همان ابتدا اجرا می‌شوند**
- تعداد query = تعداد navigationها
- هیچ query داخل حلقه اجرا نمی‌شود
