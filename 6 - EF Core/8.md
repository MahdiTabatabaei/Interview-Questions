
در EF Core دو راه برای دخالت در رفتار فریم‌ورک وجود دارد: **Interceptors** و **رویدادهای داخلی مثل ChangeTracker events**. تفاوت اصلی آن‌ها در **سطحی از سیستم که روی آن کار می‌کنند** و **زمانی که اجرا می‌شوند** است.

---

# 1. IInterceptor در EF Core

درواقع `IInterceptor` یک مکانیزم **پایین‌سطح (low-level)** برای دخالت در **عملیات دیتابیس و pipeline داخلی EF** است.

معمولاً برای این موارد استفاده می‌شود:

- مشاهده یا تغییر **SQL قبل از اجرا**
- تغییر **DbCommand و پارامترها**
- اندازه‌گیری زمان اجرای query
- کنترل transaction
- لاگ گرفتن از دستورات دیتابیس

مثال:

```csharp
public class MyInterceptor : DbCommandInterceptor
{
    public override InterceptionResult<DbDataReader> ReaderExecuting(
        DbCommand command,
        CommandEventData eventData,
        InterceptionResult<DbDataReader> result)
    {
        Console.WriteLine(command.CommandText);
        return base.ReaderExecuting(command, eventData, result);
    }
}
```

ویژگی‌ها:

- روی **commandهای واقعی SQL** کار می‌کند
- امکان **تغییر command قبل از اجرا** وجود دارد
- در سطح **دسترسی به دیتابیس (ADO.NET)** عمل می‌کند
- برای **performance monitoring و infrastructure** مناسب است

---

# 2. ChangeTracker Events

رویدادهای ChangeTracker در سطح **مدل و entityها** کار می‌کنند، نه SQL.

این رویدادها وقتی اتفاق می‌افتند که EF وضعیت entityها را تغییر می‌دهد.

مثال رویدادها:

- `Tracked`
- `StateChanged`

مثال:

```csharp
context.ChangeTracker.Tracked += (sender, e) =>
{
    Console.WriteLine($"Entity tracked: {e.Entry.Entity}");
};
```

یا:

```csharp
context.ChangeTracker.StateChanged += (sender, e) =>
{
    Console.WriteLine($"State changed: {e.NewState}");
};
```

ویژگی‌ها:

- روی **entityها** کار می‌کند
- قبل از تبدیل شدن به SQL اجرا می‌شود
- برای **Domain logic** مفید است
- برای **Audit یا validation** کاربرد دارد

---

# 3. تفاوت اصلی

| ویژگی | IInterceptor | ChangeTracker Events |
|---|---|---|
| سطح اجرا | سطح دیتابیس | سطح Entity |
| زمان اجرا | هنگام اجرای SQL | هنگام تغییر state entity |
| دسترسی به SQL | دارد | ندارد |
| امکان تغییر Query | دارد | ندارد |
| کاربرد اصلی | logging، performance، security | audit، validation، domain logic |

---

✅ خلاصه:

- ویژگی **Interceptors** برای کنترل **SQL و عملیات دیتابیس** استفاده می‌شوند.  
- ویژگی **ChangeTracker events** برای واکنش به **تغییرات entityها در حافظه** استفاده می‌شوند.
