در **DDD** هر **Aggregate** باید مستقل باشد و فقط از طریق **Aggregate Root** خود دسترسی داشته باشد. بنابراین:

- یک Aggregate **نباید Navigation Property به Aggregate دیگر داشته باشد**
- ارتباط فقط از طریق **Id (Reference by Id)** انجام می‌شود

اما در دیتابیس معمولاً **Foreign Key** وجود دارد. پس چالش این است که:

- در **Domain Model** هیچ Navigation نداشته باشیم  
- ولی در **EF Core** رابطهٔ دیتابیسی درست ایجاد شود

راه‌حل: **Shadow Foreign Key یا FK بدون Navigation**

---

# الگوی صحیح در DDD

فرض کنید دو Aggregate داریم:

```
Order (Aggregate Root)
Customer (Aggregate Root)
```

در DDD، `Order` نباید Navigation به `Customer` داشته باشد.

### Domain Model

```csharp
public class Order
{
    public Guid Id { get; private set; }

    public Guid CustomerId { get; private set; }   // فقط Id

    public decimal TotalPrice { get; private set; }
}
```

و Aggregate دیگر:

```csharp
public class Customer
{
    public Guid Id { get; private set; }
    public string Name { get; private set; }
}
```

هیچ Navigation ای مثل این نداریم:

```
public Customer Customer   ❌
```

---

# تنظیم Relation در EF Core

در `OnModelCreating` رابطه را تعریف می‌کنیم ولی Navigation نداریم.

```csharp
modelBuilder.Entity<Order>()
    .HasOne<Customer>()
    .WithMany()
    .HasForeignKey(o => o.CustomerId)
    .OnDelete(DeleteBehavior.Restrict);
```

نکات مهم:

- `HasOne<Customer>()` → نوع موجودیت مرتبط
- `WithMany()` → چون Navigation نداریم
- `HasForeignKey` → ستون FK در جدول

---

# نتیجه در دیتابیس

EF همچنان FK می‌سازد:

```
Orders
------
Id
CustomerId (FK)

Customers
---------
Id
Name
```

اما در Domain Model:

- Aggregate ها **به هم Navigation ندارند**
- فقط **Id reference** دارند

---

# چرا این روش با DDD سازگار است؟

در DDD:

```
Aggregate → فقط از طریق ID به Aggregate دیگر اشاره می‌کند
```

چون:

- Transaction boundary جدا است
- Consistency هر Aggregate مستقل است
- Lazy loading بین Aggregateها خطرناک است

---

# اگر به اطلاعات Aggregate دیگر نیاز داشته باشیم؟

از **Application Service یا Query** استفاده می‌کنیم.

مثال:

```csharp
var order = await orderRepository.Get(orderId);
var customer = await customerRepository.Get(order.CustomerId);
```

یا در Query:

```
Order + Customer DTO
```

با **JOIN در Query Layer**

---

# تکنیک پیشرفته‌تر: Shadow FK

حتی می‌توانید FK را در Domain Model هم نگذارید.

```csharp
modelBuilder.Entity<Order>()
    .Property<Guid>("CustomerId");
```

و سپس:

```csharp
.HasForeignKey("CustomerId")
```

در این حالت:

- Domain کاملاً پاک می‌ماند
- FK فقط در EF وجود دارد

---

# خلاصه

برای هماهنگی **DDD + EF Core**:

1. Navigation بین Aggregateها نداشته باشید
2. فقط **Id reference** نگه دارید
3. Relation را در **Fluent API** تعریف کنید

```csharp
.HasOne<OtherAggregate>()
.WithMany()
.HasForeignKey(...)
```

4. Queryهای cross-aggregate را در **Application Layer** انجام دهید
