درواقع **Global Query Filter** در EF Core فیلتری است که روی یک **Entity** تعریف می‌شود و به‌صورت **خودکار به تمام Queryها**ی آن Entity اعمال می‌شود.

یعنی هر بار که از آن جدول داده می‌خوانیم، EF Core این شرط را **به‌طور اتوماتیک به SQL اضافه می‌کند**.

---

## مثال ساده

فرض کنید سیستم **Soft Delete** دارد.

Entity:

```csharp
public class Post
{
    public int Id { get; set; }
    public string Title { get; set; }
    public bool IsDeleted { get; set; }
}
```

در `OnModelCreating`:

```csharp
protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    modelBuilder.Entity<Post>()
        .HasQueryFilter(p => !p.IsDeleted);
}
```

---

## نتیجه

وقتی این query را بزنیم:

```csharp
var posts = context.Posts.ToList();
```

ابزار EF در واقع SQL زیر را می‌سازد:

```sql
SELECT * FROM Posts
WHERE IsDeleted = 0
```

حتی اگر ما در query شرطی ننوشته باشیم.

---

## کاربردهای رایج

### 1. Soft Delete

رایج‌ترین استفاده:

```csharp
.HasQueryFilter(e => !e.IsDeleted)
```

به این صورت رکورد حذف نمی‌شود، فقط **نمایش داده نمی‌شود**.

---

### 2. Multi‑Tenancy

فیلتر کردن داده‌ها بر اساس tenant.

```csharp
.HasQueryFilter(e => e.TenantId == _tenantId)
```

پس هر tenant فقط داده‌های خودش را می‌بیند.

---

### 3. فیلتر داده‌های فعال

مثلاً:

```csharp
.HasQueryFilter(e => e.IsActive)
```

---

## نادیده گرفتن Global Filter

گاهی لازم است فیلتر اعمال نشود.

```csharp
var posts = context.Posts
    .IgnoreQueryFilters()
    .ToList();
```

مثلاً برای **Admin** یا گزارش‌ها.

---

## مزایا

- جلوگیری از تکرار شرط در همه queryها
- کاهش خطای انسانی
- تمیزتر شدن کد
- مناسب برای soft delete و multi‑tenant

---

✅ خلاصه:

درواقع **Global Query Filter** مکانیزمی در EF Core است که یک شرط ثابت را تعریف می‌کند تا **به‌طور خودکار به تمام Queryهای یک Entity اعمال شود**؛ کاربرد اصلی آن در **Soft Delete، Multi‑Tenancy و فیلتر داده‌های فعال** است.
