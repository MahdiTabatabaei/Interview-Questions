در **Entity Framework Core** می‌توان با استفاده از **CommandInterceptor** روی SQLای که EF تولید می‌کند قبل یا بعد از اجرا **دخالت کرد**؛ مثلاً:

- زمان اجرای کوئری را اندازه بگیریم  
- دستورات SQL را لاگ کنیم  
- پارامترها را تغییر دهیم  
- کوئری را تغییر دهیم یا حتی لغو کنیم

این کار با ارث‌بری از کلاس **`DbCommandInterceptor`** انجام می‌شود.

---

# 1. ساخت یک CommandInterceptor

```csharp
using Microsoft.EntityFrameworkCore.Diagnostics;
using System.Data.Common;
using System.Diagnostics;

public class QueryTimingInterceptor : DbCommandInterceptor
{
    private readonly Stopwatch _stopwatch = new Stopwatch();

    public override InterceptionResult<DbDataReader> ReaderExecuting(
        DbCommand command,
        CommandEventData eventData,
        InterceptionResult<DbDataReader> result)
    {
        _stopwatch.Restart();

        Console.WriteLine("SQL Command:");
        Console.WriteLine(command.CommandText);

        return base.ReaderExecuting(command, eventData, result);
    }

    public override DbDataReader ReaderExecuted(
        DbCommand command,
        CommandExecutedEventData eventData,
        DbDataReader result)
    {
        _stopwatch.Stop();

        Console.WriteLine($"Execution Time: {_stopwatch.ElapsedMilliseconds} ms");

        return base.ReaderExecuted(command, eventData, result);
    }
}
```

در اینجا:

- قبل از اجرا → `ReaderExecuting`
- بعد از اجرا → `ReaderExecuted`
- زمان اجرای کوئری اندازه‌گیری می‌شود.

---

# 2. ثبت Interceptor در DbContext

در `DbContext`:

```csharp
protected override void OnConfiguring(DbContextOptionsBuilder optionsBuilder)
{
    optionsBuilder
        .UseSqlServer("connection_string")
        .AddInterceptors(new QueryTimingInterceptor());
}
```

یا در **Dependency Injection**:

```csharp
services.AddDbContext<AppDbContext>(options =>
{
    options.UseSqlServer(connectionString);
    options.AddInterceptors(new QueryTimingInterceptor());
});
```

# 3. تغییر پارامترهای SQL

می‌توان قبل از اجرای کوئری پارامترها را تغییر داد.

```csharp
public override InterceptionResult<int> NonQueryExecuting(
    DbCommand command,
    CommandEventData eventData,
    InterceptionResult<int> result)
{
    foreach (DbParameter param in command.Parameters)
    {
        if (param.ParameterName == "@IsDeleted")
        {
            param.Value = false;
        }
    }

    return base.NonQueryExecuting(command, eventData, result);
}
```

مثلاً برای:

- Soft Delete
- Multi‑Tenancy
- امنیت

---

# 4. تغییر SQL قبل از اجرا

حتی می‌توان متن SQL را تغییر داد:

```csharp
public override InterceptionResult<DbDataReader> ReaderExecuting(
    DbCommand command,
    CommandEventData eventData,
    InterceptionResult<DbDataReader> result)
{
    command.CommandText += " OPTION (RECOMPILE)";

    return base.ReaderExecuting(command, eventData, result);
}
```

مثلاً برای:

- اضافه کردن **Query Hint**
- تغییر رفتار Query

---

# 5. متدهای مهم در DbCommandInterceptor

مهم‌ترین hookها:

- `ReaderExecuting` → قبل از اجرای SELECT
- `ReaderExecuted` → بعد از اجرای SELECT
- `NonQueryExecuting` → قبل از INSERT/UPDATE/DELETE
- `ScalarExecuting` → قبل از اجرای scalar query

---

✅ خلاصه:

درواقع **CommandInterceptor در EF Core اجازه می‌دهد قبل و بعد از اجرای SQL تولیدشده توسط EF، روی آن دخالت کنیم؛ مثل لاگ گرفتن، اندازه‌گیری زمان اجرا، تغییر پارامترها یا حتی تغییر متن SQL.**
