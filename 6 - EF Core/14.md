در **EF Core** برای جلوگیری از مشکلات کارایی (مثل **N+1 Query**) معمولاً **Lazy Loading را غیرفعال یا کنترل** می‌کنیم. چند روش رایج وجود دارد:

---

# 1. حذف Lazy Loading Proxy (رایج‌ترین روش)

Lazy Loading در EF Core معمولاً با پکیج زیر فعال می‌شود:

```
Microsoft.EntityFrameworkCore.Proxies
```

و در `DbContext`:

```csharp
optionsBuilder.UseLazyLoadingProxies();
```

برای غیرفعال کردن Lazy Loading کافی است:

- این خط را حذف کنیم

```csharp
optionsBuilder.UseLazyLoadingProxies();
```

یا اصلاً پکیج proxies را نصب نکنیم.

در این حالت EF فقط **Explicit یا Eager loading** انجام می‌دهد.

---

# 2. حذف `virtual` از Navigation Properties

Lazy Loading Proxy برای کار کردن نیاز دارد که navigation propertyها **virtual** باشند.

مثال:

```csharp
public class Order
{
    public int Id { get; set; }

    public virtual Customer Customer { get; set; }
}
```

اگر `virtual` را حذف کنیم:

```csharp
public Customer Customer { get; set; }
```

Lazy Loading دیگر انجام نمی‌شود.

---

# 3. استفاده از Eager Loading با Include

به جای Lazy Loading بهتر است داده‌های موردنیاز را صریح بگیریم.

```csharp
var orders = context.Orders
    .Include(o => o.Customer)
    .ToList();
```

این کار:

- تعداد queryها را کم می‌کند
- از N+1 جلوگیری می‌کند.

---

# 4. Explicit Loading (کنترل دستی)

گاهی می‌خواهیم **در صورت نیاز** داده را لود کنیم.

```csharp
var order = context.Orders.First();

context.Entry(order)
    .Reference(o => o.Customer)
    .Load();
```

یا برای collection:

```csharp
context.Entry(order)
    .Collection(o => o.Items)
    .Load();
```

---

# 5. استفاده از Projection

در APIها معمولاً بهترین روش است.

```csharp
var orders = context.Orders
    .Select(o => new
    {
        o.Id,
        CustomerName = o.Customer.Name
    })
    .ToList();
```

این روش:

- فقط داده موردنیاز را می‌گیرد
- performance بهتر دارد.

---

✅ **جمع‌بندی**

برای جلوگیری از افت کارایی ناشی از Lazy Loading:

- حذف `UseLazyLoadingProxies`
- حذف `virtual` از navigation propertyها
- استفاده از `Include` (Eager Loading)
- استفاده از `Explicit Loading`
- استفاده از `Projection`

در اکثر پروژه‌های **production**، Lazy Loading **به‌طور کامل غیرفعال** می‌شود چون به‌راحتی باعث **N+1 Query Problem** می‌شود.
