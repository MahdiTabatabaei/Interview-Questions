در EF Core دو روش برای مدل‌سازی رابطه **Many‑to‑Many** بین `Student` و `Course` وجود دارد:

1. **بدون Join Entity (روش ساده)**
2. **با Join Entity (روش کامل و قابل کنترل)**

---

# 1. روش ساده (Implicit Join Table)

در EF Core جدید اگر جدول واسط فقط شامل دو Foreign Key باشد، نیازی به تعریف کلاس واسط نیست.

### Entity ها

```csharp
public class Student
{
    public int Id { get; set; }

    public ICollection<Course> Courses { get; set; }
}

public class Course
{
    public int Id { get; set; }

    public ICollection<Student> Students { get; set; }
}
```

### Fluent API

```csharp
modelBuilder.Entity<Student>()
    .HasMany(s => s.Courses)
    .WithMany(c => c.Students);
```

EF Core خودش یک جدول واسط می‌سازد:

```
StudentCourse
-------------
StudentId (FK)
CourseId  (FK)
```

این جدول **Shadow Join Table** است و کلاس جدا ندارد.

---

# 2. روش حرفه‌ای (Explicit Join Entity)

اگر بخواهیم اطلاعات بیشتری ذخیره کنیم (مثلاً تاریخ ثبت‌نام)، باید یک **Join Entity** تعریف کنیم.

### Join Entity

```csharp
public class StudentCourse
{
    public int StudentId { get; set; }
    public int CourseId { get; set; }

    public DateTime EnrollmentDate { get; set; }

    public Student Student { get; set; }
    public Course Course { get; set; }
}
```

---

### Student

```csharp
public class Student
{
    public int Id { get; set; }

    public ICollection<StudentCourse> StudentCourses { get; set; }
}
```

---

### Course

```csharp
public class Course
{
    public int Id { get; set; }

    public ICollection<StudentCourse> StudentCourses { get; set; }
}
```

---

### Fluent API

```csharp
modelBuilder.Entity<StudentCourse>()
    .HasKey(sc => new { sc.StudentId, sc.CourseId });

modelBuilder.Entity<StudentCourse>()
    .HasOne(sc => sc.Student)
    .WithMany(s => s.StudentCourses)
    .HasForeignKey(sc => sc.StudentId);

modelBuilder.Entity<StudentCourse>()
    .HasOne(sc => sc.Course)
    .WithMany(c => c.StudentCourses)
    .HasForeignKey(sc => sc.CourseId);
```

# مقایسه دو روش

| روش | مزیت | محدودیت |
|----|----|----|
| بدون Join Entity | ساده و سریع | بدون ستون اضافی |
| با Join Entity | انعطاف‌پذیر و حرفه‌ای | کد بیشتر |

---

✅ **قاعده عملی در پروژه‌های واقعی**

- اگر فقط رابطه ساده است → **Implicit Many‑to‑Many**
- اگر metadata یا منطق دارید → **Explicit Join Entity**
