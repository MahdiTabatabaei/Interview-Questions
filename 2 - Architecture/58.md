قفل مشترک بین چند سرویس برای جلوگیری از [[1 - CSharp – Language Fundamentals/61| race condition]] .

ابزارها:

- Redis RedLock
- Zookeeper
- Consul

### مثال C# با Redis
```csharp

var redLock = await redisLockFactory.CreateLockAsync("order:123", TimeSpan.FromSeconds(30));

```

---

معنای **Distributed Lock** یعنی یک **قفل سراسری بین چند نود/سرویس** تا در یک لحظه فقط **یک پردازش** بتواند یک کار یا منبع مشترک را انجام دهد.

### خیلی ساده

اگر 3 تا میکروسرویس هم‌زمان بخواهند یک job را اجرا کنند، Distributed Lock می‌گوید:

- فقط **یکی** اجازه اجرا دارد
- بقیه باید صبر کنند یا رد شوند

---

## کجا استفاده می‌شود؟

- اجرای job تکراری فقط توسط یک نود
- جلوگیری از پردازش تکراری یک پیام
- جلوگیری از دوبار ثبت شدن عملیات
- کنترل دسترسی هم‌زمان به یک resource مشترک

---

## با چه ابزارهایی پیاده می‌شود؟

### 1) **Redis**
رایج‌ترین گزینه  
مثلاً با:
- `SET key value NX PX 30000`

یعنی:
- اگر key وجود ندارد، قفل را بگیر
- با TTL تا اگر سرویس مرد، قفل خودکار آزاد شود

الگوی معروف: **Redlock**

---

### 2) **Database**
مثلاً:
- SQL Server
- PostgreSQL
- MySQL

با روش‌هایی مثل:
- row lock
- advisory lock
- lock table

---

### 3) **ZooKeeper**
برای سیستم‌های توزیع‌شده خیلی جدی و قابل‌اعتماد  
مخصوص coordination

---

### 4) **etcd / Consul**
مخصوص service coordination و distributed systems

## یک مثال ملموس

فرض کن 4 پاد از `invoice-service` داری و هر 1 دقیقه job تولید فاکتور اجرا می‌شود.

بدون lock:
- هر 4 پاد job را اجرا می‌کنند ❌
- 4 بار فاکتور تولید می‌شود ❌

با Distributed Lock:
- فقط 1 پاد lock می‌گیرد ✅
- فقط همان job را اجرا می‌کند ✅

# مکانیزم قفل در Redis

رایج‌ترین روش:

```text
SET lock-key unique-value NX PX 30000
```

معنی:

- `NX` → فقط اگر کلید وجود ندارد ست شود
- `PX 30000` → قفل 30 ثانیه اعتبار دارد
- `unique-value` → یک شناسه یکتا برای مالک قفل

اگر دستور موفق شود:
- lock گرفته شده

اگر موفق نشود:
- یعنی یکی دیگر قفل را گرفته

---

# چرا unique value مهم است؟

چون موقع آزاد کردن lock باید مطمئن شویم **فقط همان کسی که lock را گرفته، آزادش کند**.

وگرنه ممکن است:
- سرویس A قفل بگیرد
- زمان بگذرد و TTL تمام شود
- سرویس B قفل جدید بگیرد
- بعد سرویس A اشتباهی lock سرویس B را حذف کند ❌

برای همین unlock باید با check انجام شود.

# پیاده‌سازی ساده Lock Service

## Interface

```csharp
public interface IDistributedLockService
{
    Task<string?> TryAcquireLockAsync(string key, TimeSpan expiry);
    Task<bool> ReleaseLockAsync(string key, string lockValue);
}
```

---

## Implementation

```csharp
using StackExchange.Redis;

public class RedisDistributedLockService : IDistributedLockService
{
    private readonly IDatabase _database;

    public RedisDistributedLockService(IConnectionMultiplexer redis)
    {
        _database = redis.GetDatabase();
    }

    public async Task<string?> TryAcquireLockAsync(string key, TimeSpan expiry)
    {
        var lockValue = Guid.NewGuid().ToString();

        var acquired = await _database.StringSetAsync(
            key,
            lockValue,
            expiry,
            when: When.NotExists);

        return acquired ? lockValue : null;
    }

    public async Task<bool> ReleaseLockAsync(string key, string lockValue)
    {
        const string script = @"
            if redis.call('get', KEYS[1]) == ARGV[1] then
                return redis.call('del', KEYS[1])
            else
                return 0
            end
        ";

        var result = (int)(long)await _database.ScriptEvaluateAsync(
            script,
            new RedisKey[] { key },
            new RedisValue[] { lockValue });

        return result == 1;
    }
}
```

# نمونه Background Worker

این worker هر 20 ثانیه تلاش می‌کند job را اجرا کند، ولی فقط اگر lock را بگیرد.

```csharp
using Microsoft.Extensions.Hosting;
using Microsoft.Extensions.Logging;

public class InvoiceJobWorker : BackgroundService
{
    private readonly ILogger<InvoiceJobWorker> _logger;
    private readonly IDistributedLockService _lockService;

    public InvoiceJobWorker(
        ILogger<InvoiceJobWorker> logger,
        IDistributedLockService lockService)
    {
        _logger = logger;
        _lockService = lockService;
    }

    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        while (!stoppingToken.IsCancellationRequested)
        {
            var lockKey = "lock:jobs:invoice-generation";
            var expiry = TimeSpan.FromSeconds(30);

            string? lockValue = null;

            try
            {
                lockValue = await _lockService.TryAcquireLockAsync(lockKey, expiry);

                if (lockValue is null)
                {
                    _logger.LogInformation("Could not acquire lock. Another instance is running the job.");
                }
                else
                {
                    _logger.LogInformation("Lock acquired. Running invoice generation job...");

                    await DoWorkAsync(stoppingToken);

                    _logger.LogInformation("Job completed.");
                }
            }
            catch (Exception ex)
            {
                _logger.LogError(ex, "Error while executing job.");
            }
            finally
            {
                if (lockValue is not null)
                {
                    var released = await _lockService.ReleaseLockAsync(lockKey, lockValue);

                    if (released)
                        _logger.LogInformation("Lock released.");
                    else
                        _logger.LogWarning("Lock was not released. It may have expired already.");
                }
            }

            await Task.Delay(TimeSpan.FromSeconds(20), stoppingToken);
        }
    }

    private async Task DoWorkAsync(CancellationToken cancellationToken)
    {
        // شبیه‌سازی کار اصلی
        await Task.Delay(TimeSpan.FromSeconds(10), cancellationToken);
    }
}
```

- Pod A
- Pod B
- Pod C

همه با هم می‌خواهند job را اجرا کنند.

نتیجه:

- فقط یکی `lock:jobs:invoice-generation` را در Redis ثبت می‌کند
- بقیه شکست می‌خورند
- فقط همان یکی job را اجرا می‌کند

---

# نکته بسیار مهم: TTL

چرا expiry گذاشتیم؟

چون اگر پادی که lock گرفته crash کند، قفل نباید تا ابد بماند.

مثلاً:
- تنظیم lock با TTL = 30s
- اگر سرویس وسط کار بمیرد
- بعد از 30 ثانیه lock خودکار حذف می‌شود

---

# مشکل احتمالی: job طولانی‌تر از TTL شود

مثلاً:
- تنظیم TTL = 30 ثانیه
- هر job = 2 دقیقه

در این حالت lock وسط کار expire می‌شود و یک instance دیگر هم ممکن است job را شروع کند ❌

---

# راه‌حل این مشکل

## 1) زمان TTL را مناسب انتخاب کن

اگر job معمولاً 10 ثانیه طول می‌کشد، TTL را مثلاً 1 دقیقه بگذار.

## 2) تعیینLock renewal / heartbeat

در کارهای جدی‌تر باید تا وقتی job در حال اجراست، TTL را تمدید کنی.

مثلاً هر 10 ثانیه اگر هنوز مالک lock هستی:
- مقدار expire را دوباره تنظیم کن

# نمونه ایده برای تمدید Lock

می‌توانی متدی شبیه این داشته باشی:

```csharp
public async Task<bool> ExtendLockAsync(string key, string lockValue, TimeSpan expiry)
{
    const string script = @"
        if redis.call('get', KEYS[1]) == ARGV[1] then
            return redis.call('pexpire', KEYS[1], ARGV[2])
        else
            return 0
        end
    ";

    var result = (int)(long)await _database.ScriptEvaluateAsync(
        script,
        new RedisKey[] { key },
        new RedisValue[] { lockValue, (long)expiry.TotalMilliseconds });

    return result == 1;
}
```

این هم با Lua چک می‌کند که فقط مالک همان lock بتواند TTL را تمدید کند.

# معنای Redlock چیست؟

درواقع **Redlock** الگویی است که Redis برای distributed lock مقاوم‌تر پیشنهاد کرده، مخصوصاً وقتی چند Redis node داری.

اما در عمل:

- برای خیلی از پروژه‌های معمول، همین **single Redis lock with TTL** کافی است
- برای سناریوهای mission-critical باید معماری دقیق‌تر بررسی شود
