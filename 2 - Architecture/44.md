- در **Timeout**: اگر پاسخ دیر شد → درخواست Fail می‌شود.
    
- در **Circuit Breaker**: اگر سرویس زیاد خطا داد → ارتباط را قطع می‌کند.
    
- در **Bulkhead**: محدودیت تعداد درخواست همزمان برای جلوگیری از Overload
    
    (مثل اتاق‌های جدا در کشتی که از غرق شدن کل کشتی جلوگیری می‌کنند)
    

### مثال C# Bulkhead

```csharp

var bulkhead = Policy
    .BulkheadAsync(maxParallelization: 10, maxQueuingActions: 20);

```

---

در معماری میکروسرویس، الگوهای **Circuit Breaker**، **Timeout** و **Bulkhead** هر سه برای **تاب‌آوری ([[Resilience]])** استفاده می‌شوند، اما هر کدام مشکل متفاوتی را حل می‌کنند.

پایین دقیق‌ترین و ساده‌ترین توضیح همراه با مثال‌های **C# / ASP.NET Core / Polly** ارائه شده است.

----------------------------------------

# 1) Timeout Pattern  
## مشکل چیست؟

اگر سرویس مقصد کند شود یا پاسخ ندهد، کانکشن‌های شما معلق می‌مانند و CPU/Threadها قفل می‌شوند.

### هدف Timeout:
خودت تصمیم بگیری:  
«اگر سرویس X بیشتر از ۲ ثانیه جواب نداد، قطع کن.»

### نتیجه:
- منابع آزاد می‌شود  
- صف درخواست‌ها بی‌نهایت نمی‌شود  
- فشار وارد نمی‌شود  

----------------------------------------

## مثال عملی C# (Polly Timeout)

```csharp
var timeoutPolicy = Policy
    .TimeoutAsync<HttpResponseMessage>(TimeSpan.FromSeconds(2));

var httpClient = new HttpClient();

var response = await timeoutPolicy.ExecuteAsync(() =>
    httpClient.GetAsync("http://payment-service/api/pay")
);
```

### کاربرد واقعی:

در یک سفارش‌گذاری، اگر سرویس پرداخت کند باشد، سرویس سفارش ۲ ثانیه بیشتر منتظر نمی‌ماند و خطا می‌دهد، تا کل سیستم قفل نشود.

----------------------------------------

# 2) Circuit Breaker Pattern

## مشکل چیست؟

وقتی سرویس مقصد **از کار افتاده** یا **بسیار کند** است، اگر همچنان درخواست بفرستی:

- منابع خودت مصرف می‌شود  
- فشار روی سرویس مشکل‌دار بیشتر می‌شود  
- زمان انتظار زیاد می‌شود  

### هدف Circuit Breaker:

بعد از تعداد مشخصی خطا:

- **مدار باز می‌شود (Open)**  
- هیچ درخواست جدیدی ارسال نمی‌شود  
- بعد از مدتی به حالت نیمه‌باز (Half‑Open) می‌رود  
- اگر درست بود → مدار بسته  
- اگر خراب بود → دوباره باز  

### نتیجه:
به سرویس خراب فشار وارد نمی‌شود  
و سرویس شما هم محافظت می‌شود.

----------------------------------------

## مثال Circuit Breaker (C# / Polly)

```csharp
var circuitBreakerPolicy = Policy
    .Handle<HttpRequestException>()
    .CircuitBreakerAsync(
        exceptionsAllowedBeforeBreaking: 3,
        durationOfBreak: TimeSpan.FromSeconds(20)
    );

var response = await circuitBreakerPolicy.ExecuteAsync(() =>
    httpClient.GetAsync("http://inventory-service/api/check")
);
```

### مفهوم:

- اگر ۳ بار پشت‌سرهم سرویس انبار خطا بدهد → مدار ۲۰ ثانیه باز می‌شود  
- در این مدت هیچ درخواست جدید ارسال نمی‌شود  

----------------------------------------

# 3) [[Bulkhead]] Pattern  

## مشکل چیست؟

فرض کن یک ماژول تعداد زیادی درخواست به یک سرویس می‌فرستند و **Thread Pool** یا **Connection Pool** شما تمام می‌شود.  
در نتیجه **کل سرویس شما Down می‌شود**.

### هدف Bulkhead:

استفاده از ظرفیت‌های ایزوله:

- بیشترین تعداد درخواست همزمان به سرویس X = مثلاً ۲۰
- اگر پر شد → درخواست جدید رد شود، نه این‌که سیستم قفل شود

### نتیجه:

یک قسمت خراب کل سرویس را نمی‌خواباند.

----------------------------------------

## مثال Bulkhead در C# / Polly

```csharp
var bulkheadPolicy = Policy
    .BulkheadAsync<HttpResponseMessage>(
        maxParallelization: 20, 
        maxQueuingActions: 50
    );

var response = await bulkheadPolicy.ExecuteAsync(() =>
    httpClient.GetAsync("http://shipping-service/api/ship")
);
```

### مفهوم:
- حداکثر ۲۰ درخواست همزمان  
- ۵۰ درخواست در صف  
- بقیه رد می‌شوند (Rejected)  
- کل سیستم محافظت می‌شود  

----------------------------------------

# تفاوت سه الگو (خلاصه و قطعی)

| الگو | مشکل چه چیزی را حل می‌کند؟ | رفتار |
|------|------------------------------|--------|
| Timeout | سرویس کند یا هنگ کرده | اگر جواب دیر شد → قطع کن |
| Circuit Breaker | سرویس Down یا ناپایدار | اگر چند خطا → مدار باز → عدم ارسال درخواست |
| Bulkhead | فشار زیاد و کمبود منابع | محدود کردن تعداد درخواست همزمان |

----------------------------------------

# مثال ترکیبی واقعی در یک میکروسرویس ASP.NET Core

در معماری میکروسرویس واقعی معمولاً هر سه را با هم استفاده می‌کنیم.

### الگوی کامل با Polly:

```csharp
services.AddHttpClient("payment", client =>
{
    client.BaseAddress = new Uri("http://payment-service");
})
.AddPolicyHandler(Policy.TimeoutAsync<HttpResponseMessage>(5))
.AddPolicyHandler(Policy.BulkheadAsync<HttpResponseMessage>(20, 50))
.AddPolicyHandler(
    Policy.Handle<HttpRequestException>()
        .CircuitBreakerAsync(3, TimeSpan.FromSeconds(15))
);
```

این یعنی:

1. اگر پرداخت بیشتر از ۵ ثانیه طول کشید → timeout  
2. اگر بیش از ۲۰ درخواست فعال بود → bulkhead فعال  
3. اگر سرویس ۳ بار خطا داد → circuit breaker فعال  

----------------------------------------

# یک مثال کاملاً واقعی سناریویی

فرض کن API سفارش (`OrderService`) باید:

1. به `PaymentService` درخواست پرداخت دهد  
2. به `InventoryService` درخواست رزرو کالا دهد  

### سناریو: Payment خراب شده

- Timeout کاری می‌کند **درخواست‌ها معلق نماند**
- CircuitBreaker کاری می‌کند **پس از چند بار خطا اصلاً درخواست نفرستیم**
- Bulkhead کاری می‌کند **اگر هزار نفر همزمان سفارش زدند، سرویس سفارش Down نشود**

نتیجه:  
سرویس سفارش هنوز سالم است  
و فقط عملیات پرداخت از چرخه خارج شده.

----------------------------------------

# خلاصه نهایی (خیلی کوتاه و کاربردی)

- Timeout: «اه، دیر جواب دادی! قطع می‌کنم.»  
- Circuit Breaker: «سه بار خراب شدی، دیگه سمتت نمیام تا بهتر شی.»  
- Bulkhead: «بیشتر از ۲۰ تا همزمان نمی‌پذیرم، بقیه باید رد شوند.»
