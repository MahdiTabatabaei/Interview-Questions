سیستم به **سرویس‌های کوچک مستقل** تقسیم می‌شود که هر سرویس:

- دیتابیس مخصوص خود دارد
- انتشار Deploy مستقل دارد
- تیم و دامنه مجزا دارد

مزیت: مقیاس‌پذیری، استقلال تیم‌ها

عیب: پیچیدگی بالا، نیازمند DevOps قوی

----

در **Microservices** سیستم به چند سرویس مستقل تقسیم می‌شود.  
هر سرویس معمولاً **یک پروژه یا حتی یک Solution جدا** دارد.

### ساختار سلوشن (مدل رایج)

```
MySystem.sln
│
├── ApiGateway
│
├── Services
│   ├── UserService
│   │   ├── User.API
│   │   ├── User.Application
│   │   ├── User.Domain
│   │   └── User.Infrastructure
│   │
│   ├── OrderService
│   │   ├── Order.API
│   │   ├── Order.Application
│   │   ├── Order.Domain
│   │   └── Order.Infrastructure
│   │
│   └── ProductService
│       ├── Product.API
│       ├── Product.Application
│       ├── Product.Domain
│       └── Product.Infrastructure
│
└── SharedLibraries
```

### تصویر ذهنی

```
        Client
          │
      API Gateway
   ┌──────┼───────┐
   │      │       │
User   Order   Product
Service Service Service
   │      │       │
 DB1     DB2     DB3
```


```
[Service A]   [Service B]   [Service C]
    │              │              │
   DB             DB             DB
```


ویژگی‌ها:
- هر سرویس **مستقل**
- هر سرویس **دیتابیس خودش**
- هر سرویس **deploy جداگانه**
