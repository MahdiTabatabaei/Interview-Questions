
1. **Proxy**

وظیفه‌اش فقط انتقال درخواست به سرویس است.

مثال: gateway/user → user-service

1. **Aggregator**

چند سرویس را صدا می‌زند و یک پاسخ تجمیع‌شده می‌دهد.
   
مثال: ProductDetail = محصول + نظرات + موجودی

3. **Facade**

برای API هایی با هدف خاص و کمتر از فرم داخلی سرویس‌ها.

برای ساده‌سازی API برای کلاینت.

---

در **API Gateway Pattern** سه مدل رایج داریم: **Proxy ،Aggregator ،Facade**.

برای اینکه تفاوتشان واضح شود، یک سناریوی ثابت در نظر می‌گیریم:

فرض کن یک سیستم فروش آنلاین داریم با این سرویس‌ها:

کلاینت‌ها (موبایل / وب) از طریق **API Gateway** به این سرویس‌ها دسترسی دارند.

---

# 1️⃣ Proxy Pattern

در Proxy، Gateway فقط **درخواست را عبور می‌دهد** و هیچ منطق خاصی ندارد.

یعنی:

کلاینت → Gateway → سرویس

درواقع Gateway فقط نقش **Reverse Proxy + Security + Rate Limit** دارد.

### مثال درخواست

کلاینت:
```markdown

GET /api/users/10

```
در اینجا Gateway این درخواست را مستقیم می‌فرستد به:
```markdown

UserService/users/10

```
مثال ساده در C#
```csharp

[HttpGet("users/{id}")]
public async Task<IActionResult> GetUser(int id)
{
    var response = await _httpClient.GetAsync($"http://user-service/users/{id}");
    var data = await response.Content.ReadAsStringAsync();
    return Content(data, "application/json");
}

```

در اینجا Gateway فقط **Forward** می‌کند.

---

# 2️⃣ Aggregator Pattern

در این الگو Gateway **چند سرویس را صدا می‌زند و نتیجه را ترکیب می‌کند.**

برای کاهش تعداد درخواست‌های کلاینت استفاده می‌شود.

### سناریو

صفحه محصول نیاز دارد:

- اطلاعات محصول
- موجودی
- نظرات کاربران

اگر Gateway نداشته باشیم:

کلاینت باید 3 درخواست بزند:
```markdown

ProductService
InventoryService
ReviewService

```
اما با **Aggregator**:

کلاینت فقط یک درخواست می‌زند.
```markdown

GET /product-details/100

```
اینجا Gateway این کارها را انجام می‌دهد:
```markdown

ProductService
InventoryService
ReviewService

```
و نتیجه را ترکیب می‌کند.

### مثال# C#
```csharp

[HttpGet("product-details/{id}")]
public async Task<IActionResult> GetProductDetails(int id)
{
    var product = await _productService.GetProduct(id);
    var stock = await _inventoryService.GetStock(id);
    var reviews = await _reviewService.GetReviews(id);

    return Ok(new
    {
        product,
        stock,
        reviews
    });
}

```
خروجی:
```markdown

{
  product:{...},
  stock:15,
  reviews:[...]
}

```
کلاینت فقط **یک request** ارسال کرده است.

# 3️⃣ Facade Pattern

در Facade، Gateway یک **API ساده و مخصوص کلاینت** طراحی می‌کند که پشت صحنه ممکن است چند عملیات انجام دهد.

یعنی Gateway **منطق workflow** دارد.

### سناریو

در سیستم فروش، برای **ثبت سفارش** باید این مراحل انجام شود:

1. اعتبار کاربر چک شود
2. موجودی کالا چک شود
3. سفارش ثبت شود
4. پرداخت انجام شود

اگر کلاینت خودش این کارها را انجام دهد:
```markdown

UserService
InventoryService
OrderService
PaymentService

```
اما با **Facade API**:

کلاینت فقط یک endpoint صدا می‌زند:
```markdown

POST /place-order

```
Gateway خودش همه مراحل را انجام می‌دهد.

### مثال #C#
```csharp

[HttpPost("place-order")]
public async Task<IActionResult> PlaceOrder(OrderRequest request)
{
    var user = await _userService.GetUser(request.UserId);

    var stock = await _inventoryService.GetStock(request.ProductId);
    if (stock < request.Quantity)
        return BadRequest("Not enough stock");

    var order = await _orderService.CreateOrder(request);

    await _paymentService.Pay(order.Id, request.Amount);

    return Ok(order);
}

```
کلاینت فقط یک API دارد ولی پشت صحنه چند سرویس درگیرند.

# جمع‌بندی ساده

Proxy

Gateway فقط **Forward** می‌کند.

Aggregator

Gateway **چند سرویس را جمع می‌کند** و یک پاسخ می‌دهد.

Facade

Gateway **یک API ساده می‌دهد که پشت آن چند عملیات پیچیده است.**

---

### یک مثال خیلی ساده از زندگی

Proxy

اپراتور تلفن فقط تماس شما را وصل می‌کند.

Aggregator

یک اپلیکیشن هواشناسی که اطلاعات را از چند منبع جمع می‌کند.

Facade

یک آژانس مسافرتی که **پرواز + هتل + بیمه** را با یک سفارش برای شما رزرو می‌کند.
