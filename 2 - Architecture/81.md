درواقع **mTLS (Mutual TLS)** یا **Mutual Transport Layer Security** نسخه‌ای از TLS است که در آن **هر دو طرف ارتباط هویت یکدیگر را تأیید می‌کنند**.

در TLS معمولی فقط **سرور احراز هویت می‌شود**، اما در mTLS **هم سرور و هم کلاینت احراز هویت می‌شوند**.

---

# مفهوم TLS معمولی چگونه کار می‌کند

وقتی به یک سایت HTTPS وصل می‌شوی:

```
Client → Server
```

سرور یک **Certificate** می‌فرستد.

کلاینت بررسی می‌کند:

- آیا certificate معتبر است؟
- آیا توسط CA امضا شده؟
- آیا domain درست است؟

اگر درست بود ارتباط رمزنگاری می‌شود.

اما نکته مهم:

```
Server authenticated
Client NOT authenticated
```

یعنی سرور نمی‌داند کلاینت دقیقاً چه کسی است.

---

# مفهوم mTLS چگونه کار می‌کند

در mTLS هر دو طرف certificate دارند.

```
Client ↔ Server
```

مراحل:

1️⃣ Client به Server وصل می‌شود

2️⃣ Server certificate خودش را می‌فرستد

3️⃣ Client certificate سرور را verify می‌کند

4️⃣ Server از Client می‌خواهد certificate بفرستد

5️⃣ Client certificate خودش را ارسال می‌کند

6️⃣ Server آن را verify می‌کند

بعد از این مرحله ارتباط امن برقرار می‌شود.

---

# نتیجه

در mTLS:

```
Server authenticates Client
Client authenticates Server
```

یعنی **دو طرف همدیگر را می‌شناسند**.

---

# مثال ساده

بدون mTLS:

```
Client → Server ✅
Unknown client allowed
```

با mTLS:

```
Client certificate required
Only trusted clients allowed
```

اگر certificate معتبر نباشد:

```
Connection rejected
```

---

# کاربرد mTLS در Microservices

در معماری Microservices سرویس‌ها دائماً با هم ارتباط دارند:

```
OrderService → PaymentService → InventoryService
```

بدون mTLS:

هر سرویس داخل شبکه می‌تواند درخواست بفرستد.

با mTLS:

در این حالت PaymentService فقط درخواست‌هایی را قبول می‌کند که:

```
Certificate معتبر داشته باشند
```

مثلاً:

```
OrderService certificate ✅
InventoryService certificate ❌
```

---

# ساختار ارتباط با mTLS

```
OrderService
   │
   │ mTLS
   │
PaymentService
```

سرویس PaymentService بررسی می‌کند:

- مقدار certificate کلاینت معتبر است؟
- توسط CA درست امضا شده؟
- آیا این سرویس مجاز است؟

---

# نقش mTLS در Zero Trust

درواقع mTLS یکی از ابزارهای اصلی **Zero Trust Architecture** است.

چون:

```
Identity-based security
```

به جای اعتماد به شبکه، اعتماد به **هویت سرویس** داده می‌شود.

---

# تعریف mTLS در Kubernetes و Service Mesh

در سیستم‌های مدرن معمولاً mTLS توسط **Service Mesh** مدیریت می‌شود.

مثال:

```
Istio
Linkerd
Consul
```

درواقع Service Mesh این کارها را انجام می‌دهد:

- صدور certificate
- انجام rotation certificate
- احراز هویت سرویس‌ها
- و encryption

بنابراین developer نیاز نیست mTLS را دستی پیاده کند.

---

# تفاوت TLS و mTLS

TLS:

```
Client → verify Server
Server → trust any client
```

mTLS:

```
Client → verify Server
Server → verify Client
```

---

# جمع‌بندی

درواقع mTLS نوعی TLS است که در آن:

- هر دو طرف ارتباط certificate دارند
- هر دو طرف یکدیگر را authenticate می‌کنند
- ارتباط کاملاً encrypted است

به همین دلیل در:

- Microservices
- Service Mesh
- Zero Trust
- Internal API communication

بسیار رایج است.
