درواقع **Repository Pattern** و **Unit of Work** معمولاً با هم استفاده می‌شوند ولی نقش‌های متفاوتی دارند.

### Repository Pattern

الگوی Repository یک **لایه انتزاعی برای دسترسی به داده‌ها** است.

به جای اینکه کد Business Logic مستقیم با دیتابیس یا ORM کار کند، با Repository کار می‌کند.

وظیفه‌ها:

- مخفی کردن جزئیات persistence
- ارائه متدهای CRUD
- ساده کردن تست و mock کردن

مثال ساده:
```csharp

interface IUserRepository
{
    User GetById(int id);
    void Add(User user);
    void Remove(User user);
}

```
در این حالت Business Logic فقط با `IUserRepository` کار می‌کند و نمی‌داند داده از SQL، API یا Memory می‌آید.

---
### Unit of Work

درواقع Unit of Work مسئول **مدیریت یک transaction و هماهنگ کردن چند repository** است.

وظیفه‌ها:

- جمع کردن چند تغییر روی entityها
- انجام commit کردن همه تغییرات در یک transaction
- و rollback در صورت خطا

مثال ساده:
```csharp

interface IUnitOfWork
{
    IUserRepository Users { get; }
    IOrderRepository Orders { get; }

    void Commit();
}

```
استفاده:
```csharp

var user = unitOfWork.Users.GetById(1);
user.Name = "Ali";

unitOfWork.Commit();

```
اینجا تمام تغییرات با یک commit ذخیره می‌شوند.

---

### تفاوت اصلی

**Repository**

- تمرکز روی **دسترسی به یک نوع داده یا Aggregate**
- abstraction برای query و CRUD
- هر repository معمولاً برای یک entity

**Unit of Work**

- تمرکز روی **مدیریت transaction**
- هماهنگ کردن چند repository
- commit یا rollback همه تغییرات با هم

---

### رابطه آن‌ها

در معماری‌های معمول:

- Repository → عملیات روی entity
- Unit of Work → مدیریت transaction بین چند repository

یعنی:
```markdown

Service
   ↓
UnitOfWork
   ↓
Repositories
   ↓
Database

```
