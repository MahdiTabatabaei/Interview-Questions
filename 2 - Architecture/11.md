Clean:

- حلقه‌های متحدالمرکز
- ساختار Use Case در مرکز است

Hexagonal:

- تمرکز بر Ports (Interfaces) و Adapters
- ورودی/خروجی = Ports
- پیاده‌سازی = Adapters
---

تفاوت اصلی:

معماری Hexagonal روی **مرز بین دنیای داخل و خارج** تمرکز دارد

معماری Clean روی **سطح اهمیت لایه‌ها**

---
نکته **Use Case یک “موجودیت (Entity)” نیست.**

در Clean Architecture:

- تعریف **Entities** = مدل‌های دامنه (Domain Models)
- مفهوم **Use Cases** = منطق کاربردی سیستم (Application Business Rules)

بنابراین Use Case خودش یک **لایه یا بخش از لایه Application** است، نه یک Entity.

---

بهتر است بدانیم :

- ساختار **Use Case در Clean Architecture در یک لایه جدا از Entities قرار دارد.**

یا

- ساختار **Use Cases در لایه Application قرار می‌گیرند و از Entities استفاده می‌کنند.**

---

## ساختار واقعی Clean Architecture

معمولاً به این شکل است:
```markdown

Presentation
    ↓
Application (Use Cases)
    ↓
Domain (Entities)
    ↓
Infrastructure

```
یعنی:

- **Entities** → قوانین اصلی دامنه
- **Use Cases** → سناریوهای استفاده از سیستم
- **Presentation** → API / UI
- **Infrastructure** → DB / Email / External services

---

## مثال #C

### Entity
```csharp

public class Order
{
    public Guid Id { get; private set; }
    public decimal Total { get; private set; }

    public void Pay(decimal amount)
    {
        if(amount < Total)
            throw new Exception("Payment not enough");
    }
}

```
---

### Use Case
```csharp

public class PayOrderUseCase
{
    private readonly IOrderRepository _repo;

    public PayOrderUseCase(IOrderRepository repo)
    {
        _repo = repo;
    }

    public void Execute(Guid orderId, decimal amount)
    {
        var order = _repo.Get(orderId);
        order.Pay(amount);
        _repo.Save(order);
    }
}

```
در اینجا:

- `Order` → Entity
- `PayOrderUseCase` → Use Case در لایه Application

✅ جمع‌بندی:

جمله بهتر:

- ❌ «موجودیت Use Case لایه جداگانه دارد»
- ✅ ساختار «Use Case در Clean Architecture در یک لایه جدا از Entities قرار دارد»

---

معماری **Clean Architecture** و **Hexagonal (Ports & Adapters)** خیلی شبیه هم هستند و تفاوتشان در **زاویه نگاه و اصطلاحات** است، نه در هدف پایه‌ای.  
هر دو دنبال **تفکیک وابستگی‌ها و استقلال business logic از لایه‌های بیرونی** هستند.

---

## 🧱 هدف مشترک هر دو

- جدا کردن **هسته (Core/Domain)** از **زیرساخت (Infrastructure)**  
- جلوگیری از وابستگی مستقیم به Frameworkها، دیتابیس‌ها یا UI  
- اعمال «**Dependency Inversion Principle**»  
- معماری‌ای که باعث **تست‌پذیری بالا**، **تغییرپذیری آسان** و **استقلال از تکنولوژی‌ها** می‌شود.

---

## ⚙️ تفاوت در زاویه‌ی نگاه

| ویژگی | **Clean Architecture** | **Hexagonal Architecture (Ports & Adapters)** |
|:--|:--|:--|
| **دیدگاه طراح** | ساختار لایه‌ای و درونی (دایره‌ای) | تعامل از طریق پورت‌ها و آداپتورها |
| **نام‌گذاری تمرکز اصلی** | Domain, Application, Infrastructure, UI | Core, Ports (Interfaces), Adapters (Implementations) |
| **نحوه‌ی وابستگی** | وابستگی‌ها فقط به سمت داخل (Domain) | هسته از بیرون مجزا است، بیرون از طریق پورت‌ها متصل می‌شود |
| **مفاهیم کلیدی** | Use Cases, Entities, Boundaries | Ports (interfaces), Adapters (implementations) |
| **نمودار ذهنی** | دایره‌های هم‌مرکز | چندضلعی (Hexagon) با ورودی و خروجی‌ها |
| **معماری نمونه در .NET** | `Domain`, `Application`, `Infrastructure`, `API` | `Core`, `Ports`, `Adapters`, `Drivers` |
| **ارتباط با Framework** | Framework در بیرونی‌ترین لایه | Frameworkها آداپتورهایی هستند به Core |

---

## 🔄 هر دو در اصل یک چیز می‌گویند با دو استعاره متفاوت

- در **Clean Architecture:** می‌گوید *«وابستگی‌ها همیشه به سمت داخل باشند.»*  
  (دایره‌ها از بیرون به درون)

- در **Hexagonal Architecture:** می‌گوید *«Core از طریق پورت‌ها با بیرون صحبت می‌کند و آداپتورها بین آنها پل می‌زنند.»*  
  (شکل شش‌ضلعی با ورودی و خروجی)

---

## 💡 تصویر ذهنی

### 🔸 Clean Architecture (دایره‌ای)
```
┌──────────────────────────────┐
│          UI / API            │
├──────────────────────────────┤
│       Infrastructure         │
├──────────────────────────────┤
│         Application          │
├──────────────────────────────┤
│           Domain             │
└──────────────────────────────┘
```

→ وابستگی‌ها فقط به سمت داخل (Domain)

---

### 🔸 Hexagonal (Ports & Adapters)
```
         +----------------------+
   → UI  |                      |  DB →
         |      Business        |
   ← API |       Logic          |  MessageQueue ←
         +----------------------+
         | In Ports / Out Ports |
         |   Adapters map them  |
         +----------------------+
```

→ آداپتورها (Adapters) بیرونی هستند،  
→ پورت‌ها (Ports = Interfaces) نقطه تماس بین بیرون و هسته‌اند.

---

## 🧩 خلاصه ساده:

- در **Clean Architecture** = مدل مدرن‌تر و سیستماتیک‌تر که ایده Hexagonal را با مفهوم “Use Case” و نام‌گذاری مشخص‌تر ترکیب کرده است.  
- در **Hexagonal Architecture** = مدل اصلی و فلسفی‌تر (Alistair Cockburn 2005) که درباره تعاملات ورودی/خروجی سیستم صحبت می‌کند.  
- در عمل، **Clean Architecture ≈ Hexagonal + Dependency Rule + لایه Application قوی‌تر**

---

## 🔍 در پروژه‌های .NET

به طور عملی:
```text
Clean Architecture
 ├── MyApp.Domain
 ├── MyApp.Application
 ├── MyApp.Infrastructure
 └── MyApp.API
```
در مقابل (در مفهوم Hexagonal)
```text
Hexagonal Architecture
 ├── Core (Domain + Application Logic)
 ├── Ports (Interfaces)
 ├── Adapters (Implementations)
 ├── API (Inbound Adapter)
 └── Infrastructure (Outbound Adapters)
```
