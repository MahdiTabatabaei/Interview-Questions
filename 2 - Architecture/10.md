معماری Clean Architecture می‌گوید:

حرکت **Dependency باید فقط به مرکز یعنی Domain باشد.**

ساختار لایه‌ها:

- Entities (Core Domain)
- Use Cases
- Interface Adapters
- Frameworks & Drivers

مزیت:

- تست‌پذیری بالا
- استقلال از دیتابیس، UI، Framework

مثال C#:
```csharp

public class PlaceOrder : IUseCase
{
    private readonly IOrderRepository _repo;
    public PlaceOrder(IOrderRepository repo) => _repo = repo;
    public void Execute(Order order) => _repo.Add(order);
}

```

---
برای **Clean Architecture** در .NET و ویژوال استودیو، تصویر ذهنی اصلی این است که **هسته برنامه در مرکز قرار دارد و وابستگی‌ها فقط به سمت داخل می‌روند**.

## تصویر ذهنی Clean Architecture

```
+--------------------------------------+
|        Presentation / UI             |
|  (Web API, MVC, Blazor, Controllers) |
+--------------------------------------+
|           Infrastructure             |
|   (Database, EF Core, External APIs) |
+--------------------------------------+
|           Application Layer          |
|     (Use Cases, Services, DTOs)      |
+--------------------------------------+
|            Domain Layer              |
|   (Entities, Business Rules)         |
+--------------------------------------+
```

اما تصویر کلاسیک Clean Architecture بیشتر **دایره‌ای** است:

```
        ┌───────────────────────┐
        │     Presentation      │
        │   (Controllers/API)   │
        └──────────┬────────────┘
                   │
        ┌──────────▼───────────┐
        │     Infrastructure   │
        │  (DB, File, Email)   │
        └──────────┬───────────┘
                   │
        ┌──────────▼───────────┐
        │      Application     │
        │   (UseCases/Logic)   │
        └──────────┬───────────┘
                   │
        ┌──────────▼───────────┐
        │        Domain        │
        │ (Entities/Rules)     │
        └──────────────────────┘
```

اصل مهم:

```
Dependency Rule
وابستگی‌ها فقط به سمت داخل می‌روند
```

یعنی:

```
UI → Application → Domain
Infrastructure → Application → Domain
```

درواقع Domain **هیچ وابستگی به بیرون ندارد**.

```

│
├── MyApp.Application
│   ├── UseCases
│   ├── Services
│   └── DTOs
│
├── MyApp.Infrastructure
│   ├── Persistence
│   ├── Repositories
│   └── ExternalServices

└── MyApp.API
    ├── Controllers
    └── Program.cs
```

# تفاوت ذهنی با Layered

در **Layered** معمولاً وابستگی‌ها این شکلی‌اند:

```
UI → Business → Data
```

اما در **Clean Architecture**:

```
UI → Application → Domain
Infrastructure → Application → Domain
```

و **Domain کاملاً مستقل** است.
