

مفهوم **Distributed Tracing** روشی برای **ردیابی مسیر یک درخواست (Request)** در میان چندین سرویس در یک سیستم **Microservices** است.

در معماری Monolith یک درخواست فقط داخل یک برنامه اجرا می‌شود، اما در Microservices یک درخواست ممکن است از چند سرویس عبور کند.

مثلاً:

```
Client → API Gateway → OrderService → PaymentService → InventoryService
```

روش Distributed Tracing کمک می‌کند بفهمیم:

- درخواست از کجا شروع شده
- از چه سرویس‌هایی عبور کرده
- هر سرویس چقدر زمان مصرف کرده
- خطا در کدام سرویس رخ داده

---

## مشکل بدون Distributed Tracing

فرض کنید کاربر سفارش ثبت می‌کند ولی درخواست **کند** است.

سیستم شما شامل این سرویس‌هاست:

```
Order Service
Payment Service
Inventory Service
Shipping Service
```

اگر فقط **Log** داشته باشید پیدا کردن مشکل سخت می‌شود چون:

- لاگ‌ها در چند سرویس پخش شده‌اند
- نمی‌دانیم کدام لاگ مربوط به همان درخواست است

الگوی Distributed Tracing برای هر درخواست یک **TraceId** ایجاد می‌کند تا بتوان مسیر کامل آن را دنبال کرد.

---

## مفاهیم اصلی

### 1️⃣ Trace

کل مسیر یک درخواست در سیستم.

مثال:

```
Trace
 ├─ OrderService
 ├─ PaymentService
 └─ InventoryService
```

---

### 2️⃣ Span

هر عملیات داخل یک Trace یک **Span** است.

مثال:

```
Trace
 ├─ Span: OrderService (120ms)
 ├─ Span: PaymentService (90ms)
 └─ Span: InventoryService (20ms)
```

---

### 3️⃣ TraceId

شناسه یکتا برای یک درخواست.

مثال:

```
TraceId: 8f3d91ab21
```

این ID بین سرویس‌ها منتقل می‌شود.

---

# مثال در C# با OpenTelemetry

### نصب پکیج‌ها

```
dotnet add package OpenTelemetry.Extensions.Hosting
dotnet add package OpenTelemetry.Exporter.Jaeger
dotnet add package OpenTelemetry.Instrumentation.AspNetCore
```

---

### Program.cs

```csharp
using OpenTelemetry.Trace;

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddOpenTelemetry()
    .WithTracing(tracer =>
    {
        tracer
            .AddAspNetCoreInstrumentation()
            .AddHttpClientInstrumentation()
            .AddJaegerExporter();
    });

var app = builder.Build();

app.MapGet("/order", async (HttpClient httpClient) =>
{
    await httpClient.GetAsync("http://payment-service/pay");
    return "Order Completed";
});

app.Run();
```

# چرا Distributed Tracing مهم است؟

دلایل اصلی:

### 1️⃣ پیدا کردن Bottleneck

می‌فهمیم کدام سرویس کند است.

### 2️⃣ کمک به Debug کردن خطا

اگر یک سرویس خطا بدهد سریع مشخص می‌شود.

### 3️⃣ درک جریان درخواست

می‌فهمیم درخواست دقیقاً از چه مسیرهایی عبور کرده.

### 4️⃣ مانیتورینگ سیستم‌های پیچیده

در سیستم‌هایی با ده‌ها یا صدها سرویس ضروری است.

# ✅ مرحله 2: ساخت PaymentService

### نصب پکیج‌ها

```bash
dotnet add package OpenTelemetry.Extensions.Hosting
dotnet add package OpenTelemetry.Exporter.OpenTelemetryProtocol
dotnet add package OpenTelemetry.Instrumentation.AspNetCore
```

---

### Program.cs (PaymentService)

```csharp
using OpenTelemetry.Resources;
using OpenTelemetry.Trace;

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddOpenTelemetry()
    .ConfigureResource(resource => resource.AddService("PaymentService"))
    .WithTracing(tracing =>
    {
        tracing
            .AddAspNetCoreInstrumentation()
            .AddHttpClientInstrumentation()
            .AddOtlpExporter(opt =>
            {
                opt.Endpoint = new Uri("http://localhost:4317");
            });
    });

var app = builder.Build();

app.MapGet("/pay", async () =>
{
    await Task.Delay(500); // simulate work
    return Results.Ok("Payment Successful");
});

app.Run("http://localhost:5002");
```

# ✅ مرحله 3: ساخت OrderService

### نصب همان پکیج‌ها

```bash
dotnet add package OpenTelemetry.Extensions.Hosting
dotnet add package OpenTelemetry.Exporter.OpenTelemetryProtocol
dotnet add package OpenTelemetry.Instrumentation.AspNetCore
dotnet add package OpenTelemetry.Instrumentation.Http
```

---

### Program.cs (OrderService)

```csharp
using OpenTelemetry.Resources;
using OpenTelemetry.Trace;

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddHttpClient();

builder.Services.AddOpenTelemetry()
    .ConfigureResource(resource => resource.AddService("OrderService"))
    .WithTracing(tracing =>
    {
        tracing
            .AddAspNetCoreInstrumentation()
            .AddHttpClientInstrumentation()
            .AddOtlpExporter(opt =>
            {
                opt.Endpoint = new Uri("http://localhost:4317");
            });
    });

var app = builder.Build();

app.MapGet("/order", async (IHttpClientFactory factory) =>
{
    var client = factory.CreateClient();
    var response = await client.GetAsync("http://localhost:5002/pay");

    return Results.Ok("Order Completed");
});

app.Run("http://localhost:5001");
```

می‌بینید که:

- زمان دقیق هر عملیات مشخص است

# 🔥 اگر خطا رخ دهد؟

مثلاً PaymentService خطا بدهد:

```csharp
app.MapGet("/pay", () =>
{
    throw new Exception("Payment Failed");
});
```

در Jaeger خواهید دید:

```
Span Status: ERROR
Exception: Payment Failed
```

خیلی سریع می‌توان فهمید مشکل از کجاست.

# ✅ اتفاق مهمی که پشت صحنه می‌افتد

OpenTelemetry:

1. یک `TraceId` می‌سازد
2. آن را در header استاندارد W3C منتقل می‌کند:

```
traceparent: 00-4af892d...
```

3. سرویس بعدی همان Trace را ادامه می‌دهد
