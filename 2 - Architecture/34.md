Message Queue:

- پیام برای یک مصرف‌کننده
- ویژگی Point‑to‑Point
- تضمین تحویل پیام

Event Bus:

- پیام برای چند مصرف‌کننده
- الگوی Pub/Sub
- و Eventها Broadcast می‌شوند
---

این دو تا اصطلاح **خیلی وقت‌ها قاطی هم استفاده می‌شوند**، ولی از نظر مفهومی و معماری تفاوت مهمی دارند.  
بیایم دقیق، مرحله‌به‌مرحله و با مثال ملموس جلو برویم.

---

# تعریف خیلی کوتاه

| مفهوم | خلاصه |
|------|-------|
| **Message Queue** | صف پیام برای **ارتباط نقطه‌به‌نقطه** و انجام یک کار |
| **Event Bus** | کانال انتشار رویداد برای **اطلاع‌رسانی به چند مصرف‌کننده** |

---

# تعریف Message Queue چیست؟

درواقع **Message Queue** یعنی:

> یک پیام فرستاده می‌شود تا **یک مصرف‌کننده خاص** آن را پردازش کند.

ویژگی‌های اصلی:

- ✅ بصورت Point‑to‑Point
- ✅ هر پیام فقط توسط **یک Consumer** مصرف می‌شود
- ✅ معمولاً برای **Command / Task**
- ✅ ترتیب Ordering مهم است
- ✅ تضمین پردازش (At‑least‑once / Exactly‑once)

### مثال ذهنی

«لطفاً این سفارش را ثبت کن»

---

## مثال واقعی

سیستم سفارش:

- Order API
- Payment Worker

جریان:

```
Order API → Queue → Payment Worker
```

پیام:

```json
{
  "command": "ChargePayment",
  "orderId": 123,
  "amount": 500000
}
```

✅ فقط **یک Payment Worker** این پیام را می‌گیرد.  
❌ بقیه نباید ببینند.

### ابزارهای رایج Message Queue

- RabbitMQ (Queue mode)
- Azure Service Bus Queue
- Amazon SQS
- Redis Queue

---

# تعریف Event Bus چیست؟

درواقع **Event Bus** یعنی:

> چیزی اتفاق افتاده و هر کسی علاقه‌مند است، می‌تواند واکنش نشان دهد.

ویژگی‌های اصلی:

- ✅ الگوی Publish‑Subscribe
- ✅ چند Consumer همزمان
- ✅ فرستنده، مصرف‌کننده‌ها را نمی‌شناسد
- ✅ برای **Event / Fact**
- ✅ برقراری Loose Coupling

### مثال ذهنی

«سفارش ثبت شد»

---

## مثال واقعی

وقتی Order ساخته شد:

```
Order Service
     ↓ publish
  Event Bus
     ↓        ↓        ↓
Email    Inventory   Analytics
Service   Service      Service
```

رویداد:

```json
{
  "event": "OrderCreated",
  "orderId": 123,
  "userId": 45,
  "totalPrice": 500000
}
```

✅ چند سرویس می‌توانند واکنش نشان دهند  
✅ بدون تغییر Order Service

### ابزارهای رایج Event Bus

- Kafka
- Azure Event Grid
- RabbitMQ (Topic / Fanout)
- NATS
- Google Pub/Sub

---

# تفاوت مفهومی (خیلی مهم)

| جنبه | Message Queue | Event Bus |
|-----|---------------|-----------|
| هدف | انجام کار | اطلاع از وقوع اتفاق |
| پیام | Command | Event |
| مصرف‌کننده | یکی | چندتا |
| Coupling | نسبتاً بیشتر | کمتر |
| Reprocessing | معمولاً سخت‌تر | معمولاً آسان‌تر |
| Ordering | مهم | معمولاً مهم نیست |
| مثال جمله | «این کار را انجام بده» | «این اتفاق افتاد» |

---

# تفاوت Command vs Event (کلید فهم تفاوت)

### Command

- نوع [[Imperative]]
- انتظار دارد کاری انجام شود
- شکست مهم است

```
ChargePayment
ShipOrder
CreateInvoice
```

### Event
- نوع [[Past tense]]
- فقط اطلاع می‌دهد
- کسی مجبور به واکنش نیست

```
PaymentCharged
OrderShipped
InvoiceCreated
```

# در معماری Microservices

## چه زمانی Message Queue؟

✅ وقتی:

- یک کار باید دقیقاً یک بار انجام شود
- پردازش سنگین است
- می‌خواهی [[back‑pressure]] داشته باشی
- می‌خواهی [[Worker Scale]] شود

مثال‌ها:

- ارسال ایمیل
- پردازش پرداخت
- تبدیل فایل
- پردازش گزارش

---

## چه زمانی Event Bus؟

✅ وقتی:

- چند سرویس باید واکنش نشان دهند
- نمی‌خواهی سرویس‌ها به هم وابسته شوند
- می‌خواهی سیستم قابل توسعه باشد
- معماری Event‑Driven Architecture داری

مثال‌ها:

- OrderCreated
- UserRegistered
- PaymentCompleted

---

# نکتهٔ خیلی مهم (دام رایج)

> الگوی **Event Bus جای Message Queue را نمی‌گیرد و بالعکس**

اشتباه رایج:

❌ استفاده از Event برای انجام Command  
❌ استفاده از Queue برای انتشار تغییرات دامنه

---

# RabbitMQ چرا هر دو را دارد؟

ابزار RabbitMQ مثال خوبی است:

- Queue + Direct Exchange → Message Queue
- Topic / Fanout Exchange → Event Bus

پس ابزار یکی است، **الگوی استفاده فرق می‌کند**.

---

# نمونه ترکیبی (واقعی و حرفه‌ای)

سناریو Order:

1. ابتدا User سفارش ثبت می‌کند
2. سپس Order Service:
   - ✅ مقدار Order را ذخیره می‌کند
   - ✅ و در نهایت Event منتشر می‌کند

```text
OrderCreated (Event Bus)
```

3. سرویس Payment Service:
   - گوش می‌دهد
   - و Command می‌فرستد به Queue خودش

```text
ChargePayment (Message Queue)
```

---

# جمع‌بندی خیلی کوتاه

> **Message Queue = انجام کار**  
> **Event Bus = اطلاع از وقوع اتفاق**
