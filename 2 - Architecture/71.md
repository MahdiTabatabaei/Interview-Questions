درواقع CQRS و Event Sourcing دو الگوی جدا هستند، اما **خیلی وقت‌ها با هم استفاده می‌شوند** چون به‌صورت طبیعی همدیگر را تکمیل می‌کنند. مهم است بدانیم:

- **CQRS بدون Event Sourcing ممکن است**
- **Event Sourcing بدون CQRS هم ممکن است**
- ولی ترکیبشان در سیستم‌های event‑driven بسیار رایج است.

اجازه بده رابطه‌شان را مرحله‌ای توضیح بدهم.

---

# 1. تعریف CQRS چیست؟

مفهوم CQRS یعنی **جدا کردن مسیر Command و Query**.

یعنی:

- **Command side** → تغییر state
- **Query side** → خواندن داده

مثال:

```text
Command:
CreateCity
DeleteCity
UpdateCity
```

```text
Query:
GetCity
GetCities
SearchCities
```

در CQRS معمولاً:

- مدل write ساده و domain-driven است
- مدل read برای performance و query بهینه می‌شود

مثلاً:

Write DB

```
City
```

Read DB

```
CityView
CityWithPopulation
CitySearchIndex
```

---

# 2. تعریف Event Sourcing چیست؟

در Event Sourcing ما **state نهایی را ذخیره نمی‌کنیم**.

بلکه **تمام eventهایی که state را ساخته‌اند ذخیره می‌کنیم**.

به جای:

```
City
id = 10
name = Tehran
population = 9M
```

ما eventها را داریم:

```
CityCreated
CityNameChanged
CityPopulationUpdated
```

و state با replay این eventها ساخته می‌شود.

مثال:

```text
CityCreated(id=10, name=Tehran)
PopulationUpdated(id=10, population=8M)
PopulationUpdated(id=10, population=9M)
```

---

# 3. ارتباط طبیعی CQRS و Event Sourcing

وقتی Event Sourcing داریم:

- دستور command باعث تولید event می‌شود
- مقدار eventها ذخیره می‌شوند
- و read model از eventها ساخته می‌شود

پس معماری می‌شود:

```
Command -> Aggregate
           |
           v
        Events
           |
           v
      Event Store
           |
           v
    Event Handlers
           |
           v
      Read Models
```

---

# 4. جریان کامل در CQRS + Event Sourcing

فرض کنیم:

```
CreateCity
```

## مرحله 1 — Command

کاربر:

```
CreateCityCommand
```

می‌رود به:

```
City Aggregate
```

---

## مرحله 2 — Domain Logic

در این حالت Aggregate بررسی می‌کند:

- آیا city وجود دارد؟
- آیا valid است؟

اگر ok:

```
CityCreated Event
```

---

## مرحله 3 — ذخیره event

مقدرا event در Event Store ذخیره می‌شود:

```
EventStore

CityCreated
CityPopulationUpdated
CityRenamed
```

---

## مرحله 4 — publish event

مقدار event منتشر می‌شود.

---

## مرحله 5 — ساخت Read Model

یک handler می‌گوید:

```
on CityCreated
insert into CityView
```

یا

```
on PopulationUpdated
update CityView
```

---

# 5. چرا CQRS با Event Sourcing خوب کار می‌کند؟

چون Event Sourcing **خودش read model ندارد**.

اگر فقط event داشته باشیم، برای query باید:

```
replay thousands of events
```

که کند است.

پس read model ساخته می‌شود.

این همان **CQRS read side** است.

# 6. معماری کامل

معمولاً شبیه این است:

```
           +-------------+
           |   Command   |
           +-------------+
                   |
                   v
            +-------------+
            |  Aggregate  |
            +-------------+
                   |
                   v
             +-----------+
             |  Events   |
             +-----------+
                   |
                   v
            +-------------+
            | Event Store |
            +-------------+

          |                 |
          v                 v

```

# 7. مزایای ترکیب CQRS + Event Sourcing

### 1️⃣ داشتن audit کامل

تمام تاریخچه وجود دارد.

```
Who changed city name?
```

کاملاً مشخص است.

---

### 2️⃣ قابلیت replay

می‌توانید state را بازسازی کنید.

مثلاً:

```
rebuild read model
```

---

### 3️⃣ داشتن integration آسان

معماری eventها برای microservices عالی هستند.

---

### 4️⃣ قابلیت debugging بهتر

می‌توان sequence را دید.

---

# 8. مشکلات این ترکیب

این معماری **پیچیده است**.

مشکلات:

### داشتن complexity بالا

بیش از حد برای سیستم‌های ساده.

---

### مشکل schema evolution

اگر event structure تغییر کند مشکل ایجاد می‌شود.

---

### قابلیت eventual consistency

درواقع read model کمی عقب می‌افتد.

---

### فرایند debugging سخت‌تر

مقدار state مستقیم در DB نیست.

# 9. مثال ساده #C

Command

```csharp
public class CreateCityCommand
{
    public Guid Id { get; set; }
    public string Name { get; set; }
}
```

Aggregate

```csharp
public void Handle(CreateCityCommand cmd)
{
    Apply(new CityCreated(cmd.Id, cmd.Name));
}
```

Event

```csharp
public record CityCreated(Guid Id, string Name);
```

Projection

```csharp
public void Handle(CityCreated e)
{
    db.Cities.Add(new CityView
    {
        Id = e.Id,
        Name = e.Name
    });
}
```

```

                          |
                          v
                    Event Handlers
                          |
                          v
                       Read Models

                          v
```
