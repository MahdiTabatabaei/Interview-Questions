برای حل مشکل **عدم هماهنگی دیتابیس و پیام‌ها** در Microservices استفاده می‌شود.

مشکل:

- تراکنش DB موفق
- ارسال Event شکست → ناهمگامی

راه‌حل Outbox:

- هر Event را داخل جدول Outbox کنار تغییرات DB ذخیره می‌کنیم (در یک تراکنش)
- یک Background Worker Outbox را خوانده و Event را به Kafka/SQS ارسال می‌کند.

نتیجه:

- ثبات Consistency تضمین می‌شود
---

درواقع **Outbox Pattern** یعنی:  

وقتی یک سرویس یک **تغییر در دیتابیس** انجام می‌دهد و هم‌زمان باید **یک پیام (event/message)** به بیرون بفرستد، ابتدا پیام را **در همان دیتابیس خود سرویس** ذخیره می‌کند (در جدول Outbox)، نه اینکه مستقیم بفرستد.

بعداً یک **پردازشگر پس‌زمینه** پیام‌ها را از Outbox خوانده و به Message Broker (RabbitMQ/ Kafka / …) ارسال می‌کند.

این الگو تضمین می‌کند که:

- **ایونت هرگز گم نشود**
- **دوباره‌کاری (duplicate)** کنترل شود
- **تراکنش دیتابیس + ثبت پیام** اتمیک (Atomic) باشد

---

# چرا Outbox لازم است؟

مشکل کلاسیک:

```text
1) سفارش در دیتابیس ثبت شد ✓
2) پیام OrderCreated به RabbitMQ ارسال شد ✗

یا برعکس!
```

اگر وسط کار سرویس crash کند چه؟  
الگوی Outbox این مشکل را کامل حل می‌کند.

---

# معماری Outbox (خلاصه)

1. سرویس یک تغییر در دیتابیس انجام می‌دهد  
2. **در همان تراکنش** پیام را داخل جدول Outbox ذخیره می‌کند  
3. یک Job/BackgroundWorker  
   - پیام‌های Outbox را برمی‌دارد  
   - به RabbitMQ/Kafka می‌فرستد  
   - پیام را processed علامت می‌زند

---

# ساختار جدول Outbox (مثال)

```sql
CREATE TABLE OutboxMessages(
    Id UNIQUEIDENTIFIER PRIMARY KEY,
    OccurredOn DATETIME2,
    Type VARCHAR(250),
    Payload NVARCHAR(MAX),
    Processed BIT DEFAULT 0,
    ProcessedOn DATETIME2 NULL
);
```

# مثال کامل با C# و EF Core

### 1) ثبت پیام و ذخیره در Outbox (اتمیک با دیتابیس)

```csharp
public async Task CreateOrder(CreateOrderCommand command)
{
    var order = new Order(command.ProductId, command.UserId);
    _dbContext.Orders.Add(order);

    // پیام رو به عنوان Outbox ذخیره می‌کنیم
    var outboxMessage = new OutboxMessage(
        Guid.NewGuid(),
        DateTime.UtcNow,
        "OrderCreated",
        JsonSerializer.Serialize(new { order.Id, order.UserId })
    );

    _dbContext.OutboxMessages.Add(outboxMessage);

    // هر دو اتمیک و در یک تراکنش ذخیره می‌شوند
    await _dbContext.SaveChangesAsync();
}
```

### 2) مدل OutboxMessage

```csharp
public class OutboxMessage
{
    public Guid Id { get; private set; }
    public DateTime OccurredOn { get; private set; }
    public string Type { get; private set; }
    public string Payload { get; private set; }
    public bool Processed { get; set; }
    public DateTime? ProcessedOn { get; set; }

    public OutboxMessage(Guid id, DateTime occurredOn, string type, string payload)
    {
        Id = id;
        OccurredOn = occurredOn;
        Type = type;
        Payload = payload;
    }
}
```

### 3) پردازش BackgroundService که Outbox را process می‌کند

```csharp
public class OutboxProcessor : BackgroundService
{
    private readonly IServiceScopeFactory _scopeFactory;
    private readonly IRabbitMqPublisher _publisher;

    public OutboxProcessor(IServiceScopeFactory scopeFactory,
                           IRabbitMqPublisher publisher)
    {
        _scopeFactory = scopeFactory;
        _publisher = publisher;
    }

    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        while (!stoppingToken.IsCancellationRequested)
        {
            using var scope = _scopeFactory.CreateScope();
            var db = scope.ServiceProvider.GetRequiredService<AppDbContext>();

            var messages = await db.OutboxMessages
                                   .Where(x => !x.Processed)
                                   .OrderBy(x => x.OccurredOn)
                                   .Take(50)
                                   .ToListAsync(stoppingToken);

            foreach (var msg in messages)
            {
                await _publisher.PublishAsync(msg.Type, msg.Payload);

                msg.Processed = true;
                msg.ProcessedOn = DateTime.UtcNow;
            }

            await db.SaveChangesAsync(stoppingToken);

            await Task.Delay(1000, stoppingToken);
        }
    }
}
```

---

### 4) ارسال Publisher ساده به RabbitMQ

```csharp
public class RabbitMqPublisher : IRabbitMqPublisher
{
    private readonly IConnection _connection;

    public RabbitMqPublisher(IConnection connection)
    {
        _connection = connection;
    }

    public Task PublishAsync(string eventType, string json)
    {
        using var channel = _connection.CreateModel();

        channel.ExchangeDeclare("events", "topic", durable: true);

        var body = Encoding.UTF8.GetBytes(json);

        channel.BasicPublish(
            exchange: "events",
            routingKey: eventType,
            basicProperties: null,
            body: body
        );

        return Task.CompletedTask;
    }
}
```

# نتیجهٔ Outbox Pattern

با این الگو:

- دیتابیس و پیام‌ها **Atomic** می‌شوند  
- هیچ پیام event گم نمی‌شود  
- عمل retry طبیعی انجام می‌شود  
- درواقع microservice می‌تواند crash کند بدون از دست دادن event  
- داده‌ها eventual consistent باقی می‌مانند
