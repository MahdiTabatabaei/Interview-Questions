# 1) مدل MVC چیست؟

درواقع MVC یعنی:

- **Model**: داده و منطق اصلی
- **View**: رابط کاربری
- **Controller**: هماهنگ‌کننده بین Model و View

نقش‌ها:

- View داده را از Controller می‌گیرد.
- Controller ورودی کاربر را دریافت می‌کند و Model را تغییر می‌دهد.
- Model داده را نگه می‌دارد.

ویژگی‌ها:

- Controller مرکز کنترل است.
- View وابستگی مستقیم به Model دارد.

مناسب برای:

- Web frameworks مثل ASP.NET MVC، Rails، Laravel
- اپلیکیشن‌هایی که تعامل UI ساده دارند

نقاط ضعف:

- در پروژه‌های بزرگ View بیش از حد به Controller وابسته می‌شود.
- تست‌پذیری معمولی است.

# 2) مدل MVP چیست؟

درواقع MVP یعنی:

- **Model**
- **View**
- **Presenter**

ویژگی اصلی:

- **Presenter تمام منطق UI را دارد**
- View **خیلی ساده** است و فقط چیزی را نمایش می‌دهد.

ارتباط‌ها:

- View هیچ منطقی ندارد و فقط eventها را به Presenter پاس می‌دهد.
- Presenter داده را پردازش کرده و نتیجه را به View برمی‌گرداند.

مناسب برای:

- اپلیکیشن‌های ویندوزی قدیمی
- WinForms
- Android (قبل از MVVM)

مزایا:

- تست‌پذیری بسیار بهتر از MVC
- View کاملاً از منطق جداست

عیب:

- حجم زیاد کد در Presenter
- View و Presenter معمولاً one-to-one هستند (زیاد می‌شوند)

---

# 3) مدل MVVM چیست؟

درواقع MVVM یعنی:

- **Model**
- **View**
- **ViewModel**

ویژگی‌های کلیدی:

- ViewModel شامل منطق UI است **اما** View از طریق:
    - **Data Binding**
    - **Commands**

به صورت خودکار به ViewModel وصل می‌شود.

ViewModel هیچ وابستگی به View ندارد.

**این معماری به شدت به قابلیت Binding نیاز دارد.**

مناسب برای:

- WPF
- Xamarin / MAUI
- Angular / Vue
- SwiftUI / Jetpack Compose
- هر UI مدرن Reactive

مزایا:

- کمترین وابستگی بین View و ViewModel
- تست‌پذیری بسیار بالا
- منطق UI از View جداست

عیب:

- برای UIهای بدون binding پیاده‌سازی سخت می‌شود
- ممکن است ViewModel خیلی بزرگ شود اگر مدیریت نشود

---

# مقایسه خیلی کوتاه

MVC:

- Controller واسطه است
- View → راست‌راست به Model نگاه می‌کند
- مناسب وب

MVP:

- Presenter کنترل کامل دارد
- View کاملاً Passive است
- مناسب اپ‌های UI قدیمی‌تر

MVVM:

- Binding و ViewModel
- کم‌ترین وابستگی و بیشترین تست‌پذیری
- مناسب UIهای reactive و مدرن

---

# یک مثال ساده برای فهم بهتر

فرض کن کاربر روی “Save” کلیک می‌کند:

### MVC:

- Controller رویداد را دریافت می‌کند
- Model را ذخیره می‌کند
- View را آپدیت می‌کند

### MVP:

- View رویداد کلیک را به Presenter می‌دهد
- Presenter Model را ذخیره می‌کند
- Presenter صدا می‌زند: View.showSuccessMessage()

### MVVM:

- Button به Command در ViewModel بایند شده
- ViewModel منطقی اجرا می‌کند
- تغییرات ViewModel به صورت اتوماتیک در View نمایش داده می‌شود (Binding)
