تفاوت اصلی **CQRS** و **CRUD** در نحوه طراحی عملیات خواندن و نوشتن روی داده است.

### CRUD

CRUD مخفف چهار عملیات پایه روی داده است:

- **Create**
- **Read**
- **Update**
- **Delete**

در معماری CRUD:

- معمولاً **یک مدل داده و یک سرویس** برای همه عملیات استفاده می‌شود.
- همان entity و repository برای هم **خواندن** و هم **نوشتن** استفاده می‌شود.

مثال ساده:
```markdown

UserService
 ├── CreateUser
 ├── GetUser
 ├── UpdateUser
 └── DeleteUser

```
همه عملیات روی یک مدل `User` انجام می‌شود.

مزیت:

- ساده
- مناسب سیستم‌های کوچک و متوسط

---

### CQRS (Command Query Responsibility Segregation)

در **CQRS** عملیات **خواندن (Query)** و **نوشتن (Command)** از هم جدا می‌شوند.

اصل CQRS:

- **Command → تغییر داده (Write)**
- **Query → فقط خواندن داده (Read)**

در این معماری معمولاً:

- مدل **Write** با مدل **Read** متفاوت است.
- حتی ممکن است **دو دیتابیس متفاوت** برای read و write وجود داشته باشد.

مثال:
```markdown

Commands
 ├── CreateUserCommand
 └── UpdateUserCommand

Queries
 └── GetUserByIdQuery

```
مدل read ممکن است این‌طور باشد:
```markdown

UserView
{
  id
  fullName
  orderCount
}

```
در حالی که مدل write ممکن است چند entity مختلف داشته باشد.

---

### تفاوت‌های کلیدی

CRUD

- یک مدل برای read و write
- ساده‌تر
- مناسب سیستم‌های کوچک

CQRS

- جداسازی کامل read و write
- مدل‌های متفاوت
- مناسب سیستم‌های بزرگ و high‑scale

---

### یک مثال واقعی

فرض کنید یک **سیستم فروشگاهی بزرگ** دارید.

در CRUD:

- همان جدول `Orders` برای ثبت سفارش و نمایش لیست سفارش‌ها استفاده می‌شود.

در CQRS:

- ثبت سفارش → **Command model**
- نمایش گزارش سفارش‌ها → **Read model optimized برای query**

مثلاً:

- write DB → relational
- read DB → Elasticsearch / Redis

---

✅ خلاصه:

- **CRUD = مدل ساده با عملیات پایه روی یک data model**
- **CQRS = جداسازی کامل read و write برای scalability و performance**
