هدف از جایگزین‌ها:

الگوی Distributed Transaction (مثل 2PC) در Microservices مشکل دارد چون:

- کند است
- باعث Coupling شدید ایجاد می‌کند
- و Availability کم می‌شود

بنابراین روش‌های جایگزین:

### 1) **Saga Pattern**

اجرای یک تراکنش بزرگ از طریق چند مرحله محلی (Local Transaction).

دو مدل:

- مدل **Choreography** (هر سرویس Eventها را گوش می‌دهد)
- مدل **Orchestration** (یک Coordinator مراحل را مدیریت می‌کند)

مثال: سفارش ایجاد شد → موجودی کم شد → پرداخت انجام شد

اگر پرداخت Fail شد → عملیات قبلی جبران می‌شود.

### 2) **Outbox Pattern**

برای هماهنگی DB و Message Broker

ایجاد Transactional + Event Publishing به صورت قابل‌اتکا.

### 3) **Eventual Consistency**

به جای یک تراکنش واحد، سیستم اجازه می‌دهد **بعداً سازگار شود**.

مثال واقعی:

شما سفارش می‌دهید → چند لحظه بعد ایمیل می‌رسد → بعد موجودی به‌روز می‌شود.

### مثال C# (Saga – Choreography)
```csharp

public class OrderPlacedHandler : IEventHandler<OrderPlaced>
{
    public async Task Handle(OrderPlaced evt)
    {
        await _inventoryService.ReduceStock(evt.ProductId, evt.Quantity);
        await _bus.Publish(new StockReduced(evt.OrderId));
    }
}

```
