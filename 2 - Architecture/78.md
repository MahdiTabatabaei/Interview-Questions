تعریف **Correlation ID** یک شناسه یکتا است که برای **ردیابی یک درخواست در کل سیستم** استفاده می‌شود. هدفش این است که بتوانیم تمام لاگ‌ها، عملیات‌ها و سرویس‌هایی که مربوط به یک درخواست هستند را به هم **مرتبط (correlate)** کنیم.

---

# ایده اصلی Correlation ID

فرض کن یک کاربر درخواست ایجاد سفارش می‌فرستد:

```
POST /orders
```

در معماری Microservices این درخواست ممکن است از چند سرویس عبور کند:

```
Client
  ↓
API Gateway
  ↓
OrderService
  ↓
PaymentService
  ↓
InventoryService
```

اگر هر سرویس لاگ خودش را تولید کند، بدون یک شناسه مشترک تشخیص اینکه کدام لاگ‌ها مربوط به همان درخواست هستند بسیار سخت می‌شود.

اینجاست که **Correlation ID** وارد می‌شود.

---

# تعریف Correlation ID چگونه کار می‌کند

در اولین نقطه ورود درخواست (مثلاً API Gateway) یک شناسه ساخته می‌شود:

```
CorrelationId = 7f2a9c1b
```

این شناسه در تمام درخواست‌های بعدی منتقل می‌شود:

```
HTTP Header

X-Correlation-ID: 7f2a9c1b
```

حالا هر سرویس که درخواست را دریافت کند:

- همان CorrelationId را در لاگ‌ها ثبت می‌کند
- هنگام فراخوانی سرویس بعدی آن را منتقل می‌کند

مثال لاگ‌ها:

Gateway

```
[INFO] Request started
CorrelationId=7f2a9c1b
```

OrderService

```
[INFO] Creating order
CorrelationId=7f2a9c1b
```

PaymentService

```
[INFO] Charging card
CorrelationId=7f2a9c1b
```

حالا در Kibana اگر جستجو کنی:

```
CorrelationId:7f2a9c1b
```

همه لاگ‌های آن درخواست دیده می‌شوند.

---

# نقش Correlation ID در Tracing

در سیستم‌های modern tracing مثل **OpenTelemetry / Jaeger** مفاهیم پیشرفته‌تری وجود دارد:

- TraceId
- SpanId

در واقع:

```
Trace
   ├── Span
   ├── Span
   └── Span
```

معمولاً:

```
TraceId ≈ CorrelationId
```

یعنی TraceId همان شناسه‌ای است که درخواست را در کل سیستم دنبال می‌کند.

مثال:

```
TraceId: 4bf92f3577b34da6
```

تمام spanها زیر این TraceId هستند:

```
TraceId 4bf92f3577b34da6
   ├── Gateway span
   ├── OrderService span
   ├── PaymentService span
   └── InventoryService span
```

بنابراین TraceId در Distributed Tracing **نقش Correlation ID را بازی می‌کند**.

---

# تفاوت Correlation ID و Trace ID

در سیستم‌های مدرن این دو تقریباً یک نقش دارند، اما از نظر مفهومی تفاوت کوچکی دارند.

**Correlation ID**

- بیشتر برای **log correlation**
- ممکن است فقط یک شناسه ساده باشد
- معمولاً در header سفارشی مثل:

```
X-Correlation-ID
```

استفاده می‌شود.

---

**Trace ID**

- بخشی از استاندارد **distributed tracing**
- توسط OpenTelemetry تولید می‌شود
- در header استاندارد W3C منتقل می‌شود:

```
traceparent
```

مثال:

```
traceparent: 00-4bf92f3577b34da6-00f067aa0ba902b7-01
```

---

# رابطه Logging و Tracing

در سیستم‌های حرفه‌ای این اتفاق می‌افتد:

```
TraceId
   ↓
در Span ها استفاده می‌شود
   ↓
در Log ها هم ثبت می‌شود
```

یعنی لاگ‌ها چیزی شبیه این می‌شوند:

```
{
  message: "Order created",
  traceId: "4bf92f3577b34da6",
  spanId: "00f067aa0ba902b7",
  service: "OrderService"
}
```

این باعث می‌شود:

- در **Kibana** لاگ را ببینی
- با همان TraceId بروی **Jaeger**
- کل مسیر درخواست را ببینی

---

# جمع‌بندی

تعریف Correlation ID یک شناسه یکتا است که برای **ارتباط دادن عملیات‌های مختلف یک درخواست در چند سرویس** استفاده می‌شود.

در سیستم‌های Microservices:

- برای ارتباط دادن **log ها**
- برای **debug کردن درخواست‌ها**
- برای دنبال کردن مسیر یک درخواست

در سیستم‌های tracing مدرن:

```
TraceId همان نقش CorrelationId را بازی می‌کند
```
