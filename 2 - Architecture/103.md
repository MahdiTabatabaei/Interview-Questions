# 1) موجودیت Entity چیست؟

موجودیت **Entity** یک شیء در دامنه است که **هویت یکتا** دارد و با گذشت زمان **هویت آن ثابت می‌ماند** حتی اگر ویژگی‌هایش تغییر کند.

ویژگی‌های اصلی:

- هویت دارد (معمولاً ID)
- قابل تغییر است
- تغییر ویژگی‌ها هویت را از بین نمی‌برد

مثال‌ها:

- کاربر (User)
- سفارش (Order)
- محصول (Product)

مثلاً اگر نام یک کاربر تغییر کند، هنوز همان کاربر قبلی است چون **ID آن تغییری نکرده**.

---

# 2) تعریف Value Object چیست؟

درواقع **Value Object** شیئی است که **هویت ندارد** و تنها با **مقدار** تعریف می‌شود.

اگر مقدار آن عوض شود، در واقع شیء جدیدی به حساب می‌آید.

ویژگی‌ها:

- هویت ندارد
- باید **immutable** باشد (تغییرپذیر نیست؛ نسخه جدید ساخته می‌شود)
- بر اساس مقدار مقایسه می‌شود

مثال‌های رایج:

- Money (قیمت 100 دلار)
- Address (آدرس)
- DateRange (بازه تاریخ)
- Email (ایمیل)
- GeoPoint (مختصات)

مثلاً آدرس:

اگر شماره کوچه یا خیابان تغییر کند، این یک **آدرس جدید** محسوب می‌شود و آدرس قبلی دیگر معتبر نیست.

---

# 3) مفهوم Aggregate چیست؟

درواقع **Aggregate** یک خوشه منطقی از Entityها و Value Objectهاست که از نظر دامنه باید به صورت **یک واحد واحد** رفتار کنند.

Aggregate:

- واحد consistency در دامنه است
- قوانین کسب‌وکار باید داخل آن رعایت شوند
- یک **Aggregate Root** دارد (یک Entity مرکزی) که نقطه ورودی مدیریت است

ویژگی‌های مهم:

- Aggregate Root تنها جایی است که بیرون می‌تواند به آن دسترسی داشته باشد
- تغییرات داخلی Aggregate باید فقط از طریق Root انجام شود
- Aggregate باید کوچک و قابل مدیریت باشد

---

# مثال کامل (به زبان خیلی ساده)

فرض کن دامنه فروشگاه داری:

### Entity ها:

- Order (سفارش)
- Customer (مشتری)
- Product (محصول)

این‌ها هویت دارند و در طول زمان تغییر می‌کنند.

### Value Object ها:

- Address (آدرس)
- Money (قیمت)
- Quantity (تعداد)
- OrderLine (یک آیتم در سفارش – ممکن است Entity یا VO باشد)

این‌ها هویت ندارند و فقط مقدار مهم است.

### Aggregate:

فرض کن Aggregate به نام **Order** داریم:

Order Aggregate شامل:

- Order (Aggregate Root)
- لیست OrderLines (VO یا Entity بسته به طراحی)
- Money و Address

اما از بیرون فقط Order Root قابل دسترسی است.

مثلاً:

- کسی نمی‌تواند مستقیماً OrderLine را ویرایش کند
- باید فقط از طریق Order Root تغییر انجام شود:مثلاً addItem() ، removeItem()

# جمع‌بندی خیلی کوتاه

**Entity:**

هویت دارد، زمان‌مند است، تغییر می‌کند.

**Value Object:**

هویت ندارد، فقط مقدار مهم است، immutable.

**Aggregate:**

خوشه‌ای از Entityها و Value Objectها با یک Root

که قوانین دامنه را تضمین می‌کند و نقطه کنترل عملیات است.
