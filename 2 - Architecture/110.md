برای اضافه کردن **Cache بدون تغییر در Business Logic** معمولاً از **Decorator Pattern** استفاده می‌شود.

### چرا Decorator؟

Decorator به شما اجازه می‌دهد بدون تغییر دادن کلاس اصلی، رفتار جدیدی (مثل caching) به آن اضافه کنید. شما یک wrapper دور سرویس اصلی می‌پیچید که قبل از اجرای متد، cache را چک می‌کند.

### ایده کلی

1. یک **Interface مشترک** برای سرویس دارید.
2. کلاس اصلی همان Business Logic را پیاده‌سازی می‌کند.
3. یک **Caching Decorator** همان interface را پیاده‌سازی می‌کند و سرویس اصلی را wrap می‌کند.
4. ابتدا cache بررسی می‌شود؛ اگر نبود، سرویس اصلی صدا زده می‌شود و نتیجه cache می‌شود.

### مثال ساده
```csharp

class ProductService:
    def get_product(self, product_id):
        # business logic
        return database.get(product_id)


class CachedProductService:
    def __init__(self, product_service, cache):
        self.product_service = product_service
        self.cache = cache

    def get_product(self, product_id):
        if product_id in self.cache:
            return self.cache[product_id]

        product = self.product_service.get_product(product_id)
        self.cache[product_id] = product
        return product

```
در اینجا:

- `ProductService` همان Business Logic است.
- `CachedProductService` یک **Decorator** است که caching اضافه می‌کند.

### مزیت‌ها

- عدم تغییر در Business Logic
- قابل ترکیب با decoratorهای دیگر (logging, retry, metrics)
- رعایت **Open/Closed Principle**
