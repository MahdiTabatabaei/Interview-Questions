توانایی **درک وضعیت سیستم از بیرون**.

سه چیز را باید بدانیم:

- چه اتفاقی افتاده؟
- چرا اتفاق افتاده؟
- کجا اتفاق افتاده؟
----


مفهوم **Observability** یعنی توانایی درک وضعیت داخلی یک سیستم فقط از طریق **خروجی‌هایی که سیستم تولید می‌کند**.  
در معماری **Microservices** چون سیستم از سرویس‌های کوچک و مستقل تشکیل شده، پیدا کردن مشکل بدون Observability تقریباً غیرممکن می‌شود.

مفهوم Observability معمولاً روی سه ستون اصلی بنا شده است:

- **Logs (لاگ‌ها)** → چه اتفاقی افتاده؟
- **Metrics (متریک‌ها)** → وضعیت سیستم چطور است؟
- **Tracing (ردیابی درخواست‌ها)** → یک درخواست از چه سرویس‌هایی عبور کرده؟

در سیستم Microservices یک درخواست ممکن است از چند سرویس عبور کند، بنابراین باید بتوان مسیر آن را دنبال کرد.

---

# مثال ساده سناریو

فرض کنید یک سیستم فروش داریم:

```
API Gateway
   │
   ├── Order Service
   │
   ├── Payment Service
   │
   └── Inventory Service
```

یک درخواست ثبت سفارش ممکن است این مسیر را طی کند:

```
Client → OrderService → PaymentService → InventoryService
```

اگر سفارش شکست بخورد باید بفهمیم مشکل از کجاست.

الگوی Observability کمک می‌کند بفهمیم:

- آیا Payment کند بوده؟
- آیا Inventory خطا داده؟
- آیا OrderService درخواست را درست ارسال کرده؟

# 1️⃣ ابزار Logging در #C

در .NET معمولاً از **Serilog** یا **Microsoft.Extensions.Logging** استفاده می‌شود.

### نصب

```
dotnet add package Serilog.AspNetCore
```

### Program.cs

```csharp
using Serilog;

var builder = WebApplication.CreateBuilder(args);

Log.Logger = new LoggerConfiguration()
    .WriteTo.Console()
    .WriteTo.File("logs/log.txt", rollingInterval: RollingInterval.Day)
    .CreateLogger();

builder.Host.UseSerilog();

var app = builder.Build();

app.MapGet("/order", (ILogger<Program> logger) =>
{
    logger.LogInformation("Order request received at {time}", DateTime.UtcNow);

    return "Order Created";
});

app.Run();
```

نمونه لاگ:

```
[INF] Order request received at 2026-05-17T10:21:33Z
```

# 2️⃣ ابزار Metrics در #C

متریک‌ها وضعیت سیستم را نشان می‌دهند:

- تعداد درخواست‌ها
- زمان پاسخ
- میزان خطا

در .NET معمولاً با **Prometheus + OpenTelemetry** انجام می‌شود.

### نصب

```
dotnet add package OpenTelemetry.Extensions.Hosting
dotnet add package OpenTelemetry.Exporter.Prometheus
```

### Program.cs

```csharp
using OpenTelemetry.Metrics;

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddOpenTelemetry()
    .WithMetrics(metrics =>
    {
        metrics.AddAspNetCoreInstrumentation();
        metrics.AddPrometheusExporter();
    });

var app = builder.Build();

app.MapGet("/order", () =>
{
    return "Order created";
});

app.MapPrometheusScrapingEndpoint();

app.Run();
```

ابزار Prometheus می‌تواند متریک‌هایی مثل:

```
http_requests_total
http_request_duration_seconds
```

را جمع‌آوری کند.

# 3️⃣ الگوی Distributed Tracing در #C

مهم‌ترین بخش Observability در Microservices است.

با **OpenTelemetry + Jaeger** می‌توان مسیر یک درخواست را دید.

### نصب

```
dotnet add package OpenTelemetry.Exporter.Jaeger
```

### Program.cs

```csharp
using OpenTelemetry.Trace;

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddOpenTelemetry()
    .WithTracing(tracing =>
    {
        tracing
            .AddAspNetCoreInstrumentation()
            .AddHttpClientInstrumentation()
            .AddJaegerExporter();
    });

var app = builder.Build();

app.MapGet("/order", async (HttpClient http) =>
{
    await http.GetAsync("http://payment-service/pay");

    return "Order completed";
});

app.Run();
```

در **Jaeger UI** می‌توانید ببینید:

```
OrderService
   └── PaymentService
        └── InventoryService
```

و زمان هر سرویس را بررسی کنید.

TraceId: a7f12b9

# جمع‌بندی

مفهوم Observability در Microservices یعنی توانایی فهمیدن وضعیت سیستم از طریق:

- **Logs** → چه اتفاقی افتاده  
- **Metrics** → وضعیت عملکرد سیستم  
- **Tracing** → مسیر یک درخواست در بین سرویس‌ها  

در دنیای .NET معمولاً این ترکیب استفاده می‌شود:

```
Serilog + OpenTelemetry + Prometheus + Jaeger + Grafana
```
