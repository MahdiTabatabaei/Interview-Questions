درواقع JWT و OAuth2 اغلب با هم دیده می‌شوند، اما **یک چیز نیستند**. تفاوت اصلی این است:

- **JWT یک فرمت توکن است**
- **OAuth2 یک پروتکل Authorization است**

یعنی یکی **نوع داده** است و دیگری **روش کنترل دسترسی**.

---

# تعریف JWT چیست؟ (JSON Web Token)

درواقع JWT یک **فرمت استاندارد برای انتقال اطلاعات به صورت امن** است.

ساختار آن سه بخش دارد:

```
HEADER.PAYLOAD.SIGNATURE
```

مثال:

```
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9
.
eyJzdWIiOiIxMjMiLCJuYW1lIjoiQWxpIiwicm9sZSI6IkFkbWluIn0
.
SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c
```

---

### اجزای JWT

**Header**

مشخص می‌کند چه الگوریتمی استفاده شده:

```
{
  "alg": "HS256",
  "typ": "JWT"
}
```

---

**Payload**

اطلاعات کاربر یا claim ها:

```
{
  "sub": "123",
  "name": "Ali",
  "role": "Admin",
  "exp": 1716239022
}
```

---

**Signature**

برای جلوگیری از دستکاری توکن:

```
HMACSHA256(
  base64(header) + "." + base64(payload),
  secret
)
```

---

### کاربرد JWT

معمولاً برای:

- Authentication
- Authorization
- API Security
- Microservices

مثال در API:

```
Authorization: Bearer <JWT>
```

---

# تعریف OAuth2 چیست؟

درواقع OAuth2 یک **پروتکل برای Authorization** است.

هدف آن این است که:

> یک برنامه بتواند با اجازه کاربر به منابع برنامه دیگر دسترسی بگیرد.

مثال معروف:

```
Login with Google
```

در اینجا:

- Google = Authorization Server
- App = Client
- User = Resource Owner

---

### جریان OAuth2

مراحل ساده:

```
User → Client App
        │
        ▼
Authorization Server (Google/Auth0/Keycloak)
        │
        ▼
Access Token
        │
        ▼
Resource Server (API)
```

کاربر لاگین می‌کند → یک **Access Token** صادر می‌شود → کلاینت با آن API را صدا می‌زند.

---

# انواع Token در OAuth2

درواقع OAuth2 چند نوع token دارد:

**Access Token**

برای دسترسی به API.

```
Authorization: Bearer access_token
```

---

**Refresh Token**

برای گرفتن access token جدید بدون login دوباره.

---

# رابطه JWT و OAuth2

اینجا جایی است که خیلی‌ها گیج می‌شوند.

مفهوم OAuth2 مشخص نمی‌کند توکن چه فرمت باشد.

درواقع Access Token می‌تواند باشد:

```
Opaque Token
یا
JWT
```

در اکثر سیستم‌های مدرن:

```
OAuth2 Access Token = JWT
```

مثال:

```
OAuth2 flow
     ↓
Access Token issued
     ↓
Token format = JWT
```

---

# مثال واقعی

کاربر در یک سیستم Microservices لاگین می‌کند.

```
User
  ↓
Auth Server (Keycloak)
  ↓
JWT Access Token
```

مثال توکن:

```
{
  "sub": "user123",
  "role": "admin",
  "scope": "orders.read",
  "exp": 1716239022
}
```

وقتی API صدا زده می‌شود:

```
GET /orders
Authorization: Bearer <JWT>
```

در اینحالت API امضا را بررسی می‌کند و دسترسی را چک می‌کند.

---

# مقایسه خلاصه

JWT

- یک **فرمت token**
- شامل claims
- مقدار self‑contained
- قابل verify با signature

---

OAuth2

- یک **Authorization framework**
- مشخص می‌کند چگونه token صادر شود
- جریان‌های login و permission را تعریف می‌کند

---

# یک تشبیه ساده

درواقع OAuth2 مثل **سیستم صدور کارت ورود** است.

و JWT مثل **خود کارت ورود** است.

```
OAuth2 = سیستم صدور
JWT = کارت دسترسی
```

---

✅ **جمع‌بندی**

- JWT = فرمت توکن  
- OAuth2 = پروتکل authorization  
- OAuth2 معمولاً از JWT برای Access Token استفاده می‌کند.
