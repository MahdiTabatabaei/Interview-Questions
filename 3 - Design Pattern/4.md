الگوی **Abstract Factory** یکی از الگوهای **Creational** است که برای **ساخت مجموعه‌ای از اشیاء مرتبط یا وابسته به هم بدون مشخص کردن کلاس‌های دقیق آن‌ها** استفاده می‌شود.

ایده اصلی:  
به‌جای ساخت یک شیء، یک **کارخانه می‌سازیم که چند نوع شیء مرتبط را تولید می‌کند**.

تفاوت مهم با Factory Method:  
- Factory Method → ساخت **یک نوع شیء**  
- Abstract Factory → ساخت **خانواده‌ای از اشیاء مرتبط**

---

# مثال در C#

فرض کنید یک سیستم UI داریم که باید برای **Windows** و **Mac** کامپوننت‌های متفاوت بسازد:

- Button
- Checkbox

---

# 1. Abstract Products

```csharp
public interface IButton
{
    void Render();
}

public interface ICheckbox
{
    void Render();
}
```

---

# 2. Concrete Products

### Windows

```csharp
public class WindowsButton : IButton
{
    public void Render()
    {
        Console.WriteLine("Render Windows Button");
    }
}

public class WindowsCheckbox : ICheckbox
{
    public void Render()
    {
        Console.WriteLine("Render Windows Checkbox");
    }
}
```

### Mac

```csharp
public class MacButton : IButton
{
    public void Render()
    {
        Console.WriteLine("Render Mac Button");
    }
}

public class MacCheckbox : ICheckbox
{
    public void Render()
    {
        Console.WriteLine("Render Mac Checkbox");
    }
}
```

---

# 3. Abstract Factory

کارخانه‌ای که مشخص می‌کند چه محصولاتی باید ساخته شوند.

```csharp
public interface IGUIFactory
{
    IButton CreateButton();
    ICheckbox CreateCheckbox();
}
```

---

# 4. Concrete Factories

### Windows Factory

```csharp
public class WindowsFactory : IGUIFactory
{
    public IButton CreateButton()
    {
        return new WindowsButton();
    }

    public ICheckbox CreateCheckbox()
    {
        return new WindowsCheckbox();
    }
}
```

### Mac Factory

```csharp
public class MacFactory : IGUIFactory
{
    public IButton CreateButton()
    {
        return new MacButton();
    }

    public ICheckbox CreateCheckbox()
    {
        return new MacCheckbox();
    }
}
```

---

# 5. استفاده در برنامه

```csharp
class Program
{
    static void Main()
    {
        IGUIFactory factory;

        string os = "Windows";

        if (os == "Windows")
            factory = new WindowsFactory();
        else
            factory = new MacFactory();

        IButton button = factory.CreateButton();
        ICheckbox checkbox = factory.CreateCheckbox();

        button.Render();
        checkbox.Render();
    }
}
```

خروجی (برای Windows):

```
Render Windows Button
Render Windows Checkbox
```

---

# مزایای Abstract Factory

- تضمین می‌کند **محصولات یک خانواده با هم سازگار باشند**
- **Loose Coupling** بین کد و کلاس‌های واقعی
- رعایت **Open/Closed Principle**
- مناسب برای سیستم‌هایی که **چند تم یا پلتفرم** دارند

---

# یک مثال واقعی در دنیای واقعی

مثلاً در **Database Provider**:

- SqlServerFactory  
- OracleFactory  
- MySqlFactory  

هر کدام می‌سازند:

- Connection
- Command
- Transaction

همه این‌ها یک **خانواده از اشیاء مرتبط دیتابیس** هستند.
