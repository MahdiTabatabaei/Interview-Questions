الگوی **Mediator** یک الگوی طراحی از نوع **Behavioral** است که هدف آن **کاهش وابستگی مستقیم بین اشیاء** است.

ایده اصلی این است که به‌جای اینکه اشیاء مستقیماً با هم ارتباط برقرار کنند، همه ارتباطات از طریق یک **Mediator (واسط)** انجام شود.

یعنی:

```
Object ↔ Mediator ↔ Object
```

به این شکل اشیاء از هم **decoupled** می‌شوند و فقط Mediator را می‌شناسند.

---

## مشکل بدون Mediator

فرض کنید چند کامپوننت داریم که مستقیم با هم حرف می‌زنند:

```
A → B
A → C
B → C
C → A
```

به‌مرور زمان وابستگی‌ها زیاد می‌شود و سیستم تبدیل به **spaghetti dependency** می‌شود.

Mediator این مشکل را حل می‌کند.

---

## ساختار الگو

اجزای اصلی:

- **Mediator** → اینترفیس واسط
- **ConcreteMediator** → پیاده‌سازی mediator
- **Colleague** → کلاس‌هایی که با mediator کار می‌کنند
- **ConcreteColleague** → اشیاء واقعی

---

# مثال ساده در C#

فرض کنید یک **Chat Room** داریم که کاربران از طریق آن پیام می‌فرستند.

کاربران مستقیماً با هم صحبت نمی‌کنند؛ همه چیز از طریق **Mediator (ChatRoom)** انجام می‌شود.

---

## Mediator Interface

```csharp
public interface IChatMediator
{
    void SendMessage(string message, User user);
    void AddUser(User user);
}
```

---

## Concrete Mediator

```csharp
public class ChatMediator : IChatMediator
{
    private List<User> users = new List<User>();

    public void AddUser(User user)
    {
        users.Add(user);
    }

    public void SendMessage(string message, User sender)
    {
        foreach (var user in users)
        {
            if (user != sender)
            {
                user.Receive(message);
            }
        }
    }
}
```

---

## Colleague

```csharp
public class User
{
    private string name;
    private IChatMediator mediator;

    public User(string name, IChatMediator mediator)
    {
        this.name = name;
        this.mediator = mediator;
    }

    public void Send(string message)
    {
        Console.WriteLine(name + " sends: " + message);
        mediator.SendMessage(message, this);
    }

    public void Receive(string message)
    {
        Console.WriteLine(name + " receives: " + message);
    }
}
```

---

# استفاده

```csharp
class Program
{
    static void Main()
    {
        IChatMediator mediator = new ChatMediator();

        User user1 = new User("Ali", mediator);
        User user2 = new User("Sara", mediator);
        User user3 = new User("Reza", mediator);

        mediator.AddUser(user1);
        mediator.AddUser(user2);
        mediator.AddUser(user3);

        user1.Send("Hello everyone!");
    }
}
```

---

## خروجی

```
Ali sends: Hello everyone!
Sara receives: Hello everyone!
Reza receives: Hello everyone!
```

---

# مزایای Mediator

- کاهش **coupling بین کلاس‌ها**
- ساده شدن ارتباط بین چندین object
- مدیریت ارتباطات در یک نقطه

# معایب

اگر سیستم خیلی بزرگ شود ممکن است **Mediator تبدیل به God Object** شود (خیلی بزرگ و پیچیده).

# مثال واقعی در دنیای .NET

یکی از معروف‌ترین استفاده‌ها:

**کتابخانه MediatR در ASP.NET Core**

برای پیاده‌سازی **CQRS و Request/Response Pattern**

مثال ساده:

```csharp
public record GetUserQuery(int Id) : IRequest<User>;
```

و Handler:

```csharp
public class GetUserHandler : IRequestHandler<GetUserQuery, User>
{
    public Task<User> Handle(GetUserQuery request, CancellationToken cancellationToken)
    {
        // logic
    }
}
```

Controller فقط mediator را صدا می‌زند:

```csharp
await mediator.Send(new GetUserQuery(1));
```

Controller دیگر مستقیم به Service یا Repository وابسته نیست.
