تعریف **Saga Pattern** الگویی برای مدیریت **تراکنش‌های توزیع‌شده در معماری Microservices** است.  
به‌جای یک تراکنش دیتابیسی بزرگ (ACID)، عملیات به چند **تراکنش محلی** در سرویس‌های مختلف تقسیم می‌شود. اگر یکی از مراحل شکست بخورد، **Compensating Transaction** اجرا می‌شود تا مراحل قبلی rollback منطقی شوند.

مثال ساده:  
1. Order Service → ایجاد سفارش  
2. Payment Service → پرداخت  
3. Inventory Service → کم کردن موجودی  

اگر پرداخت ناموفق باشد باید **Order Cancel** شود.

---

# 1. Saga Choreography

در این مدل **هیچ orchestrator مرکزی وجود ندارد**.  
هر سرویس با **Event** با سرویس‌های دیگر ارتباط می‌گیرد.

Flow:

```
OrderCreated → PaymentService
PaymentCompleted → InventoryService
InventoryReserved → OrderCompleted
```

هر سرویس فقط **به Event گوش می‌دهد**.

### مثال ساده C#

Event:

```csharp
public class OrderCreatedEvent
{
    public int OrderId { get; set; }
}
```

Order Service:

```csharp
public class OrderService
{
    private readonly IEventBus _eventBus;

    public OrderService(IEventBus eventBus)
    {
        _eventBus = eventBus;
    }

    public void CreateOrder(int orderId)
    {
        Console.WriteLine("Order created");

        _eventBus.Publish(new OrderCreatedEvent
        {
            OrderId = orderId
        });
    }
}
```

Payment Service:

```csharp
public class PaymentService
{
    public void Handle(OrderCreatedEvent evt)
    {
        Console.WriteLine("Processing payment for order " + evt.OrderId);

        // بعد از پرداخت event جدید منتشر می‌شود
    }
}
```

ویژگی‌ها:
- بدون کنترل مرکزی
- سرویس‌ها فقط به eventها گوش می‌دهند
- باعث coupling کمتر اما **ردیابی جریان سخت‌تر**

# 2. Saga Orchestration

در این مدل یک **Orchestrator مرکزی** وجود دارد که کل جریان را کنترل می‌کند.

Flow:

```
Orchestrator
   ↓
Create Order
   ↓
Process Payment
   ↓
Reserve Inventory
   ↓
Complete Order
```

اگر مرحله‌ای fail شود، orchestrator عملیات جبرانی را اجرا می‌کند.

---

### مثال C#

Orchestrator:

```csharp
public class OrderSagaOrchestrator
{
    private readonly PaymentService _paymentService;
    private readonly InventoryService _inventoryService;

    public OrderSagaOrchestrator(
        PaymentService paymentService,
        InventoryService inventoryService)
    {
        _paymentService = paymentService;
        _inventoryService = inventoryService;
    }

    public void ProcessOrder(int orderId)
    {
        Console.WriteLine("Order created");

        bool paymentSuccess = _paymentService.Pay(orderId);

        if (!paymentSuccess)
        {
            Console.WriteLine("Cancel order");
            return;
        }

        bool inventoryReserved = _inventoryService.Reserve(orderId);

        if (!inventoryReserved)
        {
            Console.WriteLine("Refund payment");
            return;
        }

        Console.WriteLine("Order completed");
    }
}
```

Payment Service:

```csharp
public class PaymentService
{
    public bool Pay(int orderId)
    {
        Console.WriteLine("Payment processed");
        return true;
    }
}
```

Inventory Service:

```csharp
public class InventoryService
{
    public bool Reserve(int orderId)
    {
        Console.WriteLine("Inventory reserved");
        return true;
    }
}
```

# تفاوت اصلی

Choreography:
- وجود event-driven
- بدون کنترل مرکزی
- پیچیدگی در فهم جریان

Orchestration:
- یک coordinator مرکزی
- مدیریت ساده‌تر
- وابستگی بیشتر به orchestrator

---

### خلاصه در یک جمله

در **Saga Choreography:** سرویس‌ها با eventها با هم هماهنگ می‌شوند.  
در **Saga Orchestration:** یک orchestrator مرکزی مراحل تراکنش را کنترل می‌کند.
