الگوی **Factory Method** یکی از الگوهای طراحی از نوع **Creational** است که برای **ساختن اشیاء بدون مشخص کردن کلاس دقیق آن‌ها** استفاده می‌شود. به‌جای اینکه مستقیماً با `new` شیء بسازیم، ساخت شیء را به یک **متد کارخانه (Factory Method)** واگذار می‌کنیم.

ایده اصلی:  
کلاس والد یک متد برای ساخت شیء تعریف می‌کند، اما **کلاس‌های فرزند تصمیم می‌گیرند چه نوع شیئی ساخته شود**.

---

## ساختار کلی
اجزای اصلی این الگو:

- **Product** : اینترفیس یا کلاس پایه برای اشیاء
- **ConcreteProduct** : پیاده‌سازی‌های واقعی Product
- **Creator** : کلاس دارای Factory Method
- **ConcreteCreator** : کلاسی که Factory Method را پیاده‌سازی می‌کند

---

# مثال ساده در C#

فرض کنید یک سیستم ارسال پیام داریم که می‌تواند **Email** یا **SMS** ارسال کند.

## 1. Product (اینترفیس)

```csharp
public interface IMessage
{
    void Send(string message);
}
```

---

## 2. ConcreteProduct

```csharp
public class EmailMessage : IMessage
{
    public void Send(string message)
    {
        Console.WriteLine("Sending Email: " + message);
    }
}

public class SmsMessage : IMessage
{
    public void Send(string message)
    {
        Console.WriteLine("Sending SMS: " + message);
    }
}
```

---

## 3. Creator (Factory Method)

```csharp
public abstract class MessageFactory
{
    public abstract IMessage CreateMessage();
}
```

---

## 4. ConcreteCreator

```csharp
public class EmailFactory : MessageFactory
{
    public override IMessage CreateMessage()
    {
        return new EmailMessage();
    }
}

public class SmsFactory : MessageFactory
{
    public override IMessage CreateMessage()
    {
        return new SmsMessage();
    }
}
```

---

## 5. استفاده از Factory Method

```csharp
class Program
{
    static void Main()
    {
        MessageFactory factory;

        factory = new EmailFactory();
        IMessage message = factory.CreateMessage();
        message.Send("Hello");

        factory = new SmsFactory();
        message = factory.CreateMessage();
        message.Send("Hi");
    }
}
```

خروجی:

```
Sending Email: Hello
Sending SMS: Hi
```

---

# مزایای Factory Method

- **کاهش وابستگی (Loose Coupling)** بین کد و کلاس‌های واقعی
- **قابل توسعه بودن** (اضافه کردن نوع جدید بدون تغییر کد قبلی)
- رعایت **اصل Open/Closed**

---

# تفاوت با Simple Factory
در Simple Factory معمولاً یک کلاس با `switch` نوع شیء را می‌سازد، اما در **Factory Method تصمیم ساخت شیء به subclass ها سپرده می‌شود**.
