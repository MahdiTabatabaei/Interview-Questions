الگوی **Chain of Responsibility** یک الگوی طراحی از نوع **Behavioral** است که در آن **درخواست بین مجموعه‌ای از handlerها به‌صورت زنجیره‌ای عبور داده می‌شود** تا یکی از آن‌ها بتواند آن را پردازش کند.

ایده اصلی:  
به‌جای اینکه فرستنده بداند **کدام کلاس درخواست را پردازش می‌کند**، درخواست را به **اولین handler در زنجیره** می‌فرستد و اگر آن handler نتواند آن را پردازش کند، آن را به **handler بعدی** منتقل می‌کند.

این کار باعث **کاهش وابستگی (Loose Coupling)** بین فرستنده و گیرنده می‌شود.

---

# ساختار الگو

اجزا:

- **Handler (Abstract Handler)** → تعریف اینترفیس پردازش درخواست  
- **ConcreteHandler** → پردازش واقعی درخواست  
- **Client** → ارسال درخواست به ابتدای زنجیره

---

# مثال ساده

فرض کنید در یک سیستم **تأیید درخواست مرخصی** داریم.

قوانین:

- مرخصی تا **۲ روز** → Supervisor تأیید می‌کند  
- مرخصی تا **۵ روز** → Manager تأیید می‌کند  
- بیشتر از **۵ روز** → Director تأیید می‌کند

در اینجا درخواست از یک زنجیره عبور می‌کند.

---

# پیاده‌سازی در C#

## Handler

```csharp
public abstract class LeaveHandler
{
    protected LeaveHandler nextHandler;

    public void SetNext(LeaveHandler handler)
    {
        nextHandler = handler;
    }

    public abstract void HandleRequest(int days);
}
```

---

# Concrete Handlers

### Supervisor

```csharp
public class Supervisor : LeaveHandler
{
    public override void HandleRequest(int days)
    {
        if (days <= 2)
        {
            Console.WriteLine("Supervisor approved " + days + " days leave.");
        }
        else if (nextHandler != null)
        {
            nextHandler.HandleRequest(days);
        }
    }
}
```

---

### Manager

```csharp
public class Manager : LeaveHandler
{
    public override void HandleRequest(int days)
    {
        if (days <= 5)
        {
            Console.WriteLine("Manager approved " + days + " days leave.");
        }
        else if (nextHandler != null)
        {
            nextHandler.HandleRequest(days);
        }
    }
}
```

---

### Director

```csharp
public class Director : LeaveHandler
{
    public override void HandleRequest(int days)
    {
        Console.WriteLine("Director approved " + days + " days leave.");
    }
}
```

# استفاده

```csharp
class Program
{
    static void Main()
    {
        LeaveHandler supervisor = new Supervisor();
        LeaveHandler manager = new Manager();
        LeaveHandler director = new Director();

        supervisor.SetNext(manager);
        manager.SetNext(director);

        supervisor.HandleRequest(1);
        supervisor.HandleRequest(4);
        supervisor.HandleRequest(7);
    }
}
```

خروجی:

```
Supervisor approved 1 days leave.
Manager approved 4 days leave.
Director approved 7 days leave.
```

در اینجا:

- درخواست اول توسط **Supervisor**
- درخواست دوم توسط **Manager**
- درخواست سوم توسط **Director**

پردازش شده است.

# مزایا

- کاهش وابستگی بین **Client و Handler**
- امکان تغییر ترتیب Handlerها
- اضافه کردن Handler جدید بدون تغییر کد قبلی (Open/Closed)

# مثال‌های واقعی

**ASP.NET Core Middleware**

```
Request → Logging Middleware → Authentication → Authorization → Controller
```
