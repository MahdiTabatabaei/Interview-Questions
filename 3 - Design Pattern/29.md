درواقع **Dependency Injection (DI)** یعنی وابستگی‌های یک کلاس را **از بیرون به آن تزریق کنیم** به جای اینکه خود کلاس آن‌ها را بسازد.

هدف: کاهش وابستگی (coupling) و راحت‌تر شدن تست و تغییر پیاده‌سازی.

### مثال بدون DI (وابستگی سخت)

```csharp
class EmailService
{
    public void Send(string message)
    {
        Console.WriteLine("Email sent: " + message);
    }
}

class Notification
{
    private EmailService _emailService = new EmailService();

    public void Notify(string message)
    {
        _emailService.Send(message);
    }
}
```

اینجا کلاس `Notification` خودش `EmailService` می‌سازد و شدیداً به آن وابسته است.

---

### مثال با Dependency Injection

ابتدا یک اینترفیس تعریف می‌کنیم:

```csharp
public interface IMessageService
{
    void Send(string message);
}
```

پیاده‌سازی:

```csharp
public class EmailService : IMessageService
{
    public void Send(string message)
    {
        Console.WriteLine("Email sent: " + message);
    }
}
```

تزریق وابستگی در سازنده (Constructor Injection):

```csharp
public class Notification
{
    private readonly IMessageService _messageService;

    public Notification(IMessageService messageService)
    {
        _messageService = messageService;
    }

    public void Notify(string message)
    {
        _messageService.Send(message);
    }
}
```

استفاده:

```csharp
IMessageService service = new EmailService();
Notification notification = new Notification(service);

notification.Notify("Hello");
```

حالا اگر بخواهیم به جای ایمیل **SMS** بفرستیم فقط یک کلاس جدید می‌نویسیم و `Notification` تغییر نمی‌کند.

```csharp
class SmsService : IMessageService
{
    public void Send(string message)
    {
        Console.WriteLine("SMS sent: " + message);
    }
}
```

---

### خلاصه در یک جمله
الگوی **Dependency Injection یعنی وابستگی‌های یک کلاس را از بیرون به آن بدهیم تا کلاس به پیاده‌سازی خاصی وابسته نباشد.**
