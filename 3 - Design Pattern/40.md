الگوی **Strategy** و **State** از نظر ساختار خیلی شبیه‌اند (هر دو از interface و چند implementation استفاده می‌کنند)، اما **هدف و نحوه استفاده‌شان متفاوت است**.

به طور خلاصه:

- **Strategy → انتخاب الگوریتم**
- **State → تغییر رفتار بر اساس وضعیت**

---

# تفاوت مفهومی

### Strategy
کلاینت تصمیم می‌گیرد **کدام الگوریتم استفاده شود**.

مثال:  
کاربر انتخاب می‌کند پرداخت با **CreditCard یا PayPal** انجام شود.

---

### State
شیء خودش با تغییر وضعیت داخلی **رفتارش را عوض می‌کند**.

مثال:  
سفارش وقتی **پرداخت شد → ارسال می‌شود**.

---

# تفاوت ساختاری

| ویژگی | Strategy | State |
|------|------|------|
| هدف | انتخاب الگوریتم | مدیریت رفتار بر اساس وضعیت |
| تغییر رفتار | توسط Client | توسط خود Object |
| ارتباط Stateها | مستقل | معمولا به هم transition دارند |
| مثال | Payment methods | Order workflow |

---

# مثال Strategy در C#

فرض کنید چند **روش پرداخت** داریم.

### Strategy Interface

```csharp
public interface IPaymentStrategy
{
    void Pay(decimal amount);
}
```

### Concrete Strategies

```csharp
public class CreditCardPayment : IPaymentStrategy
{
    public void Pay(decimal amount)
    {
        Console.WriteLine($"Paid {amount} with Credit Card");
    }
}

public class PayPalPayment : IPaymentStrategy
{
    public void Pay(decimal amount)
    {
        Console.WriteLine($"Paid {amount} with PayPal");
    }
}
```

### Context

```csharp
public class PaymentContext
{
    private IPaymentStrategy strategy;

    public PaymentContext(IPaymentStrategy strategy)
    {
        this.strategy = strategy;
    }

    public void Pay(decimal amount)
    {
        strategy.Pay(amount);
    }
}
```

### استفاده

```csharp
var payment = new PaymentContext(new PayPalPayment());
payment.Pay(100);
```

در اینجا **کاربر انتخاب می‌کند** کدام الگوریتم اجرا شود.

# مثال State در C#

فرض کنید **Order** داریم.

### State Interface

```csharp
public interface IOrderState
{
    void Next(Order order);
}
```

---

### Concrete States

```csharp
public class NewState : IOrderState
{
    public void Next(Order order)
    {
        Console.WriteLine("Payment completed");
        order.SetState(new PaidState());
    }
}

public class PaidState : IOrderState
{
    public void Next(Order order)
    {
        Console.WriteLine("Order shipped");
        order.SetState(new ShippedState());
    }
}

public class ShippedState : IOrderState
{
    public void Next(Order order)
    {
        Console.WriteLine("Already shipped");
    }
}
```

---

### Context

```csharp
public class Order
{
    private IOrderState state;

    public Order()
    {
        state = new NewState();
    }

    public void SetState(IOrderState state)
    {
        this.state = state;
    }

    public void Next()
    {
        state.Next(this);
    }
}
```

---

### استفاده

```csharp
Order order = new Order();

order.Next();
order.Next();
order.Next();
```

در اینجا **خود state تعیین می‌کند مرحله بعد چیست**.

---

# تفاوت کلیدی در یک جمله

**Strategy**  
الگوریتم توسط **Client انتخاب می‌شود**.

**State**  
رفتار با **تغییر وضعیت داخلی Object** عوض می‌شود.

---

✅ یک نکته مهم :

> درواقع Strategy برای تغییر الگوریتم‌ها استفاده می‌شود، در حالی که State برای مدیریت رفتار یک شیء بر اساس وضعیت داخلی آن است و معمولاً stateها transition به state دیگر دارند.
