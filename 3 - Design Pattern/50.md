درواقع **Simple Factory** یک الگوی طراحی (Design Pattern) از نوع **Creational** است که مسئولیت ساختن اشیا را از کد اصلی جدا می‌کند. به‌جای اینکه در برنامه مستقیماً با `new` شی بسازیم، از یک **کلاس کارخانه (Factory)** استفاده می‌کنیم که بر اساس ورودی، شی مناسب را ایجاد می‌کند.

هدف اصلی:
- کاهش وابستگی کد به کلاس‌های مشخص
- متمرکز کردن منطق ساخت اشیا در یک مکان

---

## مثال ساده در #C

فرض کنید یک برنامه داریم که می‌تواند **دو نوع Logger** بسازد:  
- `FileLogger`
- `DatabaseLogger`

### 1. اینترفیس مشترک

```csharp
public interface ILogger
{
    void Log(string message);
}
```

---

### 2. کلاس‌های پیاده‌سازی

```csharp
public class FileLogger : ILogger
{
    public void Log(string message)
    {
        Console.WriteLine("Logging to File: " + message);
    }
}

public class DatabaseLogger : ILogger
{
    public void Log(string message)
    {
        Console.WriteLine("Logging to Database: " + message);
    }
}
```

---

### 3. کلاس Simple Factory

```csharp
public class LoggerFactory
{
    public static ILogger CreateLogger(string type)
    {
        if (type == "file")
            return new FileLogger();
        else if (type == "db")
            return new DatabaseLogger();
        else
            throw new ArgumentException("Invalid logger type");
    }
}
```

---

### 4. استفاده در برنامه

```csharp
class Program
{
    static void Main()
    {
        ILogger logger = LoggerFactory.CreateLogger("file");
        logger.Log("Hello World");
    }
}
```

---

## مزیت‌ها
- جدا شدن منطق ساخت شی از کد اصلی
- نگهداری و تغییر آسان‌تر
- کاهش وابستگی مستقیم به کلاس‌ها
