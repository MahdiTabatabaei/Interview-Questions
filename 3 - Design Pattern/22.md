الگوی **Strategy** یک الگوی طراحی از نوع **Behavioral** است که اجازه می‌دهد **چند الگوریتم مختلف برای انجام یک کار داشته باشیم و در زمان اجرا یکی از آن‌ها را انتخاب کنیم**.

به زبان ساده:  
به‌جای اینکه داخل کلاس پر از `if` یا `switch` برای انتخاب الگوریتم باشد، هر الگوریتم را در یک کلاس جداگانه قرار می‌دهیم و در زمان اجرا آن را تزریق می‌کنیم.

---

## مشکل بدون Strategy Pattern

فرض کنید سیستم **پرداخت** داریم:

```csharp
public class PaymentService
{
    public void Pay(string method)
    {
        if (method == "CreditCard")
        {
            Console.WriteLine("Pay with credit card");
        }
        else if (method == "PayPal")
        {
            Console.WriteLine("Pay with PayPal");
        }
        else if (method == "Bitcoin")
        {
            Console.WriteLine("Pay with Bitcoin");
        }
    }
}
```

مشکل‌ها:

- `if / switch` زیاد
- سخت شدن اضافه کردن روش جدید
- نقض **Open/Closed Principle**

Strategy Pattern این مشکل را حل می‌کند.

---

# ساختار Strategy Pattern

اجزا:

- **Strategy (interface)** → تعریف الگوریتم
- **ConcreteStrategy** → پیاده‌سازی الگوریتم‌ها
- **Context** → کلاسی که از strategy استفاده می‌کند

---

# مثال C#

سیستم پرداخت با چند روش مختلف.

---

## Strategy Interface

```csharp
public interface IPaymentStrategy
{
    void Pay(decimal amount);
}
```

---

## Concrete Strategies

### CreditCardPayment

```csharp
public class CreditCardPayment : IPaymentStrategy
{
    public void Pay(decimal amount)
    {
        Console.WriteLine($"Paid {amount} with Credit Card");
    }
}
```

---

### PayPalPayment

```csharp
public class PayPalPayment : IPaymentStrategy
{
    public void Pay(decimal amount)
    {
        Console.WriteLine($"Paid {amount} with PayPal");
    }
}
```

---

### BitcoinPayment

```csharp
public class BitcoinPayment : IPaymentStrategy
{
    public void Pay(decimal amount)
    {
        Console.WriteLine($"Paid {amount} with Bitcoin");
    }
}
```

---

## Context

```csharp
public class PaymentContext
{
    private IPaymentStrategy strategy;

    public PaymentContext(IPaymentStrategy strategy)
    {
        this.strategy = strategy;
    }

    public void SetStrategy(IPaymentStrategy strategy)
    {
        this.strategy = strategy;
    }

    public void Pay(decimal amount)
    {
        strategy.Pay(amount);
    }
}
```

---

# استفاده

```csharp
class Program
{
    static void Main()
    {
        PaymentContext payment = new PaymentContext(new CreditCardPayment());
        payment.Pay(100);

        payment.SetStrategy(new PayPalPayment());
        payment.Pay(200);

        payment.SetStrategy(new BitcoinPayment());
        payment.Pay(300);
    }
}
```

---

## خروجی

```
Paid 100 with Credit Card
Paid 200 with PayPal
Paid 300 with Bitcoin
```

# مزایا

- حذف `if / switch`
- رعایت **Open/Closed Principle**
- الگوریتم‌ها قابل تعویض در زمان اجرا
- تست‌پذیری بهتر

---

# معایب

- تعداد کلاس‌ها بیشتر می‌شود
- client باید strategy مناسب را انتخاب کند

---

# مثال‌های واقعی

- **Payment systems**
- **Sorting algorithms**
- **Compression algorithms**
- **Authentication strategies**
- **Tax calculation**

# تفاوت Strategy و State

این دو بسیار شبیه هستند ولی هدفشان متفاوت است.

**Strategy**

- انتخاب الگوریتم
- client تصمیم می‌گیرد کدام strategy استفاده شود

**State**

- رفتار با تغییر وضعیت داخلی object تغییر می‌کند
- خود object state را تغییر می‌دهد
