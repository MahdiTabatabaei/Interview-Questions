الگوی **Template Method** یک الگوی طراحی از نوع **Behavioral** است که در آن **اسکلت (structure) یک الگوریتم در کلاس پایه تعریف می‌شود**، اما **بعضی از مراحل آن توسط کلاس‌های فرزند پیاده‌سازی یا تغییر داده می‌شود**.

به بیان ساده:  
کلاس پایه **مراحل کلی کار را مشخص می‌کند**، ولی **جزئیات بعضی مراحل را به کلاس‌های فرزند می‌سپارد**.

---

## ایده اصلی

فرض کنید چند نوع **گزارش** داریم:

- PDF Report
- Excel Report
- HTML Report

همه این گزارش‌ها مراحل مشترک دارند:

1. خواندن داده‌ها  
2. پردازش داده‌ها  
3. تولید گزارش  

اما **نحوه تولید خروجی متفاوت است**.

Template Method این مشکل را حل می‌کند.

---

# ساختار Template Method

اجزا:

- **Abstract Class** → شامل Template Method
- **Template Method** → ترتیب اجرای مراحل الگوریتم
- **Abstract/Virtual Methods** → مراحلی که subclasses پیاده‌سازی می‌کنند
- **Concrete Classes** → پیاده‌سازی مراحل خاص

---

# مثال C#

### کلاس پایه (Template)

```csharp
public abstract class ReportGenerator
{
    public void GenerateReport()
    {
        FetchData();
        ProcessData();
        ExportReport();
    }

    protected void FetchData()
    {
        Console.WriteLine("Fetching data...");
    }

    protected void ProcessData()
    {
        Console.WriteLine("Processing data...");
    }

    protected abstract void ExportReport();
}
```

متد **GenerateReport** همان **Template Method** است که ترتیب مراحل را مشخص می‌کند.

---

# کلاس‌های فرزند

### PDF Report

```csharp
public class PdfReport : ReportGenerator
{
    protected override void ExportReport()
    {
        Console.WriteLine("Exporting report as PDF");
    }
}
```

---

### Excel Report

```csharp
public class ExcelReport : ReportGenerator
{
    protected override void ExportReport()
    {
        Console.WriteLine("Exporting report as Excel");
    }
}
```

---

# استفاده

```csharp
class Program
{
    static void Main()
    {
        ReportGenerator pdf = new PdfReport();
        pdf.GenerateReport();

        Console.WriteLine();

        ReportGenerator excel = new ExcelReport();
        excel.GenerateReport();
    }
}
```

# مزایا

- جلوگیری از تکرار کد
- کنترل ترتیب اجرای الگوریتم
- رعایت **Open/Closed Principle**
- امکان تغییر بخشی از الگوریتم بدون تغییر کل آن

---

# معایب

- وابستگی زیاد به **inheritance**
- تغییر در کلاس پایه ممکن است همه subclassها را تحت تأثیر قرار دهد

---

# مثال‌های واقعی

- **ASP.NET Core Middleware Pipeline**
- **Entity Framework SaveChanges workflow**
- **Data processing pipelines**
- **Build processes**

---

# تفاوت Template Method با Strategy

**Template Method**

- مبتنی بر **inheritance**
- الگوریتم در کلاس پایه تعریف می‌شود

**Strategy**

- مبتنی بر **composition**
- الگوریتم قابل تعویض در runtime است
