تعریف **Fanout Pattern** الگویی در سیستم‌های **event‑driven / messaging** است که در آن **یک پیام به چند مصرف‌کننده (consumer) مختلف به‌طور همزمان ارسال می‌شود**.

به بیان ساده:

> یک producer یک event منتشر می‌کند و آن event به چند سرویس مختلف پخش (broadcast) می‌شود.

---

## ایده اصلی

```
          ┌─────────────┐
          │   Producer  │
          └──────┬──────┘
                 │
                 ▼
             Fanout
              Exchange
        ┌────────┼────────┐
        ▼        ▼        ▼
   Service A  Service B  Service C
```

یک پیام → چند سرویس آن را دریافت می‌کنند.

---

## مثال واقعی

فرض کنید کاربر ثبت‌نام می‌کند.

event:

```
UserRegistered
```

چند سرویس باید واکنش نشان دهند:

- Email Service → ارسال ایمیل خوش‌آمد
- Analytics Service → ثبت در آمار
- Notification Service → ارسال نوتیفیکیشن

در Fanout همه این سرویس‌ها **همزمان event را دریافت می‌کنند**.

---

# مثال ساده در #C

فرض کنیم یک EventBus ساده داریم.

## Event

```csharp
public class UserRegistered
{
    public int UserId { get; set; }
}
```

---

## Publisher

```csharp
public class UserService
{
    private readonly IEventBus _eventBus;

    public UserService(IEventBus eventBus)
    {
        _eventBus = eventBus;
    }

    public void RegisterUser(int userId)
    {
        Console.WriteLine("User created");

        _eventBus.Publish(new UserRegistered
        {
            UserId = userId
        });
    }
}
```

---

## چند Consumer

### Email Service

```csharp
public class EmailService
{
    public void Handle(UserRegistered evt)
    {
        Console.WriteLine("Send welcome email");
    }
}
```

### Analytics Service

```csharp
public class AnalyticsService
{
    public void Handle(UserRegistered evt)
    {
        Console.WriteLine("Track user registration");
    }
}
```

### Notification Service

```csharp
public class NotificationService
{
    public void Handle(UserRegistered evt)
    {
        Console.WriteLine("Send notification");
    }
}
```

وقتی event منتشر شود:

```
UserRegistered
```

هر سه سرویس آن را دریافت می‌کنند.

---

# نمونه واقعی در RabbitMQ

در RabbitMQ یک **Fanout Exchange** وجود دارد.

```
Producer → Fanout Exchange → Queue1
                            → Queue2
                            → Queue3
```

Fanout exchange پیام را **به تمام queueهای متصل broadcast می‌کند**.

---

# تفاوت Fanout با سایر Messaging Patternها

**Fanout**

- ویژگی broadcast
- همه مصرف‌کننده‌ها پیام را می‌گیرند

**Work Queue**

- هر پیام فقط به **یک worker**

**Routing / Topic**

- پیام بر اساس **routing key** یا **topic** ارسال می‌شود

---

# خلاصه در یک جمله

الگوی **Fanout Pattern یعنی یک پیام از یک producer منتشر شود و به‌صورت broadcast به چند consumer مختلف ارسال شود.**
