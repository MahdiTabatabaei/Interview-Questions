تعریف **Service Locator** الگویی است که در آن کلاس‌ها وابستگی‌های خود را از یک **مرکز سراسری (Service Locator)** دریافت می‌کنند، به‌جای اینکه این وابستگی‌ها از بیرون به آن‌ها **تزریق (Dependency Injection)** شوند.

به همین دلیل اغلب به عنوان [[anti‑pattern]] شناخته می‌شود، چون وابستگی‌ها را **پنهان** می‌کند.


---

## مثال ساده در #C

### Service Locator

```csharp
public static class ServiceLocator
{
    private static readonly Dictionary<Type, object> _services = new();

    public static void Register<T>(T service)
    {
        _services[typeof(T)] = service;
    }

    public static T Resolve<T>()
    {
        return (T)_services[typeof(T)];
    }
}
```

---

### یک سرویس

```csharp
public interface IMessageService
{
    void Send(string message);
}

public class EmailService : IMessageService
{
    public void Send(string message)
    {
        Console.WriteLine("Email: " + message);
    }
}
```

---

### استفاده از Service Locator

```csharp
public class Notification
{
    public void Notify(string message)
    {
        var service = ServiceLocator.Resolve<IMessageService>();
        service.Send(message);
    }
}
```

---

### ثبت سرویس

```csharp
ServiceLocator.Register<IMessageService>(new EmailService());

var notification = new Notification();
notification.Notify("Hello");
```

---

# مشکل Service Locator

کلاس `Notification` ظاهراً **هیچ وابستگی‌ای ندارد**:

```csharp
public class Notification
{
}
```

اما در واقع **به IMessageService وابسته است**.  
این وابستگی **مخفی** شده است.

مشکلات:

- وابستگی‌ها مشخص نیستند
- تست‌نویسی سخت‌تر
- ایجاد coupling زیاد
- نقض اصل **Dependency Inversion**

---

# روش بهتر: Dependency Injection

به‌جای Service Locator:

```csharp
public class Notification
{
    private readonly IMessageService _service;

    public Notification(IMessageService service)
    {
        _service = service;
    }

    public void Notify(string message)
    {
        _service.Send(message);
    }
}
```

استفاده:

```csharp
var notification = new Notification(new EmailService());
```

---

# خلاصه در یک جمله

الگوی **Service Locator یعنی کلاس‌ها وابستگی‌های خود را از یک locator مرکزی می‌گیرند، اما چون وابستگی‌ها را پنهان می‌کند معمولاً به‌عنوان anti‑pattern در نظر گرفته می‌شود.**
