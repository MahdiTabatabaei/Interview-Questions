در **Saga Pattern با State Machine**، هر Saga به‌صورت یک **ماشین حالت (State Machine)** مدل می‌شود که مراحل مختلف یک فرآیند توزیع‌شده را به شکل **stateها و eventها** مدیریت می‌کند.

ایده اصلی:  
هر مرحله از Saga یک **State** است و با دریافت **Event** به state بعدی منتقل می‌شود. اگر خطایی رخ دهد، **transition به حالت جبرانی (compensation)** انجام می‌شود.

این روش در سیستم‌های event‑driven خیلی رایج است (مثلاً با **MassTransit + Automatonymous** در .NET).

---

# مثال سناریو
فرض کنید فرآیند سفارش داریم:

1. Order Created  
2. Payment Processed  
3. Inventory Reserved  
4. Order Completed  

اگر پرداخت fail شود → **Order Cancelled**

---

# مدل Saga State

```csharp
public class OrderSagaState
{
    public Guid CorrelationId { get; set; }

    public string CurrentState { get; set; }

    public int OrderId { get; set; }
}
```

---

# تعریف Event ها

```csharp
public record OrderCreated(Guid CorrelationId, int OrderId);

public record PaymentCompleted(Guid CorrelationId);

public record PaymentFailed(Guid CorrelationId);

public record InventoryReserved(Guid CorrelationId);
```

---

# State Machine

(نمونه ساده شبیه MassTransit)

```csharp
using MassTransit;

public class OrderStateMachine : MassTransitStateMachine<OrderSagaState>
{
    public State AwaitingPayment { get; private set; }
    public State AwaitingInventory { get; private set; }
    public State Completed { get; private set; }

    public Event<OrderCreated> OrderCreated { get; private set; }
    public Event<PaymentCompleted> PaymentCompleted { get; private set; }
    public Event<PaymentFailed> PaymentFailed { get; private set; }
    public Event<InventoryReserved> InventoryReserved { get; private set; }

    public OrderStateMachine()
    {
        InstanceState(x => x.CurrentState);

        Initially(
            When(OrderCreated)
                .Then(context =>
                {
                    context.Saga.OrderId = context.Message.OrderId;
                })
                .TransitionTo(AwaitingPayment)
        );

        During(AwaitingPayment,
            When(PaymentCompleted)
                .TransitionTo(AwaitingInventory),

            When(PaymentFailed)
                .Finalize()
        );

        During(AwaitingInventory,
            When(InventoryReserved)
                .TransitionTo(Completed)
                .Finalize()
        );
    }
}
```

---

# جریان اجرا

```
Initial
   │
   ▼
OrderCreated
   │
   ▼
AwaitingPayment
   │
   ├─ PaymentCompleted → AwaitingInventory
   │
   └─ PaymentFailed → Cancel / End
                         │
                         ▼
                   AwaitingInventory
                         │
                         ▼
                 InventoryReserved
                         │
                         ▼
                     Completed
```

# چرا State Machine برای Saga خوب است؟

مزایا:

- **مدل‌سازی واضح جریان فرآیند**
- مدیریت آسان **eventهای async**
- امکان تعریف **compensation**
- مناسب برای سیستم‌های **event-driven microservices**

---

# مثال واقعی در .NET

- **MassTransit Saga State Machine**
- **NServiceBus Saga**
- **Dapr Workflows**
- **Temporal / Durable Functions**

# خلاصه در یک جمله

**در Saga با State Machine، کل فرآیند توزیع‌شده به مجموعه‌ای از stateها و eventها تبدیل می‌شود که با هر event به state بعدی transition می‌کند و در صورت خطا عملیات جبرانی انجام می‌دهد.**
