تعریف **Data Mapper** الگویی است که در آن یک لایه جداگانه مسئول **انتقال داده بین Objectهای دامنه (Domain Objects) و دیتابیس** است.  
در این الگو **مدل‌ها هیچ اطلاعی از دیتابیس ندارند**.

این برعکس **Active Record** است که در آن مدل خودش عملیات دیتابیس را انجام می‌دهد.

---

## ایده اصلی

```
Domain Model  <---->  Data Mapper  <---->  Database
```

- Domain Model → فقط منطق دامنه
- Data Mapper → تبدیل Object ↔ Database
- Database → ذخیره داده

---

# مثال در C#

## Domain Model (هیچ کد دیتابیسی ندارد)

```csharp
public class User
{
    public int Id { get; set; }
    public string Name { get; set; }
}
```

---

# Data Mapper

```csharp
public class UserMapper
{
    private readonly string _connectionString;

    public UserMapper(string connectionString)
    {
        _connectionString = connectionString;
    }

    public User Find(int id)
    {
        using var conn = new SqlConnection(_connectionString);
        conn.Open();

        var cmd = new SqlCommand("SELECT Id, Name FROM Users WHERE Id=@Id", conn);
        cmd.Parameters.AddWithValue("@Id", id);

        using var reader = cmd.ExecuteReader();

        if (!reader.Read()) return null;

        return new User
        {
            Id = (int)reader["Id"],
            Name = (string)reader["Name"]
        };
    }

    public void Insert(User user)
    {
        using var conn = new SqlConnection(_connectionString);
        conn.Open();

        var cmd = new SqlCommand("INSERT INTO Users(Name) VALUES(@Name)", conn);
        cmd.Parameters.AddWithValue("@Name", user.Name);

        cmd.ExecuteNonQuery();
    }
}
```

---

# استفاده

```csharp
var mapper = new UserMapper("connection-string");

var user = new User
{
    Name = "Ali"
};

mapper.Insert(user);

var loadedUser = mapper.Find(1);
```

در اینجا:

- کلاس `User` هیچ ارتباطی با دیتابیس ندارد  
- تمام منطق دیتابیس در `UserMapper` است

---

# مزایا

- جداسازی کامل Domain و Database
- تست‌پذیری بهتر
- مناسب برای **DDD و سیستم‌های پیچیده**
- رعایت بهتر **Single Responsibility**

---

# معایب

- پیاده‌سازی پیچیده‌تر
- کد بیشتری نسبت به Active Record

---

# نمونه واقعی در .NET

بسیاری از ORMها از Data Mapper استفاده می‌کنند:

- **Entity Framework Core**
- **NHibernate**
- **Dapper (نسبتاً)**

مثلاً EF Core:

```csharp
var user = context.Users.Find(1);
```

در پشت صحنه EF نقش **Data Mapper** را بازی می‌کند.

# خلاصه در یک جمله

الگوی **Data Mapper یعنی یک لایه جدا مسئول تبدیل و انتقال داده بین Objectهای دامنه و دیتابیس باشد، بدون اینکه مدل‌ها از دیتابیس خبر داشته باشند.**
