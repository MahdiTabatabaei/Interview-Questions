درواقع **Factory Pattern** یک الگوی **Creational** است که برای **ساختن اشیاء بدون مشخص کردن کلاس دقیق آن‌ها** استفاده می‌شود.

ایده اصلی:  
به‌جای اینکه در کد مستقیماً از `new` استفاده کنیم، **یک کلاس Factory مسئول ساخت شیء می‌شود**.

---

## مشکل بدون Factory

فرض کنید سیستم ارسال پیام داریم:

```csharp
if(type == "email")
{
    var message = new EmailMessage();
}
else if(type == "sms")
{
    var message = new SmsMessage();
}
```

مشکلات:

- وابستگی زیاد به کلاس‌ها
- افزایش `if/switch`
- اضافه کردن نوع جدید سخت می‌شود

---

# راه‌حل: Factory Pattern

یک کلاس **Factory** می‌سازیم که وظیفه ساخت اشیاء را دارد.

---

# مثال کامل در C#

## Interface

```csharp
public interface IMessage
{
    void Send(string message);
}
```

---

## کلاس‌های واقعی

```csharp
public class EmailMessage : IMessage
{
    public void Send(string message)
    {
        Console.WriteLine("Sending Email: " + message);
    }
}

public class SmsMessage : IMessage
{
    public void Send(string message)
    {
        Console.WriteLine("Sending SMS: " + message);
    }
}
```

---

# Factory Class

```csharp
public class MessageFactory
{
    public static IMessage CreateMessage(string type)
    {
        if (type == "email")
            return new EmailMessage();

        if (type == "sms")
            return new SmsMessage();

        throw new Exception("Invalid type");
    }
}
```

---

# استفاده

```csharp
class Program
{
    static void Main()
    {
        IMessage message = MessageFactory.CreateMessage("email");
        message.Send("Hello World");
    }
}
```

---

# نتیجه

کد Client دیگر وابسته به کلاس‌های واقعی نیست:

```csharp
IMessage message = MessageFactory.CreateMessage("email");
```

نه:

```csharp
new EmailMessage();
```

---

# مزایا

- کاهش **Coupling**
- مخفی کردن منطق ساخت شیء
- رعایت **Open/Closed Principle**
- قابل توسعه

---

# معایب

- افزایش تعداد کلاس‌ها
- اگر Factory بزرگ شود پیچیده می‌شود

---

# کاربردهای واقعی

- Logger Factory
- Database Provider Factory
- Object Creation در Frameworkها
- Dependency Injection Container

---

# نکته مهم

در عمل چیزی که اغلب در پروژه‌ها استفاده می‌شود:

**Factory Method Pattern** است (نسخه پیشرفته‌تر Factory).

---

✅ خلاصه:

درواقع **Factory Pattern ساخت اشیاء را به یک کلاس جداگانه واگذار می‌کند تا وابستگی به کلاس‌های واقعی کاهش یابد.**
