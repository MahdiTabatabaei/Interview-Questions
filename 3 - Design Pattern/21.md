الگوی **State** یک الگوی طراحی از نوع **Behavioral** است که اجازه می‌دهد **رفتار یک شیء با تغییر وضعیت (State) داخلی آن تغییر کند**، بدون اینکه کد پر از `if` یا `switch` شود.

به بیان ساده:  
شیء وقتی state آن عوض می‌شود **انگار کلاسش عوض شده است** و رفتار متفاوتی نشان می‌دهد.

---

## مشکل بدون State Pattern

فرض کنید یک **Order** داریم:

```csharp
public class Order
{
    public string State;

    public void Next()
    {
        if (State == "New")
            State = "Paid";
        else if (State == "Paid")
            State = "Shipped";
        else if (State == "Shipped")
            State = "Delivered";
    }
}
```

مشکل‌ها:

- `if` و `switch` زیاد
- سخت شدن توسعه
- نقض **Open/Closed Principle**

State Pattern این مشکل را حل می‌کند.

---

# ساختار State Pattern

اجزا:

- **Context** → شیء اصلی که state دارد
- **State (interface)** → تعریف رفتار
- **ConcreteState** → پیاده‌سازی stateهای مختلف

---

# مثال C#

یک **سفارش (Order)** داریم با stateهای:

- New
- Paid
- Shipped

---

## State Interface

```csharp
public interface IOrderState
{
    void Next(Order order);
    void PrintStatus();
}
```

---

## Concrete States

### NewState

```csharp
public class NewState : IOrderState
{
    public void Next(Order order)
    {
        order.SetState(new PaidState());
    }

    public void PrintStatus()
    {
        Console.WriteLine("Order is New");
    }
}
```

---

### PaidState

```csharp
public class PaidState : IOrderState
{
    public void Next(Order order)
    {
        order.SetState(new ShippedState());
    }

    public void PrintStatus()
    {
        Console.WriteLine("Order is Paid");
    }
}
```

---

### ShippedState

```csharp
public class ShippedState : IOrderState
{
    public void Next(Order order)
    {
        Console.WriteLine("Order already shipped");
    }

    public void PrintStatus()
    {
        Console.WriteLine("Order is Shipped");
    }
}
```

---

## Context

```csharp
public class Order
{
    private IOrderState state;

    public Order()
    {
        state = new NewState();
    }

    public void SetState(IOrderState state)
    {
        this.state = state;
    }

    public void Next()
    {
        state.Next(this);
    }

    public void PrintStatus()
    {
        state.PrintStatus();
    }
}
```

---

# استفاده

```csharp
class Program
{
    static void Main()
    {
        Order order = new Order();

        order.PrintStatus();

        order.Next();
        order.PrintStatus();

        order.Next();
        order.PrintStatus();
    }
}
```

---

## خروجی

```
Order is New
Order is Paid
Order is Shipped
```

---

# مزایا

- حذف `if / switch` های بزرگ
- رعایت **Open/Closed Principle**
- اضافه کردن state جدید بدون تغییر کد قبلی
- کد تمیزتر و قابل نگهداری‌تر

---

# معایب

- تعداد کلاس‌ها زیاد می‌شود
- برای stateهای ساده ممکن است overengineering باشد

---

# مثال‌های واقعی

- **Workflow systems**
- **Order processing**
- **Game characters states**
- **Connection states (Connected / Disconnected)**
- **Document states (Draft / Published / Archived)**

# تفاوت State و Strategy

این دو خیلی شبیه هستند ولی هدفشان فرق دارد.

**Strategy**

- انتخاب الگوریتم
- تصمیم توسط client گرفته می‌شود

**State**

- رفتار با تغییر وضعیت داخلی عوض می‌شود
- خود object state را تغییر می‌دهد
