تعریف **Anti‑pattern** یعنی یک راه‌حل یا الگوی رایج که در ظاهر درست به نظر می‌رسد اما در عمل **باعث مشکلات طراحی، پیچیدگی یا نگهداری سخت‌تر سیستم می‌شود**.

به بیان ساده:  
درواقع **Anti‑pattern = یک روش بدِ شناخته‌شده برای حل یک مشکل.**

### مثال ساده در #C

فرض کنید یک کلاس همه‌چیز را انجام دهد:

```csharp
public class UserManager
{
    public void SaveUser()
    {
        // validation
        // database access
        // sending email
        // logging
    }
}
```

اینجا یک **God Object** ساخته‌ایم که یک **anti‑pattern** است چون:
- مسئولیت‌های زیادی دارد
- تست سخت می‌شود
- نگهداری سخت می‌شود

---

### چند Anti‑pattern معروف

- **God Object** → یک کلاس همه کاره  
- **Spaghetti Code** → کد درهم و بدون ساختار  
- **Copy-Paste Programming** → تکرار زیاد کد  
- **Service Locator** → پنهان کردن وابستگی‌ها  
- **Golden Hammer** → استفاده از یک تکنولوژی برای همه چیز

---

### خلاصه در یک جمله

الگوی **Anti‑pattern یعنی یک راه‌حل رایج اما اشتباه در طراحی نرم‌افزار که تجربه نشان داده باعث مشکلات بیشتر می‌شود.**
