در سیستم‌های **OAuth2 / OpenID Connect** (مثل **Keycloak**) دو روش رایج برای اعتبارسنجی توکن JWT وجود دارد:

1. **JWT Self‑Contained**
2. **JWT Introspection**

هر دو برای بررسی معتبر بودن Access Token استفاده می‌شوند، اما نحوه بررسی کاملاً متفاوت است.

---

# 1. JWT Self‑Contained

در این روش، **تمام اطلاعات لازم داخل خود JWT قرار دارد** و سرویس دریافت‌کننده می‌تواند **بدون تماس با سرور احراز هویت (Keycloak)** توکن را بررسی کند.

JWT شامل این بخش‌هاست:

- Header
- Payload (claims)
- Signature

مثال Payload:

```json
{
  "sub": "123456",
  "preferred_username": "ali",
  "email": "ali@test.com",
  "realm_access": {
    "roles": ["admin"]
  },
  "exp": 1715000000,
  "iss": "https://auth.example.com/realms/myrealm"
}
```

سرویس فقط کافیست:

1. امضای JWT را با **Public Key کیکلاک** بررسی کند
2. تاریخ انقضا (exp) را چک کند

و دیگر نیاز به تماس با Keycloak نیست.

---

## مثال در Keycloak

کلید عمومی از این آدرس گرفته می‌شود:

```
https://keycloak.example.com/realms/{realm}/protocol/openid-connect/certs
```

---

## مثال در C# (.NET)

در ASP.NET Core خیلی ساده انجام می‌شود:

```csharp
builder.Services.AddAuthentication("Bearer")
    .AddJwtBearer("Bearer", options =>
    {
        options.Authority = "https://keycloak.example.com/realms/myrealm";
        options.Audience = "myclient";
        options.RequireHttpsMetadata = true;
    });
```

در این حالت:

- برنامه شما **public key کیکلاک را می‌گیرد**
- امضای JWT را **لوکال verify می‌کند**
- هیچ درخواست اضافی به Keycloak نمی‌زند.

---

## مزایا

- بسیار سریع
- بدون درخواست شبکه
- مناسب برای **Microservices**

---

## مشکل

اگر توکن **revoked شود** یا کاربر logout کند،  
سرویس شما تا زمان **expire شدن JWT** متوجه نمی‌شود.

---

# 2. JWT Introspection

در این روش سرویس شما **برای هر درخواست از Keycloak می‌پرسد توکن معتبر است یا نه**.

یعنی:

```
API -> Keycloak
        /introspect
```

---

## Endpoint در Keycloak

```
/realms/{realm}/protocol/openid-connect/token/introspect
```

---

## درخواست

```http
POST /realms/myrealm/protocol/openid-connect/token/introspect
```

Body:

```
token=eyJhbGciOiJSUzI1NiIs...
```

Authentication:

```
client_id
client_secret
```

---

## پاسخ

```json
{
  "active": true,
  "username": "ali",
  "exp": 1715000000,
  "scope": "profile email"
}
```

اگر:

```
active = false
```

یعنی توکن معتبر نیست.

---

## مثال در C#

```csharp
var client = new HttpClient();

var request = new HttpRequestMessage(
    HttpMethod.Post,
    "https://keycloak.example.com/realms/myrealm/protocol/openid-connect/token/introspect"
);

var body = new Dictionary<string, string>
{
    { "token", accessToken },
    { "client_id", "myclient" },
    { "client_secret", "secret" }
};

request.Content = new FormUrlEncodedContent(body);

var response = await client.SendAsync(request);

var result = await response.Content.ReadAsStringAsync();
```

---

## مزایا

- اگر کاربر **logout کند** توکن فوراً invalid می‌شود
- و revoke شدن توکن فوراً اعمال می‌شود
- امنیت بیشتر

---

## مشکل

- برای هر درخواست باید **network call** به Keycloak زده شود
- میزان latency بالا
- برای سیستم‌های **High traffic** مناسب نیست

---

# مقایسه ساده

| ویژگی | Self-contained JWT | Introspection |
|---|---|---|
| نیاز به تماس با Keycloak | ❌ ندارد | ✅ دارد |
| سرعت | بسیار سریع | کندتر |
| امکان revoke فوری | ❌ ندارد | ✅ دارد |
| مناسب Microservice | ✅ بله | ❌ معمولاً نه |
| load روی auth server | کم | زیاد |

---

# در Keycloak کدام معمول‌تر است؟

در **۹۰٪ سیستم‌ها** از:

**Self-contained JWT**

استفاده می‌شود.

چون:

- scalable
- سریع
- مناسب معماری microservices

---

# معماری واقعی که شرکت‌ها استفاده می‌کنند

معمولاً:

- **Access Token = JWT self-contained**
- **Refresh Token = introspection / database**
