درواقع `Access Token` و `Refresh Token` هر دو در OAuth2 / OpenID Connect استفاده می‌شوند، ولی هدفشان متفاوت است.

---

# تصویر کلی

وقتی کاربر login می‌کند:

```text
User → Keycloak
```

Keycloak معمولاً دو توکن برمی‌گرداند:

```json
{
  "access_token": "...",
  "refresh_token": "..."
}
```

---

# 1. تعریف Access Token چیست؟

توکنی است که:

✅ برای دسترسی به API استفاده می‌شود.

مثلاً:

```http
Authorization: Bearer eyJhbGciOi...
```

API این توکن را بررسی می‌کند و اگر معتبر بود درخواست را قبول می‌کند.

---

# داخل Access Token چیست؟

معمولاً:

```json
{
  "sub": "123",
  "preferred_username": "ali",
  "roles": ["admin"],
  "exp": 1715000000
}
```

---

# ویژگی‌های Access Token

| ویژگی | توضیح |
|---|---|
| عمر کوتاه | معمولاً 5 تا 15 دقیقه |
| برای API | بله |
| شامل claim | بله |
| زیاد استفاده می‌شود | بله |
| امنیت | باید کوتاه‌عمر باشد |

---

# چرا کوتاه‌عمر؟

چون اگر دزدیده شود:

```text
Attacker → API
```

می‌تواند تا زمان expire از API استفاده کند.

پس باید سریع expire شود.

---

# 2. تعریف Refresh Token چیست؟

درواقع Refresh Token برای گرفتن Access Token جدید استفاده می‌شود.

یعنی:

```text
Access Token Expired
        ↓
Frontend sends Refresh Token
        ↓
Keycloak issues new Access Token
```

---

# مثال

## ابتدا login

Keycloak:

```json
{
  "access_token": "AAA",
  "refresh_token": "BBB"
}
```

---

## بعد Access Token منقضی می‌شود

Frontend:

```http
POST /token
grant_type=refresh_token
refresh_token=BBB
```

---

## Keycloak پاسخ می‌دهد

```json
{
  "access_token": "NEW_AAA",
  "refresh_token": "NEW_BBB"
}
```

---

# ویژگی‌های Refresh Token

| ویژگی | توضیح |
|---|---|
| عمر بلندتر | مثلاً چند روز |
| برای API نیست | ❌ |
| فقط برای auth server | ✅ |
| امنیت بسیار مهم | ✅ |
| معمولاً در DB/session کنترل می‌شود | ✅ |

---

# تفاوت اصلی

| Access Token | Refresh Token |
|---|---|
| دسترسی به API | گرفتن توکن جدید |
| کوتاه‌عمر | بلندعمر |
| زیاد ارسال می‌شود | کمتر استفاده می‌شود |
| به API می‌رود | فقط به Auth Server |
| معمولاً JWT | ممکن است opaque باشد |

---

# جریان کامل

```text
1. Login
   ↓
2. Access Token + Refresh Token
   ↓
3. API calls with Access Token
   ↓
4. Access Token expires
   ↓
5. Refresh Token sent to Keycloak
   ↓
6. New Access Token issued
```

---

# چرا Refresh Token مهم است؟

بدون Refresh Token:

- کاربر هر 5 دقیقه باید login کند.

با Refresh Token:

✅ تجربه کاربری خوب می‌شود.

---

# در Keycloak

معمولاً:

| Token | Default |
|---|---|
| Access Token | 5 دقیقه |
| Refresh Token | 30 دقیقه یا بیشتر |
| SSO Session | چند ساعت |

---

# امنیت مهم

## Access Token لو رفت

خطر محدود است چون کوتاه‌عمر است.

---

## Refresh Token لو برود

خیلی خطرناک‌تر است.

چون attacker می‌تواند:

```text
refresh forever
```

توکن جدید بگیرد.

---

# برای همین:

اطلاعات Refresh Token را:

✅ امن نگه می‌دارند  
✅ بصورت HttpOnly Cookie  
✅ یا Secure Cookie  
✅ هرگز داخل localStorage در سیستم حساس

---

# در معماری SPA

خیلی مهم است.

---

# آیا Refresh Token هم JWT است؟

گاهی بله، گاهی opaque.

در Keycloak معمولاً encrypted/opaque-like behavior دارد.

ولی Access Token معمولاً JWT است.

---

# فرایند Logout چگونه کار می‌کند؟

وقتی logout می‌کنی:

✅ مقدار Refresh Token invalid می‌شود.

و چون Access Token کوتاه‌عمر است:
بعد از چند دقیقه کامل logout می‌شود.

---

# چرا Access Token را revoke نمی‌کنند؟

چون Self-contained JWT است.

وقتی صادر شد:
تا expire معتبر است.

برای همین کوتاه‌عمر طراحی می‌شود.

---

# بهترین Practice

معمولاً:

| Token | عمر |
|---|---|
| Access Token | 5-15 دقیقه |
| Refresh Token | چند روز |
| Rotate Refresh Token | فعال |

---

# Refresh Token Rotation

هر بار refresh:

```text
OLD refresh token → invalid
NEW refresh token → issued
```

این امنیت را خیلی بالا می‌برد.

و Keycloak هم پشتیبانی می‌کند.
