در معماری مبتنی بر **Keycloak / Identity Provider** یا حتی Authentication سفارشی، جلوگیری از **Brute Force Attack** (حدس‌زدن رمز با تلاش‌های زیاد) یکی از مهم‌ترین بخش‌های امنیت است.  
برای جلوگیری از این حمله، ۸ لایه ثابت وجود دارد که هر سیستم حرفه‌ای باید رعایت کند.

در ادامه *هم شیوه‌های استاندارد Keycloak* را می‌گویم هم *روش‌های عمومی برای هر سیستم*.

---

# ۱) جلوگیری از Brute Force در Keycloak (Built‑in)

Keycloak یک ماژول کامل و داخلی برای تشخیص حملات Brوتفورس دارد.  
در نسخه Admin Console می‌توانی تنظیمات زیر را فعال کنی:

## **۱.۱ Brute Force Detection**
منوی:
Realm Settings → Security Defenses → Brute Force Detection

موارد قابل تنظیم:

- *Max Login Failures*  
  تعداد تلاش اشتباه قبل از مسدود شدن

- *Wait Increment*  
  مدت زمان انتظار قبل از تلاش بعدی

- *Quick Login Check*  
  جلوگیری از ورودهای سریع پشت سر هم

- *Minimum Quick Login Wait*  
  حداقل تأخیر

- *Max Failure Wait*  
  حداکثر مدت قفل حساب

- *Permanent Lockout*  
  امکان قفل شدن دائمی حساب

- *Failure Reset Time*  
  بعد از چند دقیقه تلاش‌های قبلی ریست شوند

### Keycloak چگونه تشخیص می‌دهد؟
- بر اساس **IP Address**
- بر اساس **Username**
- بر اساس **Device + IP Fingerprint**
- (در نسخه‌های جدید) بر اساس **تعداد درخواست‌های فرم لاگین**

این کار باعث می‌شود:
- حملات Password Spray ناکام بمانند  
- حملات Dictionary Attack بسیار سخت شود  
- Botها نتوانند سریع رمز را تست کنند  

---

# ۲) جلوگیری از Brute Force در API Gateway (مثلاً Traefik)

Traefik حالت Built‑in برای Brute Force ندارد  
اما از طریق Middlewareهای زیر قابل پیاده‌سازی است:

## **۲.۱ Rate Limiting**
در Traefik:

```
traefik.http.middlewares.ratelimit.rateSet.login.average=5
traefik.http.middlewares.ratelimit.rateSet.login.period=1m
```

یا:

- هر IP فقط ۵ بار در دقیقه  
- تلاش‌های بیشتر → 429 Too Many Requests

## **۲.۲ Forward Auth / Fail2Ban Integration**
Traefik می‌تواند اطلاعات Failed Login را به Fail2Ban بفرستد
و Fail2Ban IP حمله‌کننده را بلاک کند.

---

# ۳) جلوگیری از Brute Force در سطح شبکه (Nginx, Firewall, Fail2Ban)

اگر Keycloak پشت Reverse Proxy مثل Nginx باشد:

## **۳.۱ Fail2Ban**
قوانین Fail2Ban:

- اگر یک IP در ۳۰ ثانیه، ۱۰ بار لاگین اشتباه داشت → ban 10 minutes  
- اگر ۵ بار ban شد → ban 24h  

## **۳.۲ WAF Rules (Cloudflare / AWS WAF)**
WAF می‌تواند:

- Pattern Bot را تشخیص دهد
- IP Reputation را بررسی کند
- Geo-Blocking انجام دهد

---

# ۴) جلوگیری از Brute Force در سطح اپلیکیشن

## **۴.۱ CAPTCHA بعد از چند تلاش اشتباه**
بعد از 3–5 تلاش ناموفق:

- Google reCAPTCHA v3  
- Cloudflare Turnstile  
- hCaptcha

## **۴.۲ تأخیر تصادفی (Random Backoff Delay)**
بعد از هر تلاش اشتباه:

- ۰.۵ تا ۲ ثانیه تأخیر اضافه کن
- این کار حمله Brute Force را تقریباً غیرممکن می‌کند

---

# ۵) جلوگیری در سطح حساب کاربر

## **۵.۱ MFA / 2FA**
با MFA فعال، حتی اگر رمز عبور دزدیده شود:

- کد OTP  
- Authenticator app  
- FIDO2  
- WebAuthn  

حمله Brute Force بی‌اثر می‌شود.

## **۵.۲ حساب Lockout**
بعد از تعداد مشخص تلاش ناموفق، حساب برای چند دقیقه قفل می‌شود.

---

# ۶) جلوگیری از Brute Force روی API (Password Grant / Token Endpoint)

در معماری‌های OAuth2، معمولاً Brute Force روی:

```
/protocol/openid-connect/token
```

اتفاق می‌افتد.

راهکار:

- محدود کردن این endpoint توسط Rate Limiter
- جلوگیری از Password Grant (اگر لازم نیست)
- استفاده از Client Secret قوی

---

# ۷) جلوگیری در سمت Frontend

## **۷.۱ محدود کردن Retry با Local Counter**
به محض چند بار تلاش اشتباه:

- نمایش CAPTCHA  
- دیس‌ابل کردن دکمه login  
- افزودن Delay UI

---

# ۸) مانیتورینگ و Alerting

باید همیشه مانیتور کنی:

- تعداد تلاش‌های ناموفق  
- spikeها در login failure  
- IPهای مشکوک  

با ابزارهایی مثل:

- Keycloak Events  
- ELK Stack  
- Prometheus + Grafana  
- Cloudflare Logs

# جمع‌بندی جواب کوتاه

برای جلوگیری از Brute Force:

- فعال‌سازی Brute Force Protection در Keycloak

- Fail2Ban در لایه سرور  
- CAPTCHA بعد از چند تلاش  
- تأخیر تصادفی
