در معماری **Microservices** دلیل اصلی استفاده از **IdentityServer (یا هر Authorization Server مثل Keycloak)** این است که **احراز هویت و صدور توکن را از سرویس‌های بیزینسی جدا کنیم و آن را به یک سرویس مرکزی بسپاریم.**

اگر این کار را نکنیم، هر Microservice مجبور می‌شود خودش:

- کاربر را authenticate کند  
- session نگه دارد  
- token صادر کند  
- login / logout را مدیریت کند  

که هم **ناامن** می‌شود هم **غیرقابل مدیریت**.

---

# مشکل اگر Identity Server نداشته باشیم

فرض کن سیستم ۱۰ Microservice دارد:

```
User Service
Order Service
Payment Service
Product Service
Notification Service
...
```

اگر Identity Server نباشد:

- هر سرویس باید **login endpoint** داشته باشد  
- هر سرویس باید **user database** داشته باشد  
- هر سرویس باید **password hashing** انجام دهد  
- هر سرویس باید **token صادر کند**

نتیجه:

- تکرار کد زیاد  
- مدیریت امنیت سخت  
- SSO غیرممکن  
- احتمال باگ امنیتی بالا

---

# راه حل: IdentityServer

در این حالت یک سرویس مرکزی داریم:

```
                +------------------+
                |  IdentityServer  |
                |  (Auth Server)   |
                +------------------+
                         |
                         |
User ---- login ----> IdentityServer
                         |
                         v
                    Access Token
                         |
                         v
        +---------+---------+---------+
        | Order   | Product | Payment |
        | Service | Service | Service |
        +---------+---------+---------+
```

کاربر فقط **یک بار login** می‌کند  
و یک **Access Token (JWT)** دریافت می‌کند.

بعد همه سرویس‌ها همین توکن را بررسی می‌کنند.

---

# مزایای استفاده از IdentityServer در Microservices

## 1️⃣ Single Sign-On (SSO)

کاربر یک بار login می‌کند و می‌تواند به چندین سرویس دسترسی داشته باشد.

مثال:

```
login -> IdentityServer
```

بعد می‌تواند:

```
/orders
/products
/payments
```

را بدون login مجدد استفاده کند.

---

## 2️⃣ جداسازی Authentication از Business Logic

Microserviceها باید فقط **منطق بیزینسی** داشته باشند.

نباید مسئول:

- login
- password
- MFA
- token issuing

باشند.

این‌ها در IdentityServer مدیریت می‌شوند.

---

## 3️⃣ استفاده از استانداردهای امنیتی

IdentityServer استانداردهای زیر را پیاده‌سازی می‌کند:

- OAuth2
- OpenID Connect
- JWT
- PKCE
- Refresh Token
- Token Revocation

پیاده‌سازی دستی این‌ها بسیار پیچیده و خطرناک است.

---

## 4️⃣ Stateless بودن سرویس‌ها

با JWT:

- هیچ sessionی در سرویس‌ها ذخیره نمی‌شود  
- هر درخواست همراه توکن است

API فقط:

```
validate token
```

را انجام می‌دهد.

این موضوع باعث می‌شود:

- scaling راحت‌تر شود
- load balancer ساده‌تر شود

---

## 5️⃣ افزایش امنیت

می‌توان قابلیت‌های امنیتی را در یک نقطه متمرکز پیاده کرد:

- MFA
- Brute Force protection
- Account lockout
- Social login
- device management
- token revocation

---

## 6️⃣ مدیریت دسترسی (Authorization)

IdentityServer می‌تواند اطلاعات دسترسی را داخل توکن قرار دهد:

```
role: admin
scope: order.read
permission: payment.create
```

Microserviceها از این اطلاعات برای کنترل دسترسی استفاده می‌کنند.

مثلاً:

```
Only admin can delete order
```

---

## 7️⃣ پشتیبانی از چند نوع Client

IdentityServer می‌تواند همزمان برای این‌ها توکن صادر کند:

- Web App
- SPA (React / Angular)
- Mobile App
- Server to Server
- IoT

# مقایسه معماری

### بدون IdentityServer

```
Client
  |
  v
Order Service  -> login
Product Service -> login
Payment Service -> login
```

هر سرویس auth خودش را دارد.

---

### با IdentityServer

```
Client
  |
  v
IdentityServer  -> login
  |
  v
JWT Token
  |
  v
API Gateway
  |
  +------ Order Service
  +------ Product Service
  +------ Payment Service
```

---

# چرا در Microservices خیلی مهم است؟

چون در Microservices:

- سرویس‌ها زیاد هستند
- سرویس‌ها مستقل deploy می‌شوند
- سیستم باید **stateless** باشد
- نیاز به **SSO** داریم

و IdentityServer دقیقاً برای همین سناریو طراحی شده است.

---

✅ خلاصه کوتاه:

در معماری Microservices از **IdentityServer** استفاده می‌کنیم تا:

- احراز هویت را **متمرکز** کنیم  
- **SSO** فراهم کنیم  
- **JWT Token** صادر کنیم  
- امنیت را استاندارد و قابل مدیریت کنیم  
- Microserviceها فقط روی **business logic** تمرکز کنند.
