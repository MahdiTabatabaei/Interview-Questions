## Cyclomatic Complexity چیست؟

درواقع **Cyclomatic Complexity (پیچیدگی سیکلوماتیک)** معیاری در مهندسی نرم‌افزار است که توسط **Thomas McCabe** معرفی شد و نشان می‌دهد یک قطعه کد چند **مسیر منطقی مستقل (independent paths)** برای اجرا دارد.

به زبان ساده:

> هرچه تعداد شاخه‌های تصمیم‌گیری (if، switch، loops و …) در کد بیشتر باشد، تعداد مسیرهای اجرای برنامه بیشتر شده و Cyclomatic Complexity افزایش می‌یابد.

این معیار معمولاً برای **متدها یا توابع** محاسبه می‌شود.

---

## چرا Cyclomatic Complexity مهم است؟

Cyclomatic Complexity یکی از شاخص‌های مهم **کیفیت کد (Code Quality)** است.

دلایل اهمیت:

- **افزایش سختی درک کد**  
  هرچه مسیرهای منطقی بیشتر باشند، فهم کد سخت‌تر می‌شود.

- **افزایش احتمال باگ**  
  مسیرهای زیاد یعنی حالت‌های مختلف اجرای برنامه که ممکن است تست نشده باشند.

- **افزایش هزینه تست**  
  حداقل تعداد تست لازم برابر با Cyclomatic Complexity است.

- **نگهداری سخت‌تر (Maintainability)**  
  تغییر در چنین کدی احتمال شکستن رفتارهای دیگر را بالا می‌برد.

---

## محدوده‌های رایج Cyclomatic Complexity

تقریباً این محدوده‌ها در ابزارهای تحلیل کد استفاده می‌شود:

- 1 – 10 → ساده و قابل قبول
- 11 – 20 → متوسط، نیاز به بازبینی
- 21 – 50 → پیچیده
- > 50 → بسیار پیچیده و خطرناک

---

## نحوه محاسبه Cyclomatic Complexity

دو روش رایج وجود دارد.

### روش فرمول گراف کنترل جریان

فرمول اصلی:

\[
M = E - N + 2P
\]

که در آن:

- **E** = تعداد Edge ها در Control Flow Graph  
- **N** = تعداد Node ها  
- **P** = تعداد Component های متصل (معمولاً 1)

اما در عمل برای برنامه‌نویسی از روش ساده‌تر استفاده می‌شود.

---

### روش ساده (شمارش تصمیم‌ها)

فرمول ساده:

\[
CC = \text{Number of Decision Points} + 1
\]

Decision Point ها شامل موارد زیر هستند:

- if
- else if
- switch case
- for
- foreach
- while
- do while
- catch
- && و ||
- ? : (ternary)

---

## مثال در C#

### کد با Cyclomatic Complexity بالا

```csharp
public int CalculateDiscount(Customer customer)
{
    int discount = 0;

    if (customer.IsPremium)
    {
        if (customer.Orders > 10)
        {
            discount = 20;
        }
        else
        {
            discount = 10;
        }
    }
    else
    {
        if (customer.Orders > 5)
        {
            discount = 5;
        }
        else
        {
            discount = 0;
        }
    }

    return discount;
}
```

### محاسبه Cyclomatic Complexity

Decision Points:

- if (customer.IsPremium)
- if (customer.Orders > 10)
- if (customer.Orders > 5)

بنابراین:

```
CC = 3 + 1 = 4
```

یعنی **۴ مسیر منطقی مستقل** در این متد وجود دارد.

# روش‌های کاهش Cyclomatic Complexity

## 1️⃣ Extract Method (تقسیم متد)

یکی از بهترین روش‌ها تقسیم متد به چند متد کوچک است.

### نسخه بهتر

```csharp
public int CalculateDiscount(Customer customer)
{
    if (customer.IsPremium)
        return GetPremiumDiscount(customer);

    return GetRegularDiscount(customer);
}

private int GetPremiumDiscount(Customer customer)
{
    return customer.Orders > 10 ? 20 : 10;
}

private int GetRegularDiscount(Customer customer)
{
    return customer.Orders > 5 ? 5 : 0;
}
```

مزایا:

- خوانایی بهتر
- تست ساده‌تر
- کاهش پیچیدگی هر متد

---

## 2️⃣ استفاده از Guard Clauses

به جای nested if ها، خروج زودتر انجام دهیم.

### کد پیچیده

```csharp
if(user != null)
{
    if(user.IsActive)
    {
        Process(user);
    }
}
```

### نسخه بهتر

```csharp
if (user == null) return;
if (!user.IsActive) return;

Process(user);
```

این کار **nested structure** را کاهش می‌دهد.

---

## 3️⃣ استفاده از Polymorphism

در بسیاری از موارد، شرط‌های زیاد را می‌توان با **Polymorphism** جایگزین کرد.

### کد بد

```csharp
public double CalculatePrice(CustomerType type)
{
    if(type == CustomerType.Regular)
        return 100;

    if(type == CustomerType.Premium)
        return 80;

    if(type == CustomerType.VIP)
        return 60;

    return 100;
}
```

### نسخه بهتر با Polymorphism

```csharp
public interface IPriceStrategy
{
    double Calculate();
}

public class RegularPrice : IPriceStrategy
{
    public double Calculate() => 100;
}

public class PremiumPrice : IPriceStrategy
{
    public double Calculate() => 80;
}
```

---

## 4️⃣ استفاده از Dictionary یا Lookup Table

به جای شرط‌های زیاد.

```csharp
var discounts = new Dictionary<string, int>
{
    {"Regular",0},
    {"Premium",10},
    {"VIP",20}
};

return discounts[customer.Type];
```

---

## 5️⃣ جایگزینی switch های بزرگ با Strategy Pattern

وقتی switch خیلی بزرگ شود، بهتر است از **Strategy Pattern** استفاده شود.

# جمع‌بندی

**Cyclomatic Complexity** نشان می‌دهد یک متد چند مسیر منطقی مستقل دارد.

فرمول ساده:

\[
CC = Decisions + 1
\]

مزایا استفاده از این معیار:

- سنجش کیفیت کد
- تخمین تعداد تست‌ها
- کاهش باگ‌ها
- افزایش maintainability

روش‌های کاهش آن:

- Extract Method
- Guard Clauses
- Polymorphism
- Dictionary / Lookup
- Strategy Pattern
- کاهش nested if
