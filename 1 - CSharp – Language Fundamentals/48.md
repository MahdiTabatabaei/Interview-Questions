بله ✅ به طور کلی **Garbage Collector فقط روی Heap کار می‌کند و کاری به Stack ندارد.**

اما بیایید دقیق‌تر بررسی کنیم چون این سؤال مصاحبه‌ای معمولاً **کمی عمیق‌تر پرسیده می‌شود.**

### دلیل

Stack:

- بستگی به scope-based
- وقتی متد تمام شود آزاد می‌شود

Heap:

- داشتن lifetime نامشخص
- نیاز به GC

---

# 1️⃣ بخش Stack چگونه مدیریت می‌شود؟

بخش **Stack توسط خود CLR و Scope متد مدیریت می‌شود** نه توسط GC.

وقتی یک متد تمام می‌شود:

- تمام متغیرهای Stack
- به صورت **خودکار و فوری حذف می‌شوند**

مثال:
```csharp

void Test()
{
    int x = 10;
}

```

وقتی متد `Test` تمام شود:

```markdown

Stack frame حذف می‌شود
x نیز حذف می‌شود

```

✅ نیازی به Garbage Collector نیست.

---

# 2️⃣ بخش Heap چگونه مدیریت می‌شود؟

در Heap اشیاء Reference Type ذخیره می‌شوند:

مثال:

```csharp

Person p = new Person();

```

در اینجا:

```markdown

Stack: p (reference)
Heap:  Person object

```

اگر reference از بین برود:

```csharp

p = null;

```

آن شیء در Heap **دیگر قابل دسترسی نیست** → **Garbage Collector آن را پاک می‌کند.**

---

# 3️⃣ نقش GC دقیقاً چیست؟

در این حالت Garbage Collector:

1. اشیائی را که **reference ندارند** پیدا می‌کند
2. آنها را از **Heap حذف می‌کند**
3. حافظه را **compact** می‌کند

---

# 4️⃣ رابطه Stack و GC

در این حالت GC مستقیماً Stack را پاک نمی‌کند، اما:

✅ از Stack برای **پیدا کردن referenceهای زنده (Root References)** استفاده می‌کند.

مثال:

```markdown

Stack → reference → Heap object

```

اگر reference در Stack وجود داشته باشد:

❌ در این حالت GC آن شیء را حذف نمی‌کند.

---

# مثال
```csharp

void Test()
{
    Person p = new Person();
}

```

جریان:
```markdown

Stack: p
Heap: Person

```

وقتی متد تمام شود:

```markdown

Stack حذف می‌شود
reference از بین می‌رود
object بدون reference می‌شود
→ GC در آینده آن را پاک می‌کند

```

# نکته مهم 

در این حالت Garbage Collector **Heap را مدیریت می‌کند ولی Root references را از اینجا بررسی می‌کند:**

- Stack
- Static fields
- CPU registers
- GC handles

---

# خلاصه

 کار Garbage Collector در .NET فقط حافظه Heap را مدیریت می‌کند و مسئول آزادسازی اشیاء Reference Type است. متغیرهای Stack به صورت خودکار هنگام خروج از Scope یا پایان متد حذف می‌شوند و GC در آن دخالتی ندارد. البته GC برای تشخیص اشیاء زنده، referenceها را در Stack نیز بررسی می‌کند.
