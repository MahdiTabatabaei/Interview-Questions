
> برنامه به صورت **دوره‌ای و مکرر چک کند** که آیا داده‌ای در صف آمده یا نه.

یعنی به جای اینکه سیستم به شما **خبر بدهد**، شما خودتان **مدام سؤال می‌کنید**.

---

### مثال ساده با Queue

فرض کن یک `Queue<T>` داری:

```csharp
var queue = new Queue<int>();

while(true)
{
    if(queue.Count > 0)
    {
        var item = queue.Dequeue();
        Process(item);
    }
}
```

اینجا چه اتفاقی می‌افتد؟

برنامه **مدام چک می‌کند**:

```
آیا چیزی در صف هست؟
آیا چیزی در صف هست؟
آیا چیزی در صف هست؟
...
```

این رفتار را می‌گویند **polling**.

---

### مشکل Polling

اگر صف خالی باشد:

- پردازش CPU الکی مصرف می‌شود
- نیاز به loop مدام اجرا می‌شود

برای همین بعضی‌ها این کار را می‌کنند:

```csharp
while(true)
{
    if(queue.Count > 0)
    {
        var item = queue.Dequeue();
        Process(item);
    }
    else
    {
        Thread.Sleep(50);
    }
}
```

یعنی:

- اگر چیزی نبود
- **کمی صبر کن**
- بعد دوباره چک کن

باز هم این **polling** محسوب می‌شود.

---

### چرا Channel بهتر است؟

ابزار `Channel` و ابزارهای async این مشکل را حل می‌کنند.

به جای polling:

```csharp
var item = await channel.Reader.ReadAsync();
```

اینجا:

- اگر داده نباشد
- درواقع thread **منتظر می‌ماند**
- وقتی داده رسید **automatically بیدار می‌شود**

بدون:

```
loop
poll
sleep
```

---

✅ خلاصه

مفهوم **poll یعنی:**

> برنامه به صورت مداوم و دوره‌ای بررسی کند که آیا داده یا event رخ داده یا نه.

در مقابل آن:

- **event-driven**
- **async await**
- **blocking wait**

قرار دارند که **کارآمدترند**.
