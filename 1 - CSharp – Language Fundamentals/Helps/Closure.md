
### تعریف : Closure چیست؟

تعریف Closure یعنی **یک تابع که به متغیرهای scope بیرونی خودش دسترسی دارد** و آن‌ها را نگه می‌دارد.

در C#، این پدیده معمولاً زمانی اتفاق می‌افتد که یک متد ناشناس (Lambda Expression یا Anonymous Method) به متغیرهای محلی (Local Variables) متد بیرونی ارجاع می‌دهد و این متد ناشناس به شکلی نگهداری می‌شود که Garbage Collector نتواند آن متغیرها را پاک کند.

مثال فرض کنید یک کلاس `Manager` داریم که یک متد `SetupListeners` دارد که داده‌های بزرگی را لود می‌کند:

```csharp

public class DataManager
{
    // این فیلد استاتیک باعث می‌شود ارجاع به هر چیزی که به آن داده شود، دائمی شود
    private static Action _longLivedAction; 
    
    public void SetupListeners()
    {
        // شیء بزرگ محلی
        var hugeDataSet = new List<byte[]>(500000); 
        // پر کردن با داده‌های حجیم (شبیه سازی شیء بزرگ)
        for (int i = 0; i < 500000; i++)
        {
            hugeDataSet.Add(new byte[100]);
        }

        // ----------------------------------------------------
        // اینجا مشکل ایجاد می‌شود:
        // Lambda Expression به hugeDataSet ارجاع می‌دهد
        _longLivedAction = () => 
        {
            // ما فقط از hugeDataSet.Count استفاده می‌کنیم، 
            // اما چون این Lambda به متغیر محلی hugeDataSet ارجاع دارد،
            // کل hugeDataSet زنده می‌ماند.
            Console.WriteLine($"Data count is: {hugeDataSet.Count}");
        }; 
        // ----------------------------------------------------

        // به محض خروج از این متد، hugeDataSet در حالت عادی باید Garbage Collect شود،
        // اما چون _longLivedAction به آن ارجاع دارد، نمی‌شود.
    }

    // متد دیگری برای پاکسازی نیاز است:
    public static void ClearReference()
    {
        _longLivedAction = null; // حالا GC می‌تواند hugeDataSet را پاک کند
    }
}

```
### توضیح مشکل (Memory Leak)

1. **تعریف شیء بزرگ:** `hugeDataSet` به عنوان یک لیست بسیار بزرگ در متد `SetupListeners` تعریف می‌شود.
2. **ایجاد Closure:** وقتی Lambda تعریف می‌شود (`() => { ... }`)، کامپایلر C# یک کلاس پنهان می‌سازد که فیلدی برای نگهداری ارجاع به `hugeDataSet` دارد.
3. **ارجاع دائمی:** تابع Lambda به فیلد استاتیک `_longLivedAction` اختصاص داده می‌شود. **فیلدهای استاتیک تا زمان پایان عمر اپلیکیشن (یا کلاس) در حافظه باقی می‌مانند.**
4. **نتیجه:** چون `_longLivedAction` ارجاعی به Closure دارد، و Closure ارجاعی به `hugeDataSet` دارد، **Garbage Collector نمی‌تواند `hugeDataSet` را پاک کند** و در نتیجه، حافظه مصرف شده برای آن شیء بزرگ، آزاد نمی‌شود.

### راه حل در#C#

راه حل اصلی، شکستن این زنجیره ارجاع است.

1. **کوچک کردن Scope:** اگر واقعاً به داده بزرگ نیاز نداریم، داده را در Scope کوچک‌تری تعریف کنیم.
2. **استفاده از کپی (اگر عملی است):** اگر فقط نیاز به یک مقدار لحظه‌ای بود، یک کپی ساده (مثلاً فقط شمارش یا یک مقدار کلیدی) را به Closure پاس دهیم.
3. **پاکسازی دستی (Manual Cleanup):** همانند مثالی که در `ClearReference` نشان داده شد، ارجاع به Delegate یا Action را **صریحاً** صفر کنیم تا GC بتواند شیء بزرگ را از حافظه بردارد.

در C#، این موضوع اغلب در مدیریت **Event Handlers** که به متغیرهای محلی بزرگ ارجاع دارند و به فیلدهای استاتیک اضافه می‌شوند، خود را نشان می‌دهد.
