## خلاصهٔ خیلی کوتاه

- درواقع **.NET Framework**: قدیمی‌تر، فقط روی **ویندوز**، مناسب اپلیکیشن‌های قدیمی سازمانی.
- و **.NET Core / .NET (جدید)**: **چندسکویی (Windows, Linux, macOS)**، سریع‌تر، مدرن‌تر، مناسب توسعهٔ جدید.

---

## مقایسهٔ کامل

### 1) پشتیبانی پلتفرم‌ها

- **.NET Framework**

فقط ویندوز

کاربرد: اپلیکیشن‌های WinForms، WPF و ASP.NET قدیمی

- **.NET Core / .NET (5+)**

ویندوز + Linux + macOS

کاربرد: وب‌سرویس‌ها، APIها، اپ‌های ابری، کنسولی، کراس‌پلتفرم


---

### 2) عملکرد (Performance)

- **.NET Core / .NET جدید**

بهینه‌سازی‌های سنگین:

 - JIT و GC سریع‌تر
- Span<T>، async/await سبک‌تر
 - Kestrel Web Server بسیار سریع
- **.NET Framework**

کندتر، معماری قدیمی‌تر

توسعهٔ بهینه‌سازی برای آن متوقف شده

---

### 3) معماری و طراحی

- **.NET Core / .NET**

- ماژولار (از طریق NuGet)
- سبک‌تر و قابل سفارشی‌سازی
- نصب side-by-side نسخه‌های مختلف در یک سیستم
- سورس‌باز (open source)
- **.NET Framework**

- مونو‌لیتی (همه‌چیز با هم نصب می‌شود)
- نسخه‌ها side-by-side نیستند
- بسته و فقط توسط مایکروسافت توسعه می‌شود

---

### 4) کتابخانه‌ها و APIها

- **.NET Core / .NET**

- دارای .NET Standard (قدیماً) و اکنون یکپارچه تحت .NET
- اکثر APIهای مهم منتقل شده یا جایگزین بهینه دارند
- **.NET Framework**

- APIهای قدیمی و ناسازگار با Core
- خیلی از پکیج‌های جدید فقط برای .NET Core عرضه می‌شوند

---

### 5) پشتیبانی بلندمدت

- **.NET Framework**

توسعهٔ جدید تقریباً متوقف شده

فقط patch امنیتی دریافت می‌کند

- **.NET Core / .NET**
    
فعالانه توسعه می‌یابد

هر سال نسخهٔ جدید

- برای **پروژه‌های جدید**:
    
    همیشه **.NET Core / .NET 6/7/8+** را انتخاب کنید.

    اگر نیاز به مهاجرت ندارید، **.NET Framework** بمانید.
