## Parallel.For

برای [[bound | CPU bound]].
```csharp

Parallel.For(0,10,i =>
{
    Console.WriteLine(i);
});

```
---

## Task.WhenAll

برای **async operations**.
```csharp

await Task.WhenAll(task1, task2, task3);

```
---

در یک جمله‌ٔ ساده:

ابزار **Parallel.For = اجرای هم‌زمان حلقه‌ها به‌صورت پردازشی (CPU-[[bound]])**  
ابزار **Task.WhenAll = هماهنگ‌کردن چند وظیفهٔ async (عموماً IO-[[bound]])**

اما بیاییم تفاوت واقعی و کاربردی‌شان را دقیق و قابل درک توضیح بدهیم 👇

---

# 1) ماهیت کار
### ✔ ابزار Parallel.For

- مخصوص کارهای [[bound | CPU Bound]] است.  
- روی **ThreadPool** با Threadهای واقعی اجرا می‌شود.  
- موازی‌سازی سطح پایین حلقه‌ها (تکه‌تکه کردن iterationها بین CPU cores).  
- ویژگی Async را پشتیبانی نمی‌کند (بدون hack).

### ✔ ابزار Task.WhenAll

- مخصوص کارهای **Async / [[bound | IO-Bound]]** مثل شبکه، فایل، DB.  
- درواقع thread نمی‌گیرد مگر واقعاً لازم باشد.  
- فقط **منتظر تمام‌شدن Taskها** می‌ماند؛ قرار نیست خودش «موازی‌سازی CPU» انجام دهد.

---

# 2) فرق اصلی در عملکرد

## Parallel.For:
- برای پردازش داده‌های خطی بزرگ:
  - پردازش تصاویر
  - ریاضیات سنگین
  - تبدیل و فشرده‌سازی
  - الگوریتم‌هایی که CPU را کامل مصرف می‌کنند

مثال:

```csharp
Parallel.For(0, 1_000_000, i =>
{
    data[i] = Math.Log(data[i]);
});
```

در این حالت CPU را کامل درگیر می‌کند و کار را روی چندین core پخش می‌کند.

---

## Task.WhenAll:
- برای فراخوانی هم‌زمان چند عملیات async:
  - فراخوانی HTTP
  - کوئری‌های دیتابیس
  - عملیات فایل و IO
  - کارهای async در سیستم‌های وب

مثال:

```csharp
var tasks = urls.Select(url => httpClient.GetStringAsync(url));
var results = await Task.WhenAll(tasks);
```

اگر ۱۰۰۰ درخواست HTTP اجرا کنید،  
در این حالت `Task.WhenAll` **CPU را درگیر نمی‌کند**، فقط منتظر کامل شدن عملیات IO می‌ماند.

---

# 3) چرا Parallel.For برای async مناسب نیست؟

استفاده از Parallel.For بدین شکل اشتباه است:

```csharp
Parallel.For(0, 10, async i => { await SomethingAsync(); });
```

چرا؟  
زیرا Parallel.For منتظر async نمی‌ماند و callbackها را ناقص اجرا می‌کند.  

درواقع Taskهای async "آویزان" می‌شوند و رفتار غیرقابل‌پیش‌بینی رخ می‌دهد.

---

# 4) جدول مقایسهٔ واقعی

| ویژگی | Parallel.For | Task.WhenAll |
|-------|--------------|--------------|
| نوع کار | CPU-Bound | IO-Bound |
| مدل اجرا | ThreadPool با threadهای واقعی | async/await (بدون مصرف Thread اضافی) |
| مناسب برای | پردازش داده، محاسبات سنگین | فراخوانی سرویس‌ها، DB، فایل |
| مدیریت load | دارد | ندارد |
| پشتیبانی از async | ندارد | کاملاً دارد |
| کنترل تعداد thread | امکان‌پذیر (ParallelOptions) | ندارد (مربوط به IO scheduler است) |

---

# 5) کِی از کدام استفاده کنیم؟

### از Parallel.For استفاده کن اگر:

- محاسبات CPU زیاد داری  
- روی raw data کار می‌کنی  
- می‌خواهی از تمام coreهای سیستم استفاده کنی  
- عملیات **همگی synchronous** هستند

### از Task.WhenAll استفاده کن اگر:

- کارها async/IO هستند  
- می‌خواهی تعداد زیادی درخواست هم‌زمان بفرستی  
- نمی‌خواهی thread ذخیره‌سازی کنی  
- کار شما وابسته به async/await است

---

# 6) یک مثال که تفاوت را محسوس کند

## سناریو ۱: دانلود ۱۰۰ فایل از اینترنت

```csharp
await Task.WhenAll(
    Enumerable.Range(0, 100)
        .Select(i => DownloadAsync(files[i]))
);
```

استفاده از Parallel.For برای دانلود شبکه‌ای = **بدترین انتخاب**  
چون به ازای هر دانلود یک Thread می‌گیرد و Threadها بلاک می‌شوند.

---

## سناریو ۲: پردازش ۱۰ میلیون پیکسل تصویر

```csharp
Parallel.For(0, pixels.Length, i =>
{
    pixels[i] = ProcessPixel(pixels[i]);
});
```

استفاده از Task.WhenAll برای این کار = **بسیار کند و بی‌معنی**

---

# جمع‌بندی نهایی (کاملاً کاربردی)

- ابزار **Parallel.For = مالِ CPU**  

  سریع‌ترین روش موازی‌سازی پردازشی، اما فقط مناسب عملیات sync.

- ابزار **Task.WhenAll = مالِ IO/Async**  

  بهترین روش برای اجرای هم‌زمان عملیات async بدون درگیرکردن CPU.

اگر خواستی، یک مثال واقعی در سطح production از جایی که Parallel.For بهتر است و یک مثال از جایی که Task.WhenAll بهتر است می‌توانم برات بسازم.
