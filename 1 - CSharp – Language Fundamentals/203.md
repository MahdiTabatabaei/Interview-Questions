درواقع **Hash Table (جدول درهم‌سازی)** یک ساختار داده است که کمک می‌کند **نگهداری و پیدا کردن داده‌ها خیلی سریع** انجام شود.

ایده‌اش این است: برای هر کلید (key) یک **عدد/اندیس** تولید می‌کند (با تابع Hash)، و بعد داده را در همان جای جدول ذخیره می‌کند. بنابراین معمولاً عملیات‌ها نزدیک به **\(O(1)\)** هستند.

---

## اجزای اصلی

- متد **Hash Function**: یک تابع که کلید را به یک عدد تبدیل می‌کند.

```markdown

index = hash(key) \bmod tableSize

```

- مجموعه **Array/Buckets**: آرایه‌ای از «سبدها/باکت‌ها» (buckets)
- روش **Collision Handling**: وقتی دو کلید به یک index برسند (Collision) باید مدیریت شود.

---

## مفهوم Collision یعنی چی؟

فرض کن دو کلید مختلف `A` و `B` هر دو نتیجه‌ی hashشان یکسان شد و در یک باکت قرار گرفتند. آن‌وقت باید یکی از روش‌ها استفاده شود، مثل:

- روش **Chaining**: داخل هر bucket یک لیست/زنجیره از موارد نگه می‌داریم.
- روش **Open Addressing**: در همان آرایه دنبال جای خالی می‌گردیم (مثلاً linear probing).

در پیاده‌سازی‌های رایج (مثل دات‌نت)، موضوع collision و performance خیلی مهم است و جزئیاتش با نسخه/پیاده‌سازی دقیق فرق می‌کند.

---

## قابلیت Hash Table در عمل برای چی خوب است؟

برای عملیات زیر:

- `Add(key, value)`  → ثبت سریع
- `ContainsKey(key)` → بررسی سریع وجود
- `Remove(key)` → حذف سریع
- `TryGetValue(key)` → گرفتن مقدار

این‌ها معمولاً خیلی سریع‌تر از ساختارهایی مثل `List` هستند چون `List` برای پیدا کردن باید خطی جستجو کند.

---

## رابطه‌اش با HashSet / Dictionary

- دزواقع `HashSet<T>` عملاً یک **Hash Table** برای مجموعهٔ کلیدهاست (فقط کلید، بدون value).
- و `Dictionary<TKey, TValue>` یک **Hash Table** برای نگهداری کلید-مقدار است.

یعنی وقتی می‌گویی «HashSet سریع است»، دلیلش این است که پشتش **Hash Table** است.

---

## مثال ساده (مفهومی)

فرض کن جدول آرایه‌ای با اندازه 10 داریم.

اگر keyها:
- `"Ali"` → hash=123 → index=3
- `"Reza"` → hash=33  → index=3

هر دو در bucket 3 می‌افتند، پس collision رخ داده و باید با chaining یا probing حل شود.

---

## چه زمانی Hash Table ایده‌آل است؟

✅ وقتی:
- باید **خیلی سریع** چک کنی «کلید وجود دارد یا نه»
- می‌خواهی **کلید-مقدار** را سریع پیدا کنی
- حجم داده زیاد است

⚠️ اگر:
- تابع hash خیلی بد باشد → collision زیاد می‌شود و زمان نزدیک به \(O(n)\) می‌رسد.

---

یک مثال خیلی ساده از **Hash Table** در C# همان **Dictionary** است.  
چون `Dictionary<TKey, TValue>` در واقع روی **Hash Table** پیاده‌سازی شده است.

بیایید با یک مثال کاملاً ساده جلو برویم.

---

# مثال: ذخیره نام دانشجو با نمره

```csharp
using System;
using System.Collections.Generic;

class Program
{
    static void Main()
    {
        Dictionary<string, int> students = new Dictionary<string, int>();

        students.Add("Ali", 18);
        students.Add("Sara", 20);
        students.Add("Reza", 16);

        Console.WriteLine(students["Sara"]);
    }
}
```

خروجی:

```
20
```

---

# چه اتفاقی پشت صحنه می‌افتد؟

وقتی این خط اجرا می‌شود:

```csharp
students.Add("Ali", 18);
```

مراحل زیر اتفاق می‌افتد:

1️⃣ **کلید (key)**  
```
"Ali"
```

2️⃣ سیستم روی آن **Hash Function** اجرا می‌کند

مثلاً (فرضی):

```
hash("Ali") = 234567
```

3️⃣ از این عدد برای پیدا کردن **index در آرایه داخلی** استفاده می‌شود

مثلاً:

```
index = 234567 % tableSize
```

فرض کنیم:

```
index = 7
```

4️⃣ داده در آن خانه ذخیره می‌شود

```
index 7 → ("Ali", 18)
```

---

# وقتی داده را می‌گیریم

وقتی می‌نویسی:

```csharp
students["Sara"]
```

مراحل:

1️⃣ مقدار hash کلید `"Sara"` حساب می‌شود  
2️⃣ سپس index پیدا می‌شود  
3️⃣ مستقیم همان خانه خوانده می‌شود

پس لازم نیست کل لیست جستجو شود.

به همین دلیل سرعت تقریباً:

```
O(1)
```

است.

---

# مقایسه با List

اگر این کار را با List انجام دهی:

```csharp
List<string> names = new List<string>();
```

برای پیدا کردن `"Sara"` باید:

```
Ali
Sara
Reza
```

یکی یکی بررسی شود.

یعنی:

```
O(n)
```

---

# یک مثال خیلی کاربردی

فرض کن می‌خواهی سریع بررسی کنی آیا کاربر وجود دارد:

```csharp
Dictionary<int, string> users = new Dictionary<int, string>();

users.Add(1, "Ali");
users.Add(2, "Sara");
users.Add(3, "Reza");

if (users.ContainsKey(2))
{
    Console.WriteLine("User exists");
}
```

اینجا **Hash Table** کمک می‌کند خیلی سریع کاربر پیدا شود.

---

# خلاصه ساده

Hash Table یعنی:

```
Key → Hash Function → Index → Storage
```

و در ‎.NET‎ معمولاً با این کلاس‌ها استفاده می‌شود:

- `Dictionary<TKey, TValue>`
- `HashSet<T>`
- `Hashtable`
