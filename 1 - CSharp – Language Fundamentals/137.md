برای درک تفاوت این‌ها، بهترین راه این است که آن‌ها را به صورت **سلسله‌مراتب (Hierarchy)** تصور کنی. هر کدام از این اینترفیس‌ها، اینترفیس قبلی را به ارث می‌برد (یعنی قابلیت‌های بیشتری اضافه می‌کند).

تصویر ذهنی:
شروع : `IEnumerable` (فقط خواندنی) ⬅️ `ICollection` (اضافه/حذف) ⬅️ `IList` (دسترسی با ایندکس)

---

### 1. `IEnumerable<T>` (کوچکترین عضو - فقط خواندنی)

فقط به شما اجازه می‌دهد روی آیتم‌ها **Iteration** (چرخش) انجام دهید. هیچ تغییری در لیست نمی‌توانید ایجاد کنید.

*   **قابلیت:** فقط `foreach`
*   **سناریو:** وقتی فقط می‌خواهید داده‌ها را نمایش دهید یا پردازش کنید.

```csharp
IEnumerable<string> names = new List<string> { "Ali", "Reza" };
// names.Add("Hassan"); // ❌ خطا: متد Add وجود ندارد
foreach(var n in names) { Console.WriteLine(n); }
```

---

### 2. `ICollection<T>` (اضافه و حذف)

علاوه بر قابلیت `IEnumerable`، به شما اجازه می‌دهد آیتم‌ها را **تغییر** دهید (اضافه یا حذف کنید) و تعداد را بدانید.

*   **قابلیت:** `Add`, `Remove`, `Clear`, `Count`, `Contains`
*   **سناریو:** وقتی نیاز دارید یک مجموعه داده را مدیریت کنید (بدون نیاز به دسترسی با ایندکس).

```csharp
ICollection<string> names = new List<string> { "Ali" };
names.Add("Reza"); // ✅ کار می‌کند
names.Remove("Ali"); // ✅ کار می‌کند
Console.WriteLine(names.Count); // ✅ 1
// names[0] = "Hassan"; // ❌ خطا: دسترسی با ایندکس ندارد
```

---

### 3. `IList<T>` (دسترسی با ایندکس - قدرتمندترین)

علاوه بر `ICollection`، به شما اجازه می‌دهد به آیتم‌ها از طریق **ایندکس (Index)** دسترسی داشته باشید.

*   **قابلیت:** `this[index]`, `Insert`, `RemoveAt`
*   **سناریو:** وقتی نیاز دارید آیتم‌ها را بر اساس مکانشان در لیست تغییر دهید یا جابه‌جا کنید.

```csharp
IList<string> names = new List<string> { "Ali", "Reza" };
names[0] = "Hassan"; // ✅ تغییر با ایندکس
names.Insert(1, "Mahdi"); // ✅ درج در مکان خاص
```

---

### 4. `IReadOnlyList<T>` (ویژه - خواندن با ایندکس)
این اینترفیس ترکیبی است: شما نمی‌توانید لیست را تغییر دهید (مثل `IEnumerable`)، اما می‌توانید **با ایندکس به آیتم‌ها دسترسی داشته باشید**.

*   **قابلیت:** `this[index]`, `Count`
*   **سناریو:** وقتی می‌خواهید به لیست دسترسی "فقط خواندنی" بدهید، اما لازم است مصرف‌کننده بتواند از طریق ایندکس به آیتم خاصی دسترسی سریع داشته باشد (بدون پیمایش کل لیست).

```csharp
IReadOnlyList<string> names = new List<string> { "Ali", "Reza" };
string first = names[0]; // ✅ خواندن با ایندکس
// names.Add("..."); // ❌ خطا
```

### جدول مقایسه سریع (برای مصاحبه)

| Interface | Iteration | Count | Add/Remove | Index Access |
| :--- | :---: | :---: | :---: | :---: |
| **IEnumerable** | ✅ | ❌ | ❌ | ❌ |
| **ICollection** | ✅ | ✅ | ✅ | ❌ |

### یک نکته طلایی 
اگر متدی می‌نویسید که قرار است داده‌ای را دریافت کند:
1.  **همیشه محدودترین اینترفیس ممکن را استفاده کنید.**
2.  اگر فقط می‌خواهید داده را نشان دهید، پارامتر ورودی را `IEnumerable<T>` بگیرید.
3.  اگر می‌خواهید کنترل داده را به کلاینت بدهید، از `ICollection<T>` یا `IList<T>` استفاده کنید.

**چرا؟** چون این کار باعث می‌شود کلاینت متوجه شود که متد شما قرار نیست داده‌ها را دستکاری کند (کد ایمن‌تر و قابل درک‌تر).

آیا در مورد اینکه چرا گاهی تبدیل `List` به `IEnumerable` باعث از دست رفتن کارایی (Performance) می‌شود سوالی دارید؟ این یکی از سوالات پرطرفدار در سطح Senior است.
