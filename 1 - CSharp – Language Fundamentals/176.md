در GC این دو اصطلاح به دو **نوع رفتار و معماری اجرای Garbage Collector** اشاره دارند.

## 1. Wake‑up GC

در این مدل، GC **به صورت عادی در حال اجرا نیست**.  
وقتی شرایط خاصی رخ دهد، GC **بیدار می‌شود (wake up)** و شروع به کار می‌کند.

این شرایط معمولاً یکی از این‌هاست:

- حافظه نسل‌ها پر شود
- میزان allocation از حد مشخصی عبور کند
- فشار حافظه بالا برود

جریان کار:

```
Application Threads running
        ↓
Memory pressure detected
        ↓
GC wakes up
        ↓
Garbage collection runs
```

ویژگی‌ها:

- ابزار GC همیشه فعال نیست
- هنگام نیاز فعال می‌شود
- معمولاً با **Workstation GC** مرتبط است
- تمرکز روی **latency کمتر برای برنامه‌های desktop**

---

## 2. Server GC

وضعیت Server GC یک **حالت (mode)** از GC است که برای **سرورها و سیستم‌های چند هسته‌ای** طراحی شده.

در این حالت:

- برای هر CPU یک **GC heap جدا** وجود دارد
- چند **GC thread اختصاصی** وجود دارد
- ابزار GC به صورت **parallel** اجرا می‌شود

معماری:

```
CPU1 → Heap1 → GC Thread1
CPU2 → Heap2 → GC Thread2
CPU3 → Heap3 → GC Thread3
CPU4 → Heap4 → GC Thread4
```

ویژگی‌ها:

- parallel collection
- throughput بسیار بالا
- pause بزرگ‌تر ولی کمتر
- مناسب برای **ASP.NET / backend services**

---

## تفاوت اصلی

| ویژگی | Wake‑up GC | Server GC |
|---|---|---|
| مدل اجرا | GC فقط هنگام نیاز بیدار می‌شود | GC با threadهای اختصاصی اجرا می‌شود |
| هدف | latency کم | throughput بالا |
| تعداد heap | معمولاً یک heap | یک heap برای هر CPU |
| parallelism | محدود | بسیار بالا |
| کاربرد | desktop apps | server apps |

---

## نکته مهم

این دو در واقع **مستقیماً مقابل هم نیستند**.

حالت‌های واقعی GC در .NET:

```
Workstation GC
Server GC
```

و هر کدام می‌توانند:

```
Background GC
Non-concurrent GC
```

داشته باشند.

اصطلاح **wake‑up** بیشتر به **نحوه trigger شدن GC** اشاره دارد، نه یک mode رسمی مثل Server GC.
