ابزارهایی مثل **Visual Studio** و **SonarQube** پیچیدگی سیکلوماتیک را با تحلیل **Control Flow** کد محاسبه می‌کنند. آن‌ها کد را parse کرده و یک **Control Flow Graph (CFG)** می‌سازند و سپس تعداد **شاخه‌های تصمیم‌گیری** را می‌شمارند.

در عمل، بیشتر ابزارها از همان تعریف **McCabe Cyclomatic Complexity** استفاده می‌کنند.

---

# 1. روش محاسبه در Visual Studio

ابزار Visual Studio از طریق **Code Metrics** این مقدار را محاسبه می‌کند.

مسیر:

```
Analyze → Calculate Code Metrics → For Solution
```

در گزارش، چند شاخص نشان داده می‌شود:

- Maintainability Index
- Cyclomatic Complexity
- Depth of Inheritance
- Class Coupling
- Lines of Code

---

## نحوه محاسبه

ابزار Visual Studio از این فرمول استفاده می‌کند:

```markdown

CC = 1 + {Number of Branching Points}

```

که Branching Points شامل موارد زیر هستند:

- `if`
- `else if`
- `switch case`
- `for`
- `foreach`
- `while`
- `do`
- `catch`
- `?:`
- `&&`
- `||`

---

## مثال C#

```csharp
public int Example(int a, int b)
{
    if (a > 0 && b > 0)
    {
        return a + b;
    }
    else if (a > 0)
    {
        return a;
    }
    else
    {
        return b;
    }
}
```

### محاسبه

Decision Points:

- `if`
- `&&`
- `else if`

پس:

```
CC = 1 + 3 = 4
```

# 2. نحوه محاسبه در SonarQube

ابزار SonarQube هم **Cyclomatic Complexity** را محاسبه می‌کند اما علاوه بر آن یک معیار دیگر به نام **Cognitive Complexity** هم دارد.

تفاوت:

- **Cyclomatic Complexity** → تعداد مسیرهای منطقی
- **Cognitive Complexity** → سختی فهم کد برای انسان

---

## Cyclomatic Complexity در SonarQube

ابزار SonarQube نیز تقریباً همین موارد را به عنوان decision در نظر می‌گیرد:

- `if`
- `else if`
- `switch`
- `case`
- `for`
- `foreach`
- `while`
- `do while`
- `catch`
- `?:`
- `&&`
- `||`

هر کدام **+1** به پیچیدگی اضافه می‌کند.

---

## مثال

```csharp
public string GetCategory(int score)
{
    switch(score)
    {
        case > 90:
            return "A";
        case > 80:
            return "B";
        case > 70:
            return "C";
        default:
            return "D";
    }
}
```

### محاسبه

- switch → +1
- case → +3

```
CC = 1 + 4 = 5
```

---

# 3. تفاوت Cyclomatic و Cognitive Complexity در SonarQube

ابزار SonarQube برای مشکل اصلی Cyclomatic Complexity یک معیار جدید معرفی کرد.

مثال:

```csharp
if(a)
{
    if(b)
    {
        if(c)
        {
            DoSomething();
        }
    }
}
```

Cyclomatic Complexity:

```
4
```

اما مشکل واقعی **nested بودن** است.

برای همین **Cognitive Complexity** بیشتر می‌شود چون:

- میزان nesting زیاد
- فهم سخت‌تر

---

# 4. گزارش Cyclomatic Complexity در Visual Studio

مثال خروجی Code Metrics:

```
Method                    Cyclomatic Complexity
------------------------------------------------
CalculateDiscount                 4
ProcessOrder                      12
ValidateUser                      3
```

اگر مقدار خیلی بالا باشد:

- Visual Studio هشدار می‌دهد
- SonarQube issue ایجاد می‌کند

مثلاً:

```
Cyclomatic Complexity > 15
```

---

# 5. چرا SonarQube آستانه 15 را پیشنهاد می‌دهد

طبق تجربه صنعتی:

- زیر 10 → عالی
- 10 تا 15 → قابل قبول
- بیشتر از 15 → نیاز به refactor

به همین دلیل در بسیاری از پروژه‌ها rule زیر فعال است:

```
Functions should not have Cyclomatic Complexity > 15
```

---

✅ **خلاصه**

ابزار Visual Studio و SonarQube:

1. کد را parse می‌کنند
2. و Control Flow Graph می‌سازند
3. تعداد branch ها را می‌شمارند

فرمول عملی:

```
Cyclomatic Complexity = Decisions + 1
```
