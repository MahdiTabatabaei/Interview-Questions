
ویژگی های **ConcurrentQueue** و **BlockingCollection** هر دو برای سناریوهای چند‌تردی استفاده می‌شوند، ولی نقششان فرق می‌کند.

## ConcurrentQueue
یک **queue thread‑safe** است.

یعنی چند thread می‌توانند همزمان در آن:

- اضافه کنند
- بردارند

بدون اینکه race condition رخ دهد.

متدهای اصلی:

```csharp
queue.Enqueue(item);
queue.TryDequeue(out item);
queue.TryPeek(out item);
```

ویژگی مهم:

- قابلیت **Non‑blocking** است  
- اگر خالی باشد `TryDequeue` فقط **false** برمی‌گرداند، منتظر نمی‌ماند.

مثال:

```csharp
ConcurrentQueue<int> queue = new ConcurrentQueue<int>();

queue.Enqueue(1);

if(queue.TryDequeue(out int x))
{
    Console.WriteLine(x);
}
```

## BlockingCollection
یک **wrapper سطح بالاتر** برای سناریوی **Producer / Consumer** است.

ویژگی مهمش:

**Blocking behavior**

یعنی اگر:

- هر consumer بخواهد بردارد ولی collection خالی باشد → **صبر می‌کند**
- هر producer بخواهد اضافه کند ولی ظرفیت پر باشد → **صبر می‌کند**

متدهای اصلی:

```csharp
Add()
Take()
CompleteAdding()
GetConsumingEnumerable()
```

مثال:

```csharp
BlockingCollection<int> bc = new BlockingCollection<int>();

Task.Run(() =>
{
    bc.Add(10);
});

int x = bc.Take(); // اگر خالی باشد صبر می‌کند
```

---

## نکته مهم
`BlockingCollection` خودش ساختار داده نیست.

به صورت پیش‌فرض از این استفاده می‌کند:

```
ConcurrentQueue
```

ولی می‌تواند از این‌ها هم استفاده کند:

- ConcurrentQueue
- ConcurrentStack
- ConcurrentBag

مثال:

```csharp
var bc = new BlockingCollection<int>(new ConcurrentQueue<int>());
```

---

## تفاوت اصلی

**ConcurrentQueue**

- فقط queue thread‑safe
- non‑blocking
- کنترل ظرفیت ندارد
- برای queue ساده

**BlockingCollection**

- abstraction برای producer/consumer
- blocking دارد
- می‌تواند capacity داشته باشد
- iteration مصرفی دارد (`GetConsumingEnumerable`)

---

## خلاصه خیلی کوتاه

ConcurrentQueue:
```
thread-safe queue
```

BlockingCollection:
```
producer-consumer framework
+ blocking
+ capacity control
```
