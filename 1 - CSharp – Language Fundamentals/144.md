ابزارهای **ChannelReader** و **ChannelWriter** در C# (در فضای نام `System.Threading.Channels`) دو بخش اصلی یک **Channel** هستند و برای ساختن سیستم‌های پیام‌محور، high‑throughput و بدون نیاز به lock استفاده می‌شوند.

در واقع یک Channel دو قسمت دارد:
- **ChannelWriter** برای *نوشتن/ارسال* داده  
- **ChannelReader** برای *خواندن/دریافت* داده  

این دو نقش را مستقل می‌کنند تا تولیدکننده و مصرف‌کننده decouple شوند.

---

# نقش ChannelWriter
ChannelWriter مسئول عملیات ارسال داده است:

- `WriteAsync(T item)`  
- `TryWrite(T item)`  
- `Complete()` → اعلام پایان ارسال داده  
- `TryComplete(Exception ex)` → با خطا پایان بده

ویژگی‌ها:
- غیر بلوکی (non‑blocking) در نسخه‌ی try  
- بلوکی (async) در نسخه‌ی async  
- مدیریت backpressure در حالت channel محدود (bounded channel)

نویسنده فقط اجازه دارد داده وارد channel کند، و دسترسی به خواندن ندارد → **ایمنی و استقلال نقش‌ها**.

---

# نقش ChannelReader
ChannelReader مسئول دریافت داده و مصرف آن است:

- `ReadAsync()`  
- `TryRead(out T item)`  
- `Completion` (Task) برای فهمیدن اینکه writer تمام شده  
- `WaitToReadAsync()` برای pipelineهای async

خواننده Reader تنها بخش دریافت است و هیچ دسترسی به نوشتن ندارد → مناسب برای pipelineهای multi‑consumer.

---

# چرا ChannelReader و ChannelWriter جدا شده‌اند؟

سه دلیل اصلی:

### 1. ایجاد Decoupling امنیتی و منطقی

تولیدکننده فقط writer می‌گیرد؛ مصرف‌کننده فقط reader.  
این باعث می‌شود:
- بخش‌ها نتوانند اشتباه عمل متقابل انجام دهند  
- APIها ایمن‌تر باشند  
- pipeline تمیزتر و مطمئن‌تر پیاده شود

### 2. پشتیبانی از Producer-Consumer و Pipeline

می‌توان چند producer و چند consumer تعریف کرد.  
تقسیم نقش‌ها این معماری را ساده و سریع می‌کند.

### 3. اثربخشی در High‑Throughput

درواقع Channel از ساختارهای lock‑free استفاده می‌کند؛ جداسازی reader/writer به آن اجازه می‌دهد **مسیرهای hot path** را بهتر بهینه‌سازی کند.

---

# یک مثال ساده
```csharp
var channel = Channel.CreateBounded<int>(100);

ChannelWriter<int> writer = channel.Writer;
ChannelReader<int> reader = channel.Reader;

// Producer
_ = Task.Run(async () =>
{
    for (int i = 0; i < 1000; i++)
        await writer.WriteAsync(i);

    writer.Complete();
});

// Consumer
await foreach (var item in reader.ReadAllAsync())
{
    Console.WriteLine(item);
}
```

در این معماری:
- producer فقط به writer دسترسی دارد  
- consumer فقط reader را می‌گیرد  
- channel خودش queue و synchronization را مدیریت می‌کند  

---

# خلاصه مستقیم
ChannelWriter → ورود داده  
ChannelReader → خروج داده  
این دو با هم امکان ساخت queue سریع و thread‑safe بدون lock برای سیستم‌های high‑throughput را می‌دهند.
