**مفهوم:** `Span<T>` یک ساختار (struct) است که به ما اجازه می‌دهد به بخش‌هایی از حافظه (آرایه، رشته یا حافظه Unmanaged) دسترسی داشته باشیم **بدون اینکه کپی از آن‌ها بسازیم**.

**دلیل بهبود عملکرد:**

1. **بدون کپی (Zero-copy):** به جای بریدن (Substring) یک رشته و اشغال حافظه جدید، به همان حافظه قبلی نگاه می‌کند.
2. حالت **Stack-only:** چون یک `ref struct` است، در Stack ذخیره می‌شود و فشاری به Garbage Collector نمی‌آورد.
## مثال ۱: مقایسه Substring با Span (بدون کپی کردن حافظه)

فرض کن یک رشته طولانی داریم و می‌خواهیم فقط **بخشی از آن** را بخوانیم.

### روش معمول با Substring (کند – ساخت رشته جدید)
```csharp

string text = "Hello World!";
string part = text.Substring(0, 5);

Console.WriteLine(part); // Hello

```
در این روش:

• متد `Substring` یک رشته جدید می‌سازد

• یعنی **کپی از حافظه** ایجاد می‌شود → فشار روی GC → حافظه بیشتر

---

## روش سریع با Span<T> (بدون ساخت رشته جدید – Zero-copy)

```csharp

string text = "Hello World!";
ReadOnlySpan<char> span = text.AsSpan().Slice(0, 5);

Console.WriteLine(span.ToString()); // Hello

```

مزیت این روش:

• هیچ داده‌ای کپی نشده

• فقط یک “نمایش” (View) روی همان حافظه اصلی ایجاد شده

• هیچ رشته جدیدی ساخته نشده → GC بسیار کمتر

---

# مثال ۲: پردازش سریع‌تر آرایه‌ها بدون کپی

## روش معمول (کند):

```csharp

int[] numbers = { 1, 2, 3, 4, 5 };
int[] slice = numbers[1..4]; // این کپی می‌کند!

```
این کد مقدار جدید می‌سازد → باعث مصرف حافظه و CPU.

---

### روش با Span<T> (سریع – بدون کپی)

```csharp

int[] numbers = { 1, 2, 3, 4, 5 };
Span<int> part = numbers.AsSpan().Slice(1, 3);

foreach (var n in part)
    Console.WriteLine(n);

```
نتیجه:
```markdown

2
3
4

```
• هیچ آرایه جدیدی ساخته نشده

• فقط اشاره به بخشی از آرایه اصلی داریم

---

# مثال ۳: افزایش سرعت Parse اعداد از رشته

بدون Span (کند و حافظه‌بر):

```csharp

string number = "12345";
int n = int.Parse(number.Substring(0, 3)); // ساخت رشته جدید "123"

```
با Span (سریع و بدون کپی):
```csharp

string number = "12345";
ReadOnlySpan<char> span = number.AsSpan().Slice(0, 3);
int n = int.Parse(span);

```

# مثال ۴: پردازش فایل‌ها با سرعت چندین برابر

تصور کن داده‌های زیاد داریم:

بدون Span:
```csharp

foreach (var line in File.ReadAllLines("data.txt"))
{
    var firstName = line.Substring(0, 10);
}

```
با Span:
```csharp

foreach (var line in File.ReadLines("data.txt"))
{
    ReadOnlySpan<char> span = line.AsSpan();
    var firstName = span.Slice(0, 10); // بدون ساخت String جدید
}

```
در کار با فایل‌ها، این کار **ده‌ها برابر سریع‌تر** است چون

در هر خط به‌جای ساخت چند string جدید، فقط یک view ایجاد می‌شود.

# خلاصه شفاف عملکرد Span<T>

### ویژگی Span<T> سریع‌تر است چون:

• باعث **Zero-Copy** → هیچ حافظه جدیدی تولید نمی‌کند

• **روی Stack ذخیره می‌شود** → GC درگیر نمی‌شود

• **به بخش‌های یک آرایه/رشته نگاه می‌کند بدون ساخت نسخه جدید**

• قابلیت suitable برای کار با دیتای بزرگ (فایل، شبکه، پردازش متن)
