ویژگی `TaskScheduler` مشخص می‌کند **Taskها روی چه threadی اجرا شوند**.

به‌صورت پیش‌فرض:

```markdown

ThreadPoolTaskScheduler

```

یعنی Taskها روی **ThreadPool** اجرا می‌شوند.

---

## مثال استفاده
```csharp

Task.Factory.StartNew(() =>
{
    Console.WriteLine("Task running");
}, CancellationToken.None, TaskCreationOptions.None, TaskScheduler.Default);

```
## ساخت TaskScheduler سفارشی

باید کلاس را از `TaskScheduler` ارث‌بری کنیم.

مثال ساده:
```csharp

class CustomScheduler : TaskScheduler
{
    protected override IEnumerable<Task> GetScheduledTasks()
    {
        return null;
    }

    protected override void QueueTask(Task task)
    {
        Thread thread = new Thread(() => TryExecuteTask(task));
        thread.Start();
    }

    protected override bool TryExecuteTaskInline(Task task, bool taskWasPreviouslyQueued)
    {
        return TryExecuteTask(task);
    }
}

```

---

# کاربردهای واقعی TaskScheduler سفارشی

### 1️⃣ محدود کردن تعداد Taskهای همزمان (Concurrency Limit)

گاهی نمی‌خواهی همه Taskها همزمان اجرا شوند.

مثلاً:

- درخواست زیاد به دیتابیس
- ایجاد API rate limit
- پردازش سنگین CPU

در این حالت می‌توانی TaskScheduler بسازی که مثلاً **فقط ۲ Task همزمان اجرا کند**.

مثال سناریو:
```markdown

100 task برای دانلود فایل داریم
اما می‌خواهیم فقط 5 تا همزمان اجرا شوند

```
---

### 2️⃣ اجرای Taskها روی یک Thread خاص

گاهی لازم است همه Taskها روی **یک thread خاص** اجرا شوند.

مثلاً:
- برنامه‌های UI
- بعضی کتابخانه‌های قدیمی
- منابعی که thread-safe نیستند

مثل چیزی شبیه **single-thread scheduler**.

---

### 3️⃣ صف‌بندی سفارشی Taskها (Priority Queue)

گاهی می‌خواهی Taskها **اولویت داشته باشند**.

مثلاً:
```markdown

High priority
Normal priority
Low priority

```
در این وضعیت Scheduler می‌تواند اول Taskهای مهم را اجرا کند.

---

### 4️⃣ کنترل کامل روی Threadها

مثلاً:

- ایجاد Thread اختصاصی بسازی
- مزیت affinity خاص بدهی
- افزودن logging یا monitoring اضافه کنی.

---

# مثال ساده: محدود کردن Taskهای همزمان

یک سناریو:

ما می‌خواهیم **حداکثر 2 Task همزمان اجرا شوند**.

ایده ساده:
```csharp

class LimitedConcurrencyScheduler : TaskScheduler
{
    private readonly SemaphoreSlim _semaphore;

    public LimitedConcurrencyScheduler(int maxConcurrency)
    {
        _semaphore = new SemaphoreSlim(maxConcurrency);
    }

    protected override void QueueTask(Task task)
    {
        Task.Run(async () =>
        {
            await _semaphore.WaitAsync();

            try
            {
                TryExecuteTask(task);
            }
            finally
            {
                _semaphore.Release();
            }
        });
    }

    protected override bool TryExecuteTaskInline(Task task, bool taskWasPreviouslyQueued)
    {
        return false;
    }

    protected override IEnumerable<Task> GetScheduledTasks()
    {
        return null;
    }
}

```
استفاده:
```csharp

var scheduler = new LimitedConcurrencyScheduler(2);

var factory = new TaskFactory(scheduler);

for (int i = 0; i < 10; i++)
{
    int id = i;

    factory.StartNew(() =>
    {
        Console.WriteLine($"Task {id} started");
        Thread.Sleep(2000);
        Console.WriteLine($"Task {id} finished");
    });
}

```
نتیجه:
```markdown

در هر لحظه فقط 2 Task اجرا می‌شوند

```
# یک مثال واقعی‌تر

فرض کن سیستمی داری که:
```markdown

1000 image processing task

```
اگر همه همزمان اجرا شوند:
```markdown

CPU overload
Memory pressure

```
با **TaskScheduler سفارشی** می‌توانی بگویی:
```markdown

max concurrency = 4

```
و سیستم پایدار می‌ماند.
