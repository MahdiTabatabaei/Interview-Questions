کلمه کلیدی **`volatile`** در C# (و زبان‌های مشابه مثل Java و C++) برای مدیریت **دسترسی همزمان چند نخ (Thread)** به یک متغیر استفاده می‌شود.

به زبان ساده: `volatile` به کامپایلر و CPU می‌گوید: **«این متغیر را بهینه‌سازی نکن! هر بار که می‌خواهی آن را بخوانی، برو سراغ حافظه اصلی (RAM) و از ککش (Cache) استفاده نکن.»**

---

### چرا به `volatile` نیاز داریم؟ (مشکل بهینه‌سازی)

کامپایلرها و CPUها برای افزایش سرعت، کدهایی که می‌نویسیم را بهینه‌سازی می‌کنند. یکی از این بهینه‌سازی‌ها، **کش کردن (Caching)** مقدار متغیرها در ثبات‌های (Registers) پردازنده است.

فرض کن کد زیر را داریم:

```csharp
class Worker
{
    private bool _shouldStop = false;

    public void DoWork()
    {
        while (!_shouldStop)
        {
            // انجام یک کار تکراری
        }
        Console.WriteLine("Worker Stopped.");
    }

    public void Stop()
    {
        _shouldStop = true;
    }
}
```

#### سناریوی خطرناک:
1. ابتدا **Thread 1** متد `DoWork` را اجرا می‌کند. 
2. کامپایلر (JIT) می‌بیند که داخل حلقه `while` هیچ تغییری روی `_shouldStop` داده نمی‌شود. 
3. برای سرعت بیشتر، مقدار `_shouldStop` را از RAM می‌خواند و در یک **Register پردازنده** نگه می‌دارد و دیگر سراغ RAM نمی‌رود.
4. و **Thread 2** متد `Stop` را صدا می‌زند و مقدار `_shouldStop` را در RAM برابر `true` می‌کند.
5. **مشکل:** Thread 1 هنوز دارد به Register خودش نگاه می‌کند (که `false` است) و هرگز متوقف نمی‌شود!

---

### راه حل: استفاده از `volatile`

اگر متغیر را به این صورت تعریف کنیم:
```csharp
private volatile bool _shouldStop = false;
```

اتفاقی که می‌افتد این است:
1. **جلوگیری از Caching:** پردازنده مجبور است در هر تکرار حلقه، مقدار را مستقیماً از حافظه (RAM) بخواند.
2. **جلوگیری از Reordering:** کامپایلر اجازه ندارد ترتیب دستورات مربوط به این متغیر را برای بهینه‌سازی عوض کند.

---

### تفاوت `volatile` با `lock`

بسیاری از برنامه نویسان این دو را اشتباه می‌گیرند:

| ویژگی | `volatile` | `lock` |
| :--- | :--- | :--- |
| **هدف** | اطمینان از خواندن آخرین مقدار (Visibility) | ایجاد انحصار متقابل (Mutual Exclusion) |
| **اتمیک بودن** | عملیات را Atomic نمی‌کند (مثلاً `i++` امن نیست) | عملیات را کاملاً Atomic می‌کند |
| **هزینه پردازشی** | بسیار بسیار کم | نسبت به volatile سنگین‌تر است |
| **بلاک کردن** | هیچ Threadای را متوقف (Block) نمی‌کند | بقیه Threadها را پشت در نگه می‌دارد |

---

### محدودیت‌های مهم `volatile` (چه زمانی کافی نیست؟)

درواقع `volatile` فقط **آخرین مقدار** را به شما نشان می‌دهد، اما از [[1 - CSharp – Language Fundamentals/61| race condition]]  در عملیات ترکیبی جلوگیری نمی‌کند.

**مثال اشتباه:**
```csharp
private volatile int _counter = 0;

public void Increment()
{
    _counter++; // این عملیات Thread-Safe نیست!
}
```
عملیات `++` در واقع سه مرحله است: (خواندن -> افزایش -> نوشتن). اگر دو Thread همزمان این کار را بکنند، ممکن است نتیجه غلط شود. برای این کار باید از **`Interlocked.Increment`** یا **`lock`** استفاده کنید.

---

### خلاصه

- درواقع **`volatile`** یعنی: همیشه برو از RAM بخون، ککش نکن.
- **کاربرد اصلی:** پرچم‌های وضعیت (Status Flags) که توسط یک Thread تغییر می‌کنند و بقیه فقط باید آخرین وضعیت را ببینند.
- **نکته طلایی:** اگر می‌خواهی عملیات ریاضی (مثل ++ یا --) انجام دهی، `volatile` به تنهایی کافی نیست.

آیا می‌خواهی مثالی از **Interlocked** بزنم تا فرقش با `volatile` در عمل مشخص شود؟
