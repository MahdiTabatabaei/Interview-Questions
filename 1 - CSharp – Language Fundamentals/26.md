```csharp

Span<int> numbers = stackalloc int[5];

numbers[0] = 10;
numbers[1] = 20;

```

دستور **`stackalloc`** واقعاً یکی از اون ویژگی‌های سطح پایین C# است که خیلی از برنامه‌نویس‌های اپلیکیشن‌های معمولی (وب، ERP، WinForms، WPF، حتی بیشتر بک‌اندها) هیچ‌وقت مستقیم باهاش سروکار پیدا نمی‌کنن.  
اما در **نرم‌افزارهای performance-sensitive** مثل **پردازش تصویر، گرافیک، شبکه، رمزنگاری، بازی‌ها، یا کتابخانه‌های سیستمی** کاربرد کاملاً واقعی و مهم داره.

---

## 🔹 مفهوم `stackalloc` یعنی چی؟

درواقع `stackalloc` آرایه‌ای را **روی پشته (stack)** به جای heap می‌سازد، مثل کاری که در زبان‌های C/C++ با آرایه‌های محلی انجام می‌دهید.  
در مقابل، آرایه‌های معمولی (`new T[] { ... }`) روی heap هستند و باید توسط GC جمع‌آوری شوند.

بنابراین:
- ساخت با `stackalloc` فوق‌العاده سریع‌تر است.  
- نیازی به garbage collection ندارد.  
- عمرش محدود به بلوک فعلی است (خارج از scope از بین می‌رود).  
- فقط با **نوع‌های `struct` ساده و value type** کار می‌کند.  

---

## 🔹 نمونه ساده

```csharp
Span<byte> buffer = stackalloc byte[256]; // ساخت آرایه روی پشته
for (int i = 0; i < buffer.Length; i++)
    buffer[i] = (byte)(i * 2);

ProcessData(buffer); // فقط در محدوده تابع معتبر است
```

اینجا از `Span<T>` استفاده شده چون `stackalloc` یک نوع span برمی‌گرداند — ایمن‌تر از اشاره‌گر خام است.

## 🔹 کاربرد واقعی در سبک نرم‌افزارها

### 🎮 1. موتور بازی یا پردازش گرافیکی

در رندر هر فریم، هزاران بار محاسبات ماتریسی یا رنگ انجام می‌شود.  
استفاده از `stackalloc` برای آرایه‌های کوچک چند عنصری (مثلاً `Vector3`) باعث می‌شود GC اصلاً وسط فریم استاپ نکند.

```csharp
void TransformVectors(ReadOnlySpan<Vector3> input, Span<Vector3> output)
{
    Span<Vector3> temp = stackalloc Vector3[4]; // آرایه موقتی برای ماتریس تبدیل
    // انجام محاسبات سریع ماتریسی – بدون تخصیص heap
}
```

---

### 🔐 2. رمزنگاری و امنیت

کتابخانه‌های رمزنگاری مثل `System.Security.Cryptography` یا `libsodium` از `stackalloc` زیاد استفاده می‌کنند برای کار با **بلیه‌های رمز (key، nonce، iv)** که فقط چند بایت هستند و باید بلافاصله پاک شوند.

```csharp
Span<byte> iv = stackalloc byte[16];
RandomNumberGenerator.Fill(iv);
// استفاده از iv در رمزنگاری و سپس...
iv.Clear(); // پاک از حافظه قبل از پایان scope
```

چون روی heap نیست → GC تاخیر ندارد → احتمال نشت داده محرمانه کمتر است.

---

### ⚡ 3. شبکه و serialization

وقتی ده‌ها هزار پیام کوچک در ثانیه serialize/deserialize می‌شوند، تخصیص heap برای هر بسته فشار زیادی روی GC می‌آورد.  
در زیرساخت‌های high-throughput (مثل سرورهای بازی، telemetry، یا socket server) از `stackalloc` به‌صورت موقتی برای bufferها استفاده می‌شود:

```csharp
int headerSize = 8;
Span<byte> header = stackalloc byte[headerSize];
BinaryPrimitives.WriteInt32LittleEndian(header, packetLength);
SendHeader(header);
```

---

### 🧮 4. پردازش عددی و الگوریتمی (مثلاً FFT یا Parsing)

اگر چند آرایه کم‌حجم دارید که در هر Iteration لازمند، `stackalloc` باعث حذف تخصیص heap می‌شود:

```csharp
Span<double> temp = stackalloc double[32];
ComputeFourier(temp);  // در حلقه بزرگ و پرتکرار، سرعت معنا‌دار
```

### 🧠 5. قابلیت CodeGen / Compiler / Runtime داخلی خود .NET

خود 👆 **Roslyn**, **CoreCLR** و **Span/Memory API** از `stackalloc` استفاده می‌کنند برای ساخت bufferهای پارسینگ یا موقت در زمان کامپایل یا اجرای محاسبات.

## ⚠️ نکات مهم

- اندازه‌ی استک معمولاً محدود است (مثلاً چند مگابایت). `stackalloc byte[1000000]` باعث StackOverflow می‌شود.
- فقط داخل **توابع unsafe** قبلاً قابل استفاده بود، ولی از C# 7.2 به بعد با `Span<T>` کاملاً ایمن است.
- برای داده‌های کوچک و کوتاه‌عمر عالی است، نه برای آرایه‌های بزرگ.
