# مثال 1 — استفاده از virtual

در این حالت متد در کلاس والد **پیاده‌سازی دارد** و کلاس فرزند **می‌تواند override کند یا نکند**.
### مثال


```csharp

class Animal
{
    public virtual void Speak()
    {
        Console.WriteLine("Animal makes sound");
    }
}

class Dog : Animal
{
    public override void Speak()
    {
        Console.WriteLine("Dog barks");
    }
}

```
استفاده:
```csharp

Animal a = new Dog();
a.Speak();

```
خروجی:
```markdown

Dog barks

```
اگر override نکنیم:
```csharp

class Cat : Animal
{
}

```

```csharp

Animal a = new Cat();
a.Speak();

```

خروجی:

```markdown

Animal makes sound

```

یعنی متد والد اجرا می‌شود.

# مثال 2 — استفاده از abstract

در اینجا متد **هیچ پیاده‌سازی ندارد** و فرزند **حتماً باید override کند**.
```csharp

abstract class Animal
{
    public abstract void Speak();
}

```
کلاس فرزند:
```csharp

class Dog : Animal
{
    public override void Speak()
    {
        Console.WriteLine("Dog barks");
    }
}

```
استفاده:
```csharp

Animal a = new Dog();
a.Speak();

```
خروجی:
```markdown

Dog barks

```
# نکته مهم

نمی‌توان از کلاس abstract نمونه ساخت.

❌
```csharp

Animal a = new Animal();

```
✅
```csharp

Animal a = new Dog();

```

# مثال واقعی‌تر (سناریوی سیستم پرداخت)

## با abstract

چون هر پرداخت باید پیاده‌سازی خودش را داشته باشد.
```csharp

abstract class Payment
{
    public abstract void Pay();
}

```
پیاده‌سازی:
```csharp

class CreditCardPayment : Payment
{
    public override void Pay()
    {
        Console.WriteLine("Pay with credit card");
    }
}

class PaypalPayment : Payment
{
    public override void Pay()
    {
        Console.WriteLine("Pay with paypal");
    }
}

```

# مثال virtual در همین سناریو

فرض کنیم متد پیش‌فرض داریم.
```csharp

class Payment
{
    public virtual void PrintReceipt()
    {
        Console.WriteLine("Default receipt");
    }
}

```
فرزند می‌تواند تغییر دهد:
```csharp

class CreditCardPayment : Payment
{
    public override void PrintReceipt()
    {
        Console.WriteLine("Credit card receipt");
    }
}

```
# مثال ترکیب abstract و virtual

خیلی رایج است.

```csharp

abstract class Animal
{
    public abstract void Speak();

    public virtual void Sleep()
    {
        Console.WriteLine("Animal sleeping");
    }
}

```
فرزند:
```csharp

class Dog : Animal
{
    public override void Speak()
    {
        Console.WriteLine("Bark");
    }

    public override void Sleep()
    {
        Console.WriteLine("Dog sleeping");
    }
}

```
# تفاوت مفهومی

### virtual

“یک رفتار پیش‌فرض دارم، اگر لازم بود تغییرش بده.”

### abstract

“رفتار مشخصی ندارم، فرزند باید آن را تعریف کند.”
# مثال واقعی در .NET

مثلاً در `Stream`
```csharp

public abstract class Stream
{
    public abstract int Read(byte[] buffer, int offset, int count);
}

```
هر Stream (FileStream, MemoryStream) باید Read را پیاده‌سازی کند.

# جمع‌بندی ساده

**virtual**

- implementation دارد
- override اختیاری

**abstract**

- implementation ندارد
- override اجباری
