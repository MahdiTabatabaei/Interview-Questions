درواقع `ValueTask` برای کاهش **allocation** در async ساخته شده، اما محدودیت‌هایی دارد که اگر رعایت نشوند باعث باگ می‌شود. مهم‌ترینشان:

- **multi‑await problem**
- **reuse problem**

قبلش یک نکته مهم:

```
Task → reference type
ValueTask → struct
```

`Task` می‌تواند چند بار await شود، ولی **ValueTask همیشه این تضمین را نمی‌دهد**.

---

# 1️⃣ Multi‑await problem

یک `ValueTask` ممکن است **فقط یک بار await شود**.

اگر دوبار await شود ممکن است:

- استثنا exception بگیرید
- رفتار undefined شود
- نتیجه اشتباه برگردد

مثال:

```csharp
ValueTask<int> GetNumberAsync()
{
    return new ValueTask<int>(42);
}

async Task Test()
{
    var vt = GetNumberAsync();

    int a = await vt;
    int b = await vt; // ❌ مشکل
}
```

چرا؟

چون `ValueTask` ممکن است پشت صحنه از این استفاده کند:

```
IValueTaskSource
```

این object **بعد از await مصرف می‌شود** و دوباره قابل استفاده نیست.

برخلاف `Task`:

```csharp
var t = Task.FromResult(42);

await t;
await t; // ✅ کاملاً مجاز
```

---

# 2️⃣ Reuse problem

گاهی `ValueTask` از objectهای **pool شده** استفاده می‌کند.

مثلاً در ASP.NET Core یا pipelineهای high-performance.

اگر `ValueTask` را ذخیره کنید و بعداً await کنید ممکن است object underlying **قبلاً reuse شده باشد**.

مثال خطرناک:

```csharp
ValueTask<int> vt = GetDataAsync();

DoSomethingElse();

int result = await vt; // ❌ ممکن است unsafe باشد
```

چرا؟

ممکن است implementation از این استفاده کند:

```
ManualResetValueTaskSourceCore
```

که objectها را **pool** می‌کند.

پس ممکن است همان object برای operation دیگری reuse شود.

---

# مثال واقعی از مشکل

فرض کن:

```csharp
ValueTask<int> vt = stream.ReadAsync(buffer);

var t1 = vt.AsTask();
var t2 = vt.AsTask();
```

یا:

```csharp
await vt;
await vt; // ❌
```

یا:

```csharp
var vt = GetAsync();
list.Add(vt); // ❌ نگهداری خطرناک
```

---

# قانون مهم استفاده از ValueTask

مایکروسافت چند قانون ساده داده:

### قانون 1

```
ValueTask را فقط یک بار await کن
```

---

### قانون 2

اگر نیاز داری چند بار await کنی:

```
vt.AsTask()
```

مثال:

```csharp
var task = GetDataAsync().AsTask();

await task;
await task; // ✅ safe
```

---

### قانون 3

مقدار ValueTask را **cache یا store نکن**.

یعنی:

```
List<ValueTask>
Dictionary<ValueTask>
field
```

کار خطرناکی است.

---

# چرا اصلاً ValueTask وجود دارد؟

برای کاهش allocation در متدهایی که **اغلب synchronous کامل می‌شوند**.

مثال:

```
MemoryStream.ReadAsync
PipeReader.ReadAsync
Socket operations
```

اگر هر بار `Task` ساخته شود:

```
allocation زیاد
GC pressure
```

پس `ValueTask` ساخته شد.

---

# خلاصه 

**Pitfall های ValueTask:**

1️⃣ **Multi‑await problem**

```
ValueTask ممکن است فقط یک بار await شود
```

2️⃣ **Reuse problem**

```
ممکن است object underlying reuse شود
پس نباید ذخیره یا reuse شود
```

قانون طلایی:

```
ValueTask → await once
اگر چند await لازم است → AsTask()
```
