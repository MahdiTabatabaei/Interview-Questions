اجازه استفاده از **pointer مثل C/C++** را می‌دهد.

مثال:
```csharp

unsafe
{
    int x = 10;
    int* p = &x;

    Console.WriteLine(*p);
}

```
---

✅ کاربردها

- برای high performance
- استفاده interop با C/C++
- سیستم‌های low-level
---

کلمه **Unsafe** در دنیای ‎.NET‎ به معنای «بد نوشتن کد» یا «غیرحرفه‌ای بودن» نیست، بلکه یک **اصطلاح فنی** است.

بیا دقیق‌تر بررسی کنیم که چرا به آن می‌گوییم Unsafe و چه زمانی استفاده از آن درست است:

---

### ۱. چرا به آن می‌گویند “Unsafe” (ناامن)؟

در حالت عادی، کد سی‌شارپ **Managed** (مدیریت شده) است. یعنی:

- در حالت کلی **Garbage Collector (GC)** مراقب حافظه است.
- اگر بخواهی به خانه‌ای از آرایه دسترسی پیدا کنی که وجود ندارد (Index out of range)، خود دات‌نت جلوی تو را می‌گیرد.

وقتی از `unsafe` استفاده می‌کنی، به کامپایلر می‌گویی: **«لطفاً کنار برو، من خودم می‌خواهم مستقیماً با آدرس‌های حافظه کار کنم.»**

در این حالت، دات‌نت دیگر نمی‌تواند امنیت حافظه را تضمین کند. به همین دلیل به آن می‌گویند **ناامن**.

---

### ۲. آیا خطرناک است؟ (Dangers)

بله، به چند دلیل:

1. **خطای سیستمی (Crash):** اگر به آدرس اشتباهی در حافظه اشاره کنی، برنامه بلافاصله بسته می‌شود (Access Violation).
2. **فساد داده (Data Corruption):** ممکن است ناخواسته مقداری را در جایی از حافظه بنویسی که مربوط به متغیر دیگری است و باعث رفتار عجیب برنامه شوی.
3. **چالش با GC:** زباله‌روب (GC) مدام اشیاء را در حافظه جابجا می‌کند تا حافظه را بهینه کند. اگر تو آدرس یک شیء را داشته باشی و GC آن را جابجا کند، پوینتر تو به یک جای خالی یا اشتباه اشاره خواهد کرد (مگر اینکه از کلمه کلیدی `fixed` استفاده کنی).

---

### ۳. آیا “کد بد” محسوب می‌شود؟

**خیر.** اگر در جای درست استفاده شود، نشان‌دهنده تسلط برنامه‌نویس است.

در این موارد استفاده از آن کاملاً منطقی و حرفه‌ای است:

- داشتن **High Performance:** وقتی نیاز داری یک پردازش سنگین تصویر یا محاسبات ریاضی را با سرعت خیره‌کننده انجام دهی (چون چک کردنِ محدوده آرایه در هر بار تکرار حلقه، زمان‌بر است).
- نیاز به **Interop:** وقتی می‌خواهی با کتابخانه‌های قدیمی که با C یا C++ نوشته شده‌اند ارتباط برقرار کنی.
- قابلیت **Low-level programming:** کار با سخت‌افزار یا نوشتن درایور.

## 🔹 کاربرد واقعی «unsafe»

در اپ‌های روزمره (مثلاً وب، سازمانی و معمولی) نیازی به `unsafe` نیست.  
اما در **نرم‌افزارهایی که با کارایی، native interop یا حافظه خام سروکار دارند** — مثل:

- **موتور بازی و گرافیک (Unity, DirectX, OpenGL)**  
- **پردازش تصویر و صدا (FFmpeg bindings, DSP)**  
- **شبکه و رمزنگاری سطح پایین (TLS, secure buffers)**  
- **IoT یا ارتباط با دیوایس‌ها (USB, serial, sensors)**  
- **نوشتن binding برای کتابخانه‌های C/C++ (P/Invoke)**  
- **نوشتن API یا runtime در خود .NET (مثلاً Span, Memory)**

## 🔹 یک مثال ساده و شفاف

فرض کنید می‌خواهیم **بسیار سریع** آرایه‌ای از پیکسل‌ها را پردازش کنیم  
و می‌دانیم این کار به‌صورت بایتی بهتر با اشاره‌گر انجام می‌شود، نه با ایندکس عادی.

```csharp
using System;

class Program
{
    static void Main()
    {
        byte[] pixels = new byte[] { 10, 50, 200, 255 };

        unsafe
        {
            fixed (byte* p = pixels) // آرایه در حافظه pin می‌شود
            {
                byte* cur = p;
                for (int i = 0; i < pixels.Length; i++)
                {
                    *cur = (byte)(255 - *cur); // معکوس کردن رنگ
                    cur++;
                }
            }
        }

        Console.WriteLine(string.Join(", ", pixels));
        // خروجی: 245, 205, 55, 0
    }
}
```

✅ کاری که این کد انجام می‌دهد:
1. `unsafe` اجازه استفاده از اشاره‌گرها (`byte*`) می‌دهد.  
2. `fixed` باعث می‌شود آرایه در حافظه «ثابت» شود تا GC آن را جابه‌جا نکند.  
3. ما مستقیم روی حافظه‌ی خام عمل می‌کنیم، بدون دردسر ایندکس یا Bounds Check.  

📈 در حلقه‌های بسیار پرتکرار (مثل پردازش تصویر یا بازی‌ها) این روش چند برابر سریع‌تر از دسترسی معمولی است.

## 🔹 مثال کاربردی دیگر — کار با struct native

فرض کنید کتابخانه‌ای C دارید که مختصات نقطه را تحویل می‌دهد:

```c
typedef struct {
    float x;
    float y;
} Point;
```

در C# برای دریافت داده به شکل مستقیم:

```csharp
unsafe struct Point
{
    public float x;
    public float y;
}
```

و اگر تابع native دارید که با اشاره‌گر کار می‌کند:

```csharp
[DllImport("NativeLib.dll")]
private static extern void GetPoints(Point* buffer, int count);

unsafe static void Main()
{
    Point[] arr = new Point[100];
    fixed (Point* p = arr)
    {
        GetPoints(p, arr.Length); // خواندن داده مستقیم از حافظه
    }
}
```

👉 این دقیقا در اپ‌های interop یا driver-level مفید است.  
(مثلاً در Unity یا بازی‌ها برای گرفتن داده از libraryهای C++)

## 🔹 نکات مهم

| مورد | توضیح |
|------|--------|
| 🔸 نیاز به `unsafe` | باید پروژه را با گزینه “Allow unsafe code” در تنظیمات فعال کنید |
| ⚠️ با دقت استفاده شود | اشتباه در اشاره‌گر ممکن است باعث کرش یا خراب شدن حافظه شود |
| ☠️ GC نمی‌تواند ایمنی را تضمین کند | `fixed` یا `GCHandle` لازم است برای pin کردن |
| 💡 Span و Memory جایگزین ایمن | در اکثر کارها بهتر است از `Span<T>` و `MemoryMarshal` استفاده کنید، ولی اگر با API native کار دارید، `unsafe` هنوز لازم است |

---

## ✅ جمع‌بندی
`unsafe` در C#:
- برای دسترسی مستقیم و سریع به حافظه‌ی unmanaged استفاده می‌شود؛  
- در اپ‌های معمولی کم دیده می‌شود، اما در حوزه‌های  
  **گرافیک، رمزنگاری، شبکه، بازی، و interop با C/C++** کاملاً کاربرد دارد؛  
- همراه با `fixed` یا `GCHandle` استفاده می‌شود تا حافظه در طول عملیات ثابت بماند؛  
- قدرت زیاد دارد، ولی مسئولیت ایمنی کاملاً با شماست.
