سیستمی در .NET که **memory object های استفاده نشده را آزاد می‌کند**.

به دلیل یک اصل مهم:

> اکثر objectها عمر کوتاهی دارند.

بنابراین:

- در GC بیشتر **Gen0** را پاکسازی می‌کند
- عملیات سریع‌تر می‌شود
- و performance بهتر می‌شود
---
## چند نسل دارد

### 1. Generation 0 (Gen 0)

- محل ذخیره **objectهای تازه ساخته شده**
- کوچک‌ترین و سریع‌ترین بخش GC
- بیشتر objectها در همین مرحله جمع‌آوری می‌شوند

مثال:
```csharp

var obj = new MyClass()


```

این object ابتدا وارد **Gen0** می‌شود.

### 2. Generation 1 (Gen 1)

- سطح **میانی**
- در این حالت object هایی که از Gen0 زنده مانده‌اند به اینجا منتقل می‌شوند
- نقش آن **buffer بین Gen0 و Gen2** است

---

### 3. Generation 2 (Gen 2)

- برای objectهایی که **عمر طولانی دارند**
- مثل:
    - static objects
    - cache
    - singleton

جمع‌آوری Gen2 **کندتر و سنگین‌تر** است.

---

## Large Object Heap (LOH)

تمامی object های بزرگ‌تر از **85KB** در بخش جداگانه‌ای به نام:

**LOH (Large Object Heap)**

ذخیره می‌شوند.

مثال:

- آرایه arrayهای بزرگ
- تصاویر
- بافر bufferهای بزرگ

# نحوه رفتار Garbage Collector

عملکرد GC طبق چند مرحله کار می‌کند:

### 1. Allocation

وقتی object ساخته می‌شود:

```csharp

var obj = new object();

```

در **Gen0** قرار می‌گیرد.

---

### 2. Mark

ابتدا GC بررسی می‌کند کدام objectها هنوز **reference دارند**.

-  وضعیت object دارای reference → زنده
- بدون reference → قابل حذف

---

### 3. Sweep

در این حالت objectهای بدون reference از حافظه حذف می‌شوند.

---

### 4. Compact

حافظه فشرده می‌شود تا **fragmentation** از بین برود.

---

# Promotion

اگر object بعد از GC هنوز زنده باشد:
```markdown

Gen0 → Gen1 → Gen2

```

به این فرآیند **Promotion** گفته می‌شود.

میتوان گفت Garbage Collector در .NET از مدل Generational استفاده می‌کند و شامل سه سطح Gen0، Gen1 و Gen2 است. Objectهای جدید ابتدا وارد Gen0 می‌شوند و اگر بعد از جمع‌آوری زنده بمانند به نسل‌های بالاتر منتقل می‌شوند. هدف این طراحی بهبود performance است زیرا اکثر objectها عمر کوتاهی دارند.
