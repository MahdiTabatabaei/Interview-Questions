## Large Object Heap (LOH)

برای object های **بزرگ‌تر از 85KB**

مثلا:

- آرایه بزرگ
- تصاویر

---

در واقع **LOH خودش یک بخش از Heap است**.

در .NET حافظه به این شکل مدیریت می‌شود:
```markdown

RAM
 ├─ Stack
 └─ Managed Heap
      ├─ Gen 0
      ├─ Gen 1
      ├─ Gen 2
      └─ Large Object Heap (LOH)


```
### Stack

برای موارد زیر استفاده می‌شود:

- متغیرهای محلی
- نوع reference ها
- و call stack متدها

سریع است و با پایان متد آزاد می‌شود.

---

### Heap

برای **object هایی که با `new` ساخته می‌شوند**.

این heap در .NET توسط **Garbage Collector** مدیریت می‌شود و چند بخش دارد:

- **Gen0** → آبجکت‌های تازه ساخته شده
- **Gen1** → آبجکت‌هایی که کمی عمر کرده‌اند
- **Gen2** → آبجکت‌های با عمر طولانی
- **LOH** → آبجکت‌های خیلی بزرگ

---

### Large Object Heap (LOH)

وقتی اندازه یک object **بزرگ‌تر از حدود 85KB** باشد، مستقیم در **LOH** قرار می‌گیرد.

مثال:
```csharp

byte[] data = new byte[100000];

```
این آرایه بزرگ است → در **LOH** ذخیره می‌شود.

---

### چرا LOH جداست؟

جابجا کردن object های بزرگ برای GC هزینه زیادی دارد.

بنابراین .NET آن‌ها را در یک heap جدا نگه می‌دارد تا:

- کمتر جابجا شوند
- عملیات GC سریع‌تر شود

---

### یک نکته مهم

برخلاف heap معمولی:

- درواقع **LOH معمولاً compact نمی‌شود**
- بنابراین ممکن است **fragmentation** ایجاد شود.
