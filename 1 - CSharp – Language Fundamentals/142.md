تفاوت اصلی در **محدودیت ظرفیت (capacity)** و **رفتار هنگام پر شدن صف** است.

---

# UnboundedChannel

کانالی است که **هیچ محدودیت ظرفیتی ندارد**.

```csharp
var channel = Channel.CreateUnbounded<int>();
```

ویژگی‌ها:

- ظرفیت نامحدود
- `WriteAsync` تقریباً **هیچ‌وقت منتظر نمی‌شود**
- اگر producer سریع باشد ⇒ صف دائماً بزرگ می‌شود

مثال:

```
Producer → 10000 item
Consumer → 100 item
```

نتیجه:

```
Queue size ↑
Memory usage ↑
```

ریسک:

```
OutOfMemory
```

---

# BoundedChannel

کانالی است که **ظرفیت محدود دارد**.

```csharp
var channel = Channel.CreateBounded<int>(100);
```

یعنی حداکثر **100 آیتم** در صف.

اگر صف پر شود:

```
Producer باید صبر کند
```

مثال:

```
Producer → WriteAsync
Channel full
↓
await
↓
Consumer چند آیتم می‌خواند
↓
Producer ادامه می‌دهد
```

این همان **Back‑pressure** است.

---

# تفاوت رفتار هنگام پر شدن

در `BoundedChannel` می‌توان رفتار را کنترل کرد:

```csharp
new BoundedChannelOptions(100)
{
    FullMode = BoundedChannelFullMode.Wait
}
```

حالت‌ها:

- `Wait`  
  producer صبر می‌کند (رایج‌ترین)

- `DropNewest`  
  جدیدترین پیام حذف می‌شود

- `DropOldest`  
  قدیمی‌ترین پیام حذف می‌شود

- `DropWrite`  
  آیتم جدید اصلاً نوشته نمی‌شود

---

# مقایسه سریع

UnboundedChannel

- ظرفیت: نامحدود  
- back‑pressure: ندارد  
- producer: تقریباً هیچ‌وقت صبر نمی‌کند  
- ریسک: مصرف زیاد حافظه  

BoundedChannel

- ظرفیت: محدود  
- back‑pressure: دارد  
- producer: ممکن است await شود  
- مناسب سیستم‌های پایدار

---

# چه زمانی از هرکدام استفاده کنیم؟

### Unbounded
وقتی:

- حجم داده کم است
- memory مهم نیست
- producer تقریباً هم‌سرعت consumer است

مثال:

```
logging pipeline
```

---

### Bounded
وقتی:

- سیستم high‑load دارد
- memory مهم است
- producer سریع‌تر از consumer است

مثال:

```
web server
background job queue
message processing
```

---

# خلاصه 

درواقع **UnboundedChannel ظرفیت نامحدود دارد و producer تقریباً هیچ‌وقت بلوکه نمی‌شود، اما BoundedChannel ظرفیت محدود دارد و وقتی صف پر شود با اعمال back‑pressure باعث می‌شود producer منتظر بماند یا طبق policy مشخص آیتم‌ها حذف شوند.**
