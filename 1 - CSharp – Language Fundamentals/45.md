## 💡 تعریف ساده‌ی ThreadPool

تعریف **ThreadPool** یک **استخر (Pool)** از **نخ‌های آماده‌ی استفاده‌ی مجدد (Reusable Threads)** است

که **CLR (.NET Runtime)** آن را مدیریت می‌کند تا هر بار نیاز نباشد نخ جدید بسازیم یا نابود کنیم.

---

### 🔹 بدون ThreadPool:

هر بار که `new Thread()` می‌زنی، یک نخ جدید از سیستم‌عامل گرفته می‌شود.

- ساخت نخ = سنگین ✅
- نابود کردن نخ = سنگین ❌
- اگر تعداد Threadها زیاد شود = Context Switching زیاد = افت Performance ⚠️

---

### 🔹 با ThreadPool:

نخ‌هایی از قبل ساخته شده‌اند و آماده‌ی اجرای کارند.

وقتی کاری داری، فقط یکی را قرض می‌گیری، اجرا می‌کنی، بعد نخ به Pool برمی‌گردد.

```markdown

---------------------------
| Thread | Thread | Thread |
---------------------------
        ↑       ↑
   Queue of Tasks waiting


```

⚙️ ویژگی‌های کلیدی ThreadPool

![[15_ThreadPool_Properties.png]]

🧩 مثال ساده استفاده از ThreadPool

```csharp

using System;
using System.Threading;

class Program
{
    static void Main()
    {
        for (int i = 0; i < 5; i++)
        {
            ThreadPool.QueueUserWorkItem(DoWork, i);
        }

        Console.ReadLine();
    }

    static void DoWork(object state)
    {
        Console.WriteLine($"Task {state} running on thread {Thread.CurrentThread.ManagedThreadId}");
    }
}

```

🔹 در این مثال:

- کارها (`DoWork`) به **ThreadPool** صف می‌شوند.
- نخ‌ها از قبل آماده‌اند.
- هیچ `new Thread()` ساخته نمی‌شود.

---

## 🧠 چه زمانی ThreadPool استفاده می‌شود؟

- توسط `Task.Run()` و `async/await`
- توسط `Parallel.For` و TPL (Task Parallel Library)
- توسط ASP.NET و SignalR برای پردازش requestها

> یعنی در بیشتر برنامه‌های مدرن C#، تو مستقیم با ThreadPool کار نمی‌کنی — بلکه از طریق Taskها.

## 🚦 محدودیت‌ها و نکات مهم

- نخ‌های ThreadPool برای کارهای **طولانی یا بلاک‌شده** مناسب نیستند.
    
    اگر کاری زیاد طول می‌کشد یا Thread را بلوکه می‌کند → نخ‌ها تمام می‌شوند!
    
- نباید در ThreadPool:
    
    - از `Thread.Sleep()` زیاد استفاده کنید.
    - کاری سنگین (مثل محاسبات بسیار بزرگ یا I/O سنگین بلاک‌شده) انجام دهید.

---

## 🌐 ارتباط با Task

در واقع:
```csharp

Task.Run(() => DoWork());

```
≡ از درون:
```csharp

ThreadPool.QueueUserWorkItem(...)

```

یعنی Task فقط یک **رابط دوستانه‌تر و امن‌تر** برای کار با ThreadPool است.

## 🔑 جمع‌بندی 

> در واقع ThreadPool مجموعه‌ای از نخ‌های از پیش ساخته‌شده است که توسط CLR مدیریت می‌شوند تا کارهای کوتاه و پرتکرار بدون هزینه‌ی زیاد ساخت و نابودی نخ اجرا شوند.
> 
 و Task‌ها به‌صورت پیش‌فرض از ThreadPool استفاده می‌کنند، و این باعث بهینه‌شدن Performance نسبت به ساخت Threadهای تکی می‌شود.
