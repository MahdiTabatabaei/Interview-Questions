درواقع **Preprocessor Directives** در C# دستوراتی هستند که قبل از مرحله کامپایل اجرا می‌شوند و به کامپایلر می‌گویند **کدام بخش از کد باید کامپایل شود یا نشود**.  

این دستورات با علامت `#` شروع می‌شوند و برخلاف کد معمولی C#، **منطق اجرایی برنامه نیستند** بلکه فقط روی **فرآیند کامپایل** تأثیر می‌گذارند.

به زبان ساده:  
> تعریف Preprocessor Directive ها به کامپایلر دستور می‌دهند چگونه کد را قبل از تبدیل شدن به IL پردازش کند.

---

# مهم‌ترین Preprocessor Directive ها در C#

## 1️⃣ ‎`#define`
برای تعریف یک **symbol** در زمان کامپایل استفاده می‌شود.

```csharp
#define DEBUG_MODE
```

---

## 2️⃣ ‎`#if` و `#endif`
برای **کامپایل شرطی** استفاده می‌شود.

```csharp
#define DEBUG_MODE

#if DEBUG_MODE
Console.WriteLine("Debug Mode");
#endif
```

اگر `DEBUG_MODE` تعریف شده باشد، کد کامپایل می‌شود؛ در غیر این صورت کاملاً حذف می‌شود.

---

## 3️⃣ ‎`#else` و `#elif`

```csharp
#define VERSION1

#if VERSION1
Console.WriteLine("Version 1");
#elif VERSION2
Console.WriteLine("Version 2");
#else
Console.WriteLine("Default Version");
#endif
```

---

## 4️⃣ ‎`#undef`
برای حذف یک symbol استفاده می‌شود.

```csharp
#define TEST
#undef TEST
```

بعد از `#undef` دیگر آن symbol وجود ندارد.

---

## 5️⃣ ‎`#warning`
برای تولید **هشدار در زمان کامپایل**.

```csharp
#warning This code needs review
```

کامپایل می‌شود اما Warning می‌دهد.

---

## 6️⃣ ‎`#error`
برای **متوقف کردن کامپایل**.

```csharp
#error This code should not be compiled
```

کامپایلر خطا می‌دهد و build متوقف می‌شود.

---

## 7️⃣ ‎`#region` و `#endregion`

برای **گروه‌بندی کد در IDE** (مثل Visual Studio).

```csharp
#region Database Methods

void Save() { }
void Delete() { }

#endregion
```

این فقط برای مرتب‌سازی کد در editor است و روی کامپایل اثر ندارد.

---

## 8️⃣ ‎`#nullable`
برای کنترل **nullable reference types**.

```csharp
#nullable enable
string? name = null;
```

---

# مثال کاربردی واقعی

فرض کن می‌خواهیم لاگ‌ها فقط در حالت Debug اجرا شوند.

```csharp
#define DEBUG

class Program
{
    static void Main()
    {
        #if DEBUG
        Console.WriteLine("Debug information");
        #endif

        Console.WriteLine("Application running");
    }
}
```

در **Release Build** کد داخل `#if DEBUG` اصلاً در برنامه وجود نخواهد داشت.

---

# تفاوت `#if` با `if` معمولی

| ویژگی | `#if` | `if` |
|------|------|------|
| زمان اجرا | زمان کامپایل | زمان اجرا |
| حذف کد | بله | خیر |
| نوع شرط | symbol | متغیر |

مثال:

### Preprocessor
```csharp
#if DEBUG
Console.WriteLine("Debug");
#endif
```

### Runtime
```csharp
if(isDebug)
{
    Console.WriteLine("Debug");
}
```

در حالت اول کد حتی در برنامه نهایی وجود ندارد.

# کاربردهای رایج در پروژه‌های واقعی

✅ فعال یا غیرفعال کردن **Debug code**  
✅ پشتیبانی از **چند پلتفرم**  
✅ مدیریت **نسخه‌های مختلف برنامه**  
✅ خاموش کردن موقت بخش‌هایی از کد  
✅ مدیریت **Nullable behavior**

---

✅ **خلاصه**

دستورات Preprocessor Directives دستوراتی هستند که با `#` شروع می‌شوند و قبل از کامپایل اجرا می‌شوند تا تعیین کنند چه بخشی از کد باید کامپایل شود، هشدار یا خطا ایجاد شود یا کد در IDE سازماندهی گردد.
