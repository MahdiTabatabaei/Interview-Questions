مدیریت **Concurrency Control** یعنی جلوگیری از مشکل وقتی که **چند کاربر یا چند Thread همزمان می‌خواهند یک داده مشترک را بخوانند یا تغییر دهند**. این موضوع در دو سطح مهم بررسی می‌شود:

- **Database / EF Level (در Entity Framework)**
- **Thread Level (داخل خود برنامه و Threadها)**

هر کدام روش‌های متفاوتی دارند.

---

# 1. Concurrency Control در Entity Framework

وقتی دو کاربر همزمان یک رکورد را ویرایش کنند، ممکن است **آخرین ذخیره تغییرات، تغییرات قبلی را overwrite کند**. EF برای جلوگیری از این مشکل چند روش دارد.

## 1. Optimistic Concurrency (روش رایج)

فرض می‌کند **تداخل کم است** و هنگام ذخیره بررسی می‌کند آیا داده تغییر کرده یا نه.

### روش RowVersion / Timestamp

در دیتابیس یک ستون version داریم.

مثال در EF:
```csharp

public class Product
{
    public int Id { get; set; }
    public string Name { get; set; }

    [Timestamp]
    public byte[] RowVersion { get; set; }
}

```
وقتی EF update می‌زند:

```sql

UPDATE Products
SET Name = 'NewName'
WHERE Id = 1 AND RowVersion = @originalVersion

```

اگر RowVersion تغییر کرده باشد:

```markdown

DbUpdateConcurrencyException

```
یعنی یک نفر دیگر رکورد را تغییر داده است.

### مدیریت Exception
```csharp

try
{
    context.SaveChanges();
}
catch (DbUpdateConcurrencyException ex)
{
    // reload data
}

```
در اینجا می‌توان:

- reload
- merge
- یا پیغام به کاربر داد.

---

## 2. Pessimistic Concurrency

در این روش **داده قبل از ویرایش lock می‌شود**.

مثال SQL:
```sql

SELECT * FROM Products WITH (UPDLOCK)
WHERE Id = 1

```
یا Transaction با isolation level.

در EF معمولاً از Transaction استفاده می‌شود.

---

# 2. Concurrency Control در Thread Level

این مشکل وقتی رخ می‌دهد که **چند Thread به یک resource مشترک دسترسی دارند**.

مثال مشکل:
```csharp

int counter = 0;

Parallel.For(0,1000,i =>
{
    counter++;
});

```
نتیجه ممکن است **کمتر از 1000** شود چون [[1 - CSharp – Language Fundamentals/61| race condition]]  رخ می‌دهد.

---

# روش‌های حل در Thread Level

## 1. lock

ساده‌ترین روش.
```csharp

private static object locker = new object();

lock(locker)
{
    counter++;
}

```
فقط یک Thread وارد بخش بحرانی می‌شود.

---

## 2. Monitor

نسخه پیشرفته‌تر lock.
```csharp

Monitor.Enter(locker);

try
{
    counter++;
}
finally
{
    Monitor.Exit(locker);
}

```
---

## 3. Mutex

برای synchronization بین **processها**.
```csharp

Mutex mutex = new Mutex();

mutex.WaitOne();
counter++;
mutex.ReleaseMutex();

```
---

## 4. Semaphore / SemaphoreSlim

برای محدود کردن تعداد Threadها.
```csharp

SemaphoreSlim sem = new SemaphoreSlim(3);

await sem.WaitAsync();

try
{
    // code
}
finally
{
    sem.Release();
}

```
## 5. Interlocked

برای عملیات ساده مثل increment.

خیلی سریع است.
```csharp

Interlocked.Increment(ref counter);

```

# یک مثال واقعی

فرض کن:

دو کاربر یک محصول را ویرایش می‌کنند.

کاربر A:
```markdown

Price = 100

```
کاربر B:
```markdown

Price = 120

```
اگر Concurrency نباشد:

آخرین Save → قبلی را حذف می‌کند.

با **RowVersion**:

کاربر دوم خطای concurrency می‌گیرد و باید داده را دوباره بخواند.

---

✅ **خلاصه**

Concurrency در دو سطح مدیریت می‌شود:

1️⃣ **EF / Database level**

- Optimistic concurrency (RowVersion)
- Pessimistic concurrency
- Transaction isolation

2️⃣ **Thread level**

- lock
- Monitor
- Mutex
- Semaphore
- Interlocked
