یعنی **بعد از ساخته شدن قابل تغییر نیست**.

مثال:
```csharp

string name = "Ali";

name = name + " Reza";

```
در واقع:

1️⃣ در این حالت object جدید ساخته می‌شود

2️⃣ مقدار جدید داخل آن قرار می‌گیرد

---

✅ دلیل immutable بودن:

- **thread safety**
- **performance در string pool**
- **security**

---
# 1️⃣ Thread Safety

چون string تغییر نمی‌کند، چند thread می‌توانند **همزمان از یک رشته استفاده کنند بدون اینکه داده خراب شود**.

### مثال
```csharp

string message = "Hello";

Task.Run(() => Console.WriteLine(message));
Task.Run(() => Console.WriteLine(message));
Task.Run(() => Console.WriteLine(message));

```
همه thread ها دارند از **همان object** استفاده می‌کنند.

اگر string قابل تغییر بود ممکن بود این اتفاق بیفتد:

Thread1:
```markdown

Hello → Hallo

```
Thread2 همزمان:
```markdown

Hello → Hella

```
در نتیجه داده خراب می‌شد.

اما چون string **immutable** است هیچ thread نمی‌تواند آن را تغییر دهد.

اگر کسی تغییر بدهد در واقع **string جدید ساخته می‌شود**.

مثال:
```csharp

string a = "Hello";
string b = a;

a = "Hi";

```
نتیجه:
```markdown

a → "Hi"
b → "Hello"

```

# 2️⃣ Performance در String Pool

در ‎.NET‎ یک چیزی به نام **String Intern Pool** وجود دارد. [[String Intern Pool]]

اگر چند بار یک رشته یکسان بنویسیم، **یک object مشترک استفاده می‌شود**.

### مثال
```csharp

string a = "Ali";
string b = "Ali";

```
در حافظه:
```markdown

String Pool
   "Ali"
    ↑
   a , b

```
هر دو اشاره می‌کنند به **یک object**.

اگر string mutable بود مشکل ایجاد می‌شد:

فرض کن:
```csharp

a = "Ali"
b = "Ali"

```
آن وقت b هم ناخواسته می‌شد:
```markdown

"Mli"

```
به همین دلیل **string باید immutable باشد تا pooling امن باشد**.

این باعث **صرفه‌جویی در حافظه و سرعت بیشتر** می‌شود.

---

# 3️⃣ Security

درواقع immutable بودن باعث می‌شود **داده‌ای که به متدها پاس می‌دهیم تغییر نکند**.

### مثال

فرض کن یک متد رمز عبور را بررسی می‌کند:
```csharp

void CheckPassword(string password)
{
    // بررسی رمز
}

```
استفاده:
```csharp

string pwd = "123456";

CheckPassword(pwd);

```
اگر string mutable بود ممکن بود متد داخلش آن را تغییر دهد:
```markdown

123456 → hacked

```
ولی چون immutable است **هیچ متدی نمی‌تواند مقدار اصلی را تغییر دهد**.

اگر تغییری انجام شود:
```markdown

string جدید ساخته می‌شود

```
پس مقدار اولیه امن باقی می‌ماند.
