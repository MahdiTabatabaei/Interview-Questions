در برنامه‌های async، در واقع Memory Leak زمانی رخ می‌دهد که **Task یا objectهای مرتبط با آن هنوز reference داشته باشند و GC نتواند آنها را حذف کند**.

### دلایل رایج

• نگهداری Task در Collection بدون پاکسازی
• استفاده از event بدون unsubscribe
• نگه داشتن ارجاع توسط closureهایی که object بزرگ را نگه می‌دارند [[Closure]]
• ایجاد async loopهای بی‌پایان
• استفاده نادرست از CancellationToken

## مثال Memory Leak

```csharp

static List<Task> tasks = new List<Task>();

async Task Process()
{
    await Task.Delay(1000);
}

void Run()
{
    for(int i=0;i<100000;i++)
    {
        tasks.Add(Process());
    }
}

```
اینجا Taskها در List باقی می‌مانند و GC نمی‌تواند حذف کند.

---

### راه‌حل

- پاک کردن collection
- استفاده از `CancellationToken`
- فراخوانی unsubscribe event


## مثال Memory Leak در C# — استفاده از Event بدون Unsubscribe

این دقیقاً همان چیزی است که ازت پرسیده بود:

اگر عضو یک Event بشوی و آخرش Unsubscribe نکنی، GC نمی‌تواند شیء را پاک کند ⇒ **Memory Leak**

### مثال بد (Leak دارد)

```csharp

public class Publisher
{
    public event Action SomethingChanged;
}

public class Consumer
{
    private readonly Publisher _publisher;

    public Consumer(Publisher publisher)
    {
        _publisher = publisher;

        // ❌ مشکل: این event باعث می‌شود این object هرگز جمع‌آوری نشود
        _publisher.SomethingChanged += OnChanged;
    }

    private void OnChanged()
    {
        Console.WriteLine("Event received");
    }
}

```
تا زمان زنده بودن Publisher، Consumer حذف نمی‌شود.

---

### نسخه درست (بدون Memory Leak)
```csharp

public class Consumer : IDisposable
{
    private readonly Publisher _publisher;

    public Consumer(Publisher publisher)
    {
        _publisher = publisher;
        _publisher.SomethingChanged += OnChanged;
    }

    private void OnChanged()
    {
        Console.WriteLine("Event received");
    }

    public void Dispose()
    {
        // ✔ پاک‌سازی صحیح
        _publisher.SomethingChanged -= OnChanged;
    }
}

```
با این کار GC می‌تواند Consumer را آزاد کند.
