**مفهوم:** `yield` به ما اجازه می‌دهد که یک **Iterative Navigation** بسازیم بدون اینکه کل لیست را در حافظه لود کنیم. این دستور داده‌ها را به صورت “تنبل” (Lazy) تولید می‌کند. یعنی هر بار که حلقه `foreach` یک آیتم می‌خواهد، کد اجرا می‌شود تا آن آیتم را برگرداند و سپس وضعیت متد حفظ می‌شود تا درخواست بعدی.

**مثال:**
```csharp

public IEnumerable<int> GetNumbers() {
    yield return 1;
    yield return 2;
    yield return 3;
}
// هنگام فراخوانی، هر بار فقط یک عدد تولید و به حلقه فرستاده می‌شود.

```

---

درواقع `yield return` در C# برای **تولید تدریجی داده‌ها در یک Iterator** استفاده می‌شود. یعنی به‌جای اینکه همهٔ نتایج را یک‌جا در حافظه بسازیم، **هر بار که مصرف‌کننده درخواست کرد، عنصر بعدی تولید می‌شود**. این کار هم **حافظه کمتر مصرف می‌کند** هم برای داده‌های بزرگ بسیار مفید است.

## مثال عملی: تولید اعداد زوج تا یک حد مشخص

بدون `yield`:

```csharp
using System;
using System.Collections.Generic;

class Program
{
    static List<int> GetEvenNumbers(int max)
    {
        var list = new List<int>();

        for (int i = 0; i <= max; i++)
        {
            if (i % 2 == 0)
                list.Add(i);
        }

        return list;
    }

    static void Main()
    {
        foreach (var n in GetEvenNumbers(10))
        {
            Console.WriteLine(n);
        }
    }
}
```

مشکل:  
ابتدا **کل لیست ساخته می‌شود** سپس مصرف می‌شود.

---

## همان مثال با `yield return`

```csharp
using System;
using System.Collections.Generic;

class Program
{
    static IEnumerable<int> GetEvenNumbers(int max)
    {
        for (int i = 0; i <= max; i++)
        {
            if (i % 2 == 0)
                yield return i;
        }
    }

    static void Main()
    {
        foreach (var n in GetEvenNumbers(10))
        {
            Console.WriteLine(n);
        }
    }
}
```

## چه اتفاقی می‌افتد؟

وقتی `foreach` اجرا می‌شود:

1. متد شروع می‌شود.
2. وقتی به `yield return` می‌رسد → مقدار را برمی‌گرداند.
3. اجرای متد **متوقف می‌شود ولی state حفظ می‌شود**.
4. در iteration بعدی → از همان نقطه ادامه می‌دهد.

پس خروجی:

```
0
2
4
6
8
10
```

## مثال واقعی‌تر: خواندن فایل بزرگ (کاربرد عملی)

فرض کنید فایل لاگ چند گیگابایتی دارید.

### بدون yield (بد)

```csharp
List<string> ReadLines()
{
    return File.ReadAllLines("log.txt").ToList();
}
```

کل فایل یک‌جا در RAM لود می‌شود.

---

### با yield (بهینه)

```csharp
IEnumerable<string> ReadLines()
{
    using var reader = new StreamReader("log.txt");

    string line;
    while ((line = reader.ReadLine()) != null)
    {
        yield return line;
    }
}
```

مصرف:

```csharp
foreach (var line in ReadLines())
{
    if (line.Contains("ERROR"))
        Console.WriteLine(line);
}
```

ویژگی مهم:  
فقط **یک خط در هر لحظه در حافظه است**.

## یک مثال جالب‌تر: تولید اعداد Fibonacci

```csharp
IEnumerable<int> Fibonacci(int count)
{
    int a = 0;
    int b = 1;

    for (int i = 0; i < count; i++)
    {
        yield return a;

        int temp = a;
        a = b;
        b = temp + b;
    }
}
```

استفاده:

```csharp
foreach (var n in Fibonacci(10))
{
    Console.WriteLine(n);
}
```

## نکته مهم
قابلیت `yield return` در واقع توسط کامپایلر به یک **state machine + IEnumerator** تبدیل می‌شود.

یعنی این:

```csharp
yield return x;
```

در پشت صحنه تقریباً مثل یک کلاس `IEnumerator` ساخته می‌شود.

---

✅ جمع‌بندی

قابلیت `yield return` باعث می‌شود:

- داده‌ها **lazy** تولید شوند
- حافظه کمتر مصرف شود
- مناسب برای **داده‌های بزرگ یا نامحدود**
- در متدهایی که `IEnumerable<T>` برمی‌گردانند استفاده می‌شود
