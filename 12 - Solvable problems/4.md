اگر قرار است API شما یک عدد ۲۰۰ رقمی دریافت کند، استفاده از انواع عددی معمول مثل `int`, `long`, حتی `decimal` کافی نیست، چون این نوع‌ها محدودیت اندازه دارند.

در #C بهترین راه‌حل‌ها معمولاً این‌ها هستند:

- دریافت عدد به صورت `string`
- استفاده از `BigInteger`
- اعتبارسنجی طول و فرمت عدد

کتابخانه `System.Numerics.BigInteger` برای اعداد بسیار بزرگ طراحی شده است.

نمونه کامل:

```csharp
using Microsoft.AspNetCore.Mvc;
using System.Numerics;

namespace LargeNumberApi.Controllers
{
    [ApiController]
    [Route("api/[controller]")]
    public class NumberController : ControllerBase
    {
        [HttpPost]
        public IActionResult ReceiveLargeNumber([FromBody] LargeNumberRequest request)
        {
            // اعتبارسنجی اولیه
            if (string.IsNullOrWhiteSpace(request.Number))
            {
                return BadRequest("Number is required.");
            }

            // فقط عدد بودن
            if (!BigInteger.TryParse(request.Number, out BigInteger bigNumber))
            {
                return BadRequest("Invalid number format.");
            }

            // بررسی تعداد رقم
            if (request.Number.Length > 200)
            {
                return BadRequest("Number must not exceed 200 digits.");
            }

            // نمونه عملیات
            BigInteger result = bigNumber * 2;

            return Ok(new
            {
                Original = request.Number,
                Doubled = result.ToString(),
                Digits = request.Number.Length
            });
        }
    }

    public class LargeNumberRequest
    {
        public string Number { get; set; }
    }
}
```

نمونه Request:

```json
{
  "number": "12345678901234567890123456789012345678901234567890"
}
```

نمونه Response:

```json
{
  "original": "12345678901234567890123456789012345678901234567890",
  "doubled": "24691357802469135780246913578024691357802469135780",
  "digits": 50
}
```

نکات مهم طراحی API:

- عدد را به صورت `string` در JSON بفرستید
  - چون JavaScript و JSON برای اعداد خیلی بزرگ دقت را از دست می‌دهند.
- در DTO از `string` استفاده کنید نه `long`
- داخل Backend آن را به `BigInteger` تبدیل کنید
- حتماً validation داشته باشید:
  - فقط رقم باشد
  - طول مجاز
  - جلوگیری از حملات ورودی بزرگ

نمونه اشتباه:

```json
{
  "number": 999999999999999999999999999999999999999
}
```

چون ممکن است در فرانت یا serializer دقت از بین برود.

نمونه درست:

```json
{
  "number": "999999999999999999999999999999999999999"
}
```

برای ذخیره عدد ۲۰۰ رقمی در پایگاه داده دو نکته مهم وجود دارد:  
۱) نوع داده عددی معمولاً محدودیت دارد.  
۲) باید مطمئن شوید دقت (precision) از بین نمی‌رود.

دو راه‌حل اصلی وجود دارد.

------------------------------------------------

## 1. ذخیره به صورت عددی (Numeric / Decimal)

اگر مطمئن هستید فقط **عدد صحیح یا عدد با دقت مشخص** دارید، بهترین راه استفاده از نوع‌های **precision بالا** است.

### SQL Server

در SQL Server نوع `decimal` یا `numeric` حداکثر **38 رقم** را پشتیبانی می‌کند.

```sql
CREATE TABLE BigNumbers
(
    Id INT IDENTITY PRIMARY KEY,
    Value DECIMAL(38,0)
)
```

بنابراین **SQL Server به صورت مستقیم عدد ۲۰۰ رقمی را پشتیبانی نمی‌کند.**

پس برای ۲۰۰ رقم باید:

- آن را به صورت `VARCHAR` ذخیره کنید
یا
- عدد را به چند بخش تقسیم کنید

روش رایج:

```sql
CREATE TABLE BigNumbers
(
    Id INT IDENTITY PRIMARY KEY,
    Value VARCHAR(200)
)
```

### ذخیره در #C

```csharp
using System.Data.SqlClient;

string number = "12345678901234567890...."; // 200 digits

var command = new SqlCommand(
    "INSERT INTO BigNumbers(Value) VALUES (@value)", connection);

command.Parameters.AddWithValue("@value", number);

command.ExecuteNonQuery();
```

------------------------------------------------

## 2. ابزار PostgreSQL (بهترین گزینه برای اعداد خیلی بزرگ)

در PostgreSQL نوع داده‌ای به نام `NUMERIC` دارد که **تقریباً نامحدود** است.

می‌توانید precision دقیق تعریف کنید:

```sql
CREATE TABLE big_numbers (
    id SERIAL PRIMARY KEY,
    value NUMERIC(200,0)
);
```

یا حتی بدون محدودیت:

```sql
CREATE TABLE big_numbers (
    id SERIAL PRIMARY KEY,
    value NUMERIC
);
```

### ذخیره از #C

با `Npgsql`:

```csharp
using Npgsql;
using System.Numerics;

BigInteger number = BigInteger.Parse(
"12345678901234567890123456789012345678901234567890");

using var conn = new NpgsqlConnection(connectionString);
conn.Open();

var cmd = new NpgsqlCommand(
"INSERT INTO big_numbers(value) VALUES (@value)", conn);

cmd.Parameters.AddWithValue("value", number.ToString());

cmd.ExecuteNonQuery();
```

------------------------------------------------

## مقایسه SQL Server و PostgreSQL

| دیتابیس | حداکثر رقم |
|--------|-------------|
| SQL Server | 38 رقم |
| PostgreSQL | بسیار بزرگ (تقریباً نامحدود) |

بنابراین:

- اگر **SQL Server** استفاده می‌کنید → بهترین روش `VARCHAR(200)` است.  
- اگر **PostgreSQL** استفاده می‌کنید → بهتر است از `NUMERIC(200,0)` استفاده کنید.

------------------------------------------------

## نکته مهم در طراحی سیستم

در بسیاری از سیستم‌ها (مثلاً شماره کارت، شماره بلاک‌چین، شناسه‌ها) بهتر است حتی اگر عدد هستند، **به صورت string ذخیره شوند** چون:

- عملیات ریاضی روی آن‌ها انجام نمی‌شود
- محدودیت precision ندارند
- سریع‌تر و ساده‌تر مدیریت می‌شوند
