# 4. DbContext + Unique Constraint + Fluent API

```csharp
public class CinemaDbContext : DbContext
{
    public DbSet<Cinema> Cinemas { get; set; }
    public DbSet<Hall> Halls { get; set; }
    public DbSet<Movie> Movies { get; set; }
    public DbSet<ShowTime> ShowTimes { get; set; }
    public DbSet<Seat> Seats { get; set; }
    public DbSet<User> Users { get; set; }
    public DbSet<Reservation> Reservations { get; set; }

    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        modelBuilder.Entity<Reservation>()
            .HasIndex(r => new { r.SeatId, r.ShowTimeId })
            .IsUnique();  // جلوگیری از رزرو همزمان

        modelBuilder.Entity<Reservation>()
            .Property(r => r.Status)
            .HasConversion<string>();
    }
}
```

# 5. منطق رزرو با Transaction + Check Overlap

```csharp
public async Task<bool> ReserveSeatAsync(int userId, int seatId, int showTimeId)
{
    using var transaction = await _db.Database.BeginTransactionAsync();

    var showTime = await _db.ShowTimes.FindAsync(showTimeId);
    if (showTime == null) return false;

    var exists = await _db.Reservations
        .AnyAsync(r =>
            r.SeatId == seatId &&
            r.ShowTimeId == showTimeId &&
            r.Status == ReservationStatus.Confirmed);

    if (exists) return false;

    var reservation = new Reservation
    {
        UserId = userId,
        SeatId = seatId,
        ShowTimeId = showTimeId,
        Status = ReservationStatus.Pending,
        ReservedAt = DateTime.UtcNow,
        ExpireAt = DateTime.UtcNow.AddMinutes(10)
    };

    _db.Reservations.Add(reservation);

    await _db.SaveChangesAsync();
    await transaction.CommitAsync();

    return true;
}
```

در این حالت اگر دو کاربر به‌طور همزمان بخواهند رزرو کنند:

- اولین کسی که SaveChanges انجام دهد موفق می‌شود  
- دومی خطای Constraint Violation می‌گیرد  

البته در این کدی که نوشته‌شده هنوز در معرض [[1 - CSharp – Language Fundamentals/61| race condition]]  است.

# سناریوی مشکل ([[1 - CSharp – Language Fundamentals/61| race condition]] )

فرض کنید دو درخواست همزمان برسند:
```markdown

Request A
Request B

```
### مرحله 1

هر دو به این خط می‌رسند:

```csharp

var exists = await _db.Reservations.AnyAsync(...)

```

چون هنوز هیچ رزروی ثبت نشده:

```markdown

exists = false

```

برای هر دو درخواست.

---

### مرحله 2

هر دو از این شرط عبور می‌کنند:
```csharp

if (exists) return false;

```
---

### مرحله 3

هر دو این رکورد را می‌سازند:
```markdown

Reservation
SeatId = 10
ShowTimeId = 5

```
### مرحله 4

اگر **Unique Constraint** نداشته باشیم:

✅ هر دو رکورد ثبت می‌شوند

❌ دو نفر یک صندلی را رزرو کرده‌اند

سناریو دوباره:
```markdown

Request A
Request B

```
### هر دو از if عبور می‌کنند

اما هنگام SaveChanges:

- یکی موفق

# کد درست باید Exception را هم مدیریت کند
```csharp

public async Task<bool> ReserveSeatAsync(int userId, int seatId, int showTimeId)
{
    var reservation = new Reservation
    {
        UserId = userId,
        SeatId = seatId,

    try
    {
        await _db.SaveChangesAsync();

```
در این حالت حتی اگر **۱۰۰۰ درخواست همزمان** برسد:

✅ فقط یکی موفق می‌شود.

# 6. تحلیل سناریوی Deadlock

Deadlock زمانی ایجاد می‌شود که:

- Transaction A قفل روی Reservation می‌گیرد  
- Transaction B قفل روی ShowTime می‌گیرد  
- سپس A می‌خواهد ShowTime را قفل کند  
- B می‌خواهد Reservation را قفل کند  

### راه‌حل‌ها:

1. همیشه ترتیب دسترسی به جداول را ثابت نگه دارید  
   مثلا:
   ```
   First → ShowTime
   Second → Seat
   Third → Reservation
   ```

2. Transaction را **کوتاه** نگه دارید  
3. از Isolation Level مناسب استفاده کنید (مثلاً `ReadCommitted`)  
4. در SQL Server:
   ```
   WITH (UPDLOCK, ROWLOCK)
   ```

درصورتی که بخواهیم بررسی کنیم که یک کاربر نباید در بازه زمانی `FromTime` تا `ToTime` دو سانس هم‌پوشان رزرو کند. یعنی حتی اگر صندلی متفاوت باشد، کاربر نمی‌تواند همزمان در دو سالن باشد.

اینجا وارد بحث **Business Rule Validation قبل از Insert** می‌شویم.

# 📌 مثال واقعی

کاربر قبلاً رزرو دارد:

```
فیلم اول:  18:00 → 20:00
```

حالا می‌خواهد رزرو کند:

```
فیلم دوم: 19:30 → 21:30
```

بررسی می‌کنیم:

```
19:30 < 20:00 ✅
21:30 > 18:00 ✅
```

پس تداخل دارد ❌

---

مثال بدون تداخل:

```
فیلم اول: 18:00 → 20:00
فیلم دوم: 20:00 → 22:00
```

بررسی:

```
20:00 < 20:00 ❌ (برابر است، کمتر نیست)
```

پس تداخل ندارد ✅

(این رفتار استاندارد سیستم‌های رزرو است)

# ✅ نسخه کامل متد رزرو با این بررسی

```csharp
public async Task<string> ReserveSeatAsync(int userId, int seatId, int showTimeId)
{
    var showTime = await _db.ShowTimes
        .FirstOrDefaultAsync(s => s.Id == showTimeId);

    if (showTime == null)
        return "سانس یافت نشد";

    // ✅ بررسی تداخل زمانی کاربر
    var hasOverlap = await _db.Reservations
        .Include(r => r.ShowTime)
        .Where(r => r.UserId == userId &&
                    (r.Status == ReservationStatus.Pending ||
                     r.Status == ReservationStatus.Confirmed))
        .AnyAsync(r =>
            showTime.FromTime < r.ShowTime.ToTime &&
            showTime.ToTime > r.ShowTime.FromTime
        );

    if (hasOverlap)
        return "شما در این بازه زمانی قبلاً فیلم دیگری رزرو کرده‌اید.";

    var reservation = new Reservation
    {
        UserId = userId,
        SeatId = seatId,
        ShowTimeId = showTimeId,
        Status = ReservationStatus.Pending,
        ReservedAt = DateTime.UtcNow,
        ExpireAt = DateTime.UtcNow.AddMinutes(10)
    };

    _db.Reservations.Add(reservation);

    try
    {
        await _db.SaveChangesAsync();
        return "رزرو با موفقیت انجام شد";
    }
    catch (DbUpdateException)
    {
        return "این صندلی قبلاً رزرو شده است";
    }
}
```

# ⚠ نکته مهم معماری (خیلی مهم)

این بررسی فقط برای **Business Rule** است.  
اما باز هم ممکن است دو درخواست همزمان از همین چک عبور کنند.

پس اگر این قانون برایتان بسیار حیاتی است:

✅ می‌توانید روی `(UserId, FromTime, ToTime)` هم constraint منطقی بگذارید  
✅ یا از Isolation Level بالاتر استفاده کنید  
✅ یا Lock سطح کاربر بگذارید (User-based locking)
